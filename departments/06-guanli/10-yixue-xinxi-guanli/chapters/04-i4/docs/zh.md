# 第 4 章 · 信息安全管理：权限不是一张表，是一条能被审计的证据链

> **MOTTO:** 「慢藏诲盗，冶容诲淫。」——《周易·系辞上》
>
> **PROBLEM:** 一次院内自查：系统里 200 个可查病历的账号，43 个属于已离职或已转岗人员，其中 9 个在近半年仍有登录记录；再看 30 天的导出日志，6 个账号在凌晨 1 点到 4 点之间批量导出过病案，单次最多 1,800 条，没有一条触发告警。系统通过了等保测评，权限表也配得整整齐齐——问题在于，没有人定期看那张表和那份日志。

**双根因定位:** 环境逼迫（临床要快、要能跨科调阅，安全要严、要能拒绝，两个目标在同一秒冲突，默认结果永远是「先放开」）+ 知识积累（安全管理被当成买设备与过测评，缺的是把「谁在什么时候能动哪条数据」变成可验证、可追溯的证据链的能力）。

## 一、风险管理的起点是承认残余

安全管理的目标不是零风险——零风险意味着系统不可用。可行目标是：**识别资产、列出威胁、评估影响、把风险降到可接受并留下记录**。

一个够用的评估表四列就够：

| 资产 | 威胁 | 影响 | 现有控制 |
|---|---|---|---|
| 病案数据库 | 内部越权查询 | 隐私泄露、处罚 | 角色权限 + 日志（未审） |
| 检验接口 | 报文被篡改 | 错误结果进入病历 | 传输加密、未做完整性校验 |
| 运维终端 | 弱口令、共享账号 | 全库失守 | 域账号（部分本地管理员） |
| 备份介质 | 丢失、未加密 | 全量泄露 | 机房上锁，介质未加密 |

这张表的用处在于暴露「控制写在制度里、没落在系统里」的项。比如「日志未审」——有日志不等于有审计，日志只有被人定期看、并且能触发动作，才构成控制。评估结论要写成可验收的句子：「高风险项 2 个，Q2 前完成日志审阅制度化，责任人××」，而不是「已加强安全管理」。

风险接受要留痕。已知某台老设备不能打补丁，仍然接入内网，这个决定必须有人签字、有补偿措施（网段隔离、访问白名单）、有复核期限。没有签字的风险接受，出事时就是「无人知情」。

## 二、身份与权限：四个能被检查的判据

权限设计的原则人人会背，能落地的判据只有四条，且每条都能被抽查：

**唯一身份**。一人一号，禁止科室共用。共用账号一旦出事，日志只能指到科室，指不到人；而绝大多数内部泄露的第一层掩护就是共用账号。

**离职即停**。账号生命周期必须与人事异动联动。做不到实时联动，就做定期对账：每月拿在岗名单与账号列表做一次差集，差集必须清零。上面那个 43 个未停用账号的例子，缺的就是这一步——技术上十分钟，管理上一年没人做。

**最小权限 + 定期复核**。角色按岗位设，不按人设；授权要有到期时间，默认三个月，续期需重新确认。急诊、会诊等场景需要跨科调阅，用**紧急授权（break-glass）**：允许临时打开，但必须填写理由、强制弹窗告知、事后 24 小时内由科室负责人复核。把 break-glass 做成静默开关，等于给越权查询发了一张通行证。

**职责分离**。能改权限的人不能审日志，能导数据的人不能批自己的申请。小机构人手不足时允许兼任，但要书面写明兼的是哪几个角色，并由上级做补偿性复核。

权限模型的选择不必追新：角色模型（RBAC）覆盖八成场景，属性模型（ABAC）适合「同科室 + 主管医师 + 就诊期间」这类复合条件。混用时要把判定逻辑集中在一处，否则前端隐藏了按钮、后端没校验，等于没做。

## 三、加密与脱敏：三种手段，三种失效方式

加密解决「拿到文件也读不出」，脱敏解决「能读但不该认出是谁」。两者常被当成同义词，实际互补。

**传输加密**是底线，且要双向校验——只加密不校验证书，中间人可以合法地坐在中间。**存储加密**要区分介质加密（整盘）与字段加密（身份证号、联系方式），前者防丢盘，后者防越权查询与备份泄露。**密钥管理**是最容易被忽略的一环：密钥与应用配置放在同一台机器上，加密只剩形式。

脱敏有三种做法，各自有明确的失效场景：

| 做法 | 示例 | 失效场景 |
|---|---|---|
| 掩码 | 张*、138****1234 | 小样本中结合科室与日期仍可定位 |
| 泛化 | 出生日期→年龄段，住址→区县 | 泛化粒度过细（如 5 岁一段 + 邮编）仍可重识别 |
| 假名化 | 患者号替换为随机串 | 保留映射表，本质仍是个人信息 |

判断脱敏是否足够，不看处理了多少字段，看**准标识符的组合是否仍唯一**。一个实用的自检：任取一条记录，用剩余字段在数据集内做一次查询，命中条数是否为 1。命中为 1 就说明还能锁定个体。

假名化要额外管好映射表：单独存放、单独授权、访问留痕、设定销毁期。映射表和数据放在同一个库里，等于没做假名化。

## 四、审计：日志的五个要素与一条链

一条合格的访问日志至少包含五要素：**谁**（唯一账号，不是共用账号）、**何时**（统一时钟，精确到秒）、**从哪**（终端 IP 与设备标识）、**做了什么**（查询、修改、导出，含对象标识与条数）、**结果**（成功/失败/被拒）。缺「结果」的日志无法区分「尝试越权」与「越权成功」，这两种事件的处置完全不同。

日志本身要满足三条：**不可篡改**（写入后只追加，或用哈希链把每条记录的摘要串起来）、**可检索**（能按患者、按账号、按时间反查）、**有保留期**（不少机构按半年滚动覆盖，恰好覆盖掉需要追溯的窗口）。

哈希链的做法很轻：

```js
// 每条日志的 hash 包含上一条的 hash，任何回改都会断链
function append(prev, entry) {
  const body = JSON.stringify({ ...entry, prevHash: prev.hash });
  return { ...entry, prevHash: prev.hash, hash: sha256(body) };
}

function verify(chain) {
  let prev = { hash: 'GENESIS' };
  for (const e of chain) {
    const body = JSON.stringify({ ...e, prevHash: prev.hash });
    if (sha256(body) !== e.hash || e.prevHash !== prev.hash) return false;
    prev = e;
  }
  return true;
}
```

真正的难点不在实现，在**审阅**。可操作的制度是：高危操作（批量导出、跨科调阅、权限变更）实时告警；全量日志每周抽样审阅并留记录；每季度做一次「异常账号」专项（长期未登录、非工作时间高频访问、单日导出量超阈值）。上面凌晨导出 1,800 条的例子，只要有一条「单日导出超 500 条即告警」的规则，就会在第一次发生时就暴露。

## 五、分级保护与事件响应：从「过测评」到「能处置」

分级保护的正确理解是**按重要程度分配控制强度**，不是一次性拿证。流程是：定级（业务受侵害的程度）→ 备案 → 建设整改 → 测评 → 持续监督。测评通过只说明某一天的状态合规，不说明此后一年有效；真正的持续性是月度自查与年度复测。

数据分类分级是同一件事的另一面。按敏感度分四级足够用：可公开（科室介绍、专家出诊）、内部（排班、库存）、敏感（病历、检验）、高敏（精神心理、遗传、生殖、传染病特定病种）。分级的结果要直接映射到控制：高敏数据默认不导出、不跨院区、不做批量查询，需要单独审批。

分级落地最常见的失败是「分完了没有控制差异」。表格上四级写得清楚，实际权限配置里四级共用一个角色，谁都能查。可验收的做法是：每一级选一个典型操作（如「按科室导出一个月明细」），实际执行一次，看是否被拦、是否触发审批、是否留痕。三个动作有一个不成立，分级就只停在文档上。

事件响应分四步，每步都要有预案而不是临场发挥：**遏制**（断网、停账号、保现场，先别急着重装系统）、**取证**（镜像磁盘、导出日志、记录时间线，注意取证动作本身要留痕）、**恢复**（从干净备份恢复，验证完整性）、**复盘**（根因、影响范围、整改项与责任人）。演练频率建议每年至少一次桌面推演、一次实操；只写预案不演练，第一次执行就是真事故。

对外报告要分清两类：涉及个人信息泄露的，按规定的时限与渠道报告并通知受影响个人；涉及系统故障的，按业务连续性预案处理。两类混在一起报，容易既误了时限又说不清影响。

备份与业务连续性要落到两个数上：**RTO**（能容忍停多久）与**RPO**（能容忍丢多少数据）。门诊系统 RTO 可能是 30 分钟、RPO 5 分钟；病案归档系统 RTO 一天也能接受。定了这两个数，备份策略、异地机房、双活还是主备，才有讨论的基础。只问「有没有灾备」而不问 RTO/RPO，答案必然是「有」，而真停机时没人知道要等多久。

「慢藏诲盗」，收藏不严等于招贼。信息安全的实质不是把门锁得更厚，而是让每一次开门都有人、有理由、有记录、有人复核。

## 六、代价与边界

- 本章账号数、导出条数均为**演算设定**，用于说明检查方法，不代表任何机构的真实审计结果。
- 提到的技术手段（哈希链、字段加密、break-glass）是常见工程做法，具体强度须按本机构定级结果与业务连续性要求确定，不能照抄阈值。
- 安全控制与临床效率存在真实冲突。跨科调阅每多一次确认，急诊就多几秒；本章主张的是**把摩擦放在可解释的地方**（紧急授权 + 事后复核），而不是取消摩擦。
- 安全不是一次性项目。任何「已通过测评所以安全」的结论都不成立；评价应看近 12 个月的告警处置率、账号对账差集、演练整改完成率。
