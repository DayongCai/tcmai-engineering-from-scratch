# 第 2 章 · 标准编码与法规伦理：编码错一位，统计算的是另一个病人

> **MOTTO:** 「名不正则言不顺，言不顺则事不成。」——《论语·子路》
>
> **PROBLEM:** 同一位慢性阻塞性肺病急性加重的病人，在 A 院首页写 J44.1，在 B 院写 J44.0，在 C 院因为合并肺炎直接写 J18.9。三次住院，三个主诊断，三条 DRG 路径，三份不同的资源消耗。省级平台把三家数据合起来算「COPD 住院费用」，得出的均值没有意义——它把三种病人混成了一种。而每一份首页在自己的医院里都「填完了、编码了、上传了」，没人报错。

**双根因定位:** 环境逼迫（临床要写得准、医保要结得对、上报要报得全，三套诉求压在同一串码上）+ 知识积累（编码长期被当成查表工作，缺的是分类学训练：分类是有轴心的，轴心一变，同一批病人在统计上就不是同一批人）。

## 一、标准体系分四层，缺一层就落不了地

卫生信息标准不是一份文件，是一组互相引用的规范，通常分四层：

| 层 | 内容 | 典型产物 | 失败的后果 |
|---|---|---|---|
| 基础类 | 数据元、值域、代码表 | 数据元目录、值域表 | 同一字段各处定义不同 |
| 方法类 | 分类与编码、术语体系 | 疾病分类、手术操作分类、术语集 | 同一病人各处编码不同 |
| 管理类 | 安全、隐私、质量、评估 | 分级规范、质控指标 | 有标准无人执行 |
| 应用类 | 病历、报告、交换格式 | 共享文档、资源接口 | 系统之间传得通、读不懂 |

四层是有依赖顺序的：基础类没定，方法类就是各写各的；方法类没定，应用类只能在接口里塞自由文本。工程上最容易犯的错是从应用层倒着修——先买一台集成引擎，把 A 系统的心电报告 PDF 传给 B 系统，看起来「打通了」，实际上 B 系统里那份 PDF 是不可计算的黑盒，出院摘要仍要人工抄一遍。

判断一次标准化投入是否有效，只看一件事：**新产生的数据里，有多少字段是可被机器直接比较的**。看板上有多少个接口、接入了多少家机构，都不算数。

## 二、分类是有轴心的，轴心决定你数的是谁

分类与编码的第一原则不是「码要短」，而是**每次归类只能沿一个轴心切**。ICD 的疾病分类以病因为主轴，解剖部位与病理类型作为补充轴；手术操作分类以术式与部位为主轴。轴心一旦混用，类目之间就会重叠，重叠处的病人被数两次或一次都没数到。

举个具体的：慢性阻塞性肺病在分类里既有「伴急性下呼吸道感染」（J44.0）也有「伴急性加重」（J44.1）。这两个类目在临床上经常同时成立——病人急性加重，诱因是感染。此时编码员必须选一个作为主码，另一个作为附加码。选哪个，取决于本次住院**主要治疗的是什么**，而不是哪个听起来更严重。选错不违反任何规则，只让统计口径偏一点点；一万份病历各偏一点点，科室的病种结构就变形了。

分类还有几条硬约束，可直接当验收标准：

- **穷尽且互斥**：每个病例必须能归入且只能归入一个类目（用附加码表达合并情况）。
- **可扩展但不可随意扩展**：扩展位要有规则，不能在科室层面自行加后缀，否则区域汇总时无法回收。
- **版本可追**：分类每若干年修订一次，跨版本比较必须带版本号，否则「发病率上升」可能只是类目拆分造成的假象。

到了数据元这一层，问题从「归到哪一类」变成「这个字段怎么填」。一个可交换的数据元至少要写全六项：名称、定义、数据类型、表示格式、值域、计量单位。中医与护理数据元的特点是值域多为枚举（舌质、脉象、面色、体位、自理能力），枚举必须封闭；一旦允许自由输入，「淡红」「淡红偏白」「淡红，偏暗」会同时存在，而系统不会报错，只在半年后的统计里表现为一个莫名其妙的长尾。

## 三、编码质量：五种错法，三个可算的数

编码错误不是随机的，按发生位置可以归成五类，每类的成因与对策不同：

| 错法 | 表现 | 成因 | 对策 |
|---|---|---|---|
| 漏编 | 有诊断未编 | 病程记录未提炼 | 编码前病历完整性核查 |
| 错编 | 类目选错 | 轴心理解错 | 编码员培训 + 双人复核 |
| 过度编码 | 把可疑诊断写成确诊 | 绩效导向 | 主诊断与证据链比对 |
| 主要诊断选错 | 选了资源消耗小的那个 | 规则不清 | 主诊断选择规则培训 |
| 版本混用 | 新老码并存 | 字典未同步 | 字典版本与生效日期绑定 |

三个能拿上台面的数：**编码一致率**（两名编码员对同一批病历独立编码，主诊断一致的比例，抽查 200 份即可算出）、**主诊断符合率**（与临床医师确认的主诊断一致的比例）、**入组失败率**（上传后未进入任何 DRG 组的比例）。前两个衡量人，后一个衡量数据。

三个数要一起看，单看一个会误导。编码一致率高，可能只是两人用了同一条错误规则；主诊断符合率高，可能因为医师照着编码员给的选项确认；入组失败率低，可能因为系统把可疑编码一律塞进了兜底组。可行的做法是每季度抽 100–200 份，两人独立编、不一致的逐份讨论并记录理由，讨论记录本身就是最好的培训材料——它积累的是本院的分歧点，而不是教科书上的通用规则。

一个最小的自动核查可以抓住相当一部分硬错误——性别与诊断矛盾、年龄与诊断矛盾、主诊断与主手术不匹配：

```js
// 规则示意：编码前置校验（不是完整编码器）
const RULES = [
  { code: /^N[7-9][0-9]/, sex: 'M', msg: '男性不应出现女性生殖系统主诊断' },
  { code: /^O[0-9]{2}/, sex: 'M', msg: '男性不应出现妊娠分娩相关主诊断' },
  { code: /^P[0-9]{2}/, maxAgeDays: 28, msg: '围生期诊断仅适用于 28 天以内' },
  { code: /^C[0-9]{2}/, requireEvidence: true, msg: '恶性肿瘤须有病理或影像证据字段' },
];

function validate({ code, sex, ageDays, evidence }) {
  return RULES
    .filter((r) => r.code.test(code))
    .filter((r) => (r.sex ? sex !== r.sex : false)
      || (r.maxAgeDays != null && ageDays > r.maxAgeDays)
      || (r.requireEvidence && !evidence))
    .map((r) => r.msg);
}
```

这类规则的价值不在聪明，而在**便宜且不误伤**：它抓的是逻辑上不可能的组合，不需要读懂病历。真正难的是「本次住院主要治疗了什么」这种语义判断，只能靠人，也只能靠抽样。把两类问题混在一个指标里考核，编码员会先去优化机器能查的那部分，语义质量反而下降。

映射表同样被低估。院内码到标准码、旧版到新版、中医病名到分类码，本质都是多对多，且**方向不对称**：正向可以精确、可以窄、可以宽，反向往往一对多。所以一张可用的映射表至少要有四列：源码、目标码、映射类型（精确/窄/宽/近似）、生效版本；再加两列治理信息：审核人、审核日期。缺了映射类型，下游就无法判断「合并统计」是否安全——把宽映射当精确映射用，是所有数据合并事故里最常见的一种。

## 四、互操作：传得通不等于读得懂

互操作分三级，很多人只做到第一级就宣布完成：**语法级**（报文能解析、字段不报错）、**语义级**（同一个字段两边指的是同一件事）、**流程级**（对方收到后能触发正确的业务动作）。

语法级靠格式，语义级靠术语与数据元，流程级靠约定与回执。三级里最容易忽略的是回执：一条检验结果发出去，对方收没收到、有没有入病历、有没有触发危急值，发送方往往不知道。没有回执的接口，在故障时表现为「系统显示已发送」，在复盘时表现为「查不到」。

用 HL7 v2 与 FHIR 做对照能看清差别：v2 是消息驱动的，一条 ORU 消息自带患者、申请、结果、参考范围，一次传输一个事件，实现简单但语义埋在位置与本地约定里；FHIR 是资源驱动的，Observation 单独存在、可被引用、可被订阅，天然适合按需查询与增量同步，代价是需要先有稳定的资源标识与术语服务。选哪个不取决于先进程度，取决于**对方系统能不能稳定提供患者与医嘱的唯一标识**——提供不了，FHIR 也只能退化成一条条推消息。

## 五、伦理与合规：授权是一个可撤回的过程

标准解决「能不能对上」，伦理解决「该不该用」。两者在工程上会合流到同一处：**授权**。

把授权当成一次签字，是绝大多数隐私事故的起点。可用的授权模型至少包含五项：谁授权（患者本人或法定代理人）、授权什么（数据范围与字段粒度）、给谁用（具体机构与角色，不是「科研用途」这种笼统表述）、用到什么时候（期限与撤回方式）、以及撤回后怎么处理已衍生的数据（删除、还是仅停止使用）。缺任何一项，事后都无法界定责任边界。

去标识化与匿名化要分清。去标识化是移除直接标识（姓名、身份证号、住址、联系方式），但保留重识别可能；匿名化要求不可复原。工程上判断是否真的匿名，看三件事：准标识符组合是否仍能唯一锁定个体（出生日期 + 邮编 + 性别，在小区尺度上常常足够）、是否存在可关联的外部数据、是否保留了映射表。保留了映射表的「匿名数据」，本质是假名化，必须按个人信息管理。

医学研究还有一层：即使数据已去标识，涉及人的研究仍需伦理审查，审查的重点是风险受益比与知情同意的免除是否成立。免除不是默认项，要有理由、有记录、有批准主体。

「名定而实辨。」——《荀子·正名》。标准让名称与实体对上，伦理让使用与授权对上。两件事都不做，数据规模越大，错得越贵。

## 六、代价与边界

- 本章的抽样错误率、结算金额均为**演算设定**，用于说明错误的放大方式，不对应任何机构的真实质控结果。
- 编码规则片段只覆盖逻辑矛盾类错误，**不能替代编码员**；把它当成自动编码器使用，会制造更隐蔽的错误。
- 标准编号、版本与类目名称以主管部门与标委会发布的最新文本为准，本章不逐一列号，避免过期误导。
- 标准化有真实成本：封闭值域会挡住少数真实病例，映射维护需要长期人力。**这些成本必须显式承认**，否则标准会被绕开，而绕开的标准比没有标准更危险——它让人以为已经对齐了。
