# 第 6 章 · 统计分析与病案：首页是一张会被结算和评审同时读的表

> **MOTTO:** 「不明于计数而欲举大事，犹无舟楫而欲经于水险者也。」——《管子·七法》
>
> **PROBLEM:** 一位慢性心衰病人住院 12 天，出院时首页主诊断写「心力衰竭」（I50.9），而病程记录里明确记载本次入院诱因是肺部感染、住院期间主要治疗是抗感染与利尿。主诊断换与不换，DRG 从「循环系统疾病伴严重并发症」掉到「呼吸系统感染」，权重差 0.4 上下。同一个病人、同一份病历、同一批费用，只因首页一行字，结算与科室绩效是两套结果。而这张表一年要被读三次：临床看摘要、医保看结算、评审看指标。

**双根因定位:** 环境逼迫（同一张表同时服务临床、结算、监管三种用途，三方的「准确」定义不同：临床要说得清，医保要付得对，监管要统得齐）+ 知识积累（统计与病案长期分属两个科室，缺少共同的指标定义与数据血缘，导致同一个名字在不同报表里是不同的算法）。

## 一、一张首页，三种读法

病案首页的字段按用途可以分成三组，三组的质量要求不一样：

| 组 | 典型字段 | 主要读者 | 质量要求 |
|---|---|---|---|
| 临床摘要 | 主诊断、其他诊断、手术、离院方式 | 复诊、随访、科研 | 语义准确、可回溯到病程 |
| 结算要素 | 主诊断、主手术、并发症、年龄、性别 | 医保 | 符合入组规则、编码版本正确 |
| 监管指标 | 入院途径、住院日、费用、抢救次数 | 卫生行政、评审 | 口径统一、可汇总 |

三组共用字段，冲突就出在共用字段上。以「离院方式」为例：临床关心的是「转院还是自动出院」，医保关心的是「是否属于结算例外」，监管关心的是「死亡率分母」。一个字段三个含义，填写时只能满足一个，另两个靠事后解释。

可行的处理不是把字段拆成三套（那会导致首页无限膨胀），而是**给每个用途定义明确的派生规则**，并把这些规则写进指标字典。比如死亡率的分子是「离院方式=死亡」且「入院时间与死亡时间在同一统计期」，分母是「同期出院患者」，不含「当天入出院」与「转院」。规则不写下来，每个科室都会有一套自己的算法。

## 二、主要诊断：三条规则与三个反例

主要诊断的定义是：**经研究确定的、导致本次住院的主要原因，且本次住院主要针对它进行了诊疗**。三个限定词缺一不可——原因、主要、针对它诊疗。很多争议都源于只看了第一个。

规则可以压缩成三条：

1. **优先选本次住院主要治疗的疾病**，不是最严重的、也不是花钱最多的。
2. **优先选能解释主要症状与主要治疗的疾病**，症状性诊断（如「发热待查」「腹痛」）只在确实未查明时使用。
3. **并发症与合并症作为其他诊断**，只有当它就是本次住院的主要原因时才升为主诊断。

三个常见反例：

- 肺炎入院，住院期间查出糖尿病并调整了降糖方案。主诊断仍是肺炎——糖尿病是合并症，除非本次住院的主要资源消耗在糖尿病及其并发症上。
- 肿瘤患者入院化疗。主诊断是「恶性肿瘤化学治疗」，不是「恶性肿瘤」本身；把化疗写成肿瘤，入组会落到外科组，权重与付费都不对。
- 转院病人。主诊断按本次住院实际处理的疾病写，不能照抄转出医院的诊断；上级医院的诊断是参考，不是结论。

谁来决定？制度上必须由**医师**确定，编码员负责翻译成码，不能反向决定临床诊断。现实里常倒过来：编码员为了入组，建议医师改主诊断。这个做法短期能提高结算，长期会污染整个病种数据库——因为入组数据同时被用于学科评价、资源配置和科研，改一处，三处都错。

## 三、DRG 入组：要素、失败类型与可查的证据

入组本质是一次分类：把「主诊断 + 主手术/操作 + 并发症合并症 + 年龄 + 性别 + 离院方式」映射到一个组。要素少一个，就会落到兜底组或直接不入组。

四类入组失败最容易查，也最容易修：

| 失败类型 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 主诊断不可作主 | 症状码、晚期效应码 | 未查明就出院 | 补检查、按规则改码 |
| 主手术与主诊断不匹配 | 手术码属于另一系统 | 手术编码选错或主诊断错 | 双向核对 |
| 性别年龄矛盾 | 男性妊娠码、成人新生儿码 | 录入或字典错 | 前置校验拦截 |
| 版本缺码 | 新码在本地字典不存在 | 字典未升级 | 字典与上报版本同步 |

前两类占了大头，且都可以用「诊断—手术一致性表」在提交前自动提示。第三类靠前置校验，第四类靠版本管理。真正难的是那些「规则上能入组、语义上不对」的病例：主诊断选了一个权重更高的码，病程记录却支持不了。这类只能靠抽样复核，且复核要读病历，不能只看码。

一个可用的指标计算骨架（口径须按本机构规定调整）：

```sql
-- 出院人次与平均住院日：先定分母，再算指标
WITH d AS (
  SELECT medical_record_no, admit_at, discharge_at, discharge_type
  FROM inpatient
  WHERE discharge_at >= :start AND discharge_at < :end
    AND discharge_type <> '转院'          -- 分母是否含转院，必须写进口径
)
SELECT COUNT(*)                                   AS discharges,
       AVG(julianday(discharge_at) - julianday(admit_at)) AS avg_los_days,
       SUM(CASE WHEN discharge_type = '死亡' THEN 1 ELSE 0 END) AS deaths
FROM d;
```

这段 SQL 里最值得注意的不是算法，是那一行注释。分母含不含转院、含不含当天入出院、含不含死亡，会让平均住院日在同一批数据上相差 0.3–0.8 天。指标争议十次有八次是分母之争，而不是计算错误。

## 四、统计指标：分母定义决定结论

医院常用指标不过二三十个，但每一个都有至少两种算法在同时使用：

| 指标 | 分子 | 分母的两种写法 | 后果 |
|---|---|---|---|
| 平均住院日 | 总占用床日 | 出院人数 / 在院+出院 | 前者偏低，后者偏高 |
| 术前平均住院日 | 术前占用床日 | 手术例数 / 全部出院 | 混入非手术病人会拉低 |
| 治愈好转率 | 治愈+好转 | 出院人数 / 治疗人数 | 危重病人多的科室被低估 |
| 病死率 | 死亡人数 | 出院人数 / 住院人数 | 转院病人处理不同则不可比 |
| CMI | 总权重 | 入组病例数 / 全部出院 | 未入组病例的处置影响结果 |

比算法更容易错的是**比较**。两个科室的治愈好转率不能直接比，因为病人构成不同；两年的病死率不能直接比，因为病种结构变了。要比较就得标准化：按病种、按年龄、按病情危重度分层，或者直接用风险调整后的指标。不标准化的比较，结论通常是「谁的病人轻谁的成绩好」。

还有一类错误是把率和构成比混用。「本月肺炎患者占出院人数的 12%」是构成比，不能说「肺炎发病上升了 12%」；分子分母都变的时候，构成比的变化可能完全由分母驱动。这类错误在月度汇报里极常见，且很难被听众发现。

## 五、口径统一：指标字典与一张能对上的报表

口径漂移的解药只有一个：**指标字典**，且必须由一个人或一个小组统一维护。一个够用的字典每条至少八项：

| 项 | 示例 |
|---|---|
| 指标名 | 出院患者平均住院日 |
| 定义 | 出院患者占用总床日数与出院人数之比 |
| 公式 | Σ(出院日−入院日) / 出院人数 |
| 分子 | 出院患者占用总床日数 |
| 分母 | 同期出院人数（不含转院、不含当天入出院） |
| 排除 | 观察床、日间手术（另设指标） |
| 数据源 | 住院登记表 admit_at / discharge_at |
| 责任人 | 医务处 + 病案室 |

有了字典，报表之间的差异就从「谁算错了」变成「用了哪条口径」，可讨论、可裁决。没有字典，每次对不上都要重新吵一遍，最后还是按领导的印象定。

病案质控要分两层。**形式质控**查完整性：签名有没有、必填项齐不齐、时限内归档没有，可以全量自动查。**内涵质控**查一致性：诊断与病程记录是否相符、手术记录与手术码是否对应、用药与诊断是否匹配，只能抽样人工查。两层混在一个分数里，会导致「形式分很高、内涵没人看」——因为形式项好补，内涵项要读病历。可行的配比是全量形式质控 + 每月按病种分层抽 5% 做内涵质控，抽到的病历把问题逐条反馈给主治医师，反馈闭环率作为科室指标，而不是编码员的指标。

可视化是最后一公里。管理驾驶舱最常见的失败不是图不好看，是**图上没有分母、没有时间范围、没有口径版本**。一张「本月手术占比 38%」的卡片，若不写分母是出院还是住院、是否含日间手术，读者只能凭印象解读。可用的做法是每张卡片都带一行小字：口径编号、数据截止时间、责任人。

## 六、代价与边界

- 本章的权重差、平均住院日差异均为**演算设定**，用于说明口径与入组的影响方向，不代表任何机构的真实结算数据。
- 主要诊断规则以现行病案管理与分组方案为准，本章给的是判断逻辑，不是编码细则；具体病例须由临床医师确定诊断、编码员按版本编码。
- 指标字典需要长期维护，且每次口径变更都要保留历史版本，否则跨年比较失效。这是一项看起来不产出、实际决定所有报表可信度的投入。
- 统计能说明关联与差异，不能单独说明因果。用病案数据评价科室绩效时，必须同时说明病例组合与风险调整方式。

**免责声明：** 本章为病案统计与数据口径管理的教学讨论，不构成医保结算、绩效分配或临床诊断建议；具体入组与指标计算，须依现行分组方案与本机构病案管理制度执行。
