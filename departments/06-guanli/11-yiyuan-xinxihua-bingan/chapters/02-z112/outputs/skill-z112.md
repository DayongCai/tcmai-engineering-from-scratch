# 标准、编码与互操作：编码少一位，整组就匹配不上

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 2 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 一个长期不清理的待定池，就是数据质量的沉默黑洞
- 具体码值以本院在用版本为准

## 边界

- 编码位数与形态按通行码表结构说明，**具体码值以本院在用版本为准**，不得据本章抄录使用。
- 映射表的维护成本随并行码表数量增长。双码表并行期间，每季度至少一次全量比对，并出一次对不上的清单。
- 编码细化有边界。为入组而「高编」——把没做的术式编上去、把没证的合并症编上去——属违规，一旦被抽审，追回金额远大于多得的部分，且会连带影响科室的信用记录。
- 本章为医院信息化与病案管理的教学讨论，不构成编码指导、分组规则解释或合规审查意见。
