# 信息科实习的成品是一份口径字典，不是一张好看的报表

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 7 道题自检，答不上就回到对应小节。

## 核心判据

- 一份完整的记录
- 一个可复用的数
- 分子、分母、数据来源
- 绝对数与相对数不能互相替代
- 查全率与查准率
- 受控语言与自然语言

## 边界

- **口径统一是有成本的，而且成本落在最不方便的地方。** 建字典要拉着业务、统计、信息三方逐条对，一个指标可能要吵半小时。省下这个半小时，代价是此后每一次跨科室比较都要重吵一遍。
- **字典只能管「已定义的指标」。** 大量管理问题是临时提出的，没有现成指标；这时正确的做法是先定义再取数，而不是拿一个近似的指标顶上去。用近似指标回答问题，比不回答更危险。
- **可视化会把误差放大。** 图的作用是让人一眼看懂，也让人一眼误信。纵轴不从零开始的条图、把连续资料画成有间隙的条图、三维装饰遮挡数据，这三类误用之所以常见，是因为它们都让图「更好看」。
- 本章讨论病案与信息科实习中的指标口径、检索方法与报表规范，属管理教学方法内容，不构成诊疗意见、不构成信息公开或数据合规的法律意见。实际取数、对外报送与数据共享，须依现行统计制度、个人信息保护规定与本院授权流程办理。
