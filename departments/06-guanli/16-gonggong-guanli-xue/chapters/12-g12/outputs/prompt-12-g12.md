# 数字化省下的是跑腿，不是判断 · 提示词

## 用途

给「数字化省下的是跑腿，不是判断」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「三层，别混着说 → 数据治理的四个真问题 → 流程再造必须先于系统建设 → 算法进入裁量之后，责任链要重画」这条链。

## 提示词

```
我在学《公共管理学》第 12 章「数字化省下的是跑腿，不是判断」，本章 5 节 / 2,697 汉字，习题 6 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 记录层：把纸变成数据
   - 流程层：把串联变成并联
   - 决策层：把判断交给规则或模型
   - 一件事要跑几次、交几份材料、等多少天
   - 共享后的责任划分
   - 先画出「一件事」的完整链条，再决定哪些环节可以取消，最后才谈用什么系统承载
4. 本章自陈的边界（不得越过）：
   - **本章数字为演算设定。** 事项数、跑动次数、环节数只用于说明三层深度的差别，不对应任何真实城市或平台。
   - **技术不解决职责问题。** 数据共享与流程合并的阻力来自职责与风险分配，系统只能降低协调成本，不能替代协调。
   - **线上化不是目的。** 判断标准是群众与企业的实际成本，不是上线率、注册数、访问量。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章为教学材料，讨论数字政府与电子政务的层次划分、数据治理与责任配置，不构成对任何平台、工程或地区的评价，也不构成技术与合规建议；具体操作以现行规范与所在机构制度为准。
