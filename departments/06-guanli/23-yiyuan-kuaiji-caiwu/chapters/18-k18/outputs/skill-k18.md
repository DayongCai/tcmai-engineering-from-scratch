# 门禁查得出形式，查不出判断：课程与平台的接口是可复算

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 单元数完全一致，只有字数有一成半的波动——整齐的是结构，不是内容
- 单元回答"有哪些"
- 章回答"选哪个、为什么、代价是什么"
- 其一，给每章一个可争论的命题
- 其二，把单元里的并列项改写成有优先级的判断
- 其三，让数字承担论证

## 边界

- **平台能保证下限，保证不了上限。** 引文、免责、边界段、篇幅四项可自动校验；"这一章有没有讲清一个判断"无法自动校验。把质量完全托付给门禁，得到的是"全部合格、无人想读"的课程。
- **可复算的写法牺牲了一部分可读性。** 每章都要摆算式、标设定、写复算链条，读起来不如叙述流畅。这个代价必须付——不可复算的数字，在教材里就是装饰。
- **术语 id 化会增加编写成本。** 同一个词在不同章要反复核对定义，写作速度会下降。收益在读者侧：他不会在第三章和第十三章遇到两个"结余"。
- 本章讨论课程正文与教学平台的对接契约、门禁与能力映射，属课程建设与教学管理内容，不构成技术方案、数据合规结论或评价制度。
