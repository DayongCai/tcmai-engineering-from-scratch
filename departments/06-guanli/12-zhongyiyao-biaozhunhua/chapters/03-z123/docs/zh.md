# 第 3 章 · 编码错一位，临床上就是另一味药

> **MOTTO:** 「方以类聚，物以群分。」——《周易·系辞上》
>
> **PROBLEM:** 一张中药处方要过四套代码：院内系统、医保结算、省级平台、国家上报。四套码之间靠三次映射连起来，每映射一次，明细级错率按半个百分点计（演算设定）；四次下来累计差错约百分之二——十八万张处方、每张十二味，一年二百一十六万条明细，就是四万三千条对不上。真正麻烦的不是这个数，而是错在哪儿没人说得清：映射表只记「A 对应 B」，不记这是等价、包含还是勉强凑合，于是审核无从下手，只能等下一年度对账时成片暴露。

**双根因定位:** 环境逼迫（院内码为收费设计、医保码为结算设计、上报码为统计设计，三套码的切分粒度天然不同；谁能改谁就先承担一次全量重刷的成本，于是都选择在边界上加转换层）+ 知识积累（本章底本二十二单元、三万二千余汉字，主体是医院信息系统、区域平台与电子病历，编码与分类只在前一组里占一节；炮制位、映射关系类型这些结构问题未展开）

## 一、分类先于编码，分类错了编码只能错

编码是给分类结果贴标签。分类这一步做歪，编码再整齐也只是把错误编得更有秩序。分类有三条要求，缺一条就会在数据里显形。

互斥：一个对象只能进一个类目。中药按药用部位分（根及根茎、茎木、皮、叶、花、果实种子、全草、树脂、动物、矿物），一条「全草」与一条「地上部分」并列，就会出现同一批货两个归属。穷尽：所有对象都要有位置，不能出现「其他」占了半壁江山——「其他」超过一定比例，说明分类轴选错了。稳定：类目不要随年度调整，调整要留旧码。

轴的选择比类目数量更重要。中医病证分类至少涉及三个轴：病位（脏腑、经络、形体）、病性（寒热虚实、气血津液）、病因（六淫、疫毒、饮食劳倦）。一次只能选一个主轴，其余靠组配；若想「一个类目同时表达病位与病性」，类目数会呈乘积爆炸。以十个病位、八种病性为例，组配只需 18 个基本单元，交叉建类则要 80 个，再加病因维度就是数百个——维护成本按类目数的平方增长，没人维护得动。

## 二、四种编码结构，各有各的失效方式

| 结构 | 形态 | 容量 | 可读性 | 典型失效 |
|---|---|---|---|---|
| 顺序码 | 流水号 1、2、3 | 无限 | 无 | 插入新码即乱序，无法按类检索 |
| 层次码 | 门类-亚类-品种 | 受位宽限制 | 强 | 位宽不足时被迫扩位，全量重编 |
| 组配码 | 轴A + 轴B 组合 | 组合爆炸式 | 中 | 轴序不固定则同一概念两个码 |
| 并置码 | 数字段表达含义 | 中 | 中 | 语义不透明，靠查表 |

顺序码只适合「不需要按类检索」的对象，比如检验申请单号。层次码是药材与病证分类的常用结构，好处是能从码看出归属，坏处是位宽一旦定死就难扩；实务中的补救是预留空段，而不是事后加位。组配码适合多轴对象（病位 + 病性），但它有一条硬要求：轴序必须固定并写进规则，否则「脾 + 气虚」与「气虚 + 脾」会生成两个码，统计时各算一半。并置码（含义码）在饮片与规格上很常见，可读性差，但表达力强，适合把「品种 + 炮制 + 片型 + 等级」压进一个短码。

## 三、饮片必须单设炮制位，这是安全条款不是洁癖

中药材与饮片之间隔着一道炮制。同一基原、不同炮制，成品是两味药：半夏有生品与姜制、法制、清制之分，生品有毒、需炮制后内服，不同炮制品的作用方向与毒性都不同；附子经炮制前后，毒性成分与药效成分的关系整个改变。若这些炮制品共用一个品种码，处方审核端就分不出「法半夏」与「清半夏」，毒性饮片的拦截规则形同虚设。

所以饮片码至少要分四段：门类、基原品种、炮制类、规格。示意如下（结构示意，非任何现行标准的码表）：

```text
J - 0417 - 3 - 02
│    │      │   └─ 规格位：片型与等级
│    │      └───── 炮制位：0 生品 / 1 炒 / 2 酒炙 / 3 姜制 / 4 法制 …
│    └──────────── 品种位：基原 + 药用部位
└───────────────── 门类位：植物 / 动物 / 矿物
```

这段设计的两个要点值得说清。第一，炮制位独立成位，不并入品种位——并入就等于把「炮制」当成品种的属性，而它其实是加工工艺的产物，工艺会新增、会废止。第二，规格位放在最后，因为规格变化最频繁（片型、等级、包装），放在尾位可以在不改前段的前提下扩位。

病证方向的组配码同理。固定轴序（先病位、后病性、再病因），每一轴用定长位表达，缺轴补零位而不是省略——省略会让「脾气虚」与「脾」在字面上无法区分，也让长度校验失效。

## 四、映射不是复制，要记关系类型

两套码之间不是「翻译」，而是建立关系。关系至少有五种：一对一（等价）、一对多（一码拆成多码）、多对一（多码合成一码）、部分重叠（外延交叉）、无对应。五种关系的处理方式完全不同：等价可以自动转换；一对多必须人工拆分并留下依据；部分重叠必须标注「仅供检索，不可用于结算」；无对应必须显式留空，不能强行挂到一个「其他」类目上。

因此映射表不能只有两列。最小可用结构是：源码、目标码、关系类型、置信度、审核人、生效日期。少了关系类型，这张表只能查不能审——审计时问「这条映射凭什么成立」，答不上来；少了审核人与生效日期，一条错误映射可以在系统里活很多年，谁也不知道它是谁加的、什么时候加的。

还有一条工程经验：映射要可回溯。任何一次自动转换，都要在记录里留源码与目标码两个值，而不是只留目标码。只留目标码的系统，在发现映射错误时无法反向修正历史数据，只能全量重刷。

## 五、版本与废弃：码表是有时间维度的

码表不是一张静态表，它有时间。新增品种、废止品种、炮制工艺变更、分类调整，每一次变动都应该在码表里留下生效日期与失效日期；旧码不删，只标废弃，并注明被谁替代。

这一条对应的是「时点正确性」：一份三年前的处方，必须能按三年前的码表解释。如果系统只存「当前码」，那么历史数据在每次改版后都会悄悄变形——当年统计的「法半夏用量」，今年按新码重算，可能变成了「半夏（制）用量」，趋势图上的拐点就这么凭空出现。中医药的数据跨度动辄十年以上，这条尤其要紧。

## 六、编码质量的三个可核指标

编码不是编完就算，得有指标能算，否则「编码工作已完成」永远无法被证伪。三个够用且可复算的指标：

唯一性，即「一物多码率」。抽取若干条处方明细，按「品名 + 规格 + 炮制」人工判定它们是否指向同一对象，再逐条比对各家系统里的码，统计判为同一对象却出现两个以上码的条数占比。分母是抽样明细数，分子是冲突条数。抽样量按比例估计的常规算法，取 95% 置信、误差 ±5 个百分点、p 取 0.5，需要约 384 条；院内自查可降到 200 条，但结论只能说到「大致在几个百分点」。

覆盖率。分母是在用品种数，分子是码表中可用码对应的品种数。这个指标最容易被做高——把「其他」类目算成已覆盖，数字立刻漂亮，可下游拿它什么也做不了。因此统计时必须剔除兜底类目，否则覆盖率测的是「有没有填」，不是「能不能用」。

映射可审率。分母是全部映射记录，分子是同时具备关系类型、审核人、生效日期的记录。缺这三项的记录只能叫「疑似映射」，不能进自动转换。

三个指标可以相乘，得到一个粗口径的健康度，但相乘没有理论依据，它唯一的作用是把三项都差的系统排到前面。演算一下：一物多码率百分之二、覆盖率百分之九十二、映射可审率百分之七十，则 0.98 × 0.92 × 0.70 ≈ 0.63。注意第一项要取补数——指标方向不一致，是这类「健康度」最常见的算错方式。

## 七、代价与边界

- 本章的码段结构是**设计示意**，用来讨论位宽与位序，不是任何现行标准的码表；实际编码一律以现行发布的标准为准，本章不引标准编号与年份。
- 编码越细，录入成本越高。四段码比一个流水号好用，但也要求药房在收货时逐项确认炮制与规格；若一线没有这个人力，细化只会催生「默认选第一项」的批量错误。细化的前提是录入端能自动带出，而不是靠人填。
- 映射没有免费的准确率。一对多与部分重叠的映射必须人工审，把审的人、依据、时间记下来，否则映射表会退化成一张谁都不敢用的表。
- 本章不评价任何具体编码体系，也不构成药事管理或医保结算建议。

**免责声明：** 本章为分类与编码工程的教学讨论，不构成诊疗、用药、医保结算或监管符合性建议。
