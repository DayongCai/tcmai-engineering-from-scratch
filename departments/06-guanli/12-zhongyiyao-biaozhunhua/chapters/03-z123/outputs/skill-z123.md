# 编码错一位，临床上就是另一味药

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 若干 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 边界

- 本章的码段结构是**设计示意**，用来讨论位宽与位序，不是任何现行标准的码表；实际编码一律以现行发布的标准为准，本章不引标准编号与年份。
- 编码越细，录入成本越高。四段码比一个流水号好用，但也要求药房在收货时逐项确认炮制与规格；若一线没有这个人力，细化只会催生「默认选第一项」的批量错误。细化的前提是录入端能自动带出，而不是靠人填。
- 映射没有免费的准确率。一对多与部分重叠的映射必须人工审，把审的人、依据、时间记下来，否则映射表会退化成一张谁都不敢用的表。
- 本章为分类与编码工程的教学讨论，不构成诊疗、用药、医保结算或监管符合性建议。
