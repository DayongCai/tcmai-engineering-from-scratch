# 编码错一位，临床上就是另一味药 · 提示词

## 用途

给「编码错一位，临床上就是另一味药」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「分类先于编码，分类错了编码只能错 → 四种编码结构，各有各的失效方式 → 饮片必须单设炮制位，这是安全条款不是洁癖 → 映射不是复制，要记关系类型」这条链。

## 提示词

```

正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据请从小节标题与正文段落中自行提取，不要补充正文没有的内容；
4. 本章自陈的边界（不得越过）：
   - 本章的码段结构是**设计示意**，用来讨论位宽与位序，不是任何现行标准的码表；实际编码一律以现行发布的标准为准，本章不引标准编号与年份。
   - 编码越细，录入成本越高。四段码比一个流水号好用，但也要求药房在收货时逐项确认炮制与规格；若一线没有这个人力，细化只会催生「默认选第一项」的批量错误。细化的前提是录入端能自动带出，而不是靠人填。
   - 映射没有免费的准确率。一对多与部分重叠的映射必须人工审，把审的人、依据、时间记下来，否则映射表会退化成一张谁都不敢用的表。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章为分类与编码工程的教学讨论，不构成诊疗、用药、医保结算或监管符合性建议；具体操作以现行规范与所在机构制度为准。
