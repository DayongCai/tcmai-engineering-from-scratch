# 移交的验收标准是「人走了系统还在转」，不是「文档齐了」 · 提示词

## 用途

给「移交的验收标准是「人走了系统还在转」，不是「文档齐了」」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「移交的三类资产：制度、数据、人 → 主数据与字典：一物多码会让三年数据接不上 → 权限、脱敏与审批：去标识化不等于匿名化 → 运维与升级：服务级别、回退条件、迁移校验」这条链。

## 提示词

```
我在学《管理毕业设计与知识移交》第 6 章「移交的验收标准是「人走了系统还在转」，不是「文档齐了」」，本章 6 节 / 3,322 汉字，习题 6 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 第三项是唯一真正的验收
   - 不是系统坏了，是数据接不上了
   - 是个人信息经过处理，使其在不借助额外信息的情况下无法识别特定自然人的过程
   - 混称的后果是把仍受限的数据当成可自由使用的数据
   - 升级的回退条件
   - 数据迁移的校验
4. 本章自陈的边界（不得越过）：
   - **移交做得好，作者要额外付出。** 写字典、留脚本、做对照表、带一次变更演练，通常要花掉项目收尾阶段三分之一的时间，而这部分工作不计入答辩评分。这是真实的激励错配，只能靠制度补，不能靠自觉。
   - **文档齐全不等于可维护。** 一百页说明书可能不如一份「改这个参数要走哪三步」的操作卡有用。可维护性的判据是接手者能在不问原作者的情况下完成一次变更，不是文档的页数。
   - **数据不是越开放越好。** 移交常伴随「数据共享」的诉求，但共享的范围、目的与期限必须事先界定；把全量明细交出去，既不必要，也不合规。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章讨论毕业设计的成果移交、数据治理与运维安排，属管理教学方法内容，不构成诊疗意见、不构成法律意见，也不构成对任何信息系统安全水平的评价。数据使用、共享与科研应用，须依现行个人信息保护、伦理审查与网络安全规定办理；具体操作以现行规范与所在机构制度为准。
