# peiwu-gongxian

## 何时使用

- 要把方剂组成表变成一张药物共现网络（节点、边、边权）
- 需要在讲义里解释"为什么甘草度数最高却不是核心药"
- 要核一份方剂知识图谱的规模（方数 / 药位 / 药味 / 八法方数），并判断某个数像不像抽取缺陷
- 要评估"AI 组方按共现推荐"这类工具的可信度
- 下游统计撞到"某首方只有 1 味"这类不可能的记录，需要决定往上游查还是就地修补

## 不适用

- 判定某方的主药、君臣佐使配置（共现层做不了，须回原文）
- 推论配伍规律、药对协同机制、疗效
- 临床选方与剂量
- 替代教材的分章分类

## 步骤

1. **报底座**：方数、药位数（一方一药位）、去重药味数、归八法的方数，四个数先摆出来，并注明数据版本。
2. **查完整性**：逐首看组成药味数的最小值。出现 0 味或 1 味的方，先当成上游抽取缺陷，不当成方剂事实；最小值为 2 且 114/114 首有组成，才谈得上统计。
3. **留修复回执**：把"曾抽错的方 → 修正后的逐味组成 → 原缺陷原因"写成一张表，放在正文里，不要静默改数。旧读数（如 821 药位）要标明"历史读数，已作废"，不能写成"下限"。
4. **建网络**：方内药味去重 → 完全图投影 C(n,2) → 同一药对跨方累加边权。
5. **算头部**：按入方数排（度）、按加权度排，两列并列给出，并补一列加权度÷入方数；只看一列必错。
6. **算药对**：边权前 10，统计其中含"调和类"药（甘草、生姜、大枣）的比例；并列项要说明次序判据（否则不可复现）。
7. **叠角色**：把君臣佐使覆盖率叠回网络；对头部药逐味算"角色足迹"（君/臣/佐/使/未标各几次），缺口单列不并入任何角色。
8. **看长尾**：只出现 1 次的药味占比；长尾越厚，头部节点的"通用"性质越明显。
9. **查药名层**：统计不在《中药学》287 味词表的药名，并按"长度 ≥5 字或含虚词"分出散文残串；组成层修好不等于药名层干净。
10. **写不可推论**：明确"度≠主药""共现≠配伍""覆盖高≠有鉴别力""重跑一致≠数据正确"。

## 输出模板

```text
【底座】114 / 836 / 246 / 52（注明数据版本与脚本入口）
【完整性】114/114 首有组成 · 最短 2 味 · 最长 24 味
【修复回执】方 → 修正后逐味 → 原缺陷原因（≥1 行，无则写"无已知缺陷"）
【网络】2,364 对不同药 / 3,341 次共现 / 可能边 30,135 / 密度 7.84%
【头部】药（入方数 / 加权度 / 加权度÷入方数）× 6 + 解读
【药对】甲+乙（共现方数）× 5 + 解读
【角色】君/臣/佐/使覆盖 + 四角色齐方数 + 头部药的角色足迹
【长尾】1 次药味数 / 总数
【药名边界】词表外味数 / 其中残串数
【不可推论】…
```

## 质量判据

- 任何数字都能由同一份 JSON 复算；脚本自带断言，任一规模数不符即抛错
- 度、加权度、加权度÷入方数三列并列，不混为一谈
- 头部解读指向"通用角色"，不指向"主攻地位"
- 缺陷先查上游，修好后留回执；**不许把已知缺陷写成"下限"带进正文**
- 药名层缺陷与组成层缺陷分开报，不因修好一处就宣称数据干净
- 结尾给出"不可推论"清单

## 一次实测（2026-10-29，114 首方）

底座 114 / 836 / 246 / 52。修复回执 5 行（六一散 2 味、生脉散 3 味、当归补血汤 2 味、四神丸 4 味、消风散 13 味），114/114 首有组成。网络 2,364 对 / 3,341 次 / 可能边 30,135 / 密度 7.84%。头部甘草 61 首（加权度 454），但 61 首里使 28、佐 6、君 1、未标 27。长尾 138/246（56.1%）。词表外 86 味，其中 16 条是散文残串。

> 本技能只做共现网络的描述性统计，不构成诊断或用药依据。
