# qingre-qushu

## 何时使用

- 教学复盘：学生把「清热」当成一个强度旋钮，需要说明六节其实是六条不同的出口
- 建库：要给「某方治某脏之火」这类横向定位与「热入营血」这类纵深分层分别建键，而不是共用一列
- 做统计前的自检：任何基于药味集合的关系（子集、相似度）都要先问「这条记录自身完整吗」

## 不适用

- 决定患者该清哪一层、用何方（本技能不含四诊、剂量与禁忌判定）
- 含犀角、朱砂等禁用/受限药材的任何实际使用（临床以水牛角等替代须遵法规与药典）
- 把 Pearson r 当作机制证据——本章 n = 6，r 只能作为一个很弱的信号
- 单味残方参与的集合运算（六一散曾只有 1 味、生脉散曾只有 1 味），必须先标 incomplete；这两处已由上游抽取器修复

## 步骤

1. **取子集**：按 `chapter ∈ {'8','9'}` 从 `formulas.json` 过滤，得 16 方（13 清 + 3 祛暑）；不手抄方名。
2. **清残句**：药名按「2–4 字且不含虚词」判；本章 116 → 109 药位，「临证可依表寒与」「于清暑益气之外」等 8 条剔除并留账（其中「五味子」是被谓词误伤的，也要留账）。
3. **归坐标**：每方打两个键——纵深（气分 / 营血）、横向（毒 / 脏腑位）、外加虚实（虚热）与因时（暑）。三轴不合并成一个分数。
4. **检验直觉**：算「节序 vs 每节平均药位」的 Pearson r，同时报 n 与聚合方式；聚合量一换（平均改最大），结论必须重算。
5. **查完整性**：药味数 < 3 的方先标 incomplete，再跑子集判定；上一版六一散只有 1 味，8 条边里 7 条是它伪造的假边，滑石补齐后这些假边归零，剩下的 0 条真边里还藏着一条漏边（生甘草梢未归并为甘草）。
6. **写护栏**：任何「药味数 / 频次」结论后面补一句它不度量什么。

## 输出模板

```text
批次：教材·第8章 + 第9章（16 方 / 109 药位 / 去重 59 味 / 每方 6.8 味）
分章：清热 13 / 祛暑 3；残句 8 条（剔除清单附后）
逐节：<节> n 方 / 药位 / 平均
假设检验：节序 vs 平均药位 r = 0.28（n = 6，聚合 = 平均，不足以当刻度）
核心药：甘草 8 / 黄连 6 / 地黄 6（附各自跨节）
最近邻：白虎汤 ~ 竹叶石膏汤 0.38（共 3 / 并 8），加减式 4 − 1 + 4 = 7
子集：0 条真边；六一散补齐滑石后上一版的 7 条假边归零，另有一条漏边（生甘草梢 ↛ 甘草）
护栏：本表未含剂量、君臣佐使位次、煎服法与患者个体情况。
```

## 质量判据

- 三轴分开存，没有出现「清热强度 0.8」这类把纵深与横向压成一维的分数
- 每个数字都能由 `node code/main.js` 重现；文档不手打「16 方」「109 药位」
- 引教材原句写成「…」——教材·第N章·N.M.K，且为底本某段正文的连续子串
- 相关系数必须同时报 n 与聚合方式，且不把「不显著」写成「无关系」
- 单味方在子集判定中被显式跳过并记入 skipped，而不是静默产出假边

> 本技能输出为教学与检索辅助，不构成诊断或用药依据。
