# xiexia-hejie

## 何时使用

- 教学复盘：学生能背方歌却分不清大承气汤与黄龙汤的攻补关系，需要一张可核对的差集表
- 建库：给「即某方加某药」「二方相合而成」这类教材句子找一个可判定的形式化写法
- 做类方检索：想知道一首方在教材同一治法里最近的邻居是哪一首，以及这个邻居为什么不能替代它

## 不适用

- 决定患者该下还是该和（本技能不含四诊、不含剂量、不含禁忌判定）
- 峻下逐水药（十枣汤：甘遂、大戟、芫花）与攻补兼施方的任何实际使用
- 需要剂量比较的场景——集合表示里厚朴与甘草同权，抹掉了「厚朴半斤」这一层
- 君臣佐使统计——`formulas.json` 的角色是抽取结果，每角色只取第一条，本章四角色齐的仅 1 方

## 步骤

1. **取子集**：按 `chapter ∈ {'6','7'}` 从 `formulas.json` 过滤，得 11 方；不要手抄方名。
2. **清残句**：药名按「2–4 字且不含虚词（为/故/无/另/自/三味/于）」判，剔出的条目单独留账（本章 1 条，出自温脾汤组成段对《千金》两版差异的交代）。
3. **算规模**：方数 / 药位 / 去重味数 / 每方平均味数，四个数一起报，缺一个就无法判断解析是否走偏。
4. **排最近邻**：两两算 Jaccard，取前 5 对；每对必须同时报「共有味数 / 并集味数」，只报一个比值不可复核。
5. **判合方**：另算真子集对（A 的每一味都在 B 里且 |A| < |B|）。本章只有一条：大承气汤（4 味）⊂ 黄龙汤（10 味）。
6. **写护栏**：凡引用相似度排序，必须同时写出「相似度高不等于可互换」的反例对。

## 输出模板

```text
批次：教材·第6章 + 第7章（11 方 / 67 药位 / 去重 34 味 / 每方 6.1 味）
剔出残句：<条目>（来源段：<方名> 组成段）
八法分组：下 6 方 / 和 5 方
最近邻前 5：<A> ~ <B>  J=…（共 x / 并 y） 是否子集：是/否
合方边：<A>（n 味）⊂ <B>（m 味）
角色覆盖：君 … / 臣 … / 佐 … / 使 … · 四角色齐 … 方 · 全空 … 方
反例：药味数不度量峻猛（4 味峻下 vs 10 味攻补兼施）；相似度不度量可替换
护栏：本表未含剂量、君臣佐使位次、煎服法差异与患者个体情况。
```

## 质量判据

- 每个数字都能由 `node code/main.js` 重现，文档里不出现手打的「11 方」「67 药位」
- 引教材原句时写成「…」——教材·第N章·N.M.K，且原句是底本某段正文的连续子串（改一个字即判失败）
- 残句剔除有代码判据、有单测正反例、有边界段留账，三者缺一即视为静默失真
- 子集判定与相似度排序分列，没有用「相似度 > 0.5」冒充合方关系

> 本技能输出为教学与检索辅助，不构成诊断或用药依据。
