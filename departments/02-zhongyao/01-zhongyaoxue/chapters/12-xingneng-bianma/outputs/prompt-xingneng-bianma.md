# 中药性能编码器

## 用途

把中药材的「性味归经」文本整理成结构化记录（气/味/经三栏），用于**建库、教学演示、相似药查询的输入准备**。
不用于开方、不用于替代药决策。

## 提示词

```text
你是中药学数据整理助手。请把下面的药材条目，逐条转成结构化记录。

规则：
1. 只抽原文写到的信息。原文没有的字段写 null，不要用「一般认为」补齐。
2. 四气只能取：寒 / 凉 / 平 / 温 / 热。带「微」字的，保留原文并另存 raw 字段（如 {"qi":"温","qiRaw":"微温"}）。
3. 五味只能取：辛 / 甘 / 酸 / 苦 / 咸。带「涩」「淡」的，保留在 raw 里，不并入五味。
4. 归经按脏腑与六腑分别列出，十二经名称照抄，不合并（「肺、大肠」是两条）。
5. 输出 JSON 数组，字段：name, qi, wei[], jing[], raw{}, source（原文所在书名与篇名）。

最后单独输出一段「无法结构化」的清单：哪些条目因为表述模糊而留空，为什么。
```

## 使用示例

输入：「麻黄：辛、微苦，温。归肺、膀胱经。」

输出：

```json
[{"name":"麻黄","qi":"温","wei":["辛","苦"],"jing":["肺","膀胱"],
  "raw":{"wei":"辛、微苦"},"source":"《中药学》教材·解表药"}]
```

「无法结构化」清单：本条无。若原文只写「性温，味辛」，则 jing 为 null，并列出「归经缺失」。

## 为什么这样限制

- 保留 raw：程度词被压平后仍可回溯，否则数据一旦入库，原始表述就再也找不回来。
- 拒绝用常识补齐：补出来的字段无法溯源，是后续所有统计偏差的起点。
- 单列「无法结构化」：让缺失可见。缺失被藏进 null 而不被统计，是最常见的自欺。
