>
> **PROBLEM:** 你能背「大黄苦寒，泻下攻积」，但一张方子里同时出现大黄、苍术、茯苓时，你说不清它们各自在解决什么——更说不清为什么巴豆霜的用量是 0.1–0.3g，而金钱草是 15–60g，两者相差两百倍却都叫「祛湿」。

## 核心概念

### 中医：水湿的四种走法

教材把这一大块拆成四个各论章，顺序本身就是答案：

| 教材章 | 通道 | 一句话机理 | 代表药 |
|--------|------|-----------|--------|
| 第 11 章 | 泻下 | 从大肠走，把积与水分一起推出去 | 大黄、芒硝、巴豆霜 |
| 第 12 章 | 祛风湿 | 从经络走，把留着不去的风寒湿热赶出去 | 独活、威灵仙、秦艽 |
| 第 13 章 | 化湿 | 从脾胃走，把中焦的浊气「化」掉（不是排掉） | 广藿香、苍术、厚朴 |
| 第 14 章 | 利水渗湿 | 从小便走，把水一点点渗出去 | 茯苓、泽泻、车前子 |

四条通道的关键差别不在「祛不祛湿」，而在**从哪个出口走、走得多急**。教材·第11章·11.1 的大黄一条药就横跨两个出口：「大黄功效泻下攻积、清热泻火、凉血解毒、逐瘀通经、利湿退黄」——前四字走大肠，末四字走小便。而教材·第14章·14.1 的茯苓恰恰相反：「利水而不伤正，为利水渗湿之要药」，它的价值在于**慢而不伤**。

这就是本章的题眼：**同目的，不同力**。教材把它们编在一起，是因为它们回答同一个问题——水湿从哪走；不是因为它们可以互换。

### AI/工程：把「力」变成一个可排序的数

四气本来是有序的（大寒 → … → 大热），所以能折成一个整数；五味与归经是类别，只能数频次。本章只做三件机器擅长的事：

1. **结构计数**：节 / 小节 / 段 / 字，逐章与教材 `counts` 对账，任何一项对不上就报错。
2. **有序标度**：`大寒 -4 … 平 0 … 大热 +4`，按教材章求均值，得到「这一组药整体偏寒还是偏热」。
3. **剂量代理量**：从用法段正则抓 `(\d+)-(\d+)g` 的上限。上限越小，安全窗越窄，峻猛度越高。

```js
const QI_SCORE = { 大寒: -4, 寒: -3, 微寒: -2, 凉: -1, 平: 0, 微温: 1, 温: 2, 热: 3, 大热: 4 };
const doseCap = (d) => {
  const m = d.fields['用法用量与使用注意'].match(/(\d+(?:\.\d+)?)\s*[-~～]\s*(\d+(?:\.\d+)?)\s*g/);
  return m ? parseFloat(m[2]) : null;   // 解析不到返回 null，不猜、不填 0
};
```

`null` 的处理是本章的工程要点：解析失败**不参与排序**，也不在表里显示成 0。把缺失当 0 是最常见的静默失真。

### 一个反例：苦味不能用来分通道

含苦 25/45、含辛 18/45、含甘 16/45。苦能泄、能燥、能坚，所以泻下（泄）、燥湿（燥）、渗泄（泄）三条通道都能挂上「苦」。若用「苦味」当分类特征，45 味里 25 味会被划进同一堆——**特征选错，分类必错**。这也是所有「用性味做向量」的工程做法必须警惕的第一件事。

## 代价与边界

- **剂量上限只是代理量**。同一味药生用与制用剂量不同（大黄生用后下 vs 大黄炭），教材一句话里塞了两种用法，正则只取了第一个区间。十枣汤里甘遂、大戟、芫花同用，各自剂量都小，但合起来的峻猛度不是三者之和——**剂量不能线性相加**。
- **热性均分把程度词压平了**。`微寒` 记 −2、`寒` 记 −3，这个间距是人为设定的；换成 −1.5 与 −3，第 14 章的 −2.00 会变，排序不变，但绝对值不能说成「客观」。教材里还有「大寒」，常规词表漏掉它会让石膏一类读成空值——这是解析缺口，不是教材缺口。
- **7726 字只算正文**。段标题、表格、图表说明不在内，所以「字数」不能当「信息量」用。
- **45 味是教材选载，不是药典**。教材第 11–14 章收录的是代表药，去掉的药既可能更平和，也可能更毒。用这 45 味算出的任何分布，都只描述这 45 味。
- **雷公藤的味与归经为空**，本仓库按「拆不出就留空」处理，不用药典补、不推断。它的四气能读（凉），五味与归经留 `[]`。做统计时它会系统性地少计入两个维度，这不是 bug，是如实。
- **本章不回答「能不能一起用」**。十八反、十九畏、妊娠禁忌都在教材各药的「使用注意」里，本课只做了关键词统计（10 味出现毒性词），没有做配伍推理。

## 进阶思考

「攻、燥、渗」这三类药在教材里是并列的章节，在临床上是**次序**：先化（把浊气化开）、再渗（从小便走）、最后才攻（从大肠走）。章节的并列是编排需要，次序才是判断。任何把并列结构直接读成「可替换」的系统，都会在第一步就错——而这类错误在代码里看起来完全正常，因为它只比较了标签，没有比较力。
