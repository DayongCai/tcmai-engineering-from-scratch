# shouse-yongtu

## 何时使用

- 编写或校对《中药学》收涩药、涌吐药部分的教案与复习题
- 设计"症状 → 药"检索接口，需要先分清"收"与"吐"两条分支
- 要向人解释"为什么止汗的药和催吐的药会出现在同一章附近"（一个闸门的两侧）
- 核对某一方向的实际构成：几味药、四气几档、归经落点、是否标有毒

## 不适用

- 判断某人该收还是该吐（那是辨证中的虚实判断，不在数据层）
- 用"有毒"当功效分类特征（它是安全性标签，只在"峻烈与否"上有效）
- 毒理、剂量上限、长期安全性评估（教材未标有毒 ≠ 安全）
- 急症处置：涌吐药三味均标有毒，任何相关操作须在医疗机构内由医师决定

## 步骤

1. **取数**：读 `standards/zhongyao/底本.json`（两章结构 + 段原文）与 `drugs.json`（药味 + 性味归经）。
2. **核规模**：26 章 3 节/14 味/42 段/2523 字；27 章 1 节/3 味/9 段/460 字；合计 4/17/51/2983。
   段数必须等于药味 × 3，不等就是解析错位。
3. **先定方向**：功效语含"固表止汗/敛肺/涩肠/固精/缩尿/止带"→ 收涩；含"涌吐"→ 涌吐。
4. **再验方向**：收＝病势外泄且属虚；吐＝病邪壅上且属实。两条同时成立的，标"需人工判定"。
5. **出画像**：收涩 14 味（平温为主、无一标有毒、归肾 9 味）；涌吐 3 味（全寒、全标有毒、无一归肾）。
6. **标缺口**：五味白名单未收「微涩」，麻黄根只剩「甘」，因此"含酸或涩"是 10 味而非 11 味。
7. **复核**：每条结论能指到 `教材·第26章·26.x.y` / `教材·第27章·27.1.x`，且禁忌句逐字引用。

## 命令

```bash
cd departments/02-zhongyao/01-zhongyaoxue/chapters/11-shouse-yongtu
node code/main.js                # 两章规模 + 四节×四气 + 收/吐对照画像 + 单味药
node --test code/main.test.js    # 10 项：规模/结构/原文核对/口径/教学边界
```

## 质量判据

- 方向判断只引功效语与适应证，不用症状计数投票
- 四气保留五档（寒/凉/平/温/微温），"微温"未丢
- 涌吐 3 味逐条标出「有毒」，收涩 14 味标明"未标"
- 补涩兼施的药（山茱萸、菟丝子、覆盆子）标 dual，并写明本书归属章
- 明确指出负类样本仅 3 条，不给"涌吐药都如何"这类推断

> 本技能输出为分类校对与检索辅助，不构成诊断、处方或自救建议。
