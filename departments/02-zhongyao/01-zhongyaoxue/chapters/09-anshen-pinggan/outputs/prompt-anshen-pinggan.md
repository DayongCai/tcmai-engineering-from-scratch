# 安神 / 平肝息风 / 开窍 · 三章合并解析器

## 用途

把教材·第22、23、24 章（安神药 9 味、平肝息风药 13 味、开窍药 4 味，共 26 味）合并成一份**带分章口径**的结构化表，用于建库、教学演示、讲课前的口径对账。
不用于开方，也不用于按「归经相同」推替代药。

## 提示词

```text
你是中药学数据整理助手。输入是教材三章的 26 个小节：
第22章 安神药（22.1 重镇安神 4 味 / 22.2 养心安神 5 味）
第23章 平肝息风药（23.1 平抑肝阳 5 味 / 23.2 息风止痉 8 味）
第24章 开窍药（24.1 4 味）
每节三段：来源与性味归经 / 功效与主治 / 用法用量与使用注意。

任务一：逐味输出 JSON：
{"name","chapter","sec","qi","wei":[],"guijing":[],"toxicity","pregnancy","badges":[],"source"}

规则：
1. 归经照抄，不合并、不推断。字段为空就留空数组，并在任务三里列入缺口清单；
   不要用「一般认为」补齐，也不要抄同章其他药的字段。
2. toxicity 四值：大毒 / 小毒 / 有毒 / 无毒。pregnancy 四值：禁用 / 忌用 / 慎用 / 未标注。
3. qi 原样保留「微寒」「凉」等字，不压平。
4. badges 抽正文中带「要药」的定位短语，逐条保留。

任务二：分章统计，禁止只给合并数。逐章输出：节数 / 味数 / 段数 / 字数，
并给出每章归经覆盖最高的一条经与该经的覆盖比（x/y）。
最后再给合并数，并写明「合并数掩盖了什么」。

任务三：缺口清单。列出味或归经为空的药，逐条写：
教材哪一段、断在哪里、为什么不能补。

任务四：规模校验。逐章字数相加与三章合计必须相等（1601+2565+757=4923）；
不相等时先查漏段与重复计段，不要先解释差异。
```

## 使用示例

输入（节选）：「龙骨为古代哺乳动物……的骨骼化石或象类门齿的化石。性平」

输出：

```json
[{"name":"龙骨","chapter":"22","sec":"22.1","qi":"平","wei":[],"guijing":[],
  "toxicity":"无毒","pregnancy":"未标注","badges":[],
  "source":"教材·第22章·22.1.3 龙骨"}]
```

「缺口清单」：龙骨——教材首段在「性平」处截断，味与归经均未写出；标为缺失，不补，不得用牡蛎字段代替。
「合并掩盖了什么」：分章为 22 章心 8/9、23 章肝 13/13、24 章心 4/4；合并成「肝 18 · 心 16」会让读者以为两轴均衡。

## 为什么这样限制

- 强制分章：合并数是聚合结果，聚合必然丢信息；不给分章数，读者无法还原「每章一条轴」的事实。
- 缺口单列且禁止补：补出来的字段读起来毫无破绽，但整份数据从此无法溯源——这比明显的缺失更危险。
- 规模校验放在最后但必须跑：1601+2565+757 是最便宜的完整性检查，漏一段就会被它抓住。
- 原样保留四气：微寒、凉一旦压平，矿物介类的寒凉倾向就被抹掉，而「咸 + 寒凉 + 质重」正是重镇潜阳的用药逻辑。
