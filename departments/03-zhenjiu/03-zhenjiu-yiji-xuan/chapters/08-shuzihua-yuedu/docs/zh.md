# 第 8 章 · 检索能把找不到变成找得到太多，判断仍要回到原文

> **MOTTO:** 「凡刺之真，必先治神。」——《素问·宝命全形论》
>
> **PROBLEM:** 教材第 10 章 6 节、12,819 汉字，是全课唯一一章**没有一条**标为「原文」的条文——全书 211 条【原文】、8 条【原文·待核】，这一章是零。它有的是另一种标记：「可辅助参考」出现 28 次，占全书 114 次的 24.6%，而它的篇幅只占全书的 7.7%。一边是零条原文，一边是每 458 字一次的免责标签。这两个数字放在一起，就把这一章的性质说清了：它不是选读章，是操作章；它讲的是怎么找原文、怎么核原文、怎么在找不到时承认找不到。麻烦也正在这里——学生学完前七章，习惯的是「读原文」；到了这一章，手上没有原文可读，只有工具、流程与边界。工具用顺了，最容易发生的不是找不到，而是找到太多，然后随手挑一条像的用。
>
> **双根因定位:** 环境逼迫（古籍数字化的三层资源各有各的失真方式：影像层看得见版式但不可检索，文本层可检索但 OCR 会认错字，结构化层可计算但标注者的判断已经嵌进数据；任何一层单独用，都会把「某数据库里这样写」当成「原书这样写」） + 知识积累（这一章的知识形态与前七章不同：前七章的知识在条文里，这一章的知识在流程与边界里——核对三步、边可溯源、样本范围、三类 AI 风险，全是可执行的规矩，背不下来条文不要紧，漏掉一条规矩就会把错的引文写进作业）

**教材出处:** 教材·第10章·10.1.1–10.3.2（6 节 / 12,819 汉字）；单元层 `standards/zhenjiu-yiji/units.json`

## 一、六节没有一条原文，这个空缺本身就是内容

六节的题目连起来读，是一条完整的作业流程：先讲资源（医籍数字化资源与校勘数据库），再讲结构化（针灸医籍知识图谱），再讲检索与注释（AI 辅助原文检索与注释），再讲统计（数据挖掘与取穴规律研究），然后是平台（医籍研读功能），最后收在边界（数字化研读与经典原义的边界）。六节单节字数从 2,033 到 2,188，极差 155 字——长度几乎被均分。传统选读章的节长随材料长短起伏，这一章不是：它按功能切块，每块写满一个主题就收。

零条原文不是缺点，是这个主题的必然。讲「怎么找原文」的章节，如果自己也塞满原文，就变成了第七种选读，跑题。但零条原文有一个副作用必须提前说清：本章的所有结论都没有条文可对照，读者只能靠流程自证。所以本章的判据不是「记住几条结论」，而是「能不能按规矩完成一次检索并说明它的边界」。

这也解释了那 28 处「可辅助参考」为什么密度这么高。它们是这一章的自我限定：凡涉及工具给出的判断（检索结果、AI 注释、图谱关系、统计规律），一律标注其可靠性等级。一个 12,819 字的章节里标 28 次，平均 458 字一次，密度高到近乎啰嗦——但正是这种啰嗦，把「工具产出」和「经典原文」在文本层面隔开了。

## 二、三层资源，各有一层失真

教材把数字化资源分三层，这个分层不是分类学，是失真谱。

第一层是影像化：对善本、孤本作高清影印，如国家图书馆「中华古籍资源库」、各中医药院校古籍馆藏与海外汉籍数字库。读者可逐叶浏览原书版式、版心、鱼尾乃至钤印纸墨，最大限度保留古籍原貌，是版本鉴定与校勘工作的重要底本来源。它的优点是没说谎——看到什么就是什么；缺点是不可检索，也不可复制，读一叶得一叶。

第二层是文本化：通过 OCR 与人工校录生成全文文本，如各类中医药古籍全文数据库、《中华医典》等大型汇编，实现字词级检索。这一层的失真最隐蔽。针灸古籍存世版本多、异文繁杂，繁体、异体、俗字密集，明堂经络图等插图难以自动识别，故数字文本普遍存在识别误差。一个认错的字在检索时不会报警：它只是让你搜「沈涩紧」时漏掉那一条，或者搜出一堆不该有的结果。

第三层是结构化：以 XML、TEI 等标准对文本作篇、章、段、句、词的多级标记，把「条文—出处—异文—注家」组织成可程序处理的数据。这一层最像「知识」，失真也最像「判断」——标记谁做的、按什么体例分的篇、异文挂在哪个节点下，全是人的决定，一旦入库就看不见了。

教材给的对策是「数字化核对三步」：第一步核对出处，确认篇名、卷次无误；第二步核对文字，与权威整理本逐字比对；第三步核对语境，通读前后文判断引文是否切当。三步的顺序有讲究：先钉身份，再钉字句，最后钉用法。顺序颠倒就会出典型错误——先被一句话打动，再回头找它的出处，找到相似的就认了。

教材还有一句总纲，本章照此执行：数字化资源仅为可辅助参考的检索与比对工具，凡正式引用、临床运用与学术发表，仍应以可靠整理本与善本原件为据，数字文本不可替代校勘定本。

## 三、图谱与挖掘：可溯源与样本范围，两条都不能省

知识图谱的组织方式是「实体—关系—实体」的三元组：节点为腧穴、经络、病症、刺灸法、医家、典籍，边为它们之间的关系，如「合谷—属于—手阳明大肠经」「风池—主治—头痛」「《灵枢·经脉》—记载—肺手太阴之脉循行」。构建循四步：本体设计、语料标注、关系构建、存储与可视化。

它的价值在于把散见各篇的零散知识连成网络：沿「足阳明胃经」这个节点，可一次览其循行、腧穴、主治、刺法与相关条文出处。它的风险在于边太多而无人负责。教材因此立了两条纪律，这两条是本章最该背下来的句子。

第一条：每条关系边都须可溯源，即标注所据典籍、篇目与原文片段，点击可回原文核对，无出处的边一律不得入库。第二条：图谱须标注样本范围，说明语料来源、条目数量与时间跨度，使使用者知晓其覆盖边界。

数据挖掘的纪律与前两条同构，只是对象换成了统计。流程是：构建语料、分词与命名实体识别、频次与关联分析、聚类与归纳。教材举的例子很具体：对头痛类条文与医案作频次统计，可发现风池、合谷、太阳等穴出现频率较高，这与《标幽赋》所强调的「宁失其穴，勿失其经」的取穴思想相互印证。

这里要停一下。「相互印证」四个字很容易被读成「统计证明了经典」。教材紧接着用《流注指微赋》的话把方向扳回来：「观虚实于肥瘦，辨四时之浅深，是见取穴之法」——古人取穴本来就依体质、季节、虚实而辨，统计只是以现代语言重新呈现这些规律，属现代认识，不改经典原义。换句话说：频次高说明文献里这么写，不说明这么治最有效；共现多说明两个穴常一起出现，不说明它们有因果关系。

教材还设了一道程序闸门：统计结论须经审稿环节把关后方可进入教学与研读场景，称「统计结论送审」，送审对象是平台上的审稿智能体，作用是核对样本范围、检查语料来源与条目数、时间跨度是否如实标注，样本过小或来源单一者予以提示。这道闸门的设计意图很清楚：统计结论的问题多半不在算法，而在样本。

## 四、AI 的能与不能：三类风险与四条规矩

教材对 AI 的定位说得比多数教材都硬：这类应用以大模型在超大规模语料上的统计学习为基础，其生成内容是对既有文本模式的重组，本身并不具备训诂学的判断能力。由此列出三类典型风险：一是幻觉，可能生成原文库中并不存在的条文或出处；二是望文生义，把后世含义附会到经典字词之上；三是版本混用，不同版本文字被无意识杂糅。

三类风险对应四条规矩。

其一，AI 检索与注释一律回链原文库，所引原文以库内逐字文本为准，AI 不得自造或改写原文。其二，AI 生成的注释统一标注「可辅助参考」，并尽可能给出所依据的注家与辞书线索。其三，凡涉关键概念、临床运用与学术判断，须回查教材词解、释义、按语及权威注本核实。其四，平台应记录 AI 回答所依据的原文库条目，供使用者一键回查。

教材还给了一个具体的研读场景，值得照做：学生读《灵枢·九针十二原》「粗守形，上守神」遇阻，向助手提问此处「神」字当如何理解；助手在原文库范围内检索相关条文，给出「治神、守神」诸篇的关联文本，并生成注释，末尾标注可辅助参考；学生随后对照教材词解与《素问·宝命全形论》「凡刺之真，必先治神」之文，才对「神」的针灸学内涵有较完整把握。这个例子里真正的动作不是提问，是提问之后的对照。

教材引张宏审稿的意见给这一章定调：数字化与 AI 均为阶梯，经典才是根本，工具之利须以不僭越原文为准绳。同一口径在别处作「经典为体、数据为梯」。本章的标题取的就是这个意思：检索解决定位，判断仍要回到原文。

## 五、代价与边界

第一个代价是本课没有影印本与版本对照表。教材未附影印件，同一段在不同版本有异文时只取一说，本课如实标「教材取某本」。这意味着本章讲的核对三步，第三步（核对语境）在本课内做不全——没有影印本，就无法完成真正的版本对校。读者若要做版本功夫，必须另找善本或权威影印库，本课只能教流程，不能提供底本。

第二个代价是平台依赖。10.3 节讲的研读功能（原文库、图谱浏览、AI 助手、笔记与随堂测验）依托特定平台，离不开账号与网络。教材描述的是一套功能设计，不是本课的运行环境；本章据此讲流程，不承诺任何平台可用。

第三个代价是「可辅助参考」这个标签的滥用风险。标签本意是分级，用久了会变成免责套话：凡结论后面挂一句「可辅助参考」，责任就轻了。本章的用法是把它当动词看——标了「可辅助参考」，就必须同时给出回链与依据；给不出，就不该写这条结论。

第四个边界是临床。数据挖掘给出的高频穴、知识图谱给出的主治关系，都不是处方依据。教材对此的要求是疗效表述宜用「治疗」「常用」「可用」等审慎之词，凡涉临床应用须经临床验证与专家把关。本章照此办理：所有涉及取穴规律的内容，一律定位为文献描述。

> **免责声明：** 本章为针灸医籍教学文本，所论数字化资源、知识图谱、数据挖掘与 AI 辅助均属研读方法，不构成诊断或治疗建议；文中不含任何刺灸操作参数。临床决策须由具备资质的执业人员依现行规范作出，读者不得据本文施术或据工具输出自行处置。

## 六、运行与验证

本章的正文与习题契约由脚本现算，可当场复核：

```bash
node code/main.js
```

脚本打印的是本章正文的规模、习题的阶段分布与接地情况；退出码为 0 表示各项契约满足，非 0 表示有不满足的项，输出里会逐条写明。


本章的数字可以逐项重算，其中最能说明问题的是「零原文」与 28 处标签这一对。

```bash
$ node -e "
const u=require('./standards/zhenjiu-yiji/units.json').units.filter(x=>x.chapter==='10');
const t=u.map(x=>x.rawBody).join('');
const c=(r)=>(t.match(r)||[]).length;
const hz=u.map(x=>x.hanzi);
console.log('单元', u.length, '汉字', u.reduce((a,x)=>a+x.hanzi,0), '单节', Math.min(...hz)+'-'+Math.max(...hz), '极差', Math.max(...hz)-Math.min(...hz));
console.log('原文', c(/【原文】/g), '待核', c(/原文·待核/g), '可辅助参考', c(/可辅助参考/g), '引书', new Set(t.match(/《[^》]{2,20}》/g)).size);
"

单元 6 汉字 12819 单节 2033-2188 极差 155
原文 0 待核 0 可辅助参考 28 引书 16
```

输出与本章开头逐项吻合：6 单元、12,819 汉字、单节 2,033 至 2,188、极差 155；原文与待核都是 0，可辅助参考 28 次，章内引书 16 部。第二行的两个零是本章的立论基础，读者可自行把 `chapter==='10'` 换成 `'9'` 对照——那一章的原文是 24 条（见前一章）。

第二条验证是比例。全书 211 条【原文】、114 处「可辅助参考」，本章占标签的 28/114 即 24.6%，而篇幅 12,819/167,066 即 7.7%。把脚本遍历范围去掉 `filter` 即可复算，两个分母都能从同一份 `units.json` 读出。

第三条是自检。合上本章做三件事：一、说出三层资源各有一种什么失真，并为每层写一句「什么时候必须换层」；二、给一条夸张的知识图谱关系边（例如「某穴—主治—某病」）写出它的两个必需附加项；三、把 AI 注释的四条规矩压缩成一句可执行的话，句子里必须出现「回链」与「标注」两个动作。第三问写出「先问、后核、再判」六个字也算过关，但若写不出回链到哪一层（原文库、整理本、善本），说明核对三步还没立在手上。
