# 方案的分量在告知，风险的分量在记录

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 先完成评估、再行告知、取得同意后实施，并在实施中观察、在异常时报告、在全程中记录
- 告知必须在评估之后
- 同意必须在实施之前
- 观察必须在实施之中
- 记录必须贯穿全程
- 方案的价值不在动作有多新，在边界有多清

## 边界

- **没有处方参数。** 51,096 字、带单位数值 0 处，强度、频次、时长、疗程、进阶条件一概不给。本章谈的是程序，不是剂量；凡「多久一次、做多久」的问题，本课不给，底本也没有。
- **「顺序不可换」是归纳。** 底本只写「先完成评估、再行告知、取得同意后实施」，七环不可换序的四条理由（告知在后、同意在前、观察在中、记录贯穿）是本章补的推论，底本无对应解释。
- **「记录不成立」是判据，不是规范条文。** 它是本章从「记录」356 处的分布里抽出来的读法，用于自检，不能当作合规判定依据；合规判定以现行规范与机构制度为准。
