# 第 3 章 · 采集工具只做四件事，多做的每一件都要从招募窗口里扣时间

> **MOTTO:** 「不先言此，卒持寸口，何病能中」——《素问·徵四失论》
>
> **PROBLEM:** 本章单元层 7 节 12,095 汉字里，「客观化」出现 16 次、「指标」8 次、「红外」50 次、「图谱」40 次、「仿真」20 次；而「字段」0 次、「导出」0 次。底本整章讲的是"怎么把经络与腧穴现象测成一个可比的量"，一个字不讲"测出来的数记在哪儿、怎么交出去"。而本环节要交的恰是后半段：底本 12 步流程里第 5–10 步（跑通一例、抽查核对、定导出、管权限、做备份、写兜底）全是这件事，12 学时摊 12 步，一步一学时。
>
> **双根因定位:** 环境逼迫（工具必须在招募开始前跑通；晚一周就是从入组里扣一周，而且一例录不进的患者等于一次脱落）+ 知识积累（同一个现象有多种测法：感传问出现率、皮肤测电阻抗、艾灸测辐射光谱、手法测算参数——口径不同就不可比。工具的职责是把口径钉死在一列字段上，不是把数据存起来；教材写的"客观化"三个字，落到工具里就是"这一列的单位和取值域"）

**教材出处：** 本课为派生课，无独立教材。六章底本是 `textbooks/03-zhenjiu/22-zhenjiu-biye-sheji/03-第3章-方法与系统实现.md`（操作型章手册，1,439 汉字、12 步流程、12 项现场清单、9 行模板、6 条常见失效、4 项考核，权重 35／25／20／20）。机器可读层 `standards/zhenjiu-biye/units.json` 的 3.1–3.7 共 7 单元 12,095 汉字，章→节映射在 `standards/zhenjiu-biye/chapter-map.json`。单元层这 7 节（经络现象与循经感传、经络实质假说、腧穴特异性、效应机制、艾灸红外物理特性、知识图谱与三维经络、仿真针刺与 AI 辅助）在本章的作用不是"系统的做法"，而是"口径的先例"——它们示范了一件事：一个传统描述要被研究，先得被指定成某一台仪器、某一个单位、某一种判定。

## 一、底本七节示范的其实是"口径"，不是"系统"

把 7 节按字数排开，最厚与最薄差 693 字（2,079 对 1,386），平均 1,728 字，规模上很均匀：

| 节 | 汉字 | 内容 | 它示范的口径 |
|---|--:|---|---|
| 3.1 | 2,079 | 经络现象与循经感传 | 出现率（%）、感传速度（cm/s）、阻滞与否 |
| 3.2 | 1,950 | 经络实质假说 | 假说并存，尚无公认形态学对应 |
| 3.3 | 1,728 | 腧穴特异性研究 | 经穴与非经非穴的组间差 |
| 3.4 | 1,875 | 腧穴效应机制 | 镇痛与调整作用的层次划分 |
| 3.5 | 1,611 | 艾灸红外物理特性 | 辐射光谱波段、表面温度 |
| 3.6 | 1,466 | 知识图谱与三维经络 | 实体—关系—属性三元组 |
| 3.7 | 1,386 | 仿真针刺与 AI 辅助 | 角度、深度、频率、力 |

七节里有五节在做同一件事：把一个说不清的传统描述，指定成一个能读数的东西。循经感传变成"出现率 + 速度"；灸的温热变成"光谱 + 温度"；手法变成"角度 + 深度 + 频率 + 力"；腧穴特异性变成"组间差"；知识图谱变成"三元组"。

这件事对你的工具有一个直接后果：**每指定一个口径，就必须在表里留一列，并写明单位与取值域。**"得气"在 3.1 里是靠受试者报告的性质词与感传现象来把握的，落到表里就是"有无／性质（酸麻胀重，多选）／是否循传／第几诊出现"四列，而不是一个"良好"。同理，电针的"疏密波"必须拆成两档频率加一个电流值，否则两个人都写"疏密波"，谁也不知道是不是同一组参数。

这也是本章为什么不能照抄底本：底本教你把现象变成数，不教你把数放进哪一格。格子的形状决定了半年后你能不能算出组间差。

## 二、功能清单只留四项，其余写进不做

系统的目的只有一个：让评价能算。围绕这个目的，第一版只需要四个功能。

| 功能 | 做 | 不做 |
|---|---|---|
| 入组登记 | 病例编号、组别、入组日期、纳排判定 | 病历全文录入、影像上传 |
| 随访提醒 | 按表头四个时点算日期、逾期标红 | 短信/微信自动推送、患者端小程序 |
| 量表录入 | 必填、范围、日期逻辑、重复编号拦截 | 自动计分以外的智能解读 |
| 导出 | 一行一例或一行一次访视，列名固定 | 自动统计、自动作图 |

四行右侧那一列不是"以后再说"，是"这一版明确不做"，写在文档首页。理由很实际：功能每多一项，就多一轮测试与培训，而测试与培训只能从招募窗口里扣。第 3 章底本把它写成一句更硬的话——功能膨胀必然拖到招募期，先跑通一条链路。

技术选型同理：两周内能跑通的方案优先。现成表单工具、轻量脚本、甚至一张带校验的表格文件，只要能满足四件事与下面的字段映射，就是合格的选择。为技术栈牺牲招募进度，是把手段当成了目的。

## 三、字段映射与四项校验：错误在这一步拦下，不然要等到分析

字段的唯一来源是病例表。工具里多一列必须写理由，少一列不许上线。映射写成三列对照，一列对不上就是一处未来要手工返工的地方：

| 工具字段 | 病例表列 | 导出列名 | 校验 |
|---|---|---|---|
| enrol_id | 病例标识 | id | 唯一、格式 `中心-组别-序号` |
| arm | 组别 | arm | 取值域 {A,B} |
| visit | 时点 | visit | 取值域 {基线, 疗程中, 疗程末, 随访} |
| needle_site | 穴位与定位 | site | 非空、须含定位方法 |
| needle_depth_mm | 进针参数 | depth | 数值、范围内 |
| deqi | 得气 | deqi | 固定描述词集合 |
| ea_hz / ea_ma | 刺激量 | hz / ma | 数值、范围内；不做电针则留空且有标记 |
| nrs | 主要结局 | nrs | 0–10 整数 |
| drop_reason | 脱落与偏离 | drop | 与完成诊次逻辑一致 |

导出列名用英文短名加一张对照表，理由不在美观：中文缩写每次分析都要重新猜一遍含义，猜错一次就多一版结果。

四类校验必须实现，缺一类就会在分析阶段以"脏数据"的形式回来找你：必填项、数值范围（如 NRS 0 到 10）、日期逻辑（随访日期不早于入组、不晚于今天）、重复编号拦截。

校验做完，还要跑一例真实病例从登记走到导出，记录每步耗时与卡点。卡点超过三处，砍功能而不是加时间——砍完重新完整跑一遍，因为砍掉的功能可能正是某一列的来源。

最后是抽查核对：随机抽三条记录，与纸质病例表逐字段比对。不一致的处理顺序是**先改字段定义，再改程序**——如果定义本身有歧义，改程序只是把一个歧义实现得更牢。改完重抽五条（比原来多两条，因为改动可能引入新错），差异与修正写进附录。这一步是整章唯一能证明"字段真的对得上"的动作，跳过它就只剩口头保证。

## 四、兜底、备份与留痕：三种故障，各写一页纸

门诊环境不会配合你的系统。三种情形必须事先写纸质流程，并且演练过：

| 情形 | 纸质兜底 | 事后处理 |
|---|---|---|
| 断网 | 打印当次访视表，当场填，签时间 | 24 小时内补录并标「补录」 |
| 设备故障（平板/电脑不可用） | 同上，另记故障起止时间 | 修好后先补录当日，再恢复当日之后的录入 |
| 患者未按时随访 | 电话记录单：联系时间、原因、下次约定 | 逾期超过窗口即按脱落记，不追补为按期 |

备份的判据不是"有没有备"，是"能不能恢复"。每日自动或手工双备份，备份不与主库同机；恢复演练做一次并记耗时，演练失败即视为没有备份——这句话不好听，但它把"以为有备份"和"真的能恢复"分开了。

权限与留痕三句话：谁可录入、谁可修改、谁可删除，写进一页说明；修改留痕（改前值、改后值、改的人、时间）；删除只做逻辑删除，记录保留但标作废。删除代替作废会让审计链断在最需要它的那一刻——争议例出现时，你无法还原当时记了什么。

版本信息四行：工具版本、依赖库版本、部署位置、数据存储位置。升级前先备份，升级后重跑一例验证，验证通过才算升级完成。

最后一步最容易被省掉：写一页使用说明（谁在何时填什么），请一位未参与开发的同学按说明独立录一例，记下他问的每一个问题，据此修订说明。他问的每个问题，都是正式上岗时评价者会问的同一个问题。

## 代价与边界

- **本课不给现成系统与代码模板**：四种功能是清单，不是实现；技术选型按两周能跑通的原则自定，本课不复述任何厂商产品。
- **本课不给字段全集**：上面的映射表以主导出为例，实际列数取决于你的量表与方案；每加一列必须写理由并记版本。
- **本课不给校验的取值域**：NRS 0–10 这类通用域可照用，其余（深度、频率、电流）须按你的方案与现行规范设定，本课不在这些参数上给数。
- **单元层讲"怎么测"，不讲"怎么记"**：「字段」「导出」在这 12,095 字里各 0 次；把本章当"系统说明书"读会失望，它给的是口径的先例。
- **12 步不等于两周**：流程是动作清单，排期要按你的招募开始日倒推；跑通一例与抽查核对合计通常占掉最长时间，不要把这两步排在最后。
- **不替代专业判断**：本章用于工具设计与自查，不构成医学意见；数据合规（伦理、知情同意、个人信息）另见本章末声明与所在机构制度。

> **免责声明：** 本章为毕业设计教学材料，不构成医学意见、诊断或治疗指导。系统只承载研究数据，不承担临床决策：涉及人的研究须先取得伦理审批，入组前完成知情同意，未获批准或未签同意书者不得录入；工具内不得存放超出研究目的的身份证件、住址与联系方式，姓名等直接标识应在入组时替换为研究编号，可还原编号与姓名的对照表单独加密存放、限定访问人，导出与共享文件一律去标识，数据保存期限、备份介质与销毁方式按机构制度执行；录入、修改、删除与补录须留痕并遵守学术规范，不得事后改写原始记录、不得隐瞒脱落与方案偏离。一切操作与判断以现行规范、所在机构制度与伦理批件为准。
