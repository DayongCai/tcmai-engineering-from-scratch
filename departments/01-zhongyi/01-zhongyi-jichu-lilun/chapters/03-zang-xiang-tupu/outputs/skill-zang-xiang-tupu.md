# 藏象关系链抽取与校验

## 何时使用

当你需要把一组散在的症状，串成一条**可核查的藏象关系链**（而不是给一个证型名称）时。
典型场景：整理医案、写病历的机理部分、检查一份辨证依据里有没有跳步。

不适用：给出证型诊断、处方、治则；判定预后。

## 输入契约

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `症状列表` | string[] | 是 | 例如 `["易怒", "流泪", "目干"]` |
| `已知体征` | object | 否 | 望闻问切的其他结果 |
| `允许的关系类型` | string[] | 否 | 默认：`相表里/开窍于/在志为/在体为/其华在/化为/属五行/相生/相克` |

## 步骤

1. **实体识别**：把每个症状映射到本体中的节点。映射不上就标 `unknown`，**不要新建节点**（新节点必须先进本体）。
2. **连边**：对每一对可连的节点，给出一条边，并标注：
   - `type`：关系类型，必须来自允许列表
   - `direction`：`forward` 或 `reverse`（真实边方向）
   - `source`：依据出处
3. **跨五行检查**：如果链路上经过五行节点，**必须**显式写出用的是相生还是相克，并给出正确方向。
   - 例：肝→悲 走的是**金克木**，遍历方向是逆向，必须标 `reverse`。
4. **跳步检查**：每一步都必须有依据。任何一步"因为中医认为……"而说不出关系类型的，标为 `unsupported`。
5. **输出关系链**，并单独列出 `unsupported` 的步骤。

## 输出契约

```json
{
  "chain": [
    {
      "from": "怒",
      "type": "在志为",
      "to": "肝",
      "direction": "reverse",
      "source": "《素问·阴阳应象大论》五行配属段"
    }
  ],
  "wuxing_hops": [
    { "from": "木", "type": "相克", "to": "金", "direction": "reverse", "note": "金克木，逆向遍历" }
  ],
  "unsupported": [],
  "disclaimer": "本输出为关系链整理，不构成临床诊疗建议。"
}
```

## 硬约束

- **每一步都必须有 `type` 与 `source`。** 无类型的一步视为无效输出。
- 跨五行的边**必须**标 `direction`。把「金克木」写成「木克金」是学术错误，不是排版问题。
- **不得新建本体外节点**。要加节点，先在章节的本体定义里加。
- 关系链是**拓扑关联**，不等于因果。输出里**不得**出现「导致」「引起」「因此会」这类因果措辞。
- 不允许输出证型、方剂、剂量、治则。
- 结尾必须带 `disclaimer`。

## 已知陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 方向讲反 | 「木克金」 | 相克只有五个方向：木克土、土克水、水克火、火克金、金克木 |
| 拓扑当因果 | 「怒 5 跳连到 骨，故易怒伤骨」 | 图上连通 ≠ 因果机制 |
| 跳步 | 直接从「流泪」跳到「肝血虚」 | 中间每一步都要有边 |
| 自造节点 | 把「目干」当成一个新实体 | 先映射到本体节点（目 / 液），映射不上就标 unknown |
| 只写相生 | 一条链上只提相生不提相克 | 跨五行的每一跳都要标明是生还是克 |

## 验证清单

- [ ] `chain` 每一项都有 `type` 与 `source`
- [ ] 每个 `wuxing_hops` 项都有 `direction`
- [ ] 输出中不含因果措辞（导致/引起/因此会）
- [ ] `unsupported` 里的步骤被显式列出，而不是被静默省略
- [ ] 没有新建本体外节点
- [ ] 任何输出路径都带 `disclaimer`
