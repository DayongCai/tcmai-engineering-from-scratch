# 五行归类的可归因流程

## 何时使用

当你需要把一个症状、一味药、一个方位或一个季节归入五行之一，并且
**必须说清是「依据哪个配属维度」归的**时。

不适用：需要给出证型诊断、处方或治则；需要判断生克传变的具体临床走向（那需要完整四诊与病程）。

## 输入契约

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `对象` | string | 是 | 待归类的对象（症状 / 药物 / 方位 / 季节 / 情志） |
| `依据维度` | string[] | 否 | 只允许从 `色/味/志/方位/季/脏/腑/官窍/形体` 中选 |
| `原文` | string | 否 | 原始描述，用于抽取 |

## 步骤

1. **取维度**：确认待归类的对象在哪些维度上有配属依据。**没有任何通行配属依据的对象直接拒答**，不要硬归。
2. **逐维度归类**：对每个可用维度，写出该维度下的五行为何。引用配属表时要写到具体来源（如《素问·阴阳应象大论》五行配属段）。
3. **一致性检查**：若不同维度给出**不同的五行**（例：某表现按「色」归木、按「味」归金），必须显式冲突，不得挑一个顺眼的上报。
4. **关系标注**：给出该五行与其余四行的生克关系。
   - 相生：木→火→土→金→水→木（外圈）
   - 相克：木克土、土克水、水克火、火克金、金克木（隔一）
5. **输出置信度**：可用维度 ≥ 2 且全部一致 → `high`；可用维度 = 1 → `medium`；维度冲突 → `conflict`（不是 low）。

## 输出契约

```json
{
  "object": "…",
  "verdict": "木 | 火 | 土 | 金 | 水 | 无法归类",
  "by_dimension": [{ "dimension": "色", "element": "木", "source": "《素问·…》" }],
  "consistency": "high | medium | conflict",
  "conflicts": [],
  "relations": { "sheng_to": "火", "sheng_from": "水", "ke_to": "土", "ke_from": "金" },
  "disclaimer": "本输出为结构化归类辅助，不构成临床诊疗建议。"
}
```

## 硬约束

- 输出**必须**包含 `by_dimension`，每项都要有 `source`。无来源的归类一律无效。
- 维度冲突时 `consistency` 必须是 `conflict`，且 `conflicts` 非空。**不得为了让结果"好看"而挑选单一维度。**
- 生克关系**必须**完整给出四条边（生我 / 我生 / 克我 / 我克），缺一条即为无效输出。
- 不允许输出证型、方剂、剂量、治则。
- 结尾必须带 `disclaimer`。

## 已知陷阱

| 陷阱 | 表现 | 修正 |
|------|------|------|
| 维度混用 | 用「味」的依据得出「木」，再拿「方位西」当理由 | 每个结论必须标注它是哪个维度得出的 |
| 关系漏边 | 只给「相生」不提「相克」 | 四条边齐全是硬约束 |
| 无依据归类 | 说「某症状属土」但说不出配属来源 | 直接判 `无法归类` |
| 把归类当诊断 | 「属木，故肝郁气滞」 | 越界。归类是结构性工作，不是辨证 |

## 验证清单

- [ ] `by_dimension` 每项都有可核查的 `source`
- [ ] 维度冲突时 `consistency = "conflict"` 且 `conflicts` 非空
- [ ] `relations` 四条边齐全
- [ ] 无配属依据的对象输出 `无法归类`
- [ ] 任何输出路径都带 `disclaimer`
