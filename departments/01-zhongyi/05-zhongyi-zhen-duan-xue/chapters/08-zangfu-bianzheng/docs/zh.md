## 核心概念

### 中医：脏腑辨证的位置

脏腑辨证不是另起一套体系，它是八纲在**病位**维度上的展开。《素问·五脏生成篇》讲「五脏之气，故色见青如草兹者死」，把面色、症状与脏气联系起来；后世《景岳全书·传忠录》把辨证拆成「表里寒热虚实」，病位仍要落到脏腑。所以一张合格的脏腑辨证规则表至少要回答两件事：**哪一脏**、**什么性质**（寒热虚实）。

教材把每一脏的证候写成「主症 + 次症 + 舌脉 + 兼症」的固定结构。这个结构本身就是一张可执行的打分表：主症是必要条件，次症是加权证据，舌脉往往是**区分寒热**的关键。

### AI/工程：加权规则表与证据缺口

设证候 $S$ 的症状-权重对集合为 $E_S$（每条形如「症状 $f_i$ + 权重 $w_i$」），病人出现的症状集合为 $P$，则

$$\text{score}(S)=\frac{\sum_{f_i\in P\cap E_S} w_i}{\sum_{f_i\in E_S} w_i}$$

三个必须同时输出的量：

1. **score**：覆盖度，不是概率，不要给它加 softmax 的外衣；
2. **missing**：未命中的**主症**——这是「还差什么」，比分数本身更有临床价值；
3. **rivals**：分数相差小于 0.15 的竞争证候，必须一并列出，因为临床上真正难的是鉴别。

把这三样一起输出，规则表才不会沦为「一个看起来很像 AI 的东西」。

## BUILD IT：从零实现

```js
// code/main.js 核心（完整文件见仓库）
function score(rule, symptoms) {
  const hit = rule.evidence.filter((e) => symptoms.includes(e.f));
  const w = rule.evidence.reduce((a, e) => a + e.w, 0);
  const s = hit.reduce((a, e) => a + e.w, 0);
  return {
    id: rule.id,
    score: +(s / w).toFixed(3),
    missing: rule.evidence.filter((e) => e.required && !symptoms.includes(e.f)).map((e) => e.f),
  };
}
```

## 代价与边界

- **权重是人的判断，不是数据学出来的**。表里的 3/2/1 来自教材对主症次症的划分，换一本教材就会变。要它稳定，必须固定版本并记录出处，否则同一病人换一家医院得出两种结论。
- **覆盖度会被「症状说得越多」的病人抬高**。问诊越细，score 越高，与病情轻重无关。所以分数只能在同一份问诊表内比较，跨病人比较没有意义。
- **规则表不能表达「按之痛减」这类需要触诊的动态信息**，也不能表达病程与传变——那需要状态机，不是打分。
- **它不处理合病并病**。多证并存时应当输出多个证候并列，而不是取 top-1。

> **免责声明：** 本章的规则表与代码是教学与工程演练材料，不构成诊疗建议，不能替代执业医师的四诊合参与鉴别诊断。任何真实病例的辨证结论由医师负责。

## 进阶思考

规则表是最容易做、也最容易被误当成「智能辨证」的一层。真正的分界不在算法复杂度，而在**是否诚实地报告证据缺口**——一个只会报 top-1 的系统，医生无法判断该不该信它。
