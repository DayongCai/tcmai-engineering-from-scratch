# jing-shi-ye

## 何时使用

- 要核「痉湿暍篇多少条、几方、讲了几个病」这类结构说法
- 讲稿里出现「刚痉无汗 / 柔痉有汗」被推广到全篇 27 条时
- 需要一份可引用的误治清单（汗 / 下 / 温针 / 火攻）作为「边界先于方」的例证
- 把篇 2 归入外感类还是内伤类产生争议时（它用内伤方，但条文属外感段）

## 数据来源

`standards/jingui/底本.json` 之 `pian[no=2]`（外源·笈成，sha256 见 `standards/jingui/README.md`）；
复算：`python scripts/build_jingui_text.py --check`；抽查：`python scripts/build_jingui_text.py --tiao 2.13`；
画像：`node code/main.js`；断言：`node --test code/main.test.js`。

## 硬约束

1. 条号是本库按源页 `<p id="篇.条">` 分的，**不得标成「宋本第 N 条」**。通行本常作 25 条，本库是 27 条。
2. 归类优先级必须是 **痉 → 暍 → 湿**。理由：2.7 是痉病主证而句中有「寒湿相得」，湿优先则痉掉到 12 条。
3. **刚柔只判 3 条**（2.1 刚、2.2 柔、2.12 欲作刚）。2.11 全条无「汗」字，不得外推为柔痉。
4. 方只计有方文者 11 个；**2.23 一条出两方**（桂枝附子汤 + 去桂加白术汤，底本作「白术附子汤方」，v2 已按 `<b>X方：</b>` 切开）。按「出方的条数」数会得 10，两个口径不得混用。
5. 误治 9 条 12 次是**本表所收**，不是「全篇所有不当处置」；2.3、2.10 的「难治」是预后判断，不入表。
6. 「可与大承气汤」（2.13）不得引作「主之」。

## 用法

1. 先跑 `node code/main.js`，把「条 / 方 / 三分 / 误治」四组数字记下来；不要用记忆里的 25 条或「三个病」。
2. 核说法：数字不符 → 写正确值 + 条号范围；归类争议 → 查该条 zhHans 的字面，不查注家。
3. 引用时写全 `外源·笈成·金匱要略方論 第2篇·第M条`，一字不改（「可与」不是「主之」）。
4. 讲「为什么这一篇方少」时，用方条比 0.23 → 0.55 → 0.67 的递进，比说「痉病复杂」有据。

## 不适用

- 方证判断、处方、剂量、煎服法
- 校勘（外源非校本，繁简两栏互校只在字面层）
- 用关键词归类作为临床诊断标准
