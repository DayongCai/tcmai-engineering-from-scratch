# 第 11 章 · 条文检索：MRR 满分不算过关，说不清「库里没有」才是问题

> **MOTTO:** 「有柴胡证，但见一证便是，不必悉具。」——《伤寒论·辨太阳病脉证并治中》（篇 5 第 222 条）
>
> **PROBLEM:** 你给 1760 条经文建了 BM25 索引，四条有金标的查询全部命中第一位，MRR = 1.000。你准备上线，却没测「查不到」：问它「乌梅丸」，它返回 19:36「病人有寒，复发汗，胃中冷，必吐蛔」——原句是真的，答的不是你问的。更麻烦的是分数：这条 19.67 分并不低，而两个分布之间的余量按一种算法只有 1.8%，换一种算法是 14%。
>
> **双根因定位:** 环境逼迫（要在 1760 条里定位一句，手工翻篇等于翻书）+ 知识积累（排序指标 × 弃答判定 × 负样本从哪来 = 一套知道自己什么时候该说「没有」的检索）

## 一、语料与分词：1760 条、平均 79.8 token、词表 13,687

底本 27 篇 1760 条，切成「单字 + 相邻双字」后平均每条 79.8 个 token，全库词表 13,687。中文没有空格，分词规矩只能自己定，而可选的路只有两条：

- **只切单字**：「脉浮」与「浮脉」落进同一堆字，次序信息全丢，查询「脉浮」会召回所有含「脉」或「浮」的条；
- **单字 + 双字**：既保留单字召回，又保住「脉浮」「恶寒」「但欲寐」这类固定搭配。

第二条的代价是词表翻倍、索引变大，收益是查询「但见一证 不必悉具」能精确落到 5:222，而不是一堆含「证」的条。演示代码的 tokenize 只有三步：先归一（𤍠→热），再逐字取单字，最后取相邻双字。归一必须做在分词之前——否则「发𤍠」与「发热」是两个词，这一点第 3 章已经用 124 条漏检付过学费。

## 二、BM25 只做一件事：数词，不判义

```
score(D,Q) = Σ idf(t) · [ f(t,D)·(k1+1) ] / [ f(t,D) + k1·(1 − b + b·|D|/avgdl) ]
idf(t) = ln(1 + (N − df + 0.5)/(df + 0.5))
```

三个部件各管一件事，都能翻译成人话：

- `k1 = 1.5`：**词频饱和**。同一个词出现 10 次，不比出现 3 次重要 3 倍——条文里的重复多是行文习惯，不是强调；
- `b = 0.75`：**长度归一**。篇 5 的长条文不因字多就自带优势，否则越长的条越容易霸榜；
- `idf`：**稀有度加权**。「太阳」全库几百条，权重低；「胃家实」只在两条里出现，权重高——所以查询「胃家实」首位得分 31.43，靠的是稀有，不是靠这句话更 "对"。

这三个部件都不判断意义。BM25 没有「这个词在不在库里」的概念，它只知道自己见过哪些字。查询里的词一个都命不中时，它也不返回空，而是把「命中了一部分」的条按分数排出来。这是后面所有麻烦的源头：**一个永远会回答的系统，最需要的功能是会说没有。**

分词粒度还会改掉 idf 的分布，这一点常被忽略。同一句话只切单字时，词表里全是高频字，「脉」的 df 接近全库条数，idf 趋近于零，排序几乎完全由长度归一决定；切成「单字 + 双字」后，「脉浮」的 df 只剩几十、「无汗」更小，稀有度才开始起作用。所以调参之前先定分词——分词一变，idf 的含义就变了，同一组查询的分数不可跨分词方案比较。本章固定「单字 + 双字」，所有分数只在这个方案内有效。

## 三、评测：有答案看排名，无答案看弃答

七条查询、四条有金标。分数与位次如下（可由 `code/main.js` 现算）：

| 查询 | BM25 首位 | 分数 | 金标位次 | 子串 AND |
|---|---|--:|--:|---|
| 太阳 脉浮 头项强痛 恶寒 | 4:1 | 62.042 | 1 | 命中 1 条，第 1 |
| 胃家实 | 9:2 | 31.43 | 1 | 命中 2 条，金标第 2 |
| 但见一证 不必悉具 | 5:222 | 57.383 | 1 | 命中 1 条，第 1 |
| 心中疼热 气上撞心 消渴 | 24:1 | 70.5 | 1 | 命中 1 条，第 1 |
| 下利 厥 恶寒 四逆汤 | 19:121 | 30.852 | 无金标 | 命中 2 条 |
| **乌梅丸 吐蛔** | 19:36 | 19.666 | 无 | **0 条** |
| **少阴之为病 但欲寐** | 24:1 | 27.051 | 无 | **0 条** |

MRR = 1.000（四条金标全在第 1 位）。子串 AND 在这四条上也全对，但它对两个「库里没有」的查询返回 0 条——不是它聪明，是它只会精确匹配。两种失败模式刚好相反：**子串 AND 假阴性**（异文、通假、省略一律空手），**BM25 假阳性**（永远给一条最像的）。工程上要的不是二选一，是给 BM25 加一道「有没有」的判定。

MRR 本身也有一个天生的盲区：它只奖励「金标排第几」，完全不惩罚「榜首错得离谱」。一个把金标排在第一、同时把十条不相干的条塞进前十一的系统，MRR 依然是 1.000。要看见那十条，得另算一个布尔指标——本章用的是「首位原文是否含查询的关键对象」，它对乌梅丸那一例立刻报错，而 MRR 不会。

判定之前先看两条负样本的成色。「乌梅丸」在底本全库 0 条（第 8 章已核），「少阴之为病」0 条（第 2、7 章已核），所以这两问确实无答案。但 BM25 给出的首位都「像」：19:36 命中了真词「吐蛔」，24:1 命中了「欲寐」的近邻「但欲寐」。**这类错误的可怕之处在于原句是真的，只是答的不是你问的。**

### 余量 0.578，而这个数还掺了一条错标的负样本

本章的查询表里有三条没有金标，其中「下利 厥 恶寒 四逆汤」并不是「库里没有」——19:121 正是四逆汤证条，它只是没有单一金标。把它算进「无答案」桶，无答案侧的最高分被抬到 30.852；而真正无答案的两条最高只有 27.051。有答案侧最低是「胃家实」的 31.43。于是同一套代码给出两个结论：

| 口径 | 无答案最高 | 有答案最低 | 余量 | 阈值中点 |
|---|--:|--:|--:|--:|
| 含错标负样本 | 30.852 | 31.43 | 0.578（1.8%） | 31.14 |
| 剔除错标负样本 | 27.051 | 31.43 | 4.38（14%） | 29.24 |

差 7.6 倍。**阈值不是一个数，是一个带口径的结论**：报阈值必须同时报负样本是怎么来的、桶里有没有混进「其实有答案」的条。这一条比调 k1 有用得多——参数只影响排序，负样本的成色直接决定「可分不可分」这个判断本身。

## 四、判据与引用动作：白名单先于排序

判据三级：

- **能当依据**：金标条号 + 该条原文，同一底本内逐字可命中。
- **能当参考**：MRR、首位分数、余量。它们描述的是这七条查询，不是这个系统的能力。
- **不能当依据**：单个分数。分数高不等于答对了问题，19.666 分的 19:36 就是反例。

读法四步，顺序不能换：

1. 把分词与归一表写进记录（𤍠→热、嘿→默，各记命中数）；
2. 报 MRR 时同时报金标条数与查询总数（本章 4/7）；
3. 报阈值时同时报两侧极值与负样本来源；
4. 检索前先查**白名单**：词不在表里，直接回「底本未收」，不进排序。

第四步是本章给出的唯一挡幻觉方案。理由是负样本几乎拿不到：本章能用「乌梅丸」「少阴之为病」当负样本，是因为底本恰好缺这两块；换成一般语料，你无法事先知道哪些词「库里没有」，也就没有分母。白名单不同——它可以离线构建、可审计、可版本化：名单里有，才允许排序；名单里没有，答案就是「底本未收，待补源」。这条规则看着笨，却把「系统替你选了一条像的」换成了「系统说不出这条」。

还有一个必须做的动作是**归一表的双向账**：查询「默默不欲饮食」在底本 raw 命中 0 条，把「嘿嘿」归一成「默默」后命中 3 条（5:209／5:214／18:126）。记录里要同时写 raw 与归一后两个数，否则读者无法判断这 3 条是原文就用「默默」，还是归一补出来的。

记录字段六个：①底本标识与 sha256 前缀；②分词与归一表版本；③查询串原文；④金标条号（无金标写 null 并注明原因）；⑤首位条号与分数；⑥白名单命中状态（命中／未收）。第六项专门用来回答「为什么没有」——没有它，弃答看起来就像失败。

实操里的次序常被做反：先拿到一句「乌梅丸主之」要查出处，再发现库里没有。这时不要改查询去凑结果——把「乌梅丸」换成「蛔」确实能查到 19:36，得到的是一条讲吐蛔的条文，不是你要的方。正确动作是先查白名单，未收就停；已收才进排序，排序结果再回原文逐字核。三个动作的次序错了，就会得出「库里有一条很像的条文」这种半真半假的话，而这句话在讲义里会变成一条引证。

三类失效，都在这七条查询上能复现：

- **把「分数高」当「答对了」**。识别信号：首位原文不含查询里的关键对象（乌梅丸那一例，首位是 19:36）。
- **把阈值当常数**。识别信号：换 k1、换 b、换查询长度后阈值不复用；或负样本桶被换过而阈值照抄。
- **归一表只做一半**。识别信号：同一查询在 raw 与归一两个口径下命中数不同，而记录里只写了一个数。

**考核项：**

1. 说出「单字 + 双字」相对「只切单字」多保住了什么，用一个查询说明；
2. 记下四条有金标查询的首位与分数，并说明「胃家实」为什么得分最低却是第 1 位；
3. 解释为什么 BM25 对「乌梅丸」不会返回空，它返回的 19:36 命中了哪个真词；
4. 用两个口径分别报出余量（0.578 与 4.38），并说明差在哪一条查询上；
5. 写出「白名单先于排序」的两段式流程，并说明它为什么比调阈值更可靠；
6. 给出三条失效各一个识别信号。

## 五、代价与边界

1. 查询集只有七条、四条有金标，由作者自拟，不是基准集。MRR 1.000 只说明「这七条能查到」，不说明系统好用；换一批查询，同一个 MRR 可能落到 0.5。
2. 金标由人工指定，存在选条偏差。「胃家实」同时命中 9:1 与 9:2，本章取 9:2，理由是提纲句以「之为病」起头、与查询同构；换一个取法，这一条的分数与位次都会变。
3. 阈值与余量不可外推。换语料、换 k1／b、换查询长度都会移动，且负样本一改就整体重算——本章给两个口径就是因为这个。
4. 未处理否定与近义。「不恶寒」仍计入「恶寒」，「手足温」与「手足热」不作等价；症状词表也未收录异体与省略写法。
5. 只做检索，不做辨证。检索命中只说明「这条原文里有这些字」，不说明这个证适用于眼前这个病人；本章不涉及方药与用量。
6. 还有一层容易忽略的量：查询里若出现词表中 df=0 的词（全库从没出现过），BM25 对它的贡献恒为零，其余词的分数照样累加。所以「查不到」的表现从来不是返回空，而是返回一条「只命中了一半」的条——这正是白名单必须放在排序之前、而不能靠分数事后过滤的另一个理由。
