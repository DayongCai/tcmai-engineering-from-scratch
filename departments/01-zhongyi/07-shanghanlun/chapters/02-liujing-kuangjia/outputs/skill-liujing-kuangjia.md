# 六经辨证的框架：五条提纲，一条失踪

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 只以目录行的形式出现
- 底本在少阴、厥阴、太阴之间的篇界是错位的
- 提纲条能当依据
- 篇域标签只能当旁证
- 条数不能当权重
- 把这句话回底本检索，命中唯一才落行；命中 0 条就落「缺」，不许落「义近」

## 边界

- 框架不等于辨证。六经表回答「这一经的入口条件是什么」，不回答「这个病人属哪一经」。后者要四诊合参，超出本章能给出的证据。
- 缺口不补。少阴条本章一律不引；凡需要少阴原文的推理，标「待补源」，转到第 7 章的外源库，且必须换来源标识。
- 篇域标签不可全信。本章只用 `domain` 做分组，所有结论都回到篇名与条号上，不落在标签上。
- 全部条文引自仓库内 `standards/shanghan/底本.json`（源为识典古籍刻本电子整理本，可复核）。
