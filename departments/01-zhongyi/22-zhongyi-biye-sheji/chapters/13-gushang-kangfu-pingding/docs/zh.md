# 第 13 章 · 缺项填零，量表就成了假分数

> **MOTTO:** 「上工救其萌芽」——《素问·八正神明论》
>
> **PROBLEM:** 本章可复算的只有包的结构与门禁条数：可复现包四件、门禁三条。量表本身尚未建立，任何「信度系数」都不可报。若开题写「量表信度 0.9」，那个 0.9 没有数据支撑；而缺项被默认填 0 时，一份十项里缺三项的表，总分会被系统性压低或抬高，这正是本章要拦的失效。
>
> **双根因定位:** 环境逼迫（社区康复与第三方评估要一份别人能重跑的评定包，不接受「我会算」）+ 知识积累（可复现包四件的口径已在库，量表结构与门禁模板可直接套用）

## 一、命题与数据锚点：先交付包，再交付量表

本章的命题是：**把一套康复评定做成可复现包，最少需要哪些文件才能让别人重跑**。这个问题问的是「包」，不是「量表准不准」。量表准不准要靠信度研究，那不是一章能完成的；包能不能重跑，一章可以做完，而且做完就能被验证。

四件与三条先摆清：

| 项 | 内容 | 可否当场验 |
|---|---|---|
| 数据 | 评定条目与受评记录（脱敏） | 可，看字段齐不齐 |
| 脚本 | 计分与汇总 | 可，跑一次出分 |
| 门禁 | 三条自动检查 | 可，改坏即报警 |
| 文档 | README 三步重跑 | 可，照做能跑通 |
| 门禁一 | 字段完整性 | 缺字段即报错 |
| 门禁二 | 分数范围 | 越界即报错 |
| 门禁三 | 缺项显式化 | 缺项不许填 0 |

「缺项显式化」这条门禁是本章的核心。多数量表都会遇到缺项：受评者某一项做不了、记录者漏填、条目本身不适用。若脚本把缺项当 0，总分就会偏低；若把缺项按其余项均值补，总分又可能偏高。两种处理都不算错，错的是**不声明**。门禁的作用就是逼作者在数据里写清「这项缺」，而不是让它在计算里消失。

为什么强调「别人能重跑」而不是「我能算对」？因为康复评定的使用者往往不是开发者：社区护士、第三方评估员拿到包，要能在没有作者在场的情况下出分。作者在场时能算对，说明的是作者会；作者不在场时能算对，说明的是包会。毕设要交的是后者。

还有一层：本章不提供量表本身的信度数据。量表要自建、要检验，那是另一项工作。这一条必须在开题时说明，否则评审会以为作者在承诺一个已经验证过的工具。承诺做不到的事，比不承诺更伤。

## 二、分阶段交付物与分工

| 节点 | 时点 | 必交物 | 责任人 | 签收人 |
|---|---|---|---|---|
| 开题 | 第 1–4 周 | 量表字段表、三条门禁定义、脱敏方案 | 学生 | 开题小组 |
| 中期 | 第 8 周 | 计分脚本 v1、样例记录十份、门禁跑通记录 | 学生 | 导师 |
| 预答辩 | 第 12 周 | 缺项处理说明、越界样本、README 初稿 | 学生 | 预答辩组 |
| 答辩 | 第 16 周 | 四件包、门禁输出、他人复跑记录 | 学生 | 答辩委员会 |

开题先定字段，再谈计分。字段表至少写清：条目名、取值范围、缺项如何标记、是否必填。四件事里最容易漏的是「缺项如何标记」，漏了之后，脚本只能用 0 代替，而这正是本章要拦的。

分工上，字段与量表结构由导师确认，脚本与门禁由学生写，脱敏由教学秘书或院内对接人核。脱敏这一项不能省：康复评定记录里含年龄、病程、功能状态，属个人信息；对外交付的样例必须是脱敏后的，且要说明脱敏方式。

中期要交十份样例记录，不是为了好看，是为了让门禁有东西可跑。没有样例，门禁只能对着空表报绿；有了样例，才能演示「改坏一个字段，门禁立刻报错」。这十份记录建议覆盖三种情形：全填、有缺项、有越界值。

### 三种典型失败

第一种是「缺项当 0」。脚本里写 `score = sum(items)`，缺项自然是 0，跑出来不报错，总分偏低。作者若拿这个分去做前后对比，改善幅度会被高估。正确写法是先判缺项，缺项超过阈值就不出总分，只出「不可评」。

第二种是「越界不拦」。量表某一项设计为 0–3 分，记录里出现 4 分，脚本照加。总分虚高，且无法追查是哪一项越界。门禁二就是为此设的：任何一项超出定义域，立即报错并指出条目名。

第三种是「README 写给我自己看」。三步重跑写成「先配置环境再运行」，没有说配置什么、运行哪条命令。别人照做跑不通，包就等于没交。合格的 README 是：一条安装命令、一条运行命令、一段预期输出。

## 三、判据与评分维度【教学设定】

移交层判据四条：

| 判据 | 合格线 | 检查方式 |
|---|---|---|
| 四件齐 | 数据／脚本／门禁／README | 逐件打开 |
| 门禁可触发 | 改坏即报警 | 当场演示 |
| 缺项有标记 | 数据里能看出哪项缺 | 抽三份看 |
| 他人可跑 | 未参与者按 README 跑通 | 留记录 |

评分维度（教学设定）：

| 维度 | 权重 | 不合格 | 合格 | 优秀 |
|---|--:|---|---|---|
| 命题可判 | 15% | 只说「做评定工具」 | 有包结构 | 预写门禁三条 |
| 数据可核 | 20% | 字段定义不明 | 字段表可读 | 样例覆盖三情形 |
| 门禁有效 | 25% | 门禁从不报警 | 三条可触发 | 报错定位到条目 |
| 评价完整 | 20% | 不报缺项处理 | 缺项有说明 | 越界样本可读 |
| 移交可用 | 20% | README 缺失 | 三步可跑 | 附他人复跑记录 |

「门禁有效」占 25%，因为它是「可复现」这句话的唯一硬证据。门禁写了但从不报警，等于没有门禁；把它故意改坏一次、看它报不报，才知道它是不是真的在检查。这一项评分时通常要求当场演示，演示不出来就按不合格计。

「评价完整」这一项看的是缺项与越界的处理有没有写进论文，而不只是写在代码里。代码里处理了但论文不提，读者无法判断作者是否意识到这个问题；论文里写清「缺项超过阈值不出总分」，才算真正交代。

## 四、记录字段与复算口径

评定台账建议八列：

| 列 | 填什么 | 例 |
|---|---|---|
| 记录号 | 脱敏编号 | R-004 |
| 条目 | 量表条目名 | 转移 |
| 取值 | 该条目得分 | 2 |
| 缺项标记 | 是／否 | 否 |
| 适用性 | 适用／不适用 | 适用 |
| 录入人 | 编号 | U2 |
| 门禁状态 | 通过／报错 | 通过 |
| 版本 | 量表版本 | v1 |

「适用性」与「缺项标记」要分开。不适用不是缺项：某一项对受评者本来就不该评，记为不适用；该评而未评，记为缺项。两者若混成一列，脚本就无法判断总分该不该出。这一列的设计，直接决定门禁三能不能成立。

复算口径两条：总分 ＝ 适用条目得分之和；可评率 ＝ 已评适用条目 ÷ 适用条目。第二条低于阈值时不出总分。两条都要写在脚本里，并在 README 中说明阈值是教学设定、可按机构制度调整。

## 五、失效模式与考核项

| 失效 | 表现 | 拦截 |
|---|---|---|
| 缺项填 0 | 总分偏低仍照出 | 缺项显式化门禁 |
| 不适用当缺项 | 可评率被拉低 | 两列分开 |
| 越界不拦 | 4 分进 0–3 的量表 | 分数范围门禁 |
| 信度随口报 | 未检验就写系数 | 开题声明不提供 |
| README 空转 | 别人跑不通 | 他人复跑留记录 |

第一条与第四条是本章的两条底线。缺项填 0 会让分数看起来正常，实际不可比；信度随口报会让工具看起来可靠，实际未经验证。两条的共同点是「用一个好看的数掩盖了未完成的工作」，而毕设评审最擅长抓的就是这一类。

八条考核项：

- [ ] 能说出可复现包的四件；
- [ ] 能说出三条门禁各拦什么；
- [ ] 能区分缺项与不适用；
- [ ] 能演示改坏一个字段后门禁报警；
- [ ] 能交出十份样例记录并覆盖三种情形；
- [ ] 能说明缺项超过阈值时为何不出总分；
- [ ] 能说明本章不提供信度数据；
- [ ] 能按 README 让未参与者跑通一次。

### 门禁不是越严越好

三条门禁若设得过严，包会变得没人用：任何一条缺项都拒绝出分，社区场景里几乎每份记录都会被拒。设得过松，缺项照样混进去。合适的度是：缺项在阈值内出分并标注，超过阈值才拒绝。

这个阈值必须在 README 里写明，并注明「教学设定，可按机构制度调整」。写明之后，使用者知道自己在用什么口径；不写，门禁就变成了作者的个人偏好，换一个机构就无法解释。

还有一条容易忽略：门禁的报错信息要可读。只报「校验失败」，使用者不知道该改哪一项；报「第 3 条取值 4，超出 0–3」，使用者立刻能改。报错信息的质量，直接决定这个包会不会被第二次使用。

### 包交付之后的第一次维护

包交出去不是终点。第一次维护通常发生在量表条目改动时：加一条、删一条、改取值范围。这时四件里哪几件要跟着改，必须有说明。数据要加列，脚本要改计分，门禁要改范围，README 要改步骤——四件全动，只改脚本等于交了个半新半旧的包。

维护说明建议写成一节，列出「改条目时的四步」。这一节不需要长，四行即可，但它是「可复现包」与「一次性脚本」的分界线。没有维护说明的包，第二次改动就会退回手工。

还有一件常被忽略的事：版本号。包里的数据、脚本、门禁各自带版本号，且要能对上。只给包一个总版本号，出问题时无法判断是数据变了还是脚本变了。三处版本号并列，是本章成本最低、收益最高的一条设计。

## 代价与边界

1. 量表本身需自建并经信度检验，本库不提供信度数据；本章交付的是包的结构与门禁，不是一套已验证的量表；
2. 门禁阈值为教学设定，各机构制度不同，实际使用须按所在机构规定调整；
3. 样例记录须脱敏，脱敏方式与范围要写进 README；未脱敏的记录不得对外交付；
4. 商业侧按本库实例：社区卫生服务中心与康复联盟客群 42,000 家、取带中位 1.55% 对应 300 家、客单 8,000 元，三年收入 2,880,000 元，回本 9.2 个月——客户基数大、客单低，依赖渠道推广；
5. **免责声明：** 本章为教学与毕设指导用，不构成诊疗建议、康复评定标准、商业承诺或法律意见；量表与评分脚本不得直接用于临床评定结论。
