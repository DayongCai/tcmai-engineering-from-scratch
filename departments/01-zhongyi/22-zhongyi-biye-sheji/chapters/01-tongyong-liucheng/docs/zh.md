# 第 1 章 · 毕业设计的硬标准是别人能重跑，不是结论漂亮

> **MOTTO:** 「必审问其所始病，与今之所方病」——《素问·三部九候论》
>
> **PROBLEM:** 27 个案例里 11 个缺底本、只能记「欠账·不可计」，占位 ¥881,400；可计的 16 案细口径 ¥727,356、粗口径 ¥1,318,400，相差 −44.8%。同一条「能不能重跑」，决定了成本是能算还是只能估。
>
> **双根因定位:** 环境逼迫（答辩要证据、评审要复算、监管要边界）+ 知识积累（本库已有底本层、门禁链与 27 案实例，可把「重跑」写成可检查的动作）

## 一、命题：把「做完了」翻译成四条可检查的话

毕设最常见的失败不是算错，而是**没人能判断你算得对不对**。答辩席上问「这个数从哪来」，答「我统计的」，再问「换个人统计会一样吗」，就答不上来了。所以本章只立一条硬标准：**另一个人在干净环境里，按你写下的路径与命令，能不能得到同一量级的数**。能，就是工程；不能，就是心得。这条标准之所以比「创新性」更硬，是因为它可以被第三方在十分钟内验证，而创新性往往只能靠同行印象。

这条标准拆成四段，每段都要交东西、都能被判不合格：

| 段 | 要回答的问题 | 合格形态 | 不合格的样子 |
|---|---|---|---|
| 选题 | 对象、对照、失败形态是什么 | 「900 单元 → 132 证，两套归并规则差多少」 | 「中医治疗失眠的探讨」 |
| 证据 | 数据在哪、多大、怎么核 | 路径 + 规模 + 复算命令 | 「查阅相关文献若干」 |
| 实现 | 换参数结果会不会按预期变 | 参数外置、跑得出差 | 结果只存在于截图里 |
| 评价 | 基线、消融、失效各是什么 | 三件齐、失效能落到参数 | 只写「效果良好」 |

四段要落进论文目录，而不是只写在开题报告里。建议的对应关系是：选题段落成第一章「问题与命题」，证据段落成第二章「数据与口径」，实现段落成第三章「方法与复跑」，评价段落成第四章「结果与失效」，第五章写限制与移交。这样安排的好处是评审按目录就能找到每一段的证据，不必在正文里翻找。反过来，如果论文写到第四章还找不到一张自己算的表，说明前四段里至少有一段是空的。

**三件必报**是评价段的全部内容：基线是不做处理时的结果，没有基线，改进无从度量；消融是去掉你这一步之后的结果，说不清哪一步起作用，等于没做方法；失效是方法不成立的参数区间，说不出失效，说明边界没摸到。三件缺一件，评价段判不合格，不论结论多漂亮。三件里最难写的是失效，因为它要求作者主动交代自己的方法在哪里不灵；也正因如此，它最能区分「做过」和「想过」。

数字还要分四类，写论文时逐条标注来源：**公开数字**（S1–S11，机构数、诊疗人次、标准编号）、**法规条款**（S12–S15，器械分类、广告、个人信息、互联网诊疗）、**客群锚**（S16–S17，医院 IT 预算占比、中医类医院均收入）、**本库假设**（客单、渗透带中位、人月单价、工时三段比例）。第四类只用来算结构，不是报价，也不是预测；把它写成结论，是把教具当成了市场调研。评审最常抓的一处，就是把「按 3 万人月投入估算」读成「项目需要 3 万人月」，两者相差一个前提。

## 二、分阶段交付物：四个节点各交什么，谁签收

毕设的进度不是「写到第几章」，而是四个节点上有没有可签收的物件。下表是本章建议的排期，周次按 16 周学期计，**具体日期以所在院系教学日历为准**：

| 节点 | 时点 | 必交物 | 责任人 | 签收人 |
|---|---|---|---|---|
| 开题 | 第 1–4 周 | 选题单（对象／对照／失败形态）、数据可得性声明、合规预判表、周计划 | 学生起草，导师改定 | 开题小组三人以上 |
| 中期 | 第 8 周 | 数据字典 v1、复跑脚本 v1、门禁清单、缺口登记、阶段记录 | 学生 | 导师 |
| 预答辩 | 第 12 周 | 论文初稿（含基线／消融／失效三节）、复现包四件、差异表 | 学生 | 导师＋预答辩组 |
| 答辩 | 第 16 周 | 定稿论文、复现包终版、他人复跑记录、失效清单、移交单 | 学生 | 答辩委员会 |

四个节点各有一票否决项：开题时**数据路径写不出**，不许开题——「数据在老师那里」不是路径，路径要能写成一个可以打开的相对地址；中期时**脚本跑不出与开题同量级的数**，不许进预答辩，说明命题或数据有一个是假的；预答辩时**三件必报缺一**，不许送审；答辩时**他人不能在干净环境跑通**，只能判「部分完成」，不能判「完成」。四处否决里，开题这一处最省钱：题目压不下去的，越往后改代价越大，到答辩前两周才发现数据拿不到，通常只能补一段「展望」糊过去。

复现包固定四件：数据（含来源与校验值）、脚本（参数外置，路径可配）、门禁（至少一条自动检查，改坏即报警）、README（三步重跑，写给没参与的人看）。四件里最容易被省掉的是门禁与 README，而它们恰好是「别人能重跑」的唯一证据。门禁不必复杂，一条「字段缺失即报错、不许默认填零」就能拦住最常见的假数；README 也不必长，三行命令加一段预期输出即可，写不出来通常说明作者自己也没在干净目录里跑过。

阶段之间还有一件常被忽略的事：**版本对齐**。中期交的字典、预答辩交的脚本、答辩交的终版，三者必须能说出改了什么、为什么改。做不到这一点，评审就无法判断最终结果是在哪一版上得到的。简单的做法是每次提交在台账里写一行「版本—改动—影响哪个数」，二十个字即可，答辩时按行回读。

## 三、判据、评分维度与考核项【教学设定】

评分按七个维度打分，权重为本章教学设定，可按院系细则调整，但**维度不得删减**：

| 维度 | 权重 | 不合格 | 合格 | 优秀 |
|---|--:|---|---|---|
| 命题可行性 | 10% | 名词堆叠，无法判真伪 | 有对象、有对照 | 能预写失败形态 |
| 数据可核性 | 20% | 无路径或规模不详 | 路径＋规模可查 | 报缺口与不可计项 |
| 方法复跑性 | 15% | 结果只此一份 | 换参数有预期变化 | 参数敏感性成表 |
| 评价完整性 | 20% | 缺基线或失效 | 三件齐 | 失效定位到参数 |
| 市场四件 | 15% | 只有「意义重大」 | 对象／内容／预算／AI 点齐 | 客户数由 SAM 推出 |
| 渠道与合规 | 10% | 默认能做 C 端 | 有四问结论 | 说清为何不做 |
| 假设披露 | 10% | 假设当数据 | 标注来源 | 报隐含渗透率与占比 |

权重之和为 100%，但**加权分不能替代否决项**：数据可核性拿满分而三件必报缺一，仍判不合格。这条规则是为了防一种常见的凑分法——把综述与意义写得极长，把方法与失效写得极短，加权后刚好过线。

评分只在两个场合使用：预答辩前自评一次，用来发现缺口；答辩时评委各打一次，取中位数并记录分歧。自评与评委分的差距超过两档，评委应要求作者说明自评依据，这比笼统地说「工作量不够」更有针对性。

配套的九条考核项，逐条可勾：

- [ ] 能用一句话说出对象、对照、失败形态；
- [ ] 能报出数据路径、规模与复算命令；
- [ ] 基线、消融、失效三件各有数；
- [ ] 换一个参数，能预判结果往哪边走；
- [ ] 客户数写成「SAM × 渗透带中位」，并报隐含渗透率；
- [ ] 客单与客群营收／IT 预算挂了钩；
- [ ] C 端四问答完，做或不做都有理由；
- [ ] 工时与客单标注为假设，未混入公开数字；
- [ ] 缺口写成一句话，进了开题报告。

**「不做」也是结论。** 27 案里 16 案判定不做 C 端，理由分别是「买不到」「有免费替代」「越线」；写不出理由而硬做，多半是 B 端还没想清卖给谁。答辩时若被问「为什么不做 C 端」，答「没想好」与答「客单低于获客成本」是两种水平，后者可以被复算，前者只能被追问。

## 四、记录字段与失效模式：把过程留成可复核的账

过程记录不是流水账，而是一张能回查的表。建议台账至少十列：

| 列 | 填什么 | 为什么必须 |
|---|---|---|
| 节点 | 开题／中期／预答辩／答辩 | 定位交付时点 |
| 交付物 | 选题单／字典／脚本／报告 | 与清单对齐 |
| 版本 | v1／v2／终版 | 防止拿旧稿答辩 |
| 路径 | 仓内相对路径 | 可被他人打开 |
| 复算命令 | 一条可直接粘贴的命令 | 复跑的唯一入口 |
| 执行人 | 姓名 | 责任可追 |
| 日期 | 年月日 | 判断先后 |
| 结果 | 通过／不通过＋关键数 | 不写「基本通过」 |
| 缺口 | 一句话 | 进论文限制节 |
| 复核人 | 导师或同学 | 双人复核 |

台账填法举例：中期一行写「中期｜数据字典 v1｜v1｜chapters/05/drugs.json｜node code/main.js｜张三｜第 8 周周一｜通过，287 味／未解析 0｜教材全量未建｜李四」。关键在于「结果」列必须有数，有数才能被复核；只写「完成」的台账，等于没有台账。

六类失效模式按出现频次排，每条都给了可执行的拦截动作：

| 失效模式 | 典型表现 | 拦截动作 |
|---|---|---|
| 选题过大 | 「中医治未病体系研究」 | 开题前把题目压到一个可数的对象 |
| 数据不可得 | 数据在院内、无授权 | 开题前交数据可得性声明，拿不到就换题 |
| 只堆文献 | 综述数十页，无一张自己的表 | 中期必须交出至少一张自算表 |
| 结论越界 | 从字段统计推到临床有效 | 结论只写到数据支持的层级 |
| 伦理缺位 | 用真实病历未脱敏 | 涉人数据先过伦理审查，未过不采集 |
| 假设不标 | 客单、工时当成事实 | 逐条标「本库假设」 |

这六类里，**伦理缺位**后果最重，因为它不是学术问题而是合规问题：涉及患者信息的采集、存储、展示，须先取得伦理审查与知情同意，脱敏后才可进数据集，且不得回传到任何公网服务。**结论越界**最容易被忽略：本库的案例只做到「字段能否结构化」「条目是否带时点」这一层，从这一层推到「临床有效」需要另一套研究设计，不是加一句「有待进一步验证」就能过关。

## 代价与边界

1. 本章的判据来自本库资产（底本层、门禁链、27 案实例），换学校、换教材，数据锚点即不成立，判据要重写；
2. 四类数字中只有前三类可对外引用，**本库假设**只用于教学演示的结构计算，不是报价、不是预测、不是投资建议；
3. 时间节点按 16 周学期设定，属教学安排而非制度规定，各校教学日历不同，须以本院系文件为准；
4. 评分权重与三档描述为【教学设定】，不同院系的毕业要求不同，权重可调、维度不可删；
5. **免责声明：** 本章为教学与毕设指导用，不构成诊疗建议、商业承诺、投资建议或法律意见；涉及患者数据与医疗器械属性的判断，须依所在机构制度与现行法规办理。
