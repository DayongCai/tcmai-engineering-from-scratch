# 一案八件

## 用途

把「132 证→护理问题——中医护理的评估翻译器」做成可复跑、可验算、假设可披露的一次毕设。只写能被第三人复核的项，并标明哪些是假设。

**命题：** 132 个证候能否稳定映射到有限的护理问题集？映射多对一时损失了什么？

## 步骤

### 1. 写命题

132 个证候能否稳定映射到有限的护理问题集？映射多对一时损失了什么？

### 2. 锚数据

132 证 / 14 族 / 208 次病证覆盖

### 3. 做方法

① 按族归并到护理问题；② 统计一对多的证；③ 记录归并时丢掉的鉴别信息

### 4. 做评价

基线＝逐证映射；消融＝按族归并；失效＝「同族异证」被合并后无法区分护理重点

### 5. 定客户数

SAM 6,498 × 中位渗透 5.5% → 采用 180

### 6. 验客单

客单占客户年营收 0.016%（IT 预算区间 910,000–1,820,000 元/年）——落在合理带内

### 7. 算预算

建设 ¥87,400／获客 ¥2,700／回本 8.0 月

### 8. 判渠道

不做：个人无对应角色

### 9. 写缺口

护理问题分类标准（如 NANDA）本库未收，只能用自建分类并声明

## 判据速查

| 项 | 本章要求 |
|---|---|
| 案例类型 | 数据层 |
| 数据规模 | 132 证 / 14 族 / 208 次病证覆盖 |
| 客群 / SAM | 中医类医院 / 6,498 |
| 客户数（采用） | 180（隐含渗透 2.77%）|
| 客单 / 回本 | ¥15,000 / 8.0 月 |

## 输出

命题三件式 + 数据锚点 + 基线／消融／失效 + B 端四件 + 客户数与客单判据 + C 端判定 + 合并账 + 缺口。

## 边界

- 工时三段为「假设·未实测」，不得去标签；
