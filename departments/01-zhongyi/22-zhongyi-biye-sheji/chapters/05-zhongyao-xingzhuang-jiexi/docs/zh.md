# 第 5 章 · 药表的价值在缺项说得清，不在味数多

> **MOTTO:** 「药有酸咸甘苦辛五味，又有寒热温凉四气」——《神农本草经·序录》
>
> **PROBLEM:** 287 味药里带气 287 味（100%）、带味 285 味（99.3%）、带归经 284 味（98.9%）；严格规则下未解析 0 条。把规则改成「允许缺项」重跑，缺口会从 0 变成 5 个字段——差的这 5 个，正是宽松解析容易把「无」误计为「有」的地方。
>
> **双根因定位:** 环境逼迫（四诊仪与 HIS 需要一张能对接的药表，接口不吃散文）+ 知识积累（287 味说明书文本已入库，气／味／归经三字段可逐条解析）

## 一、命题与数据锚点：未解析 0 是好消息还是坏消息

本章的命题是：**同一份说明书文本，严格解析与宽松解析的「未解析条数」差多少**。这个问法看着绕，其实是在问一件很实际的事——你说「解析成功」，是因为字段真的都有，还是因为解析器把缺的当成了有。

先把母体摆清：

| 项 | 数 | 占比 |
|---|--:|---|
| 药味 | 287 | 100% |
| 带气 | 287 | 100% |
| 带味 | 285 | 99.3% |
| 带归经 | 284 | 98.9% |
| 严格规则未解析 | 0 | 0% |

三个占比是本章的底盘。287 味全部有气，说明「四气」这一字段在说明书里几乎不会缺席；味缺 2 味、归经缺 3 味，合计 5 个字段缺口。严格规则把这 5 个缺口判为「未解析」，于是报 0 —— 这不是自相矛盾，而是两种口径：一种问「有多少条完全解析不了」，一种问「有多少字段是空的」。前者是 0，后者是 5。

关键在于宽松规则会做什么。允许缺项时，解析器遇到「归经：无」这类写法，可能把它当成一个有效值；遇到整段缺失，可能默认填空。两种处理都会让「未解析」保持 0，但字段的实际可用率下降了。所以本章要求同时报三个数：**未解析条数、字段空缺数、字段可用率**。只报第一个数，等于用一个好看的 0 掩盖了 5 个洞。

还有一层：287 味是词表口径，不是教材全量。它够用来验证解析管线，不够用来声称覆盖《中药学》。这一条必须写在论文第一页，因为读者最容易把「287 味」读成「全部中药」。教材全量另需建底本，那是另一项工作，不在本章范围内。

为什么非得先立严格规则？因为它把「解析不了」暴露出来，而宽松规则把它藏起来。毕业设计最怕的不是失败，是失败被自己的规则掩盖：解析器把缺项填成空字符串，统计时又不算空，最后报一个 0 未解析，看起来完美。先把严格规则跑通，等于先承认有 5 个洞；再跑宽松规则，才知道这 5 个洞会被怎么处理。顺序反过来，作者就永远看不到洞在哪。

## 二、分阶段交付物：四个节点各交什么

| 节点 | 时点 | 必交物 | 责任人 | 签收人 |
|---|---|---|---|---|
| 开题 | 第 1–4 周 | parseRule 原文、三字段定义、缺项判定规则 | 学生 | 开题小组 |
| 中期 | 第 8 周 | drugs.json v1、严格／宽松两套结果、缺口表 v1 | 学生 | 导师 |
| 预答辩 | 第 12 周 | 缺口表终版、误计「无」为「有」的案例、可用率 | 学生 | 预答辩组 |
| 答辩 | 第 16 周 | drugs.json、parseRule、缺口表、他人复跑记录 | 学生 | 答辩委员会 |

开题阶段的核心是 **parseRule 要能原文交付**。规则不能只写在论文的方法段里，要作为独立文件随数据一起交；原因是评审若想复算，必须知道「气」是怎么从「性味：甘，温」这类写法里抽出来的。规则写进论文，改一个正则就要改正文；规则独立成文件，改版本号即可。

中期的动作是两套规则各跑一遍。严格规则先跑，记下 0；宽松规则后跑，记下 5 个字段缺口，再看有没有额外的「假有」。这个顺序不能反：先跑宽松再跑严格，容易把严格结果解释成「我把宽松的错误修掉了」，而实际上严格规则本来就该先立为基线。

分工上，字段定义由导师定一次，学生负责规则与跑数，教学秘书归档两版规则。字段定义为什么不能由学生随手改？因为「味」到底算酸苦甘辛咸五味，还是算上涩与淡，会直接改变 285 这个数。定义一变，缺口表全部作废，前面跑的白跑。

中期还要留一次「失败样本」。从解析失败的 5 个字段里挑两条，把原文、正则、失败原因各写一行，放进附录。这两条看着微不足道，答辩时却最有用——评委问「你的规则有什么局限」，念这两条比说「还有待完善」有力得多。

## 三、判据、评分维度与考核项【教学设定】

数据层判据四条：

| 判据 | 合格线 | 检查方式 |
|---|---|---|
| 数可读 | 287／285／284 三数可打印 | 跑一次看输出 |
| 规则可交 | parseRule 独立成文件 | 打开即读 |
| 缺口可见 | 5 个字段缺口逐条列出 | 缺口表有行 |
| 误计可查 | 「无」被误计为「有」的案例有数 | 案例段可查 |

评分维度为教学设定：

| 维度 | 权重 | 不合格 | 合格 | 优秀 |
|---|--:|---|---|---|
| 命题可判 | 15% | 只说「建药表」 | 有宽严对照 | 预写缺口阈值 |
| 数据可核 | 25% | 三数说不清 | 可现算 | 报可用率 |
| 规则可复跑 | 25% | 规则在正文里 | 规则独立 | 两版可切换 |
| 评价完整 | 20% | 只报未解析 0 | 报缺口与误计 | 缺口定位到字段 |
| 移交可用 | 15% | 只交数据 | 数据＋规则 | 附复跑记录 |

有一点要说透：**「未解析 0」不是成绩，是口径**。评分为此把「缺口与误计」单列 20%，就是为了防止作者用一个漂亮的 0 交差。若两套规则跑出来都是 0 缺口，那才是真成绩；若严格报 0、宽松报 5，说明严格规则是靠「遇到缺项就报错」实现的，这本身没错，但必须说清楚。

评分在预答辩前自评一次，主要用来判断一件事：缺口表是否已经细到能被别人照着复查。自评时若发现某一行只有「缺归经」三个字、没有药名与原文，就说明这张表还停在给自己看的阶段。答辩时评委打分只看两处：能不能当场打开缺口表找到那一行，能不能当场跑一遍规则得到同一个数。两处都能，合格；有一处不能，其他项再高也要扣。

八条考核项：

- [ ] 能报出 287／285／284 三个数与各自占比；
- [ ] 能解释「未解析 0」与「5 个字段缺口」为何不矛盾；
- [ ] 能交出 parseRule 原文并指出关键正则；
- [ ] 能跑出严格与宽松两套结果；
- [ ] 能列出 5 个缺口分别在哪几味药；
- [ ] 能举一个「无」被误计为「有」的例子；
- [ ] 能算出字段可用率；
- [ ] 能说明 287 味不是教材全量。

## 四、记录字段与失效模式

药品台账建议八列：

| 列 | 填什么 | 例 |
|---|---|---|
| 药名 | 规范名 | 黄芪 |
| 气 | 四气之一 | 微温 |
| 味 | 五味，多值 | 甘 |
| 归经 | 脏腑经络，多值 | 脾、肺 |
| 原始串 | 说明书原文片段 | 性味：甘，微温 |
| 解析状态 | 严格成功／严格失败／宽松补入 | 严格成功 |
| 缺项 | 空／缺味／缺归经 | 空 |
| 规则版本 | parseRule 版本号 | v2 |

「原始串」这一列经常被省，省了之后无法回溯。举一个真实会遇到的场景：某味药解析出「味：甘」，但原文写的是「味甘微苦」，只抽到一个值。评审问「为什么只有甘」，若没有原始串，作者只能重查说明书；有原始串，打开表就能看到是正则只匹配了第一个味。

台账的更新节奏建议按「规则版本」而不是按日期。每改一次 parseRule，就把受影响的药重新跑一遍，只记变化行：哪味药从成功变缺项、哪味从缺项变成功。这样一张表既是进度记录，也是规则回归测试的底稿。到答辩时若被问「改了几版、每版影响多少」，按行数就能答出来。

五种失效模式：

| 失效 | 表现 | 拦截 |
|---|---|---|
| 把「无」当有 | 归经写「无」，解析器记为空值以外的东西 | 显式判定「无」 |
| 默认填空 | 缺段时填默认值 | 缺就报缺，不填 |
| 单值截断 | 多值只取第一个 | 多值字段用列表 |
| 词表当全量 | 287 味说成教材全部 | 限制节写死 |
| 规则藏在正文 | 评审无法复算 | parseRule 独立交付 |

伦理与合规边界：本章只用公开说明书文本，不涉及患者信息；若将来接入院内处方做校验，处方属敏感个人信息，须单独同意、脱敏后方可处理，且不得用于对外宣传功效。

最后要交代一件事：本章的交付物里**没有「药表本体」之外的第二个产物**。有些组会顺手做一个查询界面，界面好看，却让评审以为主体是前端。这一章的主体是 drugs.json 与 parseRule，界面最多是演示；答辩陈述的十分钟里，前七分钟讲规则与缺口，最后三分钟才演示。顺序一反，评委的问题会全部落在交互上，规则反而问不到。

## 五、三处最常见的退步

第一处是把「解析成功」当成质量指标。解析成功只说明规则跑通了，不说明字段对。要判断对不对，得抽十条人工核对：药名、气、味、归经逐项比，错一条就记一条。抽十条的成本是半小时，收益是能当场回答「你的准确率是多少」；不抽，就只能答「应该没问题」。

第二处是把缺口藏进默认值。缺归经的 3 味药，若在脚本里默认填「未知」并计入统计，字段可用率会从 98.9% 变成 100%，看起来更漂亮，实际把 3 个洞变成了 3 个假值。正确做法是缺就留空，统计时单列「空」，让读者看到 98.9% 这个数。

第三处是把词表当教材。287 味是一个可解析的样本，样本的价值在于证明管线能跑，不在于覆盖多少药。论文若写「本表覆盖临床常用中药」，就把样本说成了全集；改成「本表覆盖 287 味说明书文本，用于验证解析管线」，既准确又不减分。

这三处退步有个共同点：都能让数字变好看。也正因如此，它们最容易在预答辩前被「顺手」做掉。自检的办法很土——把三个数（未解析、字段空缺、字段可用率）并排写在论文同一段，任何一处被修饰，另外两处就会露馅。

## 代价与边界

1. 287 味是词表口径，不是《中药学》教材全量；教材全量另需建底本，本章的解析率不能外推为教材覆盖率；
2. parseRule 依赖说明书的常见写法，遇到写法特殊的厂家文本会失效，失效案例必须随规则一起交；
3. 气／味／归经三字段的取值集合为本章自定，与任何药典分类不构成对应关系；
4. 商业侧按本库实例：药企与器械客群 200 家、取带中位 8% 对应 16 家、客单 30,000 元，三年收入 600,000 元，回本 36.2 个月，恰在三年窗口边缘——这说明该产品只能做窄客群，不能靠走量；
本章可直接验证：`node code/main.js` 打印结构清点与判据清单（数字从 `docs/zh.md` 现算），`node --test code/main.test.js` 跑本章单测；两条命令只读正文与代码，不写任何文件。
