# 第 18 章 · 平台能不能用，取决于每条单元有没有「依据」和「边界」两列

> **MOTTO:** 「离娄之明，公输子之巧，不以规矩，不能成方圆。」——《孟子·离娄上》
>
> **PROBLEM:** 底本 18 章、216 个单元、360,945 字，要落成一个可检索的单元库；而一条单元只要缺「依据」或「边界」一列，检索出来的就是一个无法追责的结论。真矛盾是**宁可检索不到，还是宁可检索到一个没有出处的答案**——多数知识库选了后者，于是没人敢用。

**双根因定位:** 环境逼迫（检索框里输入一个问题，三秒内必须有结果，看到「未收录」就换一个工具） + 知识积累（把单元读成「结论＋依据＋边界」的三段结构，答案才带得走责任）

**教材出处:** 教材·第18章·18.1–18.4（12 个单元）；单元总量、章数与各章字数按 `standards/jibing-xue-jichu/units.json` 现算。课程侧的目录映射与校验命令为**教学设定**，随仓库结构变化而变。

## 一、单元的四段编码：让每条结论都能反查

单元不是一段被切开的文字，它有四段编码，每一段对应一种反查能力。

| 字段 | 取值示例 | 作用 | 缺失的后果 |
|---|---|---|---|
| chapter | 13 | 归章 | 章级统计与覆盖统计失真 |
| secNo | 13.4 | 归节 | 节内顺序丢失，正文无法对齐 |
| sub | 13.4.2 | 定位到小目 | 只能定位到节，无法与正文段落对位 |
| locator | 教材·第13章·13.4.2 | 反查纸质或电子底本 | 结论不可核，等于没有出处 |

四段编码的价值在双向：任一单元能反查到章、节、小目；任一章节能正向列出它的单元。单向的表看起来很整齐，一旦要「这一节讲了哪几条」就散了。

现算一个数：底本 216 个单元，18 章，每章 12 个。这个均分不是设计美学，是底本的结构事实——它意味着任何一章缺一条，章级计数立刻对不上，这恰好是最省事的完整性检查。

## 二、两列硬约束：依据与边界

依据列的要求是「出处到小目级」。写「某教材」「有关研究」「一般认为」，都不算依据；写「教材·第13章·13.4.2」，才算。依据不是装饰，它回答的是「这句话凭什么这么说」。

边界列的要求是「这条单元不写什么」。它看起来多余——都写进教材了，还声明不写什么干什么？作用是防止检索到就被当成答案。一条讲药物作用类别的单元，如果边界列写着「不写药物名称与剂量」，检索者拿到它就知道：这里得不到方案，得去问具备资质的人。

| 状态 | 判定 | 后果 |
|---|---|---|
| 依据、边界皆空 | 不合格 | 检索到即为无主结论 |
| 只有依据 | 不合格 | 边界不明，易被越界引用 |
| 只有边界 | 不合格 | 说得清不写什么，说不清凭什么写 |
| 两列皆备 | 合格 | 可引用、可追责、可教学 |

判据要写得硬：两列任一为空，该单元判不合格。不写「待补」——待补会一直待着，而「不合格」至少每次审计都会跳出来。

两列还有一处容易被写反：依据写成了「结论的来源」，边界写成了「作者的谦辞」。依据要能被第三方在五分钟内查到——给出章、节、小目，任何人翻到底本同一位置都能读到那句话；写成「相关章节」就等于没给。边界要能被当成拒绝的理由——「这一条不写剂量」意味着被问到剂量时，这条单元必须闭嘴，而不是补一句「一般按说明书」。

一个反例值得记住：某条单元写着「某类治疗可缓解症状」，依据空、边界空。检索出来的人会把它当结论用；补上依据与边界之后，它才变成一句可引用的教学表述。同一句话，两种命运，差别只在那两列。

## 三、平台表与契约：表给人看，契约给机器判

`chapters.json` 是这一门课的平台表，六个字段：章号、目录名（slug）、标题、状态、正文路径、代码路径。章号与目录一一对应，正文路径指向 `docs/zh.md`，代码路径指向该章的 `code/main.js`。

表与契约的关系要分清：**表是索引，契约是规则**。表写错了，人还能靠目录找回来；契约写错了，自动审核会把不合格的正文判成合格。两者不一致时，以契约为准——因为跑的是契约，不是表。

课程侧延展，教学设定：本章所说的「契约」，指本仓 `scripts/audit_course_docs.js` 的一组判据——路径在 `chapters/<slug>/docs/zh.md`、一级标题为「第 N 章 · 判断句」、引文到篇名级、正文 2,500 字以上、二级小节 4 到 8 个、含「代价与边界」与免责声明、不得残留模板句。它是本仓自己的教学约定，不指任何外部平台的接口规范。

这套判据最值得学的一点：它把「写得好不好」里可判的部分（结构、出处、字数、残留）抽出来自动判，把不可判的部分（论点是否成立、例子是否贴切）留给同行复核。自动审核不评价质量，它只保证底线。

另一层作用是让「改坏了」立刻可见。正文改到 2,400 字、删掉一个二级小节、把引文退回成只有书名，三种退化都会在同一条命令里报出来。没有这条命令，退化只能靠人读，而人读会疲劳，疲劳处正是退化发生的地方。

## 四、病例与图像、智能辅助：两条不能越的线

病例与图像材料的合规要求有三：授权、去标识、最小必要。敏感个人信息的处理原则与上一章同一把尺；脱敏与去标识化不得混称，这条在图像场景里尤其容易出错——组织图像常带标本号、日期、机构标识与设备水印，「看不见脸」不等于去标识。

智能辅助的定位是辅助：找相似单元、提示缺失字段、标出疑似超范围的表述。它能做的是「定位与提示」，不能做的是「替代判断」。教材在这一点上写得很直接：不替代专业判断与规范诊疗。

提示方式本身也分层次：指向（这里可能有一条相关单元）、提醒（这一栏为空，按契约应补）、警示（这句话超出本课表述边界）。三层的强度递增，误报的代价也递增——指向错了只是多看一眼，警示错了会让人删掉本来正确的句子。所以越强的提示越需要依据，越需要人能一眼看出它凭什么这么说。

人工复核与可解释与留痕，是这条边线的三个支点。可解释的意思是：每条机器给出的提示，都要能说出依据哪条单元、哪句话；说不出，它就只是猜测。留痕的意思是：谁复核过、改了哪里、为什么改，都要留下。三个支点缺一个，智能辅助就会从「省力的工具」变成「免责的借口」。

一条可用的判据：机器输出若指不出依据单元与具体语句，不得进入教学结论。

## 五、双交付物：正文与表为什么不能合并

这门课有双交付物：课程正文（人读）与平台表（机读）。两者的形态要求相反——正文要论证、要举例、要留余地；表要枚举、要唯一、要可校验。

合并的诱惑很真实：一份既能读又能查的文档，看起来更省事。但把论证塞进表，表就失去可校验性（一段带保留意见的话没法当值用）；把枚举塞进正文，正文就失去可读性（读者要的是思路，不是字段清单）。

分开之后，一致性靠什么保证？靠同一份底本加同一套契约，而不是靠手工同步。正文的每条论断对应一条单元，单元的 locator 指回底本；表里的章号与目录名对应仓库结构。三处一致，改一处就必须改另外两处——这个「麻烦」正是可维护性的来源。

协同的动作很朴素：改正文，跑一次契约审计；改表，跑一次映射核对。两次都过，才算改完。

## 六、代价与边界

- **单元化把连续论述切成了碎片。** 每章 12 条，条与条之间的过渡在库里消失。检索到的是点，读到的是线，两者不能互相替代。用点代替线，是知识库最常见的误用。
- **边界列写多了，单元会「什么都不敢说」；写少了，等于没有边界。** 这个度没有公式，只能靠同行复核与使用反馈慢慢调。
- **表的唯一性要求与教材的表述弹性冲突。** 教材可以「一般地说」，字段必须给一个值。折中的办法是把弹性写进边界列，而不是塞进依据列——依据列一旦含糊，整条单元就废了。
- **边界**：本章不描述任何外部平台的技术实现；课程侧的目录映射与校验命令属教学设定，随仓库结构变化，不能当作稳定接口。智能辅助的合规要求以现行法规与机构制度为准。

## 七、运行与验证

1. **映射核对。** 打印每章单元数与总字数，与平台表的 18 条逐一对齐：

```bash
node -e "const u=require('./standards/jibing-xue-jichu/units.json');const m={};for(const x of u.units)m[x.chapter]=(m[x.chapter]||0)+1;console.log(u.units.length,m)"
```

通过标准：总数为 216，18 章的每章计数均为 12，与 `chapters.json` 的条目数一致。
2. **两列抽查。** 随机抽 10 条单元，查依据与边界是否为空。通过标准：10 条皆非空，依据均到小目级。
3. **契约审计。** 跑本仓的正文审计：

```bash
node scripts/audit_course_docs.js --dept=09-jichu --subject=14-jibing-xue-jichu
```

通过标准：本人负责的各章全部通过；其余章的遗留问题单独登记，不在本章掩盖。
4. **反例构造。** 写一条「无依据、无边界」的单元，说明它被检索到会造成什么后果。通过标准：能说出「被当成结论使用」与「无法追责」两层，并给出补法。
