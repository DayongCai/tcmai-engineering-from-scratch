# 第 6 章 · 移交不是交钥匙，是把判断的依据一并交出去

> **MOTTO:** 「指穷于为薪，火传也，不知其尽也」——《庄子·养生主》
>
> **PROBLEM:** 毕业那天把移动硬盘往师弟手里一塞，说「数据都在里面」；教学设定里半年后课题组要用这批样本复核，才发现冻存管编号与表格里的编号差了一位，伦理批件只写了项目名没写样本用途，测序原始数据还躺在一台要报废的电脑里——三个人翻了两周，仍没能把链重新接上。

**双根因定位:** 环境逼迫（学生一毕业账号就停、机位就收，移交必须在一周内做完；课题组换人接手，靠的是文档不是记忆） + 知识积累（把「移交」理解成拷文件，没学过质控留痕、授权范围与技术适用边界，于是交出去的是数据，不是能继续做下去的条件）

**教材出处:** 《流行病学》·第13章·13.3–13.4 与 《生物化学》·第21章 技术部分（本课为派生课，无独立教材；第 6 章十二个单元由质量控制与数据核查、调查中的伦理与合规、DNA 测序与重组 DNA 技术、技术的规范边界与观察要求四节改写为知识移交流程）

## 一、交接前先把数据验一遍

移交给下一个人之前，先假定他会独立复核。质量控制要覆盖全流程：设计阶段的方案与标准、实施阶段的测量与记录、分析阶段的清理与核查、报告阶段的呈现与留痕。四个环节里任何一环没有记录，接手的就得从头猜。

数据核查用四把尺子量。第一把是完整性：应有多少份、实有多少份、缺项率多少；第二把是一致性：同一对象在不同表里的年龄、性别、编号对不对得上；第三把是范围与逻辑：数值有没有超出生理可能，日期有没有前后颠倒；第四把是重复：有没有同一个人被录了两次，有没有同一份样本对应两条结果。四把尺子量完，写一份核查清单，逐条注明已解决与未解决。

记录与留痕的重点不是「记了多少」，而是「能不能还原判断」。谁在什么时候、基于什么把某条异常值保留或剔除，这个理由必须写下来；只留结果不留理由，接手的人无法判断该不该沿用。修改要划改签注，不涂改；电子文件保留版本，不用「最终版」「最终版2」这种命名。

核查完要交三样东西：数据字典、核查日志、未解决问题清单。第三样最容易被藏起来，也最该交——把没解决的问题摊开，比让对方踩一遍坑省时间。

## 二、伦理与数据合规：批件和授权随项目一起走

伦理审查不是一次性的盖章。批件有批准范围：研究目的、对象、样本类型、数据用途、合作方，都在范围内。移交时如果新增了用途（比如原本只做表达检测，现在要做全基因组测序），或者新增了合作方，就要走变更审查，不能拿原批件当通行证。批件编号、批准日期、有效期、审查意见，要随项目文档一并归档。

隐私保护要落到操作层。可识别信息与分析数据分开存放：姓名、联系方式、身份证号留在受控目录，分析表里只用研究编号；编号与身份的对照表单独加密，访问要登记。样本管、冻存盒、测序单上的标签只能用编号，不能写姓名或住院号。发表与汇报时，个案信息要做去标识处理，照片、罕见特征、精确日期都可能重新识别到个人。

数据使用与共享按授权走。知情同意里写明的用途是边界：同意书写「用于本研究」，就不能拿去做别的课题；要共享给合作方，签数据使用协议，写明用途、范围、期限、保密义务与销毁方式。对外提供的应当是脱敏后的分析数据或汇总结果，不是原始可识别数据。数据导出、拷贝、上传都要留记录，谁、何时、导出了什么、给谁，一条不能少。

## 三、技术清单：每类技术都要写明能做什么、不能做什么

移交的技术部分，最忌只写「用了 PCR」或「做了测序」。要写到类别与适用关系。DNA 测序按通量与用途分：一代测序读长长、单条序列准确，适合验证与短片段；二代测序通量高、读长短，适合全基因组、外显子组与转录组的批量检测；三代测序读长很长，适合结构变异与重复区域。三类各有盲区，选哪一类取决于要回答的问题，不是越新越好。

重组 DNA 技术的环节要按顺序写清：载体选择与构建、目的片段获取、连接与转化、筛选与鉴定、表达与纯化。每一环都有失败模式：载体与片段比例不对，连接效率低；筛选标记不匹配，假阳性多；表达条件没优化，产物以包涵体形式存在。协议里写失败模式，比只写成功步骤有用。

转基因动物与基因打靶技术同样要写适用边界。随机整合的转基因动物表达位置与拷贝数不可控，表型可能受位置效应影响；基因打靶通过同源重组做定点修饰，精度高但效率低、周期长；基因编辑技术效率提高，但脱靶与嵌合问题仍需评估。移交时要交代动物的品系背景、代次、基因型鉴定方法、繁育方案与福利要求，否则接手的人养着养着就丢了基因型。

技术清单的写法是一张表：技术名称、原理类别、能回答的问题、不能回答的问题、关键参数、失败模式、替代方案。这张表比任何操作手册都更能帮接手的人做判断。

## 四、协议与观察：把「怎么做」写成「下一次怎么再做」

实验协议要写到可执行的程度：目的、适用范围、材料与试剂（含批号与保存条件）、仪器、步骤（含关键参数与允许范围）、质量控制、失败处理、安全注意事项、参考依据。步骤不写「适量」「适当时间」，要写数值与范围；参数不写「按说明书」，要写本实验室实际用的条件与偏离理由。

观察与表述的边界要一并交代。哪些结果是直接观测到的，哪些是推断的，哪些是文献支持的，要在协议与交接文档里分开写。技术能做什么、不能做什么，要写在前面：某类测序能检出变异，但不能单独判定致病性；某类表达实验能显示差异，但不能证明因果。把边界写清，接手的人才不会把提示性结果当结论用。

交接还要有验收。双方按清单逐项核对：数据文件能不能打开、编号能不能对上、批件与授权在不在、试剂与样本的库存与位置、仪器账号与权限、未完成的分析与待补的实验。核对完签字，写清移交日期、移交人、接收人、遗留问题与责任人。签字不是形式，它把「我说过了」变成「我们核对过了」。

最后留一份索引：所有文件在哪、命名规则是什么、哪个版本是当前有效版本、联系谁。索引不超过两页，但必须准确；索引错了，比没有索引更耽误事。

## 代价与边界

移交做得细，毕业前那几天会很紧：整理数据字典、核查日志、协议与索引，教学设定里通常要留出一到两周，和论文定稿争时间。可行的办法是把留痕分散到平时——每次实验与每次数据清理都顺手记，移交时只是整理，不是重建。另一个代价是披露问题：把未解决的问题、失败的模式、技术的盲区写进交接文档，看起来像给自己减分，实际上是给接手的人省下重复踩坑的时间。

边界要写死。第一，本章讨论知识移交与协议编写的方法学，不提供任何具体检测项目的操作参数、判读标准或临床建议；测序与基因编辑的具体操作须遵循现行技术规范与实验室安全要求。第二，涉及人体样本与人体数据的研究，移交不得超出伦理批准与知情同意的授权范围；新增用途须走变更审查。第三，派生课没有独立教材，本章不引具体批件编号、试剂型号或期刊结论；技术分类只写到类别与适用关系，不替代厂家说明书。

## 运行与验证

本章的正文与习题契约由脚本现算，可当场复核：

```bash
node code/main.js
```

脚本打印的是本章正文的规模、习题的阶段分布与接地情况；退出码为 0 表示各项契约满足，非 0 表示有不满足的项，输出里会逐条写明。


移交前按五步验收，每步留下签字或记录：

1. 数据核四把尺子：完整性、一致性、范围与逻辑、重复，逐项写结果。
2. 文档三件套：数据字典、核查日志、未解决问题清单，缺一件不算交完。
3. 授权核对：伦理批件范围是否覆盖现有样本与数据用途，共享是否签了协议。
4. 技术清单：每类技术写出「能回答／不能回答／关键参数／失败模式」四格。
5. 追溯演练：随机抽三份样本，只凭交接文档回答「从哪来、做过什么、结果在哪、谁批准的」。

最后核底本规模：本章十二个单元合计 18,945 汉字，输出应为 `12 18945`。

```bash
node -e "const u=require('./standards/jichu-biye-sheji/units.json').units.filter(x=>x.chapter==='6');console.log(u.length,u.reduce((a,b)=>a+b.hanzi,0))"
```
