# Skill：心衰过程的三层拆解与代偿记账

## 何时用

- 有人用「一直挺稳定」「突然就重了」把心衰的过程糊过去，需要拆开
- 要把「代偿」这个褒义词还原成中性词：它是交换，不是帮忙
- 要判断一段叙述有没有把「诱因」当成「机制」，或把「症状方向」当成「病情方向」
- 遇到「到什么程度算心衰」「这算第几级」这类追问，需要一致的拒答口径

## 核心判据（四问）

1. **输出还是需求？** 输出绝对不足与需求上升供不上都算心衰；判断依据是供需对比，不是泵的绝对值。
2. **哪一层代偿？** 即时（Starling 换压力、心率换时间）、神经体液（交感、RAAS、抗利尿激素与利钠肽）、结构（向心性 / 离心性肥厚）。三层启动速度不同，代价也不同。
3. **代价记在哪？** 淤血、缺血、后负荷、纤维化、顺应性、电不均一。说不出记账处的代偿，多半没读懂。
4. **停在链的哪一段？** 代偿（透支）、重构（功能变结构）、失代偿（三条路径）。位置不同，可干预的环节不同。

## 执行步骤

```text
1. 抄原话，不改写：把要拆的那句话原样放在第一行
2. 定供需：输出不足 / 需求上升 / 未提
3. 列代偿：三层逐层标「有 / 未提」，未提就写未提
4. 记账：每层代偿配一句代价与一个记账处，做成三列表
5. 判重构：心肌 / 间质 / 几何 / 电，四层归位；几何层要指出正反馈
6. 定失代偿：储备耗尽 / 代偿自身致病 / 诱因叠加，三条逐条标
7. 中性改写：删掉判定成分，只留机制与观察时点
8. 报边界：不写数值，不作分级，不作预后判断
```

## 硬约束

- **不给数值、单位、正常值、阈值、百分比。** 需要数值才能回答的追问，统一回「不给值，须另立数据层」。
- **不作诊断，不作心功能分级，不作预后判定。** 「代偿期」与「失代偿」在本课程里是机制位置的名字，不是对某个人的分期。
- **引文逐字。** 标 `补充·hermes-病理生理学讲义·第19章·N.M`；核不到就不引。讲义是本仓库原创讲义，不是教材，不标「教材」。
- **不把诱因写成机制。** 诱因只解释时点，机制要写储备余额。
- **不把症状方向当病情方向。** 全心衰时肺淤血可看似减轻。

## 交付物

1. 一段三层拆解（代偿 → 重构 → 失代偿），缺层如实标缺
2. 一张「代偿 → 代价 → 记账处」三列表
3. 一句失代偿归因：三条路径各标有 / 无 / 未提
4. 一段中性改写：删掉判定成分后的版本
5. 一处边界：不给值、不分级，数值须另立数据层

## 典型误用

| 误用 | 后果 | 纠正 |
|---|---|---|
| 把稳定当安全 | 「代偿期说明情况可控」 | 代偿期是以透支换表面稳定，必须同时写代价 |
| 只记益处 | 交感激活写成「身体的智慧」 | 每层代偿后强制跟一句代价 |
| 诱因当机制 | 「感染引起加重」 | 机制写储备耗尽，诱因只定时点 |
| 症状反向读 | 「喘得轻了就是好转」 | 核对是哪一段链条变了：可能是右心也衰竭 |
| 把病因去除当病情逆转 | 「血压控制住了就算治好了」 | 重构可自行推进，须说明残余结构改变 |
| 被追问就报阈值 | 「低于某值就是心衰」 | 统一回「不给值，另立数据层」 |

## 边界

本 Skill 只处理「一段叙述 → 三层 → 代价账」的结构化拆解，不涉及数值、分级与临床决策。机制框架取自《hermes-病理生理学讲义》第 19 章；任何涉及个体的评估须由具备资质的人员依现行规范与机构制度作出。
