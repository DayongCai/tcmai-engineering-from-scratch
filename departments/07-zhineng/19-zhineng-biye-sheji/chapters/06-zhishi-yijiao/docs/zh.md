# 第 6 章 · 移交不是交一份文档，是让接手的人在没有你的情况下跑出同一个数

> **MOTTO:** 「得其人不教，是谓失道；传非其人，慢泄天宝。」——《素问·气交变大论》
>
> **PROBLEM:** 毕设的交付周期在答辩之后还有一段尾巴，而作者的身份在这段时间里会从「在校生」变成「已离校」。本系的毕设按模块分包定价，一个可交付单元 200,000 元/院、回本周期 3.9 个月——这个定价隐含一个前提：接手人能独立把它跑起来并继续维护。测试这个前提只需要一个动作：**找一个没参与过你项目的人，给他交接包，看他在多长时间内跑出与你论文一致的主表数字**。多数毕设在这个动作上失败，失败原因几乎都不是代码写得差，而是缺四样东西：环境、数据、口径、失败清单。缺哪一样，接手人都得回头找你，而那时候你已经不在。

**双根因定位:** 环境逼迫（交付要能接手，接手要能复算；一份只有作者会跑的代码在定价表上等价于零）+ 知识积累（教材讲到「部署应用」就停住了，没有讲模型离开作者之后靠什么维持；维持靠的不是文档的厚度，是四件可被独立验证的材料）

## 一、模型卡：十二个字段，缺一不可

模型卡的作用是让一个陌生人判断「这个模型能不能用在我的场景里」。它不介绍你的方法有多新，只回答「它是什么、训在什么上、什么时候不该用」。

| 字段 | 写什么 | 不合格的写法 |
|---|---|---|
| 名称与版本 | 标识 + 版本号 + 生成日期 | 「最终版」 |
| 预期用途 | 一句话：给谁、在哪个环节、做什么判断 | 「辅助中医诊疗」 |
| 不适用场景 | 明确排除的人群、科室、任务 | 空着 |
| 输入 | 字段、格式、必需项、缺失处理 | 「病历文本」 |
| 输出 | 标签集、输出格式、是否含分数与依据 | 「辨证结果」 |
| 训练数据 | 来源、规模、时间段、纳排、授权状态 | 「真实病历若干」 |
| 标注 | 标注者资质、人数、一致性、弃权比例 | 「专家标注」 |
| 评估 | 指标、切分方式、基线、重复次数 | 「准确率 0.86」 |
| 分层表现 | 按类别与来源的最差子集 | 只给总体 |
| 已知失效 | 你验证过的失败情形，附最小复现 | 「少量误差」 |
| 依赖与运行 | 环境、依赖版本、一条命令、硬件要求 | 「按说明运行」 |
| 维护与退役 | 谁维护、漂移判据、何时停用 | 空着 |

「不适用场景」与「已知失效」这两栏是分水岭。一份诚实的模型卡会写「本模型未在儿科病例上验证，不建议用于十四岁以下人群」；一份不诚实的模型卡会把这两栏留空，让接手人自己去踩。留空的代价不是道德问题，是使用问题：接手人不知道边界，就会在边界外使用，然后失败，然后把失败归到「这个模型不行」。

「评估」栏里的切分方式必须写，因为它是唯一能让接手人判断「0.86 是什么条件下的 0.86」的信息。同一个数字，按记录随机切与按机构切，含义完全不同。

## 二、交接包四件：代码、数据、环境、口径

模型卡是说明书，交接包是本体。四件材料缺任何一件，复算就断在那一件上。

| 件 | 内容 | 断掉的症状 |
|---|---|---|
| 代码 | 从原始数据到主表的全部脚本，含清洗脚本 | 依赖一个手工整理的中间文件，无法重建 |
| 数据 | 原始数据或其合规引用方式、标注文件、切分文件 | 只知道有数据，拿不到或对不上 |
| 环境 | 依赖清单与版本锁定、运行命令、硬件要求 | 「我这能跑，你那报错」 |
| 口径 | 指标定义、阈值来源、弃权规则、命名对照 | 同一个词指两件事，数字对不上 |

第三件最容易被低估。Python 生态里「装最新版」是一个陷阱：同一个库的两个版本可能改变默认参数，而默认参数会改变结果。锁定版本清单（而不是只写包名）是复算的最低要求，成本是几分钟，收益是把「环境问题」这一类求助永久消除。

第四件是中医 AI 项目特有的难点。「证型」「证候」「病位」这些词在不同教材、不同科室里指的范围不一样；你的标签集用的是哪一套，必须在口径文件里写清，并给出与常用编码体系的对照。没有这份对照，接手人看到「肝郁脾虚」不知道对应你标签集里的哪一个，模型卡再详细也用不起来。

## 三、验收：三个动作，一个都不能省

交接是否成功，不由交付方宣布，由接手方验证。三个动作构成一条从「能跑」到「敢用」的阶梯。

| 动作 | 谁做 | 通过标准 | 失败说明什么 |
|---|---|---|---|
| 动作一：复算 | 未参与项目的人，只看交接包 | 跑出与论文主表一致的数字 | 环境、数据或口径有缺口 |
| 动作二：改一处 | 同一人，改一个参数或换一批输入 | 结果按预期变化，且能解释 | 参数没真正外置，或流程有隐藏假设 |
| 动作三：找一处错 | 同一人，按模型卡的失效清单复现一个失败 | 能复现，且失败形态与描述一致 | 失效清单是编的，或不可复现 |

动作二是最有用的一关，因为它测的不是「能不能跑」，而是「理解得对不对」。一个只会按原样运行的人，遇到新数据就束手无策；一个能改一处并解释结果变化的人，才算接住了。

动作三常被跳过，理由是「没必要自己揭短」。恰恰相反：把失效复现做成交接的一部分，等于把「这个模型什么时候不可信」从口头承诺变成了可检验的资产。接手人第一次遇到失败时，手里有清单，就不会把问题误判成「系统坏了」。

## 四、退役与责任边界

任何模型都有停止使用的条件。移交时若不写明，停用就只能发生在压力最大的时刻，并且由最没有停机权的人临时决定。

| 条件 | 判据 | 触发后做什么 |
|---|---|---|
| 性能漂移 | 定期复评低于交接时的分层基线一定幅度 | 暂停使用，重新评估 |
| 上游变更 | 术语表、编码体系、数据源口径更新 | 重新映射并复评，未完成前标注「未适配」 |
| 场景外使用 | 出现模型卡「不适用场景」中的输入 | 拒绝输出或强制人工复核 |
| 人员变动 | 维护人离岗且未完成再交接 | 转入手工流程，不得无人维护运行 |

性能漂移的判据必须写成可测的形式。「效果变差就停」不是判据，「每季度在固定的回访样本上复评，若某一分层低于交接时基线若干个百分点则暂停」才是。具体幅度依场景与后果确定，本章不给数值。

责任边界同样要写清：模型输出是建议，进入病历的每一条都必须有人复核并留痕；模型不承担判断责任，署名的人承担。这不是套话，它决定了出问题时能不能重建「当时可得的信息」。

## 五、常见失败模式

| 失败 | 症状 | 根因 | 纠正动作 |
|---|---|---|---|
| 文档代替交接 | 交了三十页说明，没人跑通 | 说明多、可执行材料少 | 只留四件，每件附一条命令 |
| 环境不定版 | 「装最新版就行」 | 依赖未锁定 | 生成版本清单并实测 |
| 口径各说各话 | 同一个标签两种含义 | 无术语对照表 | 补标签集与编码体系对照 |
| 失效清单空缺 | 「基本没有失败」 | 未系统采集失败 | 从误差表反推三条最小复现 |
| 单点依赖 | 只有一个人会跑 | 未做接手验收 | 强制动作一由第三方执行 |
| 无退役条件 | 出问题才临时决定 | 未预设判据 | 写四条触发条件与责任人 |

「文档代替交接」是最常见的一种。它的成因不是懒，是混淆了两种文本：说明文档写给「想知道为什么的人」，交接包写给「要把它跑起来的人」。前者可以很长，后者必须很短，并且每一步都能被执行、被验证。

「单点依赖」在毕设里几乎是结构性的——一个人做，一个人会。破解办法只有一个：在答辩之前就让第三方跑一遍。这件事要在还有时间修的时候做，而不是在离校前一天做。

## 代价与边界

**完整交接的成本可能超过开发本身。** 环境锁定、术语对照、失效复现，每一项都要额外时间；对一个 8 人月的毕设，交接准备通常要占最后阶段的相当一部分。可行的做法是把交接材料在过程中同步生成（数据卡、实验日志、参数配置本来就要写），而不是最后集中补。

**移交不等于责任转移。** 模型卡写清边界，只说明交付方尽到了说明义务，不意味着使用方可以免于复核；进入临床流程的每一条输出，仍须由具备资质的人员判断并留痕。

**本章不给退役阈值，也不给维护周期。** 漂移判据、复评频率、停机幅度，取决于预期用途、人群与后果，须依现行医疗人工智能与数据管理要求及所在机构制度确定。

**文中的定价、人月与验收时长均为本系毕设口径或便于说明的设定**，不指向任何具体项目或机构；实际交付要求以合同、批准文件与所在单位制度为准。
本章可直接验证：`node code/main.js` 打印结构清点与判据清单（数字从 `docs/zh.md` 现算），`node --test code/main.test.js` 跑本章单测；两条命令只读正文与代码，不写任何文件。
