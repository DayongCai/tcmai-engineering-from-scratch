# 知识进机器有四条路，最像捷径的那条最贵

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 7 道题自检，答不上就回到对应小节。

## 核心判据

- 硬约束用规则，概念体系用图谱，补全用嵌入，文本用模型
- 所有四条路共享同一套 ID
- 关系密度比概念数量更能决定图谱有没有用
- 图谱的成本不在建，在养
- 规则管「必须」，模型管「大概」
- 高置信度的错误

## 边界

- 文中的人日、三元组数、抽检结果均为**演算设定**，用于演示成本与区间的关系；不代表任何真实知识库的规模或质量。
- 本章不评价具体本体标准、图数据库产品与嵌入算法；RDF/OWL 与属性图的取舍依查询需求与团队能力定，没有通用答案。
- 「四路分工」是工程口径，不是学术分类；真实系统里四者常常混用，边界模糊。
- 本章为知识表示与知识工程的讨论，不构成诊疗建议或技术选型建议。
