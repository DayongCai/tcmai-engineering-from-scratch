# 「消渴」「糖尿病」「E11」：三个名字都不算错，但系统只认一个

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 7 道题自检，答不上就回到对应小节。

## 核心判据

- 强度分级的意义不是排序好看，而是让「这一条弱在哪」可查
- 合称还要再切一刀
- 一条都没有整条正名
- 不推测、不补全
- 离线降级是常态，不是异常
- 标准不是文档，是枚举与校验

## 边界

- **9 条未解 + 31 条同名多义是已知的洞，不是待修的 bug。** 它们被显式记录而非强行归类；强行归类的代价是把错误固化进下游。
- **117 类不是中医证候的全集。** 它只是当前语料与标准表能支撑的部分；覆盖不到的概念既不能声称「没有」，也不能凭构造补进去。
- **对齐不等于证据。** 把合称对齐到国标正名，只是让「要引用哪个名字」有答案，不构成该证存在或该方有效的证据。
- 本章为标准与信息治理讨论，不构成诊断、辨证或治疗建议。
