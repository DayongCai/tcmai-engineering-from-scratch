# 第 1 章 · 三元组答得出「谁和谁有关」，答不出「先学谁」

> **MOTTO:** 「知其要者，一言而终；不知其要，流散无穷。」——《灵枢·九针十二原》
>
> **PROBLEM:** 一张 3,063 节点、3,370 条边的中医图，看上去什么都不缺：病、证、方、穴、编码都在里面。可把一个知识点丢进去问三件事——它在哪门课的第几章、该排在「藏象」之前还是之后、这条关系凭什么写——图一条都答不上。这三个问题不缺边，缺的是另一种结构。

**双根因定位:** 环境逼迫（教材按章节目录组织，图谱按实体关系组织，检索按向量近邻组织，三套坐标互不换算，命中一个知识点却回不到章） + 知识积累（2,489 片章节叶 + 103 片病证叶 = 2,592 个落点，落点这件事先想清楚，才谈得上推理）

## 一、三元组能答什么，答不了什么

知识图谱的原子是三元组：`(主语, 谓语, 宾语)`。中医领域已经用这套语法拿到过实绩——中药活性成分到靶点的关联挖掘、方剂配伍的频次与网络分析、以症状为入口的智能问诊。这些成绩都是真的，它们有一个共同点：问的都是「A 和 B 有没有关系」。

把关系写成三元组，好处是极致简单：一条事实一行，不加修饰，可合并、可查、可算中心度。坏处也来自同一处简单——三元组只说「有边」，不说这条边**在哪一层**、**有多可信**、**属于哪本书**。于是三类问题立刻失效：

| 问题 | 需要的结构 | 三元组能给吗 |
|---|---|---|
| 「肝主疏泄」先从哪门课学、再在哪门课复习 | 从属链 + 先修次序 | 不能，边是无向的、无序的 |
| 同一概念在 28 门课里被讲了 28 遍，是不是 28 个节点 | 概念身份 ≠ 出现位置 | 不能，节点按出现位置建就会重复 |
| 「风寒束表证 — 麻黄汤」这条边出自哪本教材第几章 | 出处与证据等级 | 不能，三元组不带来源 |

第三条尤其要紧。中医的知识关系密度极高而证据等级极不齐：有的是《伤寒论》原文写死的，有的是现代教材归纳的，有的是统计关联挖出来的。三者写在同一个谓词位置上，图上看起来一样重，临床上完全不等价。所以第一章必须先承认：**图谱擅长「横向找关系」，不擅长「纵向定位置」**。这不是实现缺陷，是表示的边界。

## 二、两层结构：层次管从属，关系管推理

中医的知识组织从来是双轨的，只是过去没被显式拆开。

**层次**在经典与教材里：阴阳→五行→藏象→经络→证候→方药，一级一级往下分，越往下越具体。它的语义只有两种：`is-a`（是一种）与 `part-of`（是……的一部分）。学生靠这一层「学得进去」——因为任何新知识都能挂到一个已知的父节点下面。

**关系**在临证里：五行生克乘侮、十二经脉流注与表里、方证对应、君臣佐使、引经报使、六经传变。它的语义是横向的、带方向的、常常带符号（生是促进，克是抑制）。医生靠这一层「用得出神」——因为辨证就是在这些横边上走路径。

两层的性质完全不同，混在一张图里必然互相污染：

| | 层次（树） | 关系（图） |
|---|---|---|
| 边的语义 | 从属、递进、教学先后 | 影响、对应、传变 |
| 是否成环 | 不成环（否则层级自相矛盾） | 允许成环（五行就是一个环） |
| 路径数 | 任两节点之间唯一 | 可多条，可有权重 |
| 典型查询 | 这条知识属于哪一章 | 从这个症状能推到哪个方 |
| 坏了会怎样 | 导航失效，学不下去 | 推理失效，推不出来 |

结论是一句话：**树承载层次，图承载关系；叶即图节点，边即经脉。** 这句话听上去像修辞，落到工程上是一条硬约束——建图时不允许用「属于」这类谓词，建树时不允许出现跨枝的横向边。

## 三、树图一体：叶是唯一的接口

两层要能对上，只能靠一个约定：树的叶，就是图的节点。除此之外不设第二个接口。

这条约定解决了重复问题。若按「出现位置」建节点，`肝主疏泄` 在《中医基础理论》第 2 章讲一次、在《中医诊断学》第 5 章再讲一次，就会变成两个节点，两条出处，两套注释，此后永远对不齐。改成按「概念身份」建叶，情况就干净了：

```json
{
  "id": "K-8f3a91c2",
  "name": "肝主疏泄",
  "aliases": ["疏泄失职", "肝失疏泄"],
  "owner": "01-zhongyi/01-zhongyi-jichu-lilun",
  "occurs": [
    {"branch": "01-zhongyi/01-zhongyi-jichu-lilun", "chapter": 2, "unit": "2.3"},
    {"branch": "01-zhongyi/14-zhongyi-zhenghou-xue", "chapter": 5, "unit": "5.1"}
  ],
  "firstAttested": {"book": "素问", "chapter": "五常政大论"}
}
```

`id` 由规范化后的概念名取哈希得到，因此同一个概念天然同一个 ID；第一次系统讲授它的学科拿 `owner`，其余位置只往 `occurs[]` 里追加一条，**不建新叶**。跨枝想引用，只能走带理由的 `ref` 边。这一条纪律的收益是可数的：18,065 个教材单元被归并成两千余片叶，重复讲的内容变成了同一片叶上的多条出现位置，而不是多个互相矛盾的节点。

叶作为接口，还让「一个节点同时活在树里和图里」成为默认行为。取 `DSU-00001` 的邻居，返回的是四种不同性质的边：

```text
neighbors(DSU-00001)
  manifests_as → SYN-风寒束表证      （证侧：它是哪个证）
  disease_is   → 感冒（CA00）        （病侧：它对应哪个病）
  icd11_map    → CA00               （编码：对外交换用哪个码）
  hierarchy    → D01-S13            （树：它挂在哪一枝）
```

前三条是图关系，第四条是树位置。一次查询同时给出「是什么、属于谁、怎么编码、在哪门课」，这正是单一坐标做不到的事。

有一类概念需要单独处理：**跨枝公用的概念**，比如「辨证论治」「四诊」。它们既不属于某一门课，又不宜升到须层（须层只放哲学根基）。做法是把它们升为**概念丛**——一类特殊的图节点，不挂任何院系枝，但可以被任意叶以 `ref` 引用。现有 333 个概念丛，正好是这层「公用地带」的规模。判断标准也很干脆：一个概念被三个以上院系引用、且没有一门课能声称它是自己的主体内容，就进概念丛；只被一两个院系引用，就留在 `owner` 那一枝上，其余走 `ref`。这条门槛防止概念丛变成一个什么都往里丢的垃圾桶。

## 四、五级编码与四级目录：两套坐标，各管一段

树需要编址，教材也需要编址，但两者服务的对象不同。

教材目录是「篇·章·节·目」四级，面向**教学编排**：一学期多少学时、第几周讲到哪一节，靠这套编号排课。知识树是「须·根·干·枝·叶」五级点分编码，面向**知识定位**：这个概念在全学科体系里的位置，靠这套编码判断。

| 层级 | 名称 | 数量 | 语义 |
|---|---|--:|---|
| L0 | 须（哲学根基） | 6 | 象数阴阳、五行生克、精气神形、天人相应、藏象经络、恒动整体 |
| L1 | 根（核心公理） | 4 | 整体观念、辨证论治、恒动平衡、治未病 |
| L2 | 干（院系域） | 8 | D01…D08 |
| L3 | 枝（学科） | 120 | 一门课 = 一种教材 |
| L4 | 叶（知识点/病证单元） | 2,592 | 章节叶 2,489 + 病证叶 103 |
| — | 概念丛（图节点） | 333 | 跨枝公用概念，不挂任何一院 |

两套编码互为补充，不能互相替代：四级目录回答「这门课怎么教」，五级编码回答「这条知识是谁的」。一个知识点可以在一门课的第 3 章，同时在树的另一枝下——因为它 `owner` 在那枝，只是被这门课引用了。若强行让两套编号一致，就等于要求「讲授顺序 = 知识从属」，这在中医里显然不成立：诊法要在基础理论之后教，但诊法知识并不从属于基础理论。

## 五、四种老表示法的组合，与树为什么能用最少的边

知识表示史上出现过四种主流做法，中医知识树一个都没发明，只是把它们拼起来用：

- **框架表示**：槽—值结构描述对象。叶的 `attrs` 就是槽。
- **语义网络**：节点—弧表达概念关系。图的那一层就是它。
- **本体**：在语义网络上加形式化公理，使之可推理。`is-a` / `part-of` 的传递性来自这里。
- **属性图**：节点与边都带属性，工程上好落地。`nourish` 边上挂「滋养哪条公理」就是它。

组合的接口是双轨的：对外用 OWL 承载领域本体（可用 Protégé 建模、可被推理机消费），对内用 JSON 属性图承载构建与查询。二者由一份 schema 桥接，避免「建模一套、跑起来另一套」。

而树之所以值得单独存在，是因为它在数学上最省：`n` 个节点只需 `n−1` 条树边就能保证连通无环，任意两节点之间路径唯一。用 2,592 片叶和 2,591 条树边，就能让每个知识点都有唯一的祖先链——想回答「我在学哪一章」，只需一次向上遍历，成本与深度成正比，与全图大小无关。图做不到这一点：图里两点之间可能有很多条路，最短的那条未必是教学上正确的那条。

所以正确的用法是分工：**找学习路径用树算法（唯一路径、子树封闭），找推理链用图算法（多跳、带权、可成环）**。把这两件事混成一个查询，得到的既不是课表也不是辨证路径。
本章可直接验证：`node code/main.js` 打印结构清点与判据清单（数字从 `docs/zh.md` 现算），`node --test code/main.test.js` 跑本章单测；两条命令只读正文与代码，不写任何文件。

## 六、代价与边界

- **叶的粒度是最大的不确定项。** 教材单元层现有 18,065 个单元，按「一单元一叶」会得到一万八千片叶，远超源骨架的 2,592。必须走同义与上下位归并，归并率要达到三成以上才谈得上可用；这一步的判准目前靠人工抽检，而不是自动指标。
- **2,592 = 2,489 + 103 是源资料的构建结果，不是本仓库的。** 本仓库只落了 L0–L3（6 / 4 / 9 / 188），叶层尚未生成；且 188 枝与源的 120 枝差 68，差额来自护理、基础两域与推拿的归属口径不同，已逐条记账而不做静默对齐。
- **树不等于知识本身。** 位置定得再准，也不证明这条知识对；本章只讨论「怎么放」，不讨论「放得对不对」。
- 本章不涉及任何具体诊疗判断，也不能据以推断某个证候的实际归属。
