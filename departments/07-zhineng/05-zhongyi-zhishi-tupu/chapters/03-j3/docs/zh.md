## 三、逐单元读

### 3.1 病证单元（DSU）作为最小编写原子

第二类叶来自病证知识图谱。每个 DSU 同时包含病侧与证侧，不可拆分： 知识树把每个 DSU 作为一片叶，挂到其归属的学科枝（如 DSU-00001 挂 D01-S13 中医内科学（上））。

*单元规模：55 汉字；出处 `教材·原第5章·5.2`；本单元数值类命中 0。*

### 3.2 中医智能服务单元的正名与降格（学科正名／服务降格）

叶层设计贯彻两条命名纪律： - **学科正名**：凡进入「学科枝」的条目必须是真正的学科（一门课=一种教材），不把章节升格为学科； - **服务降格**：平台的工程服务（检索、编码、生成）不冒充学科，而是以「技能挂点」或「概念丛」的身份降格接入。 这一纪律防止了「学科膨胀」与「目录漂移」，是本平台教材体系稳定性的关键。

*单元规模：119 汉字；出处 `教材·原第5章·5.3`；本单元数值类命中 0。*

### 3.3 叶节点的属性与质量门禁

每片叶携带 `code5`（五级编码）、`level`、`kind` 与 `attrs`。质量门禁要求：叶必须有父（无孤儿）、必须可定位（编码非空）、DSU 叶必须带病名与证名。`schema.json` 以 JSON Schema 形式固化这些约束，构建时逐条校验。

*单元规模：58 汉字；出处 `教材·原第5章·5.4`；本单元数值类命中 0。*

### 3.4 叶级检索与定位

叶是检索的落点。给定任一关键词，先在全树叶名上做包含匹配，再回到树与图提供上下文： > 实训：统计八域各自的叶数量，观察哪一域的知识密度最高（提示：临床院系叶最多）。

*单元规模：70 汉字；出处 `教材·原第5章·5.5`；本单元数值类命中 0。*

### 3.5 五行生克乘侮的图建模

五行是中医最早的关系网络。相生为激励边，相克为抑制边，整张图是带符号的有向图。知识树把五行建为五个概念节点，并生成两类边： 乘侮（过度克制／反向欺凌）不单独建边，而是把对应边**加权放大或反向**，交由图算法（随机游走、消息传递）追踪失衡传播路径。

*单元规模：104 汉字；出处 `教材·原第6章·6.1`；本单元数值类命中 0。*

### 3.6 十二经脉流注与表里相合

十二经脉按流注次序首尾相接，构成一个大环；互为表里的两经成对。知识树把十二经建为概念节点，生成： - `meridian_liuzhu`（流注）：手太阴肺经→手阳明大肠经→…→足厥阴肝经→（回手太阴），共 12 条； - `meridian_biaoli`（表里）：肺—大肠、胃—脾、心—小肠、膀胱—肾、心包—三焦、胆—肝，共 6 条。

*单元规模：88 汉字；出处 `教材·原第6章·6.2`；本单元数值类命中 2。*

### 3.7 六经传变与病证桥接

六经（太阳、阳明、少阳、太阴、少阴、厥阴）既是辨证纲领，也是传变路径。知识树把六经建为节点，生成 `six_chuanbian`（传变）顺序边；同时，每个 DSU 的证侧若标注了六经归属，则建一条 `bridge` 边，把病证单元接回六经主线上。目前 103 个 DSU 中已有 81 条 `bridge` 边。

*单元规模：83 汉字；出处 `教材·原第6章·6.3`；本单元数值类命中 2。*

### 3.8 方证对应、君臣佐使、引经报使

*单元规模：39 汉字；出处 `教材·原第6章·6.4`；本单元数值类命中 0。*

### 3.9 经脉边的推理与路径发现

有了经脉边，知识树就能回答「多跳」问题：由「恶寒发热无汗」→ 证候「风寒束表」→ 六经「太阳病」→ 主方「麻黄汤」→ 归经「手太阴肺经」。这条推理链跨越了图与树、证与方与经络，正是中医思维的数字化表达。 > 讨论：为什么「六经」与「经络」是两套独立坐标系？在建图时应否强行合并？

*单元规模：103 汉字；出处 `教材·原第6章·6.5`；本单元数值类命中 0。*

### 3.10 病侧与证侧的双向锚定

病证单元的核心设计是**双向锚定**：病侧锚定诊断终点（辨析式流程），证侧锚定干预着力点。教材编写要求双栏：左栏写病（分子靶点、ICD-11、流行病学），右栏写证（证候场论、六经八纲、主症舌脉），中缝设桥接栏（对应类型、生物学基础、证据等级）。知识树把两侧合并为一片叶，用 `disease_is`、`manifests_as`、`bridge` 三条边分别接入西医病、证候与六经。

*单元规模：119 汉字；出处 `教材·原第7章·7.1`；本单元数值类命中 0。*

### 3.11 内网 ICD-11 镜像与本地编码库

ICD-11 编码是病证单元对接病历与医保的关键。tcmP 采用双通道： > 实测（2026）：华为云公网访问不到内网 API，中文搜索自动降级英文；编码端点由镜像能力决定，本地 db 补齐。因此**离线降级**是必须写在教材里的纪律：平台不可达时，凡依赖编码的结论标注「未能核实」。

*单元规模：97 汉字；出处 `教材·原第7章·7.2`；本单元数值类命中 0。*

### 3.12 病证桥接的证据等级体系

桥接的严格性由证据等级标定：A级多中心RCT → B级单中心RCT → C级队列研究 → D级病例对照 → E级专家共识 → F级经典理论。知识树把等级写入边的 `meta`，使「这条对应关系有多可信」可被机读与排序。

*单元规模：69 汉字；出处 `教材·原第7章·7.3`；本单元数值类命中 0。*

### 3.13 编码映射的校验与冲突消解

编码映射会冲突：同一 DSU 可能对应多个 ICD-11 候选，或一词多码。消解策略是**三查一验**：查内网 API、查本地 db、查教材标注；三者不一致时以本地 db 的 Foundation ID 为准，并把分歧记入审核队列。 > 实训：对 12 个 DSU 抽样，比较「内网 API 编码」与「本地 db 编码」的异同，统计一致率。

*单元规模：89 汉字；出处 `教材·原第7章·7.4`；本单元数值类命中 1。*
