# 一棵树值不值钱，取决于它能不能被重跑出来

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 7 道题自检，答不上就回到对应小节。

## 核心判据

- 一致性可证
- 可自动判定
- 源层只读，带指纹
- 带章节归属追踪
- 静默丢弃与从未存在，在下一个人眼里长得一模一样
- 没有它，向量检索给出的是一段文本；有了它，给出的是一个坐标

## 边界

- **构建器是唯一真相，也是单点故障。** 它错了，全树错，且错得很一致。所以构建器必须有测试，而不是「跑通就行」。
- **容错解析有上限。** 排版超出预设四种时仍会漏抽，表现为「该学科叶数为 0」；这类告警必须人工回源，不能靠调参解决。
- **向量层与树层可能不一致。** 叶文本改了而索引没重建，检索会命中旧内容。重建索引要跟着构建一起跑，不能靠记得。
- 本章为工程实现讨论，不构成诊断、辨证或治疗建议。
