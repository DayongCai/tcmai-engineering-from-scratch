# 可视化不是把模型画出来，而是把不确定度摆到台面上

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 工程上的正确做法是给每种模式一套独立的渲染配置，并在图上标注当前模式
- 它决定什么被看见
- 它不改变数据，只改变感知
- 它是可复现性的关键
- 因此降采样必须与"最小可见结构"的声明绑定
- 碰撞检测与力反馈

## 边界

- 本章的 256 MB、512 步、16.7 ms、100／200 ms 与 1 kHz 均为**量级估算与交互研究中的经验阈值**，用于说明预算关系，不对应任何具体软硬件配置。
- 传递函数、降采样与 LOD 的具体参数须按应用与数据确定，本章不给推荐值。
- 教学效果部分只陈述可替代与不可替代的类别，**不给出任何"仿真提升多少学习效果"的数值**；此类结论须以原始研究的学习结局与情境为准。
- 本章为可视化与交互系统的工程讨论，不构成医学意见、诊断或治疗建议。
