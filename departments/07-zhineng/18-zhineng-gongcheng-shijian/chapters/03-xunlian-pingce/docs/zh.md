# 第 3 章 · 一次跑通不算流水线，能跑出同一个数才算

> **MOTTO:** 「不明于计数而欲举大事，犹无舟楫而欲经于水险也。」——《管子·七法》
>
> **PROBLEM:** 同一份数据、同一个模型，两位工程师各跑一次，A 报 AUC 0.91，B 报 0.86。查了两天才找到原因：A 在划分之前做了标准化，验证集的均值泄漏进了训练；B 用了另一个随机种子，而小样本下种子带来的波动就有 0.03。更麻烦的是评测集：过去三个月它被不同的实验「顺手看一眼」看了 17 次，每次看到不好的结果就调一版再来。到第 18 次，0.91 这个数字已经不再描述模型在新数据上的表现，它描述的是**这个团队对这批样本的熟悉程度**。一次训练 6 小时，重跑一次的成本足以让人放弃追问——这正是流水线要解决的问题。
>
> **双根因定位:** 环境逼迫（数据少、标注贵，12,000 例里能用于测试的不过千余，任何一次划分失误都会显著改变结论；算力有限，试错次数被硬性限制）+ 知识积累（团队把「可复现」当成一句口号，没有把它拆成代码、数据、环境、随机性四个可校验的锁；也没有把评测集当成消耗性资源来管理）

## 一、流水线的五段与产物

流水线不是一串脚本，是五段有产物的工序。**每一段都必须落一个可校验的产物**，没有产物的步骤等于没做。

| 段 | 做什么 | 产物 | 校验方式 | 责任人 |
|---|---|---|---|---|
| ① 取数与快照 | 从源库抽取、去标识、冻结 | 数据快照（只读）+ 清单文件 | 行数、字段数、哈希值比对 | 数据工程师 |
| ② 特征与预处理 | 清洗、编码、归一化 | 特征定义文件 + 转换器 | 在折内拟合，无全量统计量 | 算法工程师 |
| ③ 训练 | 拟合参数、记录超参 | 权重文件 + 运行清单 | 同配置重跑指标一致 | 算法工程师 |
| ④ 评测 | 在冻结测试集上算指标 | 评测报告（含置信区间） | 指标可由报告复算 | 评测负责人 |
| ⑤ 登记 | 入库、定版、写模型卡 | 模型条目 + 版本号 | 能从版本号反查到①–④全部产物 | 平台管理员 |

第①段的快照必须是**只读**的。做法是给每次抽取生成一个带日期与哈希的目录，权限设为只读，后续所有训练只引用目录而不重新查库。理由很实际：源库每天都在变，如果训练脚本每次现查，同一份代码在不同日期跑出的就是不同的数据，「复现」从第一步就不成立。

第⑤段的登记常被省略，代价在三个月后显现：线上某个版本出了问题，没人说得清它是用哪批数据、哪个提交、哪套超参训出来的，只能整体回滚到一个更老的版本，而那个版本的指标同样说不清。

## 二、可复现的四个锁

「可复现」这四个字要落到四个具体的锁上，任何一个缺失，重跑结果就可能不同。

| 锁 | 锁什么 | 怎么锁 | 缺失后的症状 |
|---|---|---|---|
| 代码 | 训练与预处理的确切版本 | 记录 commit 短哈希，工作区必须干净 | 结果差了但代码「没改过」 |
| 数据 | 输入样本的集合与顺序 | 快照哈希 + 样本 ID 清单 | 行数一样但样本不同 |
| 环境 | 依赖版本、CUDA、镜像 | 容器镜像摘要（digest），不用 tag | 换机器后数值漂移 |
| 随机性 | 种子、线程数、算子确定性 | 固定种子 + 单线程 + 确定性开关 | 同机重跑差 0.5 个点 |

四个锁都要写进运行清单，字段如下（这张表就是一次训练的可追溯凭证）：

| 字段 | 示例 | 必填 |
|---|---|---|
| run_id | 20260311-1432-a7f3 | 是 |
| 代码 commit | 8c1d9e2（工作区干净） | 是 |
| 数据快照 | snap-20260301-9f2a（12,438 行） | 是 |
| 镜像 digest | sha256:3b7e… | 是 |
| 超参 | lr=3e-4, bs=32, epochs=40, wd=1e-4 | 是 |
| 种子 | 1337 | 是 |
| 硬件 | 单卡 A10，驱动 550.54 | 建议 |
| 指标 | AUC 0.874 [0.851, 0.894] | 是 |
| 产物路径 | /models/v1.3.0/ | 是 |

确定性要特别说一句：即便种子固定，GPU 上的部分算子仍有非确定性实现，多线程归约顺序不同也会带来末位差异。对分类任务，这点差异通常不改变结论；但如果你在比较两个只差 0.2 个点的方案，那点差异就足以让你选错。**比较方案时，先确认差异大于噪声**——用三个不同种子各跑一次，看指标的标准差；差异小于一个标准差，就不算差异。

## 三、泄漏检查：八条必查

模型指标虚高，九成来自泄漏而非模型好。下面八条做成清单，每个新数据集必过一遍：

1. **患者级分组**。同一患者的多次就诊必须落在同一折，否则模型记住了这个人的舌象而不是这个证型的特征。检查：按 patient_id 统计跨折分布，任一患者跨折即失败。
2. **时间切分**。用未来数据训练、过去数据测试，等于用答案训练。有明确时间轴的，训练集截止日必须早于测试集起始日。
3. **预处理在折内**。标准化、缺失填充、特征选择的统计量只能来自训练折。用全量均值做标准化是最常见的泄漏，隐蔽且影响稳定。
4. **重复与近重复**。同一张图的不同压缩版本、同一次拍摄的连拍、同一份病历的多次导出，都会造成训练集与测试集「见过面」。用图像感知哈希或文本相似度做一遍去重，阈值记录下来。
5. **目标泄漏字段**。诊断结论、开方记录、随访结果这类字段如果出现在特征里，模型会直接抄答案。做法是把所有字段按「产生时间是否晚于预测时点」过一遍。
6. **标签构造泄漏**。用 ICD 编码反推证型、用处方反推诊断，再用这个标签训练模型去预测证型，本质是在学编码规则而非临床规律。这类问题的指标往往很漂亮，上线后立刻失效。
7. **类别不平衡下的划分**。分层抽样要按「患者 + 标签」两个维度做，只按标签分层会让某些折里的阳性患者高度集中。
8. **外部验证集的来源**。跨院数据要先确认设备、拍摄规范、人群构成是否可比。不可比时，指标下降是信息，不是失败。

第 4 条最容易被放过。很多中医图像数据集来自教学拍摄，同一患者同一天拍了十几张，角度略有差别。随机划分后训练集与测试集里出现同一患者的近似图像，AUC 会虚高十几个点，而这种虚高在跨院验证时会全部还回去。

## 四、评测协议：指标、区间与预算

评测协议要在开跑之前写定，跑完再定指标等于给自己留后门。协议至少包含五项。

**指标组合。** 单看一个数一定会误导。分类任务至少报四项：AUC、敏感度、特异度、阳性预测值，并注明测试集的阳性率。若任务是不平衡筛查，PR-AUC 比 ROC-AUC 更能反映临床体验。多分类要写明平均方式：macro 让罕见证型的问题放大，micro 被常见证型掩盖，两个都报读者才知道「总体不错」是怎么来的。

**置信区间。** 点估计没有意义。1,200 例测试集、阳性率 20% 时，AUC 的 95% 区间宽度大约在 0.04–0.06；换成 300 例，宽度接近 0.12。做法是 bootstrap 重采样 1,000 次取 2.5% 与 97.5% 分位。**两个版本的区间大幅重叠时，不要宣称新版本更好。**

**分层报告。** 总体指标会掩盖子群差异。至少按年龄段、性别、来源科室、设备型号分层，每层样本量不足 50 的合并或标注「样本不足，仅供参考」。子群差异往往是上线后投诉的第一来源。

**评测预算。** 测试集是消耗品。规定：每个模型版本在测试集上只允许评测一次；调参只能用验证集；测试集评测结果全部登记，包括难看的那些。真要反复看，就得留一份从不打开的「最终测试集」，只在发布前用一次。

**基线。** 报告里必须有三个基线：多数类基线（全判为最常见类）、上一版模型、临床现行规则。没有基线的指标无法判断价值——0.87 的 AUC 在一个 0.85 的基线上几乎等于没做事。

## 五、登记与晋级：让「上线」成为一个有判据的动作

模型登记表就是模型的身份证，字段不多，但每一个都要能反查：

| 字段 | 说明 |
|---|---|
| 版本号 | 主.次.修订，语义化 |
| 训练数据 | 快照哈希 + 时间范围 + 例数 |
| 适用人群 | 明确写「不适用于」什么 |
| 指标 | 测试集四项指标 + 区间 + 阳性率 |
| 已知失效模式 | 至少三条，来自错误分析 |
| 输入要求 | 图像规格、字段清单、缺失容忍度 |
| 负责人 | 技术与临床各一名 |
| 复核日 | 到期强制重评 |

晋级判据五条，全部满足才允许进入灰度：测试集指标不低于上一版（区间重叠且点估计不降超过 0.01 可接受）；全部子群无显著恶化；已知失效模式已写入使用说明；推理延迟满足部署环境预算；模型卡与登记信息完整。任一条不满足，版本停在「候选」，不进灰度。

回滚条件也要提前写死，且必须是可自动判定的：上线后 72 小时内关键子群敏感度下降超过 5 个点、空返回率超过 1%、推翻率超过 40%，任一触发即回滚，不需要开会决定。**把回滚判据写成数字，是为了在慌乱的时刻不需要靠人判断。**

## 代价与边界

- 本章的 12,000 例、0.91 与 0.86、AUC 区间宽度、bootstrap 次数均为**演算设定**，用于演示复现与评测的组织方法，不对应任何实测模型或数据集。
- 四个锁能保证「同输入同输出」，不能保证「结论正确」。数据本身的偏倚、标签的错误、任务定义的不合理，都不在可复现性的覆盖范围内。
- 患者级分组会减少有效样本量，小数据集上可能使某些折的阳性样本过少。此时应减少折数或改用重复交叉验证，而不是退回随机划分。
- 评测预算制度会增加沟通成本，尤其在快速迭代期。折中办法是保留验证集自由使用、测试集严格受限，边界写进团队规范。
- 本章不给出任何证型判别或诊断模型的效果承诺，也不评价具体算法；模型能否用于临床，须经独立外部验证、临床评估与主管部门审批。
