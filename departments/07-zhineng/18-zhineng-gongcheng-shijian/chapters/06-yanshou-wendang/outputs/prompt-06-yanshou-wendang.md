# 验收的标准不是文档齐了，是别人能接手 · 提示词

## 用途

给「验收的标准不是文档齐了，是别人能接手」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「验收要的是四种证据 → 验收用例怎么写，抽检怎么抽 → 文档按读者的任务写，不按页数写 → 交接演练：让接手方真的做一次」这条链。

## 提示词

```
我在学《工程实践与系统交付》第 6 章「验收的标准不是文档齐了，是别人能接手」，本章 6 节 / 2,993 汉字，习题 6 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 在备用环境里真跑一遍
   - 异常用例的通过率，比正常用例更能预测上线后的稳定性
   - 「带病验收」不是不可以，不可以的是没有清单地带病验收
   - 第一件：影子值班两周
   - 第二件：三个问题测试
   - 第三件：独立完成一次发布
4. 本章自陈的边界（不得越过）：
   - 本章的页数上限、抽检比例、保修时限均为**建议值与常见实践区间**，实际条款须依合同、机构采购制度与双方约定确定，不具备法律效力。
   - 「100% 执行」的用例范围会显著增加验收工期，高风险系统值得，低风险内部工具可适当下调；下调须在验收方案中书面说明理由。
   - 文档篇幅上限是约束而非目标。强行压到上限以下而丢失关键步骤，比写长更危险。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章为交付验收与文档编写的教学材料，所述流程、比例与条款用于说明工程判据，不构成合同建议或法律意见；具体操作以现行规范与所在机构制度为准。
