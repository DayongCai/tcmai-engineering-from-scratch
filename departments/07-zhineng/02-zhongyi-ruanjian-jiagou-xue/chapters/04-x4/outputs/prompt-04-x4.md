# 可扩展性不是预留接口，是把变化关进一个盒子 · 提示词

## 用途

给「可扩展性不是预留接口，是把变化关进一个盒子」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「判据只有一个：改一处，还是改一片 → 三类扩展点，三种机制 → 插件的最小契约 → 热插拔的代价：插件地狱」这条链。

```

2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 接入一个新能力，需要改动多少个文件、多少个模块、多少个团队
   - 端口由业务定义，不由实现定义
   - 状态不一致
   - 故障定位变难
   - 加载可以热，卸载要冷
   - 变化需要所有使用方同意的东西，放内核；变化只需一方点头的东西，放插件

   - 插件化不能解决组织问题。如果需求变更没有统一入口、没有评审，插件只会让变更更快地散落到系统各处。
```

## 边界

本章为软件架构教学讨论，不构成诊疗、用药或系统采购建议；具体操作以现行规范与所在机构制度为准。
