# 没写下来的决策，等于没做过决策 · 提示词

## 用途

给「没写下来的决策，等于没做过决策」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「ADR 的五段式，以及一个具体的例子 → 什么该记，什么不必记 → 写"失效条件"比写"理由"更有用 → 评审会不是投票会」这条链。

## 提示词

```
我在学《中医软件架构学》第 6 章「没写下来的决策，等于没做过决策」，本章 7 节 / 2,896 汉字，习题 6 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 背景、选项、决定、后果、失效条件
   - 它记录了甲和乙为什么没被选
   - 不可逆或逆转很贵
   - 被反复推翻的决策
   - 什么情况下应该重新讨论这件事
   - 约束是否完整？
4. 本章自陈的边界（不得越过）：
   - 本章的 ADR 格式是**通用结构**，不强制某一套文档工具；落地方式应适配机构的文档习惯与评审流程。
   - 写 ADR 有成本：一份一页半，一年十份，大约是一个人两三天的工作量。这个成本远低于一次返工，但必须有人承担，且要计入项目计划，否则永远排在最后。
   - ADR 记录的是当时的判断，不是真理。它允许被推翻，但推翻要留痕——这是它区别于"规定"的地方。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章为软件架构与项目管理教学讨论，不构成诊疗、用药或信息化项目决策建议；具体操作以现行规范与所在机构制度为准。
