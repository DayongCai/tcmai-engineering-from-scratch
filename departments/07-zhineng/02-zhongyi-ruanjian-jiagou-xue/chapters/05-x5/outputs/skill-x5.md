# 数据模型的第一版定不了终身，改动方式才定终身

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；
3. 按正文小节顺序，逐节说出判据（本章 6 条核心判断见下）；
4. 用 `quiz.json` 的 6 道题自检，答不上就回到对应小节。

## 核心判据

- 改字段名比改字段含义安全得多
- 语义变了，标识必须变
- 允许多个字段并存
- 明确的退出条件
- 明确的截止日
- 可以从主数据重建

## 边界

- 本章的模型讨论是**结构性**的，不针对任何具体数据库产品与标准版本；术语与编码以现行发布的标准为准。
- 并存期会带来双份维护成本与一定的性能开销，这段成本无法通过技术手段消除，只能通过缩短并存期来控制。压缩并存期要以差异率为依据，不能按工期表态。
- "冻结旧语义"意味着承认历史数据不可比。这是诚实的做法，但会被要求"出一条连续曲线"的管理诉求挑战。此时应当给出分段曲线加说明，而不是把两段拼成一段。
- 本章为数据建模教学讨论，不构成诊疗、用药或系统选型建议。
