# 同意不是一次签字，是一段可撤回的授权 · 提示词

## 用途

给「同意不是一次签字，是一段可撤回的授权」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「伦理审查到底在审什么 → 同意的四要素与三个层级 → 二次利用：从「同意过」到「同意到哪一步」 → 免除同意的四个条件，与它的替代物」这条链。

## 提示词

```
我在学《医学数据安全与隐私保护》第 4 章「同意不是一次签字，是一段可撤回的授权」，本章 6 节 / 3,345 汉字，习题 7 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 第一件：风险受益比是否成立
   - 第二件：隐私保护方案是否与风险匹配
   - "在受控环境内分析、只导出聚合结果"是一句可核的话；"严格保密"不是
   - 第三件：弱势群体与利益冲突
   - 三个层级的选择
   - 没有治理的广泛同意等于一张空白授权书
4. 本章自陈的边界（不得越过）：
   - 本章的 8 万份、接通率 40%、同意率 60%、覆盖 24% 等数值均为**演算设定**，用于说明逐人同意的可行性与偏倚方向，不对应任何具体研究的实际应答率。
   - 免除同意的四个条件是本章的概括性表述，具体适用须依现行规定与伦理委员会的审查结论；本章不给任何"可以直接免除"的结论。
   - 广泛同意与动态同意在技术上依赖同意状态的可读取与可撤回，若机构尚未建立统一的同意管理，采用这两种模式会形成"纸面授权、系统不知情"的空转。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章为伦理审查与知情同意的教学讨论，不构成伦理审查结论或法律意见；具体操作以现行规范与所在机构制度为准。
