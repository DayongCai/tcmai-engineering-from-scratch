# 第 1 章 · 三元结构：中医信息学的第三根支柱是语义，不是算力

> **MOTTO:** 「方以类聚，物以群分」——《周易·系辞上》
>
> **本章判断（作者命题，非古籍引文）:** 「一个支点撑不起世界，两个支点只能“分”，三个支点才能“立”。」
>
> **PROBLEM:** 手上有了病历文本，有了症状清单，也有了一个跑得动的分类器——按「数据 + 算法」这两个支点，系统本该立起来。可它立的是一地碎片：同一段「口干、多饮、消瘦」，在一个库里归到消渴，在另一个库里归到糖尿病，在第三个库里什么也没归上。两个支点都在，缺的第三根是**语义**；而在中医信息学里，语义不在算法侧，在词表侧。

**双根因定位:** 环境逼迫（上报、结算、复核三套口径同时压在同一份病历上，任何一套不认你的病名，数据就被打回原形）+ 知识积累（本章底本 41 个单元共 1,558 汉字、平均每单元 38 字，教材给的是骨架，「词表」这件事得自己补）

## 一、两个支点立不住：四种歧义

中医数据的第一现场是文本，而文本的第一属性是「不唯一」。把它按「病名 + 症状」两个维度压进一张表，会稳定遇到四类结构性问题：

| 类型 | 现场例子 | 二维表里的后果 |
|---|---|---|
| 同义异形 | 不寐 / 失眠 / 少寐 / 目不瞑 | 同一批病人被拆进四个桶，召回率凭空掉一截 |
| 同形异义 | 少阳：六经之少阳、手少阳三焦经、少阳病之证 | 三个概念共用一个字面，合并即失真 |
| 上下位混用 | 消渴 ⊃ 上消 / 中消 / 下消 | 有人按病计、有人按证计，口径不可比 |
| 病证双轨 | 2 型糖尿病（病）/ 气阴两虚（证） | 一条记录两个主体，主从关系没有字段承载 |

这四类不是「数据脏」。脏可以洗：错别字能改、空值能补、重复能去。但这四类洗完还在——因为语言本身没有为机器准备好。教材 1.7 的例证就落在这里：只有「病名 + 症状」会歧义，加上「证候」这一维，才能唯一定位一个病证单元。

「证候作为第三维」常被读成一句理论口号。它的工程含义其实很朴素：**给每个概念一个不随字面变化的标识**。有了标识，「不寐」与「失眠」才落进同一个桶，「少阳」的三个义项才会被拆成三个桶。教材 1.1 打的比方并不玄：三项之所以能「立」，是因为第三项不与前两项共线——它提供了前两项张不出来的那个方向。在数据里，这个方向就叫语义。

## 二、受控词表的四件套

把「语义」做成可计算的东西，第一步不是建向量，是建**受控词表**（controlled vocabulary）：一张有限的、经审定的词目清单，配上每个词目的定义、上位与相关关系。它的结构通常有四件：

1. **主题词（叙词）**：允许出现在标引与检索里的规范词，一个概念只准一个首选形式。
2. **入口词（非叙词）**：读者可能写出来的所有变体，只做指引进主题词之用，本身不建索引。术语学里把它叫「用—代」关系：入口词「代」主题词，主题词被入口词「用」。
3. **参照系统**：除「用／代」外，还有「属」（上位）、「分」（下位）、「参」（相关）。前两者承载层级，后者承载联想。层级管检索的扩检与缩检，联想管发现。
4. **范畴与定义**：范畴号给词目一个粗分类，定义给边界。没有定义的主题词表只是同义词表，遇到「眩晕」与「头晕」这种程度与病因都缠在一起的词，立刻失效。

这四件里最容易被跳过的是第 4 件。工程上的后果非常具体：两个标引员对同一个「眩晕」给出不同范畴，统计出来的证候分布就带上了人差。而人差一旦进了分母，后面所有挖掘结论都跟着漂。

一张词目卡片写全了，长这样（示意）：

```text
主题词  失眠
概念号  TCM:SYM:0000307
定义    以入睡困难、或寐而易醒、或醒后不能再寐为主症的病证
入口词  不寐 · 少寐 · 目不瞑 · 不得卧
上位    睡眠障碍
下位    —（暂不分）
相关    心悸 · 健忘 · 郁证
范畴    症状与体征 / 心神
```

卡片的价值在可执行：入口词给了检索侧的召回，上位下位给了扩检缩检的路径，相关词给了「查失眠顺手看到郁证」的联想。少了「相关」这一栏，词表就退化成一棵树，只能上下走，不能横着走；而中医的临床思路恰恰大量依赖横着走——由失眠想到心悸，由心悸想到心脾两虚。

## 三、三件工具各管一段：分类法、词表、本体

初学的人常把「编码」「词表」「本体」当同义词，其实三者回答的是不同问题，混用就会既排不好架也搜不准：

| 工具 | 回答的问题 | 结构 | 中医里的形态 |
|---|---|---|---|
| 分类法 | 这条知识归到哪一类 | 单继承的树 | 病证分类与代码的类目层级；古籍的经、史、子、集与子部医家类 |
| 主题词表 | 检索时该用哪个词 | 词 + 参照关系（用／代／属／分／参） | 不寐 → 失眠；消渴 → 三消 |
| 本体 | 概念之间能不能推 | 类 + 属性 + 公理 + 约束 | 六经与脏腑的关系约束、方剂的组成约束 |

分类法的价值在**统计与排架**：它保证「消渴」不会同时出现在两个一级类目里，于是分母稳定。词表的价值在**召回**：它让写法不同的同一概念落到一处。本体的价值在**推理**：它允许系统回答「这个证候属不属于那类病机」这类没有直接写在数据里的问题。三者不是替代关系，是一套栈：分类法给坐标，词表给名字，本体给规则。

教材第二章记了 120 个学科锚点、平台记了 103 条病证单元与 396 个不同症状——这些数字能成立，前提就是每个症状在被数之前先被归一。**没归一之前，「396」只是「396 种写法」**。

## 四、词表好不好，用一致性测

词表是软的，但它的产出可以硬测：让两名标引员独立标注同一批病历，算他们的一致率。一致率高，说明词目的定义够清楚、边界够窄；一致率低，问题不在标引员，在词目定义。

| 指标 | 适用 | 说明 |
|---|---|---|
| 简单一致率 | 两人、多类别 | 一致条数 ÷ 总条数；不分部类，容易虚高 |
| Cohen's κ | 两人 | 扣掉「碰巧一致」的那部分，κ 越高越可信 |
| Fleiss' κ | 三人以上 | 多人标注的推广形式 |

判断顺序很重要：先看简单一致率是否高到值得算 κ。如果两名标引员在「气阴两虚」与「阴虚燥热」之间摇摆，一致率可能只有六成——这时该回去改那两个词目的定义，而不是加人、加培训。**一致性低的第一诊断永远是词表粒度不对，不是标引员不认真。**

这条指标还有一层用处：它是词表迭代的唯一客观依据。每次改版都重测一遍，改对了 κ 上升，改错了 κ 下降。没有这条测法，「词表优化」就只是几个人的审美之争。

## 五、从词表到编码：一条记录的骨架

词表给了概念，编码给概念一个稳定书写形式，数据元给字段一个填法。三者串起来，才是一条能进库、能比对、能追溯的记录。以病证单元为例，示意结构如下：

```json
{
  "id": "DSU-00017",
  "disease": { "preferred": "消渴", "entry": ["糖尿病", "三消"],
               "concept": "TCM:DIS:0000123" },
  "syndrome": { "preferred": "气阴两虚证", "concept": "TCM:SYN:0000451" },
  "pattern": { "sixChannel": "阳明", "bagang": ["里", "热", "虚"] },
  "manifestations": ["多饮", "多食", "多尿", "消瘦"],
  "code": { "icd11": "待核", "gb": "待核", "version": "以标委会最新发布为准" },
  "evidence": "B"
}
```

这段 JSON 里有三处值得停一下：

- `concept` 与 `preferred` 分开。字面会变（教材改词、地区用词、繁体简体），概念号不变。检索永远打概念号，展示永远用首选词。
- `code` 里写着「待核」。这不是偷懒，是纪律：标准编号与版本必须回标委会核对，教材没给的就留空，不用推测的数字把表填满。
- `evidence` 是独立字段，不是写在正文里的形容词。证据等级一旦变成字段，它才能被排序、被过滤、被审计。

同一份内容有三种表示层次——**字符串**（原文）、**结构化**（症状列表与枚举）、**向量**（数值）。教材 3.7 把这三层的互转当作信息学的基本功。要注意顺序：三层不是并列选项，而是有依赖的。字符层错了，结构化必错；结构化错了，向量只是把错误压成一个更难看出来的数。

## 六、三根支柱落地成 S × A × M

把「三元」从公理翻译成工程，最省事的写法是三层：**S 标准、A 资产、M 算子**。三者各回答一个问题，缺哪一层，失败的样子都不一样：

| 层 | 回答 | 缺失后的典型症状 |
|---|---|---|
| S 标准 | 同一概念是否同一标识 | 两份数据放一起，先花两周对词，对完发现口径还是不同 |
| A 资产 | 数据放在哪、有多大、什么版本 | 每次分析都从零采集；同一个问题问三遍，得到三个分母 |
| M 算子 | 从这批数据里能算出什么 | 系统只能查、不能算；报告靠人一条条抄 |

这三层与本章前面的工具是一一对应的：词表与编码属于 S，病证单元与编码库属于 A，检索与挖掘属于 M。**顺序也不能倒**——S 没定就堆 A，堆出来的是不可比的资产；A 没有就上 M，算出来的结论没有分母。教材说三项缺一不可，讲的就是这个依赖关系，而不是三个并列的口号。

「方以类聚，物以群分。」——《周易·系辞上》。分类这件事，古人先于数据库两千年就在做；词表要解决的问题，本质上是「以类聚」时把界线划在哪。

## 七、代价与边界

- **词表维护是无底洞，而且必须有人付账。** 词目每加一条，就要同时定定义、定上位、定入口词、定范畴。一个中等规模的中医词表，年维护成本远超建表成本。凡是宣称「词表建好了」的项目，多半是没在维护。
- **粒度是取舍，不是正解。** 「消渴」与「上消／中消／下消」都合规，选哪个取决于你要回答的问题。想统计病种就取粗，想研究证治就取细；想两头都要，就得准备两套编码加一条映射，别指望一张表全包。
- **词表不代辨证。** 词表能保证「同一个词指同一件事」，不能保证「这件事判得对」。标引一致性可以量化，辨证正确性不能靠词表兜底。
- **本章引用的标准编号与年份，一律以标委会最新发布为准。** 教材本身对不确定项就标「待核」，本章沿用这条规矩，不臆造编号。

**免责声明：** 本章讨论信息组织方法，不构成诊断、辨证或治疗建议。任何词表与编码的落地，须经所在机构与标准主管部门审定。
