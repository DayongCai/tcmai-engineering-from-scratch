# 第 4 章 · 挖掘：lift = 103 的规则，多半是语料太小的幻觉

> **MOTTO:** 「数据挖出的规则只是假设，需经中医专家复核才能成为知识。」——教材·第 4 章 4.12
>
> **PROBLEM:** 在 103 条病证单元上跑一遍关联规则，得到 45 条。其中一条的 lift 是 103。这个数字读起来像「关联强度 103 倍」，实际算术是 1 ÷ (1/103)：某个症状在全库只出现一次，于是 confidence 必然等于 1，lift 必然等于样本数。**不设 support 阈值就谈 lift，等于把「稀有」误读成「强」。**

**双根因定位:** 环境逼迫（论文与项目都要「发现规律」，规则条数最好看，阈值一降条数就上去了）+ 知识积累（本章 31 个单元 1,714 汉字里，挖掘算法只占十来节，检索与排序占前面一大段——教材把「能不能找到」放在「能不能发现」之前，这个顺序本身是判据）

## 一、四级台阶：先有召回，才谈发现

教材把信息学的能力排成台阶：检索 → 结构化 → 挖掘 → 智能。每一级有自己的判据，跳级就会做出「看起来高级但站不住」的东西。

| 级 | 任务 | 判据 | 典型失败 |
|---|---|---|---|
| 检索 | 找到相关记录 | 召回率、排序质量 | 同义词漏检，用户以为库里没有 |
| 结构化 | 让文本可计算 | 字段稳定、值域封闭 | 一个字段塞三件事，统计全废 |
| 挖掘 | 提出可检验的关系 | support 阈值、专家复核 | 虚假高提升度，规则一大堆没人用 |
| 智能 | 给出可追溯的建议 | 出处、证据等级、边界 | 答得流畅，查不到依据 |

这四级里最容易被跳过的是第二级。大量「中医数据挖掘」实际上是在非结构化文本上做词频统计，得出的「高频药物」既没有排除同药异名，也没有排除同一处方内的重复计数。**没有结构化，挖掘只是在数排版。**

## 二、检索三件套：TF-IDF、字符 n-gram、融合排序

检索回答「哪些记录与查询相关」。评价用准确率 P、召回率 R、F1，排序质量另用 MRR 或 NDCG。中医检索的固有难点是同义异形：「失眠」与「不寐」、「消渴」与「糖尿病」必须能互相命中，否则召回率会凭空虚低。

三件套的分工是这样的：

1. **TF-IDF**：一个词在当前文档出现越多越重要（TF），在全库越普遍越不重要（IDF）。它自动压低「疾病」「证候」「患者」这类高频词的权重——这一步不需要人工维护停用词表，是它的实用之处。
2. **字符 n-gram**：中文无空格，且中医术语边界灵活（「少阳病」「半表半里证」），词典分词容易切错。字符 bigram 无需词典、对未登录词稳健，是中医短文本检索最务实的起步方案。
3. **BM25 与向量召回**：倒排索引给字面命中（BM25 自带长度归一与词频饱和），向量召回给语义相近。两者互补：前者查「不寐」命中「不寐」，后者查「睡不着」也能命中「不寐」。

融合时不必调权重，用**倒数排序融合**（RRF）即可：

```python
def rrf(rankings, k=60):
    score = {}
    for lst in rankings:                 # 每个 lst 是一路召回的 id 排好序
        for rank, doc in enumerate(lst, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=score.get, reverse=True)
```

`k` 取 60 是常用默认值，作用是压平头部差异，让「两路都排前十」的文档胜过「一路排第一、另一路没有」。RRF 的好处是不需要把 BM25 的分数和余弦相似度拉到同一量纲——而那件事通常做不好。

检索之后还有个容易忽略的环节：**上下文工程**。把 Top-K 塞给大模型时，不能整库喂。教材记的平台实测是 Top-5 约 1.5K token，相对全库约 31K 下降约 95%。这不是省钱问题，是信噪比问题：上下文越长，模型越容易抓到不相关的段落并据此编造。

## 三、关联规则：三个量，一个陷阱

关联规则写作 A → B，由三个量刻画：

- **support**：A 与 B 同时出现的比例，衡量「这条规则有多少证据」。
- **confidence**：出现 A 的记录里 B 也出现的比例，衡量「规则有多准」。
- **lift**：confidence ÷ support(B)，衡量「比随机强多少」。

Apriori 利用「频繁项集的子集必频繁」逐层剪枝，先找频繁 1 项集，再拼 2 项集，逐层过滤。教材建议先掌握两两共现，再理解剪枝——因为中医语料上真正能用起来的，绝大多数就是两两关系。

现在回到开头那个 103。设某症状 A 在全库 103 条记录中只出现 1 次，它所在的记录里同时有证候 B，而 B 也只出现 1 次：

```text
support(A→B)    = 1/103 ≈ 0.0097
confidence(A→B) = 1/1   = 1.0
support(B)      = 1/103 ≈ 0.0097
lift            = 1.0 / 0.0097 ≈ 103
```

三个量全部「正确」，结论完全无意义：一条只出现过一次的症状，当然 100% 伴随某个证候，也当然比随机「强 103 倍」。这是**小语料的算术必然**，不是发现。任何「只出现一次」的 A 都会得到 confidence = 1 与 lift = N。

所以正确的顺序只有一条：**先设 support 阈值过滤低频项，再谈 lift**。把最小支持度从 1 提到 2、3，观察规则条数与 lift 分布如何变化——这个实验比背公式有用得多，因为它让人亲眼看到「规则条数」是阈值造出来的，不是知识量。

过了阈值这一关，规则仍然只是**假设**。教材 4.12 那句「需经中医专家复核才能成为知识」不是客套：数据能告诉你「证候 A 常与方剂 B 同现」，不能告诉你「所以该用 B」——同现可能来自抄方习惯、科室偏好、甚至录入模板的默认值。复核要问的正是这三件事。

## 四、聚类与降维：稀疏集合要换相似度

聚类把相似样本自动归组，无需标签。中医信息学的典型任务是证候归并、方剂分组、患者分型。

难点在相似度。症状是集合，直觉上用 Jaccard（交并比）。但中医短文本极稀疏：103 条病证单元共 396 个不同症状，单个单元通常只有 2–5 个症状，于是任意两条记录的并集都很大，Jaccard 天然偏低，阈值稍高就谁也聚不上。

这时该换**重叠系数**：|A∩B| ÷ min(|A|,|B|)。它只问「较小的那个集合被覆盖了多少」，不被并集规模惩罚。教材记的平台结果正是在换用重叠系数之后才稳定出来的——`气阴两虚证（消渴）` 与 `阴虚燥热证` 归为同族，这在临床上说得通：两者都属消渴的阴虚为本、燥热为标一线。

算法选择上有两条实用差别：层次聚类不需预设簇数，单链法把「相似度 ≥ 阈值」的样本连成图，连通分量即簇，适合探索「到底有几族」；K-means 需预设 K，用肘部法或轮廓系数选，适合数值特征、要求簇形较规整。稀疏集合先向量化再 K-means，往往会得到一堆大小极不均的簇。

降维的经典用法是**因子分析提取证候要素**：从十几个症状里提炼出「气虚」「血瘀」这类潜在因子。这一步在方法上很诱人，但要记住它是量化试探，不是辨证结论——因子载荷高只说明这些症状常一起出现，不说明它们共属一个病机。

还有两类结构常被漏掉。第一类是**序列**：关联规则不管先后，序列模式管。六经传变天生是一条序列（太阳 → 阳明 → 少阳 → 太阴 → 少阴 → 厥阴），但真实病历里的顺序会被就诊间隔打断——患者可能隔了三个月才复诊，中间转院一次。所以做序列挖掘前必须先定义「事件」与「时间窗」：什么算一次传变、超过多久算重新起病。这两个定义不定，挖出来的「序列」反映的是就诊频率，不是病机演变。

第二类是**网络**。把方剂与药物建成二部图，投影到药物侧就得到一张共现网络；用度中心性找「核心药对」，用介数找「桥梁药」，用模块度找「药组」。网络与聚类是互补的：聚类回答「哪些药常一起出现」，网络回答「哪味药把两组连起来」。中医方剂里的「君臣佐使」在网络上有可观察的痕迹——君药往往度高、臣药往往与君药强连边、佐使药往往是跨模块的桥——但这只是统计形态上的对应，不能反过来当作判定君臣的依据。

还有一条纪律贯穿全节：**算法给候选，人给意义**。聚类结果是探索性的，它提示「这些证可能同族」，命名与确认仍须专家。把簇号直接当证名写进教材，是这类研究最常见的越界。

## 五、从数据到知识：KDD、图谱与大模型的位置

知识发现是一条流水线：数据 → 清洗 → 集成 → 选择 → 变换 → 挖掘 → 评估 → 知识。教材反复强调前六步占八成工作量，算法只占两成。这句话在中医语料上尤其成立，因为清洗阶段要处理的不是缺失值，而是异名同药、证候粒度不一、方剂加减不改名这类语义问题。

知识图谱用「实体—关系—实体」表达知识。病证单元是节点（病侧与证侧锚在同一个节点上），边是有类型的：证候体现（manifests_as）、西医病（disease_is）、编码映射（icd11_map）、学科归属（hierarchy）。**边的类型比边的数量重要**——一张只有「相关」一种边的图，做不了推理，只能做展示。

大模型在这条链上的位置要说清楚：它解决自然语言的入口与出口，**不能取代编码、检索与挖掘**。原因很直接——它需要结构化知识作为锚点，否则在中医术语上极易生成看似合理、实则不存在的方证对应。信息学给大模型提供的正是那两样它自己没有的东西：可信的外部知识，与可追溯的出处。

## 六、代价与边界

- 本章的 103 条单元、396 个症状、45 条规则、lift = 103，都是**教材所载平台语料上的实测**，换个语料这些数会变；它们说明的是方法陷阱，不是疗效结论。
- 关联规则揭示的是**共现**，不是因果，更不是疗效。共现可能来自处方习惯、科室偏好、录入模板。
- 聚类与降维的结果是探索性候选，不能直接当作证候命名或诊断依据。
- 检索指标（P/R/F1）依赖人工标注的相关性判断，标注口径不同，指标不可横向比较。

**免责声明：** 本章讨论信息挖掘方法，不构成诊断、辨证、用药或疗效评价建议；任何由数据得出的规律须经专家复核与临床验证。
