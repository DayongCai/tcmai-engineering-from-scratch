# 第 6 章 · 检索的失败不在召回率，在找回来的那条没有出处

> **MOTTO:** 「博学而详说之，将以反说约也。」——《孟子·离娄下》
>
> **PROBLEM:** 底本第 6 章有 28 个单元（全课单元数最多），却只有 1,668 汉字（全课第四少，约为最长章 13,259 的八分之一），而且这 28 个单元里有一半讲的是聚类、KDD 流程与学科展望，真正讲检索的只有六节。可检索是本课所有下游任务的地基：实体抽取要用它做候选，问答要用它做证据，评测要用它做出处。地基这么薄，只能靠判据补。本章要回答的真问题是：一个中医检索系统，凭什么让人相信它排在第一的那条？

**双根因定位:** 环境逼迫（中医检索的查询词与文档词经常对不上：异体字、别名、简称、古今异名，任何单一匹配方式都只能覆盖一部分） + 知识积累（检索的评价指标衡量「相关性」，而医案场景真正需要的是「可核性」——相关性高但引不出原文的结果，在临床上等于零）

## 一、三种检索，三种失效方式

检索的五十年历史可以压成三种范式，各自的失效方式完全不同：

| 范式 | 机制 | 强在哪 | 死在哪 |
|---|---|---|---|
| 布尔检索 | 词项与、或、非 | 精确、可解释、可审计 | 一个同义词没覆盖就全漏；「鞕」搜不到「硬」 |
| 词项加权（TF-IDF/BM25） | 词频 × 逆文档频率 | 排序合理，无需训练 | 罕见字 idf 极高，把生僻句顶到第一；语义近但不共词的全漏 |
| 向量检索 | 稠密向量近邻 | 语义泛化，跨表述可匹配 | 不可解释；古汉语语料上向量空间稀疏，近邻常是同文体而非同主题 |

布尔检索在中医场景里被低估了。它的死穴是同义词，但同义词问题可以用**归一化 + 别名扩展**在索引层解决——第 2 章那套映射表正是为此准备的。归一之后，布尔检索的精确性反而是优点：医生输入「桂枝汤 汗出」，他想要的就是同时含这两个词条的条文，不是语义相近的段落。

BM25 的死穴是 idf。古籍语料的文档单位通常是「条」，一条几十字，字表小，于是生僻字的 idf 会高到荒谬：一句含「瞀」或「瘛疭」的条文，仅因为字生僻就被顶到前面，而它对查询的相关性可能为零。缓解办法是把 idf 做上限截断，或改用字 bigram 的频次而非单字。

向量检索的死穴是不可解释，这一点在医疗场景里是硬伤。它能把「恶寒」与「畏寒」匹配上（这是优点），但它说不出为什么，也无法保证不把「不恶寒」匹配成「恶寒」。在没有否定处理的向量空间里，这两句的余弦相似度往往很高。

## 二、索引单位：字、bigram 还是词

中文检索的第一个决定是切什么。三种选择：

- **字**：零分词依赖，召回高，精度低。「汗」会命中所有含汗的句子。
- **字 bigram**：兼顾顺序与召回，是中文检索的稳妥默认。「汗出」与「出汗」不再混淆。
- **词**：精度最高，但完全依赖分词与词表——第 2 章说过，中医分词没有稳定解。

古汉语的特性让这个选择偏向 bigram：单音节词占多数，双字组合往往就是一个术语（恶寒、发热、头项、脉浮），bigram 恰好落在术语边界上。现代病历则相反，多字词多、缩写多（「双肺呼吸音清」），词级索引更有优势。

所以一个可用的配置是**混合索引**：字 bigram 做召回底座，术语精确匹配做加权，词级索引留给病历。三条路各自召回一批，再融合。

混合索引有一个常被忽略的校准问题：三条路的召回长度不一样。字 bigram 的召回几乎总是满的（任何查询都能匹配到某个字），术语精确匹配的召回很短（常常只有几条），词级索引居中。不做长度归一就融合，字 bigram 会贡献大量候选，把精确匹配的结果淹掉。修法是给每路设一个召回上限，各取前若干条再融合；上限的作用不是省算力，是让每一路的话语权相当。

查询侧也要归一，方向与文档侧相反。用户输入「桂枝汤 汗出」，正确的做法是先用术语表把查询切成术语，用术语去匹配；未命中的片段才回落到字 bigram。这样精度由术语保证，召回由字符兜底。反过来——把查询切成单字去匹配——召回会涨，但精度不可控，因为「汗」会召回「汗出」「无汗」「自汗」「盗汗」，而这几条在临床上分属不同的证。

还有一个只在古籍上出现的问题：**同一条的不同版本会同时被召回**。宋本与康平本的同一句字句略有出入，字 bigram 索引会把它们当成两条不同的文档，排序时并列出现。用户看到两条几乎一样的结果，会以为系统有两条独立证据。去重必须在索引层做（按归一后的文本哈希），而不是在展示层做。

## 三、多路融合：为什么用排名而不用分数

多路召回的合并有个陷阱：不同检索器的分数量纲不同。BM25 的分数无上界，余弦相似度在零到一之间，布尔的匹配数是个整数。直接加权求和，等于让 BM25 支配整个排序。

递归排名融合（RRF）绕开了这个问题——它只用排名，不用分数：

`score(d) = Σ_r 1 / (k + rank_r(d))`

```python
def rrf(rankings, k=60):
    """rankings: 多个检索器各自返回的文档 id 有序列表"""
    score = {}
    for lst in rankings:
        for i, doc in enumerate(lst, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + i)
    return sorted(score.items(), key=lambda kv: -kv[1])
```

`k` 的作用是压低头部差异：k 越大，前几名的分差越小，融合越依赖「多个检索器都排前面」这件事，而不是某一家的第一名。取 60 是文献里的常用值，不是定理——它等价于说「排第一与排第二的差距，不该比『两家都排前十』更重要」。

RRF 的代价是丢掉了分数里的信息。如果 BM25 给第一条的分数是第二条的十倍，RRF 看不出来。在中医检索上这个代价通常可以接受，因为分数的绝对大小本来就不可比；但在需要阈值过滤（比如「相关度低于某值就不返回」）的场景里，RRF 之后就没有可用的阈值了，得另做一层校准。

## 四、排序之上：出处回链

这一节是本章的重点，也是最容易被工程实现忽略的一节。

一条检索结果，除了文本本身，必须携带四样东西：**书名、版本、篇名、条序**。缺一样，这条结果在医案场景里就不能用。

理由不是学术洁癖，是使用方式。医生看到「太阳病，头痛发热，汗出恶风，桂枝汤主之」，他的下一个动作不是采信，是核对——这条是不是原文、哪个版本、上下文有没有「若……者」的限定条件。如果系统只给一句文本，他就得自己去翻书，那么这个系统的价值只剩下「省了一次翻书」，而不是「提供了证据」。

更进一步，出处回链让检索系统变成了证据系统。有回链，一条结果可以被人复核、被引用、被追溯；没有回链，它只是一个字符串，与模型幻觉无法区分。这一点在第 10 章会再出现：**能抽不能断**的边界，本质上就是「有出处」与「没出处」的边界。

实践上有三个具体做法：

其一，切分单位选「条」而不是「段」。古籍的天然单位是条（《伤寒论》398 条这类编号），按条切，回链天然成立；按固定字数切，一条被切成两半，回链就断了。

其二，重复文本要合并而不是并列。同一段条文在不同注本、不同电子版里重复出现，若不去重，前十条全是同一句的不同版本，用户以为系统只有一条结果。去重的键应该是「归一后的文本 + 篇名」，保留版本列表。

其三，标注要跟着文本走。若某条在语料里被标了「条文性质：禁忌」，检索时必须把这条信息一并返回——因为禁忌条与主治条在临床上的用法完全相反。

## 五、把结果交给下游：预算与截断

检索的最后一步是「交出去」。如果下游是语言模型，上下文窗口就是预算，塞多了会挤掉指令，塞少了会缺证据。

三条经验，都可操作：

按条截断，不按字数截断。宁可少给三条完整的条，不给五条被腰斩的。半条条文在中医里可能意思全反（「……者，桂枝汤主之」被切掉前半句的脉症，方证对应就丢了依据）。

去重优先于扩充。同一段文本的多个版本占三个位置，等于把预算浪费了三分之二。

每条都带一句「为什么被召回」。可以是命中的查询词，可以是匹配的术语，可以是融合时的排名。这一句是给人和给模型共用的：人用它判断是否值得读，模型用它判断该不该引用。

最后一条纪律：**宁少勿滥**。检索系统最常见的失败不是漏召回，是塞进一堆似是而非的段落，让下游在噪声里挑。在中医场景里，一条错证据的代价高于三条缺证据——因为缺证据会让人去查，错证据不会。

预算分配上有一个可操作的默认：给每条结果的元数据（出处、条序、语气）留出固定比例，剩下的才给正文。看起来反直觉——正文才是用户要读的——但没有元数据，正文就无法被判断可信度。一份被截断但带着「伤寒论·宋本·第 13 条·主之」的结果，比一份完整但不知出处的段落有用得多。

检索系统还有一项常被忽略的产出：**它没找到什么**。若一次查询在某部书里零命中，这个「零」本身是信息——可能说明该术语在这部书里用了别的写法。把零命中的查询记下来，按月汇总，就是一份现成的别名发现清单。这比任何自动的新词发现方法都直接，因为它是真实需求的投影。
