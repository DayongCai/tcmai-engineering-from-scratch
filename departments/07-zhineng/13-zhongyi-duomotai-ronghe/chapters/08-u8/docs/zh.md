## 三、逐单元读

### 8.113 单一事实源与生成器模式

知识树的可信度来自**单一构建点**。全树由 `scripts/build_knowledge_tree.py` 一次生成，任何人不得手工编辑生成物。这带来三个好处：一致性可证（索引与技能同源，不可能漂移）、规模可扩展（学科从 120 增到 200 只需重跑）、可自动校验（CI 能判定生成物是否已提交）。

*单元规模：87 汉字；出处 `教材·原第8章·8.1`；本单元数值类命中 0。*

### 8.114 多源异构数据的容错解析

知识树的输入跨越四类异构源：学科目录 JSON、领域规范 Markdown、病证单元 JSON、技能目录 JSON。其中领域规范最难，因为它同时存在编号列表、表格、`<br>` 拼接单元格与代码围栏四种排版。构建器采用**多策略抽取 + 章节归属追踪**：

*单元规模：80 汉字；出处 `教材·原第8章·8.2`；本单元数值类命中 0。*

### 8.115 知识树的 Schema 设计与校验

`schema.json` 用 JSON Schema（draft-07）固化节点与边的结构：节点必须有 `id/level/level_index/name/kind`，边的 `type` 限定在 14 种枚举值内。任何越界在构建阶段即被拦截。

*单元规模：38 汉字；出处 `教材·原第8章·8.3`；本单元数值类命中 0。*

### 8.116 构建的自检与质量门禁

自检脚本把「结构完整性、树导航、图邻接、检索、API 路由」五类断言固化：

*单元规模：26 汉字；出处 `教材·原第8章·8.4`；本单元数值类命中 0。*

### 8.117 与 Embedding 引擎的双向绑定

知识树给**结构**，Embedding 引擎给**语义**，二者双向绑定：树的叶文本喂入向量库，语义检索的命中回挂到叶上。 平台引擎（`scripts/tcm_embed.py` + `/diag`、`/bianzheng`、`/semantic-search`、`/rag`）技术栈为 **TF-IDF 字符 n-gram + SQLite FTS5 + RRF 融合**，内网零 token： **上下文工程（context engineering）** 则是把树图检索的结果精确装配进 LLM 上下文：只送 Top-5 叶（约 1.5K token），而非全库（31K/次），token 下降约 95%。装配规则由知识树的路径决定——先取 `path(叶)` 给出学科坐标，再取 `neighbors(叶)` 给出关系证据，最后按证据等级排序，形成「结构化、有出处、可复核」的提示上下文。 > 实测（2026-10）：`/semantic-search?q=失眠` → DSU-00035，证「心脾两虚证」，方「归脾汤」，ICD-11「MC81」，融合分 0.1601（向量 0.160 + FTS 0）。

*单元规模：165 汉字；出处 `教材·原第8章·8.5`；本单元数值类命中 1。*

### 8.118 教材编排与目录对齐

120 门学科的教材目录必须挂在同一棵树上才有可比性。用 `path(叶)` 反查任一知识点所属的域—学科—章节，即可自动检验教材目录是否缺章、错位。

*单元规模：55 汉字；出处 `教材·原第9章·9.1`；本单元数值类命中 0。*

### 8.119 教育资源技能路由

教育技能声明其学科即可自动挂树（`skill_bind`）。于是「某学科可用哪些技能」「哪些学科尚无技能覆盖」一查即得，为技能补齐提供清单。

*单元规模：49 汉字；出处 `教材·原第9章·9.2`；本单元数值类命中 0。*

### 8.120 以病索证／以证溯病的检索

知识树与 Embedding 引擎协作，支持双向检索：以症状索病（`/diag`）、以症状辨证（`/bianzheng`）、以语义检索（`/semantic-search`）、以检索结果生成 RAG 报告（`/rag`）。

*单元规模：38 汉字；出处 `教材·原第9章·9.3`；本单元数值类命中 0。*

### 8.121 六者 Agent 的知识边界加载

六者（医·患·药·械·规·法）各自只应看到其职责内的知识。知识树用 `path(节点)` 与 `subtree(域)` 精确裁剪上下文：医者加载 D01 临床 + D07 智能；药者加载 D02 中药 + 方证边；规者加载 D08 管理 + 质控叶。同一棵树，按角色投影出不同的知识边界。

*单元规模：79 汉字；出处 `教材·原第9章·9.4`；本单元数值类命中 0。*

### 8.122 医圣成长路径的可量化考核

医圣成长以「掌握病证数」为门槛（住院医-1 约 500 → 学科带头人约 60,000）。知识树把 DSU 叶按域—学科聚合，使「已掌握多少病证」「还差哪些学科」可直接计数，成长路径从主观描述变为可量化考核。

*单元规模：69 汉字；出处 `教材·原第9章·9.5`；本单元数值类命中 0。*

### 8.123 知识树可视化与终端呈现

### 8.124 实验一：运行构建器生成知识树

**目标**：理解单一构建点，产出可校验的知识树。 **操作步骤**： 1. 观察构建日志：源文件、域/学科计数、章节叶数； 2. 打开 `kg/tree/tcm-knowledge-tree.json`，确认 `meta / stats / nodes / edges` 四段； 3. 记录 `stats.levels` 与 `stats.edge_types`。 **结果与分析**：预期 3063 节点 / 3370 边 / 章节覆盖 120/120。若某学科无章节叶，构建器以**告警**（非中断）提示，需回源修正排版。

*单元规模：89 汉字；出处 `教材·原第10章·10.1`；本单元数值类命中 0。*

### 8.125 实验二：用查询引擎做树导航与图邻接

**目标**：掌握树的路径算法与图的邻接查询。 **操作步骤**：对 `DSU-00001` 记录它的祖先链与全部邻居边类型；对 `W-木` 验证相生边「出→火、入←水」自洽。

*单元规模：50 汉字；出处 `教材·原第10章·10.2`；本单元数值类命中 0。*

### 8.126 实验三：基于知识树的中医问答／辨证辅助

**目标**：把「树定位 + 图证据 + 语义检索」装配为一次可解释的问答。 **操作步骤**： 1. 用 `/semantic-search` 由症状召回 Top-K 病证单元； 2. 对每个命中，取 `path` 给出学科坐标，取 `neighbors` 取证据（ICD-11、证候、六经、主方）； 3. 按证据等级排序，装配为 LLM 上下文（context engineering），生成带出处的回答； 4. 断言：每条结论都能回答「依据是什么」。 **结果与分析**：实测「失眠」→ DSU-00035 心脾两虚证 归脾汤（ICD-11 MC81）。核对平台不可达时的降级行为（标注「未能核实」）。
