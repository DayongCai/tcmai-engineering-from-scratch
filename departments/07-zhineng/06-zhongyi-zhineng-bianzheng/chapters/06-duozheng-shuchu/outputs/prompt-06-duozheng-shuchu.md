# 证候不是一道单选题，但系统必须给出一个答案 · 提示词

## 用途

给「证候不是一道单选题，但系统必须给出一个答案」这一章备课或自学时用的提示词。它不生成结论，只把本章的判据、规模和边界摆出来，
让使用者自己走一遍「四种「多」，不是一回事 → 从单标签到多标签：三个具体决定 → 相容与排斥：把证候关系写成约束 → 输出结构：主证、兼证、证据、不确定」这条链。

## 提示词

```
我在学《中医智能辨证系统》第 6 章「证候不是一道单选题，但系统必须给出一个答案」，本章 6 节 / 2,892 汉字，习题 6 道。
正文见本章 `docs/zh.md`，关键数字由 `node code/main.js` 从正文现算。

请按以下顺序带我走：
1. 先用一句话说清本章要回答的问题，以及它为什么不能直接套用上一章；
2. 按正文小节顺序，逐节给出该节的判据，并指出这一节最容易被误判的那一处；
3. 本章的判据包括（请逐条解释它在什么条件下成立、什么条件下失效）：
   - 是先病一经、未罢又传一经，有先后
   - 字段里没有主从与时序，模型再准也写不出来
   - 决定一：softmax 还是 sigmoid
   - 决定二：阈值不能统一
   - 决定三：基数约束
   - 系统认为第二像的是什么、为什么不是
4. 本章自陈的边界（不得越过）：
   - **多输出让医生更累。** 一次给五个候选、每个带三条证据，在门诊节奏里没人看。界面必须做减法：默认只显示主证与一个兼证，其余折叠。
   - **约束会掩盖模型错误。** 靠相容约束把不合理的组合「修」成合理，指标会变好，模型本身的缺陷被藏起来。约束的贡献要单独做消融，不能混在总分里。
   - **主从判断本身有分歧。** 两位医生对「谁是主证」意见不同很常见，这属于判断差异，不是标注错误。评估时要允许主从互换，或单独统计主从一致率。

要求：不编造正文没有的数字；引文写到《书名·篇名》级；不确定的地方直接说「正文未展开」。
```

## 边界

本章讨论多证并存时的输出设计，不构成诊断或治疗建议。证候关系约束与主从规则须经所在机构中医专家审定；具体操作以现行规范与所在机构制度为准。
