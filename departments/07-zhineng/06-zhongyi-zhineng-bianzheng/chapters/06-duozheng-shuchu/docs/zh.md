# 第 6 章 · 证候不是一道单选题，但系统必须给出一个答案

> **MOTTO:** 「太阳与阳明合病者，必自下利，葛根汤主之。」——《伤寒论·辨太阳病脉证并治中》
>
> **PROBLEM:** 「脾虚湿困、肝郁化火」同时成立，在临床上并不罕见。可系统被要求输出「最可能的证型」。argmax 一取，兼证就消失了；而立法处方恰恰要兼顾兼证。换成每个证型独立判一遍，同一个病人又会得到七条「成立」，其中四条互相排斥——系统从「太肯定」直接跳到「什么都肯定」，中间没有地方停。

**双根因定位:** 环境逼迫（处方要一个主证、病历要一个主诉、统计要一个分母）+ 知识积累（证候之间存在合病、并病、兼夹、转化四种不同关系，而输出结构里只有一个位置）

## 一、四种「多」，不是一回事

把它们压成一个「多标签集合」，是设计上最常见的偷懒。

**合病**是两经或两脏同时受邪，起病即并见。《伤寒论》说「太阳与阳明合病」，太阳与阳明同时为病，没有先后。**并病**是先病一经、未罢又传一经，有先后。**兼夹**是主证之外夹有次要证候，主从分明，如「脾虚湿困、肝郁化火」中以脾虚湿困为主、肝郁化火为兼。**转化**是同一病人在时间上的证候变迁，寒化热、实转虚。

| 关系 | 时间结构 | 主从 | 输出应长什么样 |
|---|---|---|---|
| 合病 | 同时起病 | 并列或略有偏重 | 两个并列证 + 共同证据 |
| 并病 | 先后相接 | 原证为主 | 主证 + 传变标记 + 时序 |
| 兼夹 | 同时存在 | 主从分明 | 主证 + 兼证（带权重） |
| 转化 | 跨时间 | 前后相承 | 时间序列，不是集合 |

一个多标签集合只能表达「同时存在」，表达不了「先后来」和「谁为主」。这就是为什么输出的字段设计比模型的输出层更重要：**字段里没有主从与时序，模型再准也写不出来。**

这四种关系还决定了评估的口径。合病与并病的区别在时序，若病历里没有起病时间，评估时只能按「同时存在」打分，系统被判对也可能是碰巧；兼夹的主从若没有记录，评估就只能算「集合是否命中」，掩盖了主次颠倒的错误。换句话说，评估的粒度受制于记录的粒度，这一点在第 7 章的评估设计里会再次出现。

## 二、从单标签到多标签：三个具体决定

**决定一：softmax 还是 sigmoid。** softmax 强制所有证型概率和为 1，等于宣布证型互斥。临床上证型不互斥，合病与兼夹都是常态。用 softmax 训练，模型会被迫在「脾虚湿困」与「肝郁」之间分配概率，学到的不是「两者都有」，而是「哪一个更像」。改用每个证型独立的 sigmoid，互斥性就交给显式约束去管，而不是塞进输出层。

**决定二：阈值不能统一。** 0.5 是个习惯，不是判据。阈值应由三件事决定：该证型的基础率、漏判与误判的相对代价（第 8 章会展开）、以及该证型在治疗方案里的可替代性。一个「有了就要处理」的证型，阈值应低；一个「误判会误导立法」的证型，阈值应高。

**决定三：基数约束。** 临床上一次辨证通常是一主零到二兼，很少同时立五个证。输出层不加约束，模型会在证据模糊时把所有相关证型都点亮。约束可以是硬的（最多三个），也可以是软的（超过三个时降权并提示证据不足）。硬约束简单，但会掩盖模型的混乱；软约束更诚实，但需要界面配合。

| 决定 | 常见做法 | 问题 | 建议 |
|---|---|---|---|
| 输出层 | softmax | 强制互斥 | 独立 sigmoid |
| 阈值 | 统一 0.5 | 与代价脱节 | 按证型分别设 |
| 基数 | 不限制 | 全部点亮 | 主从 + 数量约束 |
| 未定 | 不设 | 强行给答案 | 显式「证据不足」 |

## 三、相容与排斥：把证候关系写成约束

证型之间有已知的相容与排斥关系，这些关系不该由模型从数据里猜。

**排斥**：同一病位上的寒与热、虚与实，方向上相反。注意「相反」不等于「不能并存」——寒热错杂、虚实夹杂都是常见证候。真正的硬排斥很少，多数是「并存时需要特别说明」的软排斥。把软排斥写成硬约束，会把复杂的真实病例判成不成立。

**相容**：脾虚与湿困高度共现，近乎蕴含；肝郁与气滞几乎是同义。这类关系可以用来做后处理：若「脾虚」成立而「湿困」分数略低，可以提示「是否考虑湿困」，但不能自动加上。

实现上，约束满足或马尔可夫随机场都能表达。一元势是模型给每个证型的分数，二元势是证型对之间的相容或排斥强度，最终取整体势最大的组合。这样做的好处是：约束显式、可审、可单独关掉做对照。

风险也在二元势上。如果二元势从病历里学，学到的很可能是**记录习惯**——某位医生爱写「脾虚湿困」这个组合，数据里它就高度相容，模型于是永远一起输出。约束要么由专家定，要么从数据学但必须与专家判断比对，不能直接采信。

约束的强度还要能分级，否则系统会在两种错误之间摇摆。硬约束（同义合并）改的是标签体系，一旦定下不该频繁变；软约束（加减分）影响排序，可以随证据调整；有向约束（并病的传变方向）只在时序证据存在时启用。三级混在一个权重里，出了错就分不清是标签错了、排序错了，还是时序读错了。

| 约束类型 | 例子 | 强度 | 来源 |
|---|---|---|---|
| 同义 | 肝郁 / 肝气郁结 | 硬（合并） | 词表 |
| 蕴含 | 湿困 → 脾虚（多） | 软 | 专家 |
| 相容 | 脾虚 + 湿困 | 软（加分） | 专家 + 数据 |
| 排斥 | 实热 vs 虚寒（同病位） | 软（减分） | 专家 |
| 时序 | 太阳 → 阳明（并病） | 有向 | 条文 |

## 四、输出结构：主证、兼证、证据、不确定

一个能进病历的输出，至少要有四块。

**主证**：一个，且必须带选择理由。理由不是「分数最高」，而是哪些主症成立、哪些鉴别点排除了相邻证型。

**兼证**：零到数个，各自带权重或置信，并标明它与主证的关系（兼夹、合病、并病）。

**证据**：支持项与反对项都要列。只列支持项的输出是宣传，不是解释。

**不确定**：证据不足、约束冲突、超出适用范围，三种情况要能分别表达，而不是统统压成低分。

```json
{
  "primary": { "name": "脾虚湿困", "score": 0.71,
               "support": ["纳差", "腹胀", "舌淡胖有齿痕", "苔白腻"],
               "against": ["脉不弱"] },
  "secondary": [ { "name": "肝郁化火", "score": 0.44, "relation": "兼夹" } ],
  "conflicts": ["肝郁化火与脾虚湿困在病性上部分相反，已按兼夹处理"],
  "status": "sufficient",
  "alt": [ { "name": "脾阳虚", "score": 0.38, "why_not": "畏寒不著，未见完谷不化" } ]
}
```

`alt` 这一块常被省略，但它对医生最有用：**系统认为第二像的是什么、为什么不是**。这一段直接对应临床上的鉴别诊断思维，也是人机分歧最常发生的地方——医生往往不同意主证，但同意第二诊断。

## 五、评估多标签，不能只看准确率

多标签的评估指标各自惩罚不同的错误，选错了会让模型朝错误方向优化。

**子集准确率**要求整个标签集合完全正确，过严；证型稍多时几乎恒为零，没有区分度。**汉明损失**逐标签算错，过松；把所有证型都判成立，损失也不高。**micro-F1** 受高频证型主导，**macro-F1** 给稀见证型同等权重，两者要一起看。**排序指标**（如平均精度）不依赖阈值，适合评估「候选里有没有正确答案」。

对临床最有意义的是把主证与兼证分开报：主证正确率、兼证召回率、主证正确时兼证是否漏。兼证召回率显著低于主证，通常说明模型在「求稳」——只敢报最有把握的那个，把兼夹丢掉。

评估集本身也要按主从构造。若评估集里绝大多数病例只有单一证型，多标签模型的主从能力根本没被考到；上线后遇到真实的多证病例，表现会断崖式下降。构造时应刻意保留一定比例的合病、兼夹、转化病例，并在报告里说明比例，否则读者会误以为模型在真实分布上也有同样的表现。

| 指标 | 惩罚什么 | 适合回答 | 盲点 |
|---|---|---|---|
| 子集准确率 | 任一标签错 | 完全匹配率 | 过严，区分度低 |
| 汉明损失 | 单标签错 | 总体错误密度 | 忽略标签重要性 |
| macro-F1 | 稀见证型错 | 各类均衡表现 | 被长尾拉低 |
| 平均精度 | 排序质量 | 候选是否含正解 | 不直接对应决策 |
| 主/兼分报 | 主从不分 | 临床可用性 | 需人工定主从 |

## 六、代价与边界

- **多输出让医生更累。** 一次给五个候选、每个带三条证据，在门诊节奏里没人看。界面必须做减法：默认只显示主证与一个兼证，其余折叠。
- **约束会掩盖模型错误。** 靠相容约束把不合理的组合「修」成合理，指标会变好，模型本身的缺陷被藏起来。约束的贡献要单独做消融，不能混在总分里。
- **主从判断本身有分歧。** 两位医生对「谁是主证」意见不同很常见，这属于判断差异，不是标注错误。评估时要允许主从互换，或单独统计主从一致率。
- **合病与并病的区分常缺证据。** 起病时间、传变过程在病历里经常没记，模型只能按同时存在处理。这是采集的缺口，不是模型的缺口。
- **多标签会反过来改变医生的判断方式。** 系统一次给三个候选，医生可能不再自己排主次，而是从候选里挑。这种「锚定」在单标签输出时也存在，多标签时更强。界面设计要留出「都不是」与「自己填」的出口，否则输出结构会塑造诊断结构。

**免责声明：** 本章讨论多证并存时的输出设计，不构成诊断或治疗建议。证候关系约束与主从规则须经所在机构中医专家审定。
