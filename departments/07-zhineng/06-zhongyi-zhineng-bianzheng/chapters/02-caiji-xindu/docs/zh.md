# 第 2 章 · 采集界面决定了证候能算到多细

> **MOTTO:** 「诊病不问其始，忧患饮食之失节，起居之过度，或伤于毒，不先言此，卒持寸口，何病能中。」——《素问·徵四失论》
>
> **PROBLEM:** 同一个病人，A 医生问了十二句、记下九条；B 医生问了三十句、记下二十一条。系统看到的不是同一个人，而是两条长度不同的向量。缺失位被填成 0 之后，「没问」变成了「没有」——「无汗」与「未问汗」在数据里长得一模一样。这个错误不写在任何日志里，却直接改写标签。

**双根因定位:** 环境逼迫（门诊时间、界面字段、录入习惯三重约束同时收紧）+ 知识积累（问诊是「十问」式的系统排查，阴性结果与阳性结果同为证据，而界面只为阳性结果留了位置）

## 一、问诊是排查，不是检索

自《景岳全书·传忠录》立「十问」之目，问诊就被当作一张排查清单：寒热、汗、头身、便、饮食、胸腹、耳目、渴、旧病、病因，逐项过一遍。清单的意义不在「问到什么」，而在「每一项都有结论」——包括结论是「无」。

这一点与关键词检索正相反。检索是病人说「我头晕」，系统去匹配「头晕」相关的证型；排查是无论病人说不说，都要确认「有无头痛、有无耳鸣、有无恶心」。前者只收集阳性，后者同时生产阴性。阴性在辨证里不是空缺：无水饮则苔不滑，无表证则脉不浮，很多判断靠的正是「不该有的没有」。

结构化界面如果只提供「勾选症状」的输入框，它在物理上就只能记录阳性。医生看到「无汗」，找不到「无汗」这个条目，只能不勾；于是这份病历在「汗」这一项上是空的，与「未问」无法区分。数据进了模型，空值被当成默认值处理，一个「无汗」的表实证病人就可能因为字段缺失而被判成「表虚自汗」。

判断一个采集界面是否合格，第一条就是：**它能不能记录阴性，并且把阴性记录与未记录区分开。**

## 二、四值字段：阳性、阴性、未问、不适用

最小的可用设计是四值而不是二值：`present`（有）、`absent`（无）、`not_asked`（未问）、`not_applicable`（不适用）。第四项用于逻辑上不存在的组合，例如男性病历中的经带项。

四值不是洁癖。缺失机制在这里有明确的方向性：`not_asked` 不是随机缺失，它与医生的经验、科室习惯、当次门诊剩余时间都相关。经验少的医生问得少，忙的时候问得更少——这是典型的非随机缺失，直接删除会系统性丢掉「不熟练者的病例」，填 0 则等于把「没问」判成「没有」，两种处理都会偏。

| 取值 | 含义 | 进入模型时的处置 |
|---|---|---|
| present | 已问，有 | 1，或按程度分级 |
| absent | 已问，无 | 0，作为阴性证据 |
| not_asked | 未问 | 缺失，须显式建模或整条排除 |
| not_applicable | 不适用 | 不参与计算 |

工程上还要加一个可审计字段：**谁问的、通过什么方式问的**（患者自述、医生追问、家属代述、入院记录转抄）。家属代述的「大便干」与患者自述的可信度不同，这个差别若不在字段里，后面所有的一致性分析都会把它算成噪声。

## 三、界面即量表：锚点、顺序、观察者

症状一旦要分级，界面就变成了量表，量表就要讲锚点。

「纳差」分轻中重，如果没有行为锚点，三位医生会给出三种切法。可用的锚点是具体到生活事件的：轻度指饭量减少但仍能完成日常活动；中度指明显减少、活动后乏力；重度指不欲食、进食即胀。锚点不必精确到克，但必须指向可观察的行为，而不是「有点」「比较」「非常」这种程度副词。

顺序与呈现方式同样在制造答案。先问「有没有口干」再问「想不想喝水」，与反过来问，得到的组合不同；把「畏寒」与「发热」并排放，会诱导病人二选一，而临床上「恶寒发热并见」才是表证的关键。界面的排列本身隐含了一套鉴别逻辑，这套逻辑要么与教材一致，要么就是在无意中训练医生按界面思考。

舌与脉还多一层观察者依赖。舌色受光线影响，照片与目视可以给出不同结论；脉象更是如此，同一个病人两位医生摸出「弦」与「滑」并不罕见。可行的做法不是追求绝对一致，而是把条件写进流程：自然光或标准光源、伸舌时间不超过一定时长、脉诊取坐位静息片刻、必要时双人分别记录。条件不受控时，不一致里混着测量误差，不能全算作判断分歧——这一点在第 7 章评估一致性时会再次遇到。

| 变量类型 | 例子 | 锚点要求 | 常见错误 |
|---|---|---|---|
| 二值 | 有汗 / 无汗 | 定义边界（汗出部位、时相） | 把「微汗」归入无汗 |
| 等级 | 纳差轻中重 | 行为锚点 | 只用程度副词 |
| 定类 | 舌色 | 参照色卡或标准照片 | 无参照，各人各色 |
| 文本 | 脉象描述 | 限定词表（位、数、形、势） | 自由填写，无法归并 |

还有一件常被忽略的事：采集的**时相**。同一次门诊里，问诊、舌诊、脉诊发生的顺序与间隔，会改变结果。刚喝完水看舌，苔会变润；刚爬完楼摸脉，脉会变数；刚被前一位病人的情况吓到，脉会变紧。结构化系统如果把四诊压成一个时间戳，就等于宣称这些差异不存在。可行的做法是给每类观察单独记时间与条件，至少区分诊前有无进食、饮水、运动、服药。这些字段看起来琐碎，但它们是舌脉能否被当作证据的前提。

## 四、信度：先测可靠，再谈有效

采集质量有两级：可靠（同一条件下重复测得到相近结果）与有效（测的确实是它声称要测的东西）。前者可以算，后者很难算，但前者是后者的前提。

**重测信度**：同一医生隔一段时间对同一病人重复采集，看两次结果是否一致。间隔太短会记忆，太长病情会变，通常取一个既能忘掉细节、又不至于病变的窗口。

**评定者间信度**：两位医生独立采集同一病人，看一致程度。二值条目用 Cohen's kappa，等级条目用加权 kappa 或 ICC，多个评定者用 Fleiss' kappa。这里要注意：kappa 在条目阳性率极低时会失真，一个很少出现的症状，两人都判「无」就能得到很高的一致率，而这种一致没有信息量。

**内部一致**：同一构念下的若干条目是否同向。二分条目用 KR-20，等级条目用 Cronbach's α。α 低不一定是条目差，也可能是构念本身多维——「畏寒」与「肢冷」在阳虚里同向，在气郁里未必。

| 指标 | 适用 | 读法 | 误用 |
|---|---|---|---|
| 重测 kappa | 二值、稳定性 | 一致性扣掉碰巧 | 间隔设置不当 |
| 加权 kappa | 有序等级 | 按偏离距离加权 | 权重随手定 |
| ICC | 连续或等级 | 方差分解 | 混淆一致与相关 |
| KR-20 / α | 条目内部 | 同向程度 | 当成单维性证明 |

判据只有一条，但很重要：**信度低的条目，先改界面与定义，不要先改模型**。一个「口干」条目两人一致率只有六成，说明这个条目的边界不清楚（是口燥、是渴、还是欲饮），把它丢进模型只会让模型学会绕开它，而问题仍然留在病历里。

条目筛选还有一步常被跳过：区分度。一个条目如果所有病人都是阴性，信度再高也没有信息；如果所有病人都阳性，它只是在描述人群，不是在区分病例。区分度可以用条目与证型标签的关联强度粗看，也可以在预试验里看它能否把相邻证型分开。信度与区分度都低的条目，应当从正式版里删掉，而不是靠模型权重把它压到接近零——留在界面上的每一条无用字段，都在消耗医生的时间。

## 五、把采集写成契约

采集不是一次性表单，是一份契约：字段、取值、来源、时间、缺失原因，都要能被下游读到。示意结构如下：

```json
{
  "patient_id": "CASE-0001",
  "encounter": "2026-11-20 上午门诊",
  "items": [
    { "code": "SYM.SWEAT", "state": "present", "grade": 2,
      "anchor": "静息时汗出湿衣", "source": "patient", "asked_by": "医师甲" },
    { "code": "SYM.THIRST", "state": "absent", "grade": 0,
      "anchor": "不觉口渴", "source": "patient", "asked_by": "医师甲" },
    { "code": "SYM.ABDOM_PAIN", "state": "not_asked", "source": null },
    { "code": "SYM.MENSTRUATION", "state": "not_applicable", "source": null }
  ],
  "tongue": { "light": "natural", "body": "pale", "coating": "thin_white" },
  "pulse": { "position": ["left", "right"], "quality": ["thin", "weak"], "readers": 2 }
}
```

这份契约里三处值得停一下。`state` 与 `grade` 分开，避免「有」与「重」混成一个数；`not_asked` 与 `absent` 各自独立，下游可以按缺失机制处理；`asked_by` 与 `readers` 让人知道这条证据是谁产生的，后面的分歧分析才有对象。

契约之外还要有质控，质控看的不是单条记录，而是分布。**未问率**按医生、按科室统计，异常高的要回看流程；**阳性率**异常同样可疑，某位医生对「畏寒」的阳性率达到九成，多半是提问方式带了引导；**字段完整率**突然上升，可能是界面改版后默认值被批量填入。这三种异常都不需要模型，只需要一张按人分组的汇总表。
本章可直接验证：`node code/main.js` 打印结构清点与判据清单（数字从 `docs/zh.md` 现算），`node --test code/main.test.js` 跑本章单测；两条命令只读正文与代码，不写任何文件。

## 六、代价与边界

- **采集越全，门诊越慢。** 完整十问加舌脉分级，在门诊节奏里很难逐项做完。可行的折中是分层：首诊全量、复诊增量，急症只取与危候相关的条目。折中方案要写进流程，否则会被默认为「都可以省」。
- **结构化会挤压自由叙述。** 医生最有价值的那句「说不清哪里不对，但整个人不对劲」，在勾选界面里没有位置。保留一个自由文本字段并让它可检索，比再加十个选项更有用。
- **信度不等于效度。** 两位医生一致地按同一套错误定义采集，信度可以很高而效度为零。信度只能排除测量噪声，不能证明条目测对了东西。
- **语音与文本回填的诱惑。** 用大模型从自由文本里抽症状，能显著降低录入负担，但抽取错误的分布与人工录入不同：它倾向于漏掉否定与不确定表述，而这恰恰是辨证最需要的部分。抽取结果必须保留原文片段与置信标记，不能直接落成 `present`。
