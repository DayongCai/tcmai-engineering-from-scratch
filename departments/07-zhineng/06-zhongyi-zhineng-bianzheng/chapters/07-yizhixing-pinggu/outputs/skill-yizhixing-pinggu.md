# kappa 高不代表系统对，只代表它像那位医生

## 什么时候用

需要把本章的判断讲清、或检验自己是否讲清时。

## 怎么用

1. 先读 `docs/zh.md` 的 MOTTO 与 PROBLEM 段，确认这一章要回答的问题是什么；
2. 跑 `node code/main.js`，看本章的结构清点与判据词频（数字全部从 `docs/zh.md` 现算）；

## 核心判据

- 系统的一致性不应显著高于医生间的上界

## 边界

- **一致性评估很贵。** 三位医师独立盲判同一批病历，人力成本远高于跑一次模型评估。这笔钱要花在「判据是否清楚」上，而不是花在把数字做漂亮上。
- **kappa 不是唯一答案。** 有序证候用加权 kappa，连续评分的用 ICC，多评定者用 Fleiss 或 AC1。指标要跟数据类型匹配，不能一套公式打天下。
- **报告必须完整。** p_o、κ、边际分布、样本量、评定者人数、盲法与否，缺一项就无法判断这个数字的含义。只写「一致率 82%」的报告，不该被采信。
- 本章讨论一致性评估的方法与局限，不构成诊断或治疗建议。涉及人的评估须经伦理审查，评估设计应由临床与统计人员共同确定。
