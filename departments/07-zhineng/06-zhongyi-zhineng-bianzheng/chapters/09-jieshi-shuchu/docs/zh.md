# 第 9 章 · 解释不是附赠的一段话，是可被反驳的证据链

> **MOTTO:** 「至数之机，迫迮以微，其来可见，其往可追。」——《素问·天元纪大论》
>
> **PROBLEM:** 系统输出「肝郁脾虚（0.78）」，下面附一句：「因情绪不畅、纳差、脉弦。」医生一眼就皱眉：情绪不畅是三个月前的病史，纳差是化疗后反应，脉弦是疼痛所致。三条证据来源不同、时间不同、指向不同，被并排放在一句「因为」里，读起来像理由，其实只是一张相关性清单。这种解释比不解释更危险，因为它看上去可以被核对。

**双根因定位:** 环境逼迫（医生要核、患者要懂、监管要审，三方都要一个「为什么」）+ 知识积累（解释的对象是「判据是否成立」，而不是「哪些特征权重大」；这两件事在工程上常被混成一件）

## 一、三种解释，不要混着给

「可解释」在日常讨论里是一个词，在工程上是三件事。

**判据解释**回答：这个证型的主症、次症、舌脉判据，在本案是否成立。它可以对，也可以错——主症其实没成立，系统说成立了，这是可核对的错误。

**归因解释**回答：哪些输入对模型分数贡献最大。它是模型内部量的分解，可以算得很精确，但没有对错——它只描述模型怎么算的，不描述医学上是否成立。

**反事实解释**回答：去掉哪一条证据，结论会翻。它可以被检验：真的去掉，结论是否真的变了。

| 类型 | 回答的问题 | 能否判对错 | 典型实现 |
|---|---|---|---|
| 判据 | 判据是否成立 | 能 | 规则回溯、条目核对 |
| 归因 | 哪些输入贡献大 | 不能 | 权重、SHAP、注意力 |
| 反事实 | 改动哪条会翻案 | 能（可实测） | 消融、最小改动搜索 |

临床上最有用的顺序是：先判据，再反事实，最后才是归因。归因数值好看，但它回答的不是医生的问题。医生问的是「凭什么是这个证」，不是「哪个特征权重大」。这两句话听起来接近，实际差得很远。

## 二、证据链的结构：来源、时间、强度、关系

一条证据要能进解释，至少要带五个字段。

**值**：症状、体征、舌脉的具体内容。**来源**：患者自述、医生观察、家属代述、检查报告、既往病历。**时间**：本次就诊、本次病程内、既往史。**可信度**：直接观察、转述、推断。**关系**：支持该证、反对该证、与鉴别证型相关。

缺任何一个，证据就无法被正确加权。第 3 章那个例子——情绪不畅是三个月前的，纳差是化疗后的，脉弦是疼痛所致——问题不在内容错，而在时间与来源没有进入结构，三条证据被当成了同一时刻、同一来源。

| 字段 | 缺失后果 | 例子 |
|---|---|---|
| 来源 | 转述被当观察 | 家属说「没精神」当成医生所见 |
| 时间 | 旧病史被当现状 | 三个月前的情志不遂 |
| 可信度 | 推断被当事实 | 「应该有口干」写成了口干 |
| 关系 | 只列支持项 | 解释变成单方面论证 |

最后一条尤其要紧：**只列支持项的解释是宣传，不是解释。** 一份合格的输出必须包含反对项——哪些证据与结论不符，系统如何处理。医生看到「脉不弱」被列为反对项，会更信任这个系统，而不是更少。

证据还该有强度分级。主症、特异性表现、一般兼症、软性描述，四类在解释里的分量不同。把它们并列成一张清单，读者无法判断哪条是决定性的。分级不需要复杂刻度，只要能让医生一眼看出「去掉这条，结论还成不成立」——这正好接上第四节的反事实。

```json
{
  "conclusion": "肝郁脾虚",
  "evidence": [
    { "item": "情志抑郁", "value": "近两周因家事烦躁", "source": "patient",
      "time": "current", "reliability": "direct", "relation": "support" },
    { "item": "纳差", "value": "进食量减半", "source": "patient",
      "time": "current", "reliability": "direct", "relation": "support" },
    { "item": "脉弦", "value": "左关弦", "source": "physician",
      "time": "current", "reliability": "direct", "relation": "support" },
    { "item": "脉力", "value": "不弱", "source": "physician",
      "time": "current", "reliability": "direct", "relation": "against" }
  ],
  "counterfactual": "若纳差为化疗所致而非脾失健运，则脾虚依据不足，应改为肝郁为主"
}
```

## 三、归因方法的失真

归因方法能给出漂亮的条形图，但它们各有稳定的失真方式。

**特征共线。** 「舌红」与「脉数」高度相关，模型可以只用一个，也可以两个都用一点。归因算法会在两者之间随机分配贡献，今天给舌红 0.3、脉数 0.1，换个随机种子可能反过来。医生看到「脉数几乎没贡献」，会以为脉数不重要，实际上它只是被舌红代表了。

**基线选择。** SHAP 类的值依赖基线（背景分布）。基线取全体病人、取同证型病人、取全零向量，得到的归因可以完全不同。报告归因时必须同时报告基线，否则数字无法复现。

**注意力不是解释。** 注意力权重高，只说明模型在这一步看了这个位置，不说明这个位置决定了输出。把注意力图当解释，是把机制当理由。

**事后拟合。** 用简单的代理模型去拟合黑箱的局部行为，拟合得好不代表忠实。代理模型解释的是代理，不是原模型。

还有全局与局部之分。全局解释描述模型整体偏重哪些特征，局部解释描述这一例为什么这样判。医生要的是后者，模型审查要的是前者。把全局归因印在每一份报告上，看似严谨，实际上对本案没有信息量；反过来，只看局部解释，永远发现不了模型整体的系统性偏差。

| 方法 | 输出 | 主要失真 | 适用 |
|---|---|---|---|
| 线性权重 | 每特征系数 | 共线时不稳定 | 线性模型 |
| SHAP | 每特征贡献 | 依赖基线、共线分摊 | 树模型、通用 |
| 注意力 | 权重分布 | 非因果、层间不一致 | 序列模型 |
| 代理模型 | 局部规则 | 只忠实于代理 | 教学演示 |

## 四、反事实：更接近医生的思维

医生鉴别时想的不是「哪个特征权重大」，而是「如果这条不成立，还成不成立」。

反事实解释就是把这句话做成可执行的操作：固定其他证据，逐条移除或改动一条，看结论是否翻转、翻转成什么。最有价值的是**最小充分证据集**——撑起这个结论所需的最小子集。如果三条证据就能撑起，另外五条就是冗余；如果去掉任何一条都翻案，说明结论非常脆弱，应当降级。

反事实有两个必须满足的约束。**可行性**：改动后的证据组合必须是临床上可能出现的，不能出现「舌淡白且舌红绛」这种逻辑不可能的状态。**最小性**：只改必要的，不要一次改五条——改五条得到的「解释」没人能读懂。

| 反事实类型 | 问法 | 用途 | 风险 |
|---|---|---|---|
| 移除 | 去掉 X 还成立吗 | 找关键证据 | 共线证据互相替代 |
| 替换 | X 换成 Y 呢 | 鉴别相邻证型 | 替换后组合不现实 |
| 最小集 | 最少要哪几条 | 评估结论稳健性 | 忽略证据权重差异 |

反事实的呈现要克制。一次给医生五条「如果…就会…」，没人读得完。更实用的做法是只给两条：一条最脆弱的（去掉就翻案），一条最稳固的（去掉也不变）。前者提示结论的风险点，后者提示可以简化的依据。这两条合起来，比一张完整的敏感性表更接近临床思路。

## 五、解释怎么评估

「看起来合理」不是标准。可用的评估有四个维度。

**忠实度。** 把归因最高的几条特征删掉或打乱，模型分数应显著下降。下降不明显，说明归因没有反映模型实际依赖的东西。

**稳定性。** 输入加微小扰动（例如症状程度从 2 改成 2.1），解释不应整体翻转。翻转频繁，说明解释是噪声的产物。

**可读性。** 医生能否在门诊的间隙复述出「系统为什么这么判」。做不到，解释再忠实也没用。可读性可以用复述测试来测，不需要复杂工具。

**一致性。** 解释指向的病机，是否被专家认可。这一条最容易被忽略：一个忠实、稳定、可读的解释，可能指向一个医学上荒谬的理由。

| 维度 | 测法 | 失败信号 |
|---|---|---|
| 忠实度 | 删除高归因特征 | 分数几乎不变 |
| 稳定性 | 输入微扰 | 解释翻转 |
| 可读性 | 医生复述 | 复述不出或复述错 |
| 一致性 | 专家评审 | 理由与医理不符 |

解释还有一层教学价值，也有一层教学风险。价值在于：学生能看到判据如何组合成结论，比背证型名更接近临床思维。风险在于：解释把判断过程说得太顺，学生可能学会「照着解释造句」而不是「独立辨证」。所以在教学场景里，解释应当与「反例」一起给——同样的解释，在什么情况下会得出错误结论。只给正例的解释，训练出来的是模仿，不是判断。

## 六、代价与边界

- **解释增加认知负担。** 每条结论配五条证据，医生会跳过。解释需要分层：默认一句判据摘要，展开才看证据链。
- **解释会助长过度信任。** 一段流畅的理由会让医生高估系统可靠性，这叫解释性幻觉。解释越像人话，越要提示它的来源是模型而非医理。
- **解释不能替代验证。** 能说清理由的系统仍然可能是错的，理由本身也可能是事后编的。解释是审计工具，不是正确性证明。
- **有些判断说不出理由。** 老医生的整体印象、舌象的微妙差异，很难拆成字段。系统对这些部分的解释只能是「依据不足」，诚实地说不知道，好过编一条理由。
- **解释的受众不同，层次就不同。** 给医生看的是判据与反事实，给患者看的是「哪几条表现支持这个判断」，给质控看的是版本、基线与证据来源。同一段文字不可能同时满足三者，硬要统一，通常是谁都不满意。

**免责声明：** 本章讨论可解释输出的设计方法，不构成诊断或治疗建议。解释字段与证据来源的规范须经所在机构中医专家与信息管理部门审定。
