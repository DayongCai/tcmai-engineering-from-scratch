## 三、逐单元读

### 6.69 基础知识

计算学习理论（computational learning theory）是机器学习与理论计算机科学的交叉领域，研究"通过计算进行学习"的理论基础，目的在于分析学习任务的困难本质、为学习算法提供理论保证，并根据分析结果指导算法设计与数据建设。本章围绕三个根本问题展开：为什么学习是可能的（可学习性）、什么时候学习是可能的（需要多少样例）、怎样学习才能可靠（泛化误差界与稳定性）。要讨论这些问题，必须先对学习问题进行形式化描述。 设输入空间 X 与标记空间 Y（本章以二分类问题为主，Y={0,1} 或 {-1,+1}）。样本 x∈X 由未知的数据分布 D 独立同分布地产生，其真实标记由目标概念 c 决定。训练集 D={(x₁,y₁),(x₂,y₂),…,(xₘ,yₘ)} 是从分布 D 上独立同分布采样得到的 m 个样例。学习算法 A 在假设空间 H 中搜索，输出假设 h——h 是从 X 到 Y 的映射。由于算法事先并不知道目标概念的所在，H 与概念类 C 通常不同；H 中任意一个候选 h 是否真是目标概念无法确定，因此统称为"假设"。假设空间的大小与结构决定了学习算法的能力上限，是本章各节复杂度分析的主角。 假设 f 为真实目标函数，即对任何样例 (x,y) 恒有 f(x)=y 的映射，则假设 h 的泛化误差（generalization error）定义为 h 在分布 D 上犯错的概率： E(h;D)=P_{x~D}(f(x)≠h(x))。 泛化误差刻画 h 在未见样本上的期望表现，但它依赖未知的分布 D，无法直接计算。实际可观测的是经验误差（empirical error），即 h 在训练集 D 上犯错的频率： Ê(h;D)=(1/m)·Σ_{i=1}^{m}⟦h(xᵢ)≠yᵢ⟧， 其中 ⟦·⟧ 为指示函数（事件为真取 1，否则取 0）。通常用 ε 表示预先设定的误差要求，亦称误差参数。若 h 在 D 上的经验误差为 0，则称 h 与 D 一致（consistent），否则称 h 与 D 不一致。

### 6.70 PAC 学习与样例复杂度

12.2 节给出 PAC 学习框架的严格定义。先引入两个集合：概念类与假设空间。令 c 表示"概念"（concept），即从样本空间 X 到标记空间 Y 的映射，它决定示例 x 的真实标记 y；若对任何样例 (x,y) 有 c(x)=y，则称 c 为目标概念。所有我们希望学得的目标概念构成的集合称为概念类（concept class），记为 C。学习算法 A 所考虑的所有可能概念的集合称为假设空间（hypothesis space），记为 H。算法事先不知道概念类的真实情况，H 与 C 通常不同，H 中的元素统称为假设（hypothesis）。 PAC 辨识与 PAC 可学习。对 0<ε,δ<1、所有 c∈C 与分布 D，若存在学习算法 A，其输出假设 h∈H 满足 P(E(h)≤ε) ≥ 1-δ，则称 A 能从假设空间 H 中 PAC 辨识（PAC Identify）概念类 C。进一步地，令 m 表示从分布 D 中独立同分布采样得到的样例数目，若对任意 0<ε,δ<1 与任意分布 D，存在学习算法 A 和多项式函数 poly(·,·,·,·)，使得对任何 m ≥ poly(1/ε, 1/δ, size(x), size(c))，A 都能从 H 中 PAC 辨识概念类 C，则称概念类 C 对假设空间 H 是 PAC 可学习的（PAC learnable），有时也简称概念类 C 是 PAC 可学习的。其中 size(x) 与 size(c) 分别表示样例与概念编码的规模。直观上，PAC 可学习意味着：只要样本量达到某个关于 1/ε、1/δ 的多项式，算法就能以至少 1-δ 的概率学得误差不超过 ε 的假设——ε 越小、δ 越小，对样本量的要求越高。 对计算机算法还须考虑运行时间。若 A 使概念类 C 是 PAC 可学习的，且 A 的运行时间也是 poly(1/ε,1/δ,size(x),size(c)) 的多项式，则称概念类 C 是高效 PAC 可学习（efficiently PAC learnable）的，称 A 为 C 的 PAC 学习算法。

### 6.71 有限假设空间

当假设空间 H 有限时，可分与不可分两种情形的样例复杂度与泛化误差界均可精确导出，这是学习理论中最干净的一类结果，也是理解后续无限假设空间分析的基础。 可分情形：此时目标概念 c∈H，存在与训练集一致的假设（经验误差为 0）。考虑任意一个"坏"假设 h（其泛化误差 E(h)>ε）。若 h 与 m 个训练样例全部一致，则每个样例上 h 都恰好没有犯错；对二分类与 0-1 损失，单个样例被 h 正确分类的概率为 1-E(h) < 1-ε，故 h 与全部 m 个独立样例一致的概率至多为 (1-ε)^m。训练集 D 上经验误差为 0 的假设可能有多个，其中任一个若是坏假设，都会导致算法输出坏假设。由并界不等式（union bound），所有坏假设中至少一个与 D 一致的概率不超过 |H|(1-ε)^m。利用 (1-ε) ≤ e^{-ε} 放缩得 |H|(1-ε)^m ≤ |H|e^{-εm}。令该概率不超过 δ，即 |H|e^{-εm} ≤ δ，解得 m ≥ (1/ε)(ln|H|+ln(1/δ))。于是得到定理 12.1：若 H 为有限假设空间，0<ε<1，δ∈(0,1)，则对任意 m ≥ (1/ε)(ln|H|+ln(1/δ))，学习算法 A 以至少 1-δ 的概率输出满足 E(h)≤ε 的假设。也就是说，有限假设空间恒为 PAC 可学的。数值演示：取 |H|=10³、ε=0.1、δ=0.05，则 m ≥ 10×(ln10³+ln20)=10×(6.908+3.000)≈99（演示数值），即约 100 个一致样例即可保证以 95% 概率学得误差不超过 10% 的假设；若要求 ε=0.01，样本量需增至 m ≥ 100×(6.908+3.000)≈991，可见误差要求每严格一个数量级，样本量近似按反比增长。 不可分情形：现实任务中 c 往往不在 H 内，H 中任何假设都会在训练集上出现或多或少的错误，追求一致假设不再可行，转而采用经验误差最小化（ERM，Empirical Risk Minimization），即选择经验误差最小的假设。

*单元规模：1,070 汉字；出处 `教材·第12章·12.3`；本单元数值类命中 2。*

### 6.72 VC 维

现实学习任务面临的通常是无限假设空间，例如实数域上所有区间构成的假设类、R^d 空间中的所有线性超平面——假设个数无穷多，|H| 无从谈起，12.3 节的界不再适用。为度量无限假设空间的复杂度，需要引入 VC 维（Vapnik-Chervonenkis dimension，Vapnik 与 Chervonenkis 1971 年提出）。先介绍三个概念：增长函数、对分与打散。 给定包含 m 个样本的样本集 D，假设空间 H 中不同假设对 D 中示例赋予标记的结果可能相同也可能不同；尽管 H 可能包含无穷多个假设，其对 D 中 m 个示例赋予标记的可能结果数却是有限的——对二分类，最多 2^m 种。H 对 D 中示例赋予标记的每种可能结果称为 D 的一种"对分"（dichotomy）。增长函数（growth function）定义为 H 在所有大小为 m 的样本集上最多能产生的对分数： Π_H(m)=max_{|D|=m} |{h(x): h∈H}|。 显然恒有 0 ≤ Π_H(m) ≤ 2^m。增长函数描述了假设空间的表示能力：Π_H(m) 越大，H 能区分的样本模式越多、复杂度越高，对学习任务的适应能力也越强。若 H 能实现 D 上全部 2^m 种对分，即 |{h(x): h∈H}|=2^m，则称样本集 D 能被假设空间 H 打散（shatter）。 VC 维定义为 H 能打散的最大样本集大小： VC(H)=max{m: Π_H(m)=2^m}。 VC(H)=d 意味着存在大小为 d 的样本集能被 H 打散，但并不意味着所有大小为 d 的样本集都能被 H 打散。细心的读者会发现，VC 维的定义与数据分布 D 无关——在分布未知时仍可计算假设空间的 VC 维。计算 H 的 VC 维的常用判据：若存在大小为 d 的样本集能被 H 打散，且不存在任何大小为 d+1 的样本集能被 H 打散，则 VC(H)=d。 经典例题（原书实例）：二维平面上所有直线构成的假设空间，其 VC 维为 3。

### 6.73 Rademacher 复杂度

12.4 节指出，基于 VC 维的泛化误差界是分布无关、数据独立的，对任何数据分布都成立，因而具有普适性；但也正因如此，这类界通常比较"松"——它对所有分布一视同仁，未利用数据自身的信息，对那些与学习问题典型情况相差甚远的"坏"分布尤其保守。Rademacher 复杂度（Rademacher complexity）是另一种刻画假设空间复杂度的途径，与 VC 维不同的是，它在一定程度上考虑了数据分布，因而通常给出更紧的界。 定义：给定样本集 Z={z₁,…,zₘ}，其中 zᵢ=(xᵢ,yᵢ)，σ=(σ₁,…,σₘ) 为 Rademacher 随机变量向量，即每个 σᵢ 独立地以 1/2 概率取 +1、以 1/2 概率取 -1。假设空间 H 的经验 Rademacher 复杂度（empirical Rademacher complexity）定义为 R̂_H(Z)=E_σ[sup_{h∈H} (1/m)·Σ_{i=1}^{m} σᵢ·l(h(zᵢ))]， 其中 l 为损失函数；其关于数据分布的期望 R_H=E_Z[R̂_H(Z)] 称为 H 的 Rademacher 复杂度。直观理解：把 σᵢ 看作对第 i 个样本标记的随机扰动（掷硬币翻转），(1/m)·Σσᵢ·l(h(zᵢ)) 度量假设 h 与随机噪声的相关程度，sup 取 H 中与噪声相关性最强的假设，再对 σ 求期望。因此 Rademacher 复杂度衡量假设空间"拟合随机噪声"的能力：若 H 能很好地拟合随机翻转的标签，说明其表达能力过强、过拟合风险高，R̂_H(Z) 大；反之则 H 较稳健。例如：只含常数函数的假设空间，其 Rademacher 复杂度为 0（任何随机噪声都无法被"拟合"）；而包含全部标记函数的空间（可打散任意样本集），其复杂度可达 O(√(1/m)·1) 量级——两类空间的复杂度差异正好对应其泛化能力差异。

### 6.74 稳定性

无论是基于 VC 维还是基于 Rademacher 复杂度的泛化误差界，其结果均与具体学习算法无关，对所有学习算法都适用。这使人们能够脱离具体算法来研究学习问题本身的性质，但也无法回答"为什么某些算法（如正则化的逻辑回归、SVM）在实践中明显更可靠"。稳定性（stability）分析从算法本身出发，是这方面一个值得关注的方向。 直观上，算法的稳定性考察输入发生变化时输出是否随之发生较大变化：若训练集中一个样本被删除或替换，输出假设几乎不变，则称算法稳定。形式化地，给定样本集 Z={z₁,…,zₘ}，记 h_Z 为算法在 Z 上训练输出的假设，h_{Z\i} 为删除第 i 个样本后训练输出的假设。若对任意 Z、任意 i 与任意样本 z，均有 |l(h_Z, z) − l(h_{Z\i}, z)| ≤ β， 则称算法满足 β-均匀稳定性（uniform stability），β 越小越稳定。若把上述绝对差换成对 Z 与 i 的期望，则得到较弱的留一稳定性（leave-one-out stability）；若只要求对删除样本 zᵢ 本身成立，则得到假设稳定性（hypothesis stability）。均匀稳定性最强，蕴含其余两者；删除示例的稳定性还蕴含替换示例的稳定性。本章以均匀稳定性为主线。 稳定性与泛化直接关联。直观论证：若算法稳定，删除任一训练样本几乎不改变输出假设，那么对第 i 个样本的"留一预测" l(h_{Z\i}, zᵢ) 与真实输出假设在该样本上的损失 l(h_Z, zᵢ) 只差 β；而留一误差（leave-one-out error，对每个样本用删去它的模型预测所得的平均损失）是泛化误差的无偏估计，故稳定算法的留一误差与泛化误差接近。据此可导出（原书定理 12.8）：对 β-均匀稳定且损失有界的学习算法，以至少 1-δ 的概率有 E(h) ≤ Ê(h) + β + O(√(ln(1/δ)/m))， 即泛化误差被"经验误差 + 稳定性项 β + 样本项"共同控制。

### 6.75 本章小结

本章介绍了计算学习理论的核心内容，回答三个根本问题。可学习性：有限假设空间恒为 PAC 可学的（定理 12.1、12.2）；无限假设空间由 VC 维判定——VC 维有限即可 PAC 学，VC 维无穷则不可学。样例复杂度：样本需求随假设空间复杂度（ln|H| 或 VC 维 d）近似线性增长，随精度要求（1/ε 或 1/ε²）增长——"数据越多越好"由此成为可计算的预算公式。泛化误差界：有限假设空间（定理 12.2）、无限假设空间（定理 12.4）与 Rademacher 复杂度（定理 12.5、12.6）导出的界具有统一形式 泛化误差 = 经验误差 + 复杂度项， 复杂度项由 |H|、VC 维或 Rademacher 复杂度度量，随 m 增大而减小——这是偏差-方差权衡的理论基础，也是"为什么模型复杂度必须匹配数据量"的严格数学表述。稳定性：稳定算法的泛化误差有界（定理 12.8），ERM 且稳定则假设空间可学习（定理 12.9）；正则化通过提升稳定性改善泛化，从算法角度补充了前几节的复杂度分析。 理论对实践的三大指导：① 用正则化控制模型复杂度，压低复杂度项；② 增加样本量以同时压低复杂度项并支撑更大的假设空间；③ 模型复杂度必须与数据量匹配——数据少而模型复杂必然过拟合，数据多而模型过简则欠拟合。关键概念链：PAC 可学习 → 样例复杂度 → 泛化误差界（经验误差+复杂度项）→ VC 维/增长函数/Rademacher 复杂度 → 稳定性。后续章节中，半监督学习、集成学习等方法都可视为在"数据不足"约束下降低复杂度项或提升稳定性的工程策略：本章回答"为什么需要更多数据、为什么规则要精简"，为实践中的模型选择、数据建设与超参数设定提供了统一的数学视角。把各节结论并列对照，可以更清楚地看到学习理论的内在结构。

### 6.76 tcmP 平台映射

计算学习理论为 tcmP 平台建设提供量化方法论。平台的核心问题可抽象为：以 Hermes 多 Profile 为"学习算法"，以病证单元库（BZU）医案与教材正文为"训练数据"，以 ICD-11 术语库与知识图谱为"标记空间"，各 Profile 学得的"假设"是其辨证规则（SKILL.md 决策链）。本章理论给出四组映射：① PAC 样例复杂度 → 医案采集量 KPI：辨证模型要学得"近似正确"的证型判别，必须保证每个证型的医案样本量达到样例复杂度界，否则"可学习性"没有保证；② VC 维 → SKILL.md 复杂度审计：各 Profile 的 SKILL.md 行为规则条数即"假设空间复杂度"，规则膨胀 = VC 维过高 = 在有限医案上过拟合特定教材；③ 稳定性 → 多 Profile 一致性评测：同一病历多次辨证结论应一致（低方差），结论漂移即不稳定，是不良泛化的先兆；④ 泛化误差界 → 审稿标准：审稿目标 = 在教材准确（低经验误差）与规则精简（低复杂度项）之间取平衡，二者共同决定教材的"泛化误差"。核心结论：平台质量问题大多不是"算法不够好"，而是"数据不够多、规则不够简"——扩充医案库（压低复杂度项）与精简 SKILL.md 规则（降 VC 维）是改善平台泛化能力的两个根本抓手，且二者互补：数据充足时规则可以更丰富，数据不足时必须规则从简。

*单元规模：378 汉字；出处 `教材·第12章·12.8`；本单元数值类命中 0。*

### 6.77 平台配置接口-安装依赖

本章为理论章节，平台侧依赖极少：一致性评测与复杂度审计脚本仅需 Python 标准库 + numpy。安装命令：pip install numpy（如需绘制"复杂度-样本量"曲线或审稿图表，可加装 matplotlib）。平台配置接口三件套：① kpi_estimator.py 样例量估算器——输入假设空间规模 |H|、误差上限 ε、置信参数 δ，输出 m ≥ (1/ε)(ln|H|+ln(1/δ)) 的样本量预算，作为医案采集 KPI 的制定工具；② audit_skill_complexity.py SKILL.md 复杂度审计——扫描 .hermes/skills/ 下各 Profile 的 SKILL.md，统计规则条数、决策分支深度、if-then 链数量，输出复杂度报告（阈值：单卡规则 >30 条或决策深度 >5 层告警；阈值口径为统计来源，送 tcmreviewer 审稿）；③ consistency_eval.py 多 Profile 一致性评测——对测试病历集运行多轮辨证，输出结论一致率与证型分布方差（阈值：一致率 <90% 触发 SKILL.md 修订）。三个脚本均以命令行或 cron 调度运行，无服务端口依赖，输出 JSON 报告供 0改写说明/质量周报引用；如需通过 BFF 8080/API 8642 对外提供，仅在网关层包一层只读接口即可，不改变脚本本身的纯函数设计。

*单元规模：277 汉字；出处 `教材·第12章·12.9`；本单元数值类命中 2。*

### 6.78 PAC 样例量估算=医案采集 KPI

把样例复杂度公式落地为医案采集 KPI：m ≥ (1/ε)(ln|H|+ln(1/δ))。以病证单元库（BZU）为例估算：证型假设空间 |H|≈10⁴（病 B1-B20 × 证 Z01-Z17 的组合及常见兼证），取 ε=0.1（允许 10% 误判率）、δ=0.05（95% 置信度），则 m ≥ 10×(ln10⁴+ln20) ≈ 10×(9.21+3.00) ≈ 122 例/证型（演示数值，统计来源，送 tcmreviewer 审稿）。据此制定平台数据建设目标：每证型医案 ≥150 例（含安全余量），按 10⁴ 证型折算全库约 150 万条级，作为采集与验收的量化标准。执行细则：① 新证型入库前先查样本量是否达标，未达标证型标记"低置信度"，送 tcmreviewer 审稿后方可上线；② 采集按证型分布加权而非均匀分配——公式给出的是最坏情形上界，实际按先验分布加权分配更经济；③ 对低发证型（样本难凑）优先采用规则精简（降 |H|）而非硬凑样本——12.3 节理论表明 m 与 ln|H| 成正比，压缩假设空间能直接降低样本门槛；④ 医案质量（标记一致性）直接影响 δ 的达成，入库前须经 ICD-11 术语矫正与人工复核。说明：估算为统计来源，送 tcmreviewer 审稿；真实临床仅辅助不决策。

*单元规模：290 汉字；出处 `教材·第12章·12.10`；本单元数值类命中 4。*

### 6.79 VC 维=SKILL.md 复杂度审计

把每个 Profile 的 SKILL.md 视为一个假设空间：规则条数、决策分支、if-then 链数量即其"VC 维"（表达能力）。tcmP 原则"行为规则写 SKILL.md、不写 .py"的另一种表述：规则集中、可审、可精简——SKILL.md 是唯一受控的复杂度载体，禁止在 Agent 代码中隐式埋入行为规则，否则复杂度不可见、不可审。审计机制：每月对 8 个角色卡（0映射1/2/3 等）及各 Profile 的 SKILL.md 运行 audit_skill_complexity.py，统计三项指标：① 规则条数（>30 条告警）；② 决策分支深度（>5 层告警）；③ 与教材章节锚点的一致性（规则应能追溯到第 12 章及相应章节的正文结论，孤儿规则告警）。复杂度超标 → 拆分为子技能或精简冗余规则（降 VC 维），防止 Agent 在陌生病案上过度拟合少数教材案例；审稿人卡定期执行审计，结果记入 0改写说明 版本日志。理论依据：VC 维越高所需样例越多——规则膨胀而医案不足，正是平台过拟合的根源；与 12.4 节"VC 维有限则可学、无穷则不可学"对应，规则失控的 Profile 在开放病案上必然泛化失败。阈值口径为统计来源，送 tcmreviewer 审稿。

*单元规模：304 汉字；出处 `教材·第12章·12.11`；本单元数值类命中 1。*

### 6.80 稳定性=多 Profile 一致性评测

辨证结论的稳定性 = 同一病历多次/多 Profile 推理结论一致（方差小），对应学习理论中的算法稳定性（12.6 节）。评测脚本 consistency_eval.py 执行三步：① 从病证单元库按证型分层抽样 100 份病历（覆盖高低频证型，避免抽样偏倚）；② 每份病历由同一 Profile 重复辨证 5 次，并由不同 Profile（辨证 Agent、author、tcmreviewer）各辨证 1 次——前者测"重测稳定性"（算法对输入扰动的敏感度），后者测"跨 Profile 一致性"（不同假设空间的结论分歧）；③ 计算结论一致率与证型分布方差，输出稳定性报告。一致率 <90% 的 Profile 判定为不稳定：触发 SKILL.md 修订——增加决策链约束（如"先定因再定性、BZU 编码必填、禁止跳过六定分析"），等价于机器学习中的正则化（限制假设空间、提升均匀稳定性）；修订后重测直至达标。稳定性评测结果作为平台质量周报指标，与审稿流程联动：不稳定即"过拟合个别病历"的信号，先于用户投诉暴露规则缺陷。阈值口径为统计来源，送 tcmreviewer 审稿；真实临床仅辅助不决策。

*单元规模：301 汉字；出处 `教材·第12章·12.12`；本单元数值类命中 3。*

### 6.81 泛化误差界=审稿标准的理论化

"泛化误差 = 经验误差 + 复杂度项"映射到 tcmP 审稿体系：tcmreviewer 的清单 = 经验误差信号（教材正文本身是否准确、术语是否与 ICD-11 一致）；审稿人提出的规则精简、口径收敛 = 复杂度项控制。审稿目标不是"内容越多越好"，也不是"规则越少越好"，而是在二者间取平衡：正文失准（经验误差大）与规则膨胀（复杂度项大）都会抬高"泛化误差"——即教材在真实教学与临床场景中的偏差。三审通过的教材 = 低经验误差 + 低复杂度项 = 可泛化的教材。该理论依据写入 0改写说明 审稿口径，作为审稿人卡（tcmreviewer/aireviewer）的决策框架：每条标注属于"经验误差类"（改正文）还是"复杂度项类"（删规则/收敛口径），审稿结论给出两类问题的处置比例，防止审稿走向单边化；hermes-generating-content 生成的统计性结论一律标注"统计来源，送 tcmreviewer 审稿"，真实临床仅辅助不决策（安全红线）。此外，12.6 节稳定性理论还给出审稿的量化抓手：审稿可抽查"删改一个规则后结论是否漂移"，漂移过大即不稳定，直接判定该规则过拟合，予以精简。

*单元规模：335 汉字；出处 `教材·第12章·12.13`；本单元数值类命中 0。*
