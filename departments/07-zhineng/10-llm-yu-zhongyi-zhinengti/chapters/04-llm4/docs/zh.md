# 第 4 章 · 模型说的每一句话，都是在一个概率分布上抽的一次签

> **MOTTO:** 「夫人之立言，因字而生句，积句而成章。」——《文心雕龙·章句》
>
> **PROBLEM:** 一句 60 字的中医问答，若每一步有 3 个看似都通顺的候选，那么整句可能的组合是 $3^{60}$，约 $4.2\times10^{28}$ 条。模型不是「选一条正确答案」，而是在这个天文数字里按概率抽一条。这解释了两件让临床很不习惯的事：同一个问题问两次，答案措辞不同；把温度从 0.7 调到 0.2，答案变得更规矩，但也更容易套错模板。演算设定：温度 0.2 时 top-1 概率可被推到 0.95 以上，模型几乎不再「换说法」；温度 1.0 时同一位置的分布被拉平，罕见但错误的表述被抽中的机会显著上升。**「稳定」与「正确」是两件事，调参只能换前者**。

**双根因定位:** 环境逼迫（临床要求可重复：同一个输入，昨天与今天的输出不该矛盾；而生成模型的输出本质上是采样，天然不可重复）+ 知识积累（教材把语言模型讲成「概率分布＋解码」，而工程上真正的分歧在解码策略：贪心、采样、受限解码各自对应不同的失败模式，选错了会在特定题型上系统性出错）

## 一、链式分解：一句话的概率怎么拆

语言模型只做一件事：给定前文，输出下一个词的概率分布。

$$P(w_1,\dots,w_T)=\prod_{t=1}^{T}P(w_t\mid w_1,\dots,w_{t-1})$$

整句的概率是每步条件概率的连乘。这个分解带来两个直接后果。

**其一，概率随长度指数衰减。** 每步 0.5 的概率，60 步之后是 $0.5^{60}\approx8.7\times10^{-19}$。所以「整句概率最高」与「每步都最合理」不是同一件事，前者在长句上没有实际意义——所有长句的概率都极小，比较它们等于比噪声。

**其二，错误会累积但不会自动纠正。** 前一步抽错一个词，后一步只能在这个错误前提下继续。模型没有回头机制，它的「自我修正」也是顺着已生成文本往下写，而不是真的重算。

这两点合起来解释了「看起来流畅但内容错」的现象：流畅由局部条件概率保证，内容正确要靠外部知识，两者不是同一个来源。**语言模型优化的是「下一个词像不像人写的」，不是「这句话对不对」**。

## 二、概率图：把「谁依赖谁」先画出来

序列生成的上一层，是概率图模型。它做的事不是生成文字，而是**把一个联合分布按依赖关系拆成小块**：

$$P(x_1,\dots,x_n)=\prod_{i}P(x_i\mid \mathrm{pa}(x_i))$$

$\mathrm{pa}(x_i)$ 是节点 $x_i$ 的父节点集合。图上没有边，就表示条件独立——这是概率图唯一的、也是最大的贡献：**它让「哪些变量之间可以互相提供信息」变成一张可检查的图，而不是一段口头约定**。

中医里天然适合画图的地方不少。症状与证候之间不是一对一，而是一个症状可支持多个证、一个证需要多个症状共同支持；舌象、脉象、问诊各自提供部分证据，且彼此有相关性（舌淡与脉弱常同现，不是独立证据）。用朴素贝叶斯（假设证据条件独立）处理这类问题，会把「舌淡」与「脉弱」当成两份独立支持，从而**高估证候的置信度**——这是中医数据上最常见的模型误用之一，而画一张图就能看出来：这两个节点之间应该有一条边。

序列上的经典形式是隐马尔可夫模型与条件随机场。前者适合「状态隐藏、观测可见」的序列标注（如给每个字打「症状／病名／方名」标签），后者放宽了观测独立的假设，对相邻标签的约束更强。二者在今天多被神经网络替代，但它们的图结构仍然值得学：**它告诉你哪些独立性假设是必要的，哪些是偷懒**。

## 三、解码策略：四条路，四种脾气

| 策略 | 规则 | 稳定性 | 多样性 | 典型失败 |
|---|---|---|---|---|
| 贪心 | 每步取概率最大 | 最高 | 无 | 反复套同一句式；陷入循环 |
| 束搜索 | 保留 k 条候选路径 | 高 | 低 | 输出偏「平均」，缺关键细节 |
| 温度采样 | 按 $p_i^{1/T}$ 重加权后抽 | 中 | 中 | 低温套话、高温编造 |
| top-p（核采样） | 只在累积概率达 p 的集合内抽 | 中 | 较高 | p 过大时引入长尾错误 |

温度的公式值得写出来，因为它是唯一一个能被临床方直接感知的参数：

$$p_i^{(T)}=\frac{p_i^{1/T}}{\sum_j p_j^{1/T}}$$

$T<1$ 时分布变尖（高分更高），$T>1$ 时变平（低分被抬起来）。$T\to0$ 时退化为贪心。

top-p 与温度常一起用：先按 top-p 砍掉长尾，再按温度在剩下的集合里抽。这个组合的实际意义是——**保证不抽到明显离谱的词，同时允许措辞有变化**。在中医问答里，这个组合比单独调温度更可靠，因为长尾里恰恰是那些冷僻而错误的搭配（错方名、错药名）。

还有一个常被忽略的点：**束搜索不适合开放式生成，但适合有标准答案的抽取**。若任务是「从这段病案里抽出所有的症状词」，束搜索的偏「平均」反而是优点；若任务是「解释这个方为什么用黄芪」，束搜索会生成一段四平八稳、什么都说一点但什么都不说透的文字。

## 四、温度在中医问答里的实际后果

演算设定，同一个问题「黄芪在补中益气汤里起什么作用」，在三个温度下：

| 温度 | 输出特征 | 风险 |
|---|---|---|
| 0.1 | 高度模板化，每次都提「补气升阳、升举清阳」 | 遇到变证时也照模板答，不区分 |
| 0.7 | 措辞有变化，能结合上下文提到「与升麻柴胡配伍」 | 偶尔混入不准确的配伍解释 |
| 1.2 | 表述发散，可能出现「黄芪入肺脾二经」以外的说法 | 编造引文、错配方剂 |

关键结论：**低温度不是更准确，是更一致**。一个在 0.1 温度下稳定输出错误内容的系统，比在 0.7 温度下偶尔出错的系统更危险——因为前者的错误看起来权威、可复现、难以被察觉。

所以工程上应当按任务类型分温度，而不是全局设一个值：

- 抽取与结构化（把病案转成字段）：低温度 + 受限解码。
- 解释与教学（讲清一个概念）：中等温度，允许措辞变化。
- 头脑风暴（列出可能的鉴别方向）：较高温度，但输出必须标注「候选，未验证」。

## 五、结构化输出：把自由生成关进笼子

临床系统里最有用的一类生成，不是散文，是**结构化的字段**。做法有三层，可靠性递增。

**第一层，提示里给模式。** 明确要求输出 JSON，并给出字段名、类型、取值范围：

```
请从下面的病案中抽取信息，只输出 JSON，不要任何解释文字。
字段：
  symptoms: string[]        // 原文出现的症状词，逐字摘录，不得改写
  tongue:   string | null   // 舌质与舌苔，原文没有则填 null
  pulse:    string | null
  evidence: string[]        // 每条结论对应的原文片段，用于核对
规则：
  1. 只能摘录原文，不得推断或补全。
  2. 无法确定的字段填 null，不要猜。
  3. 若原文含相互矛盾的描述，写入 conflicts 数组。
```

**第二层，受限解码。** 在解码时就把输出限制在合法词表内（如症状只能取术语表里的词）。这一层能把「格式对但内容编」的错误压到很低。

**第三层，输出后校验。** 用程序检查：字段齐全？`evidence` 里的每一段是否真的出现在原文里？`symptoms` 是否都在术语表内？校验不过就拒收，不要「尽力修正」。

三层里，第一层最容易做也最不可靠，第三层最枯燥但最有效。**只做第一层的系统，会在 5%–10% 的样本上返回格式正确、内容虚构的结果**——而这类错误最难被发现，因为它长得像正常输出。

还有一条纪律：**`null` 必须被允许**。若提示里暗示「每个字段都要填」，模型就会在信息缺失时编一个。让「不知道」成为一个合法输出，是降低幻觉最便宜的手段。

## 六、生成的确定性不是正确性

最后要把一件容易混淆的事说清楚。

把温度设为 0，输出就确定了吗？不完全。同一份输入在不同批次、不同硬件、不同批大小下，浮点累加顺序可能不同，落到概率接近的两个候选上就会翻转。因此**「温度 0」不等于「完全可复现」**，只是「大幅提高一致性」。

更根本的问题是：即使输出完全确定，也不代表正确。确定性只保证「同样的错每次都一样」。临床系统需要的不是确定性，是**可核对性**——每条结论后面能指到出处，每个字段能追到原文片段。这也是第四节里 `evidence` 字段存在的理由：它把「模型说的」变成「原文有的」。

工程上的落地建议：把「生成」与「判定」分开。生成负责措辞与组织，判定交给规则与检索。前者可以不确定，后者必须确定。把两者混在一个模型里，等于把可核对的部分也交给了采样。
