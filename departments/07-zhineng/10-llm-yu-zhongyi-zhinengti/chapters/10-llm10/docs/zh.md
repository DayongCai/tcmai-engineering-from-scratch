# 第 10 章 · 智能体不是一个更会说话的模型，是一个会被工具纠正的循环

> **MOTTO:** 「善诊者，察色按脉，先别阴阳。」——《素问·阴阳应象大论》
>
> **PROBLEM:** 演算设定：一个「病案整理」任务需要八步——读病案、抽症状、查术语表、匹配证候、检索条文、生成摘要、核对引用、输出 JSON。若每步单独成功率 0.95，八步串起来的成功率是 $0.95^8\approx0.66$。**三分之一的任务会在中途失败，而每一步看起来都很靠谱**。若把单步提到 0.98，整体是 0.85——仍然有一成半失败。这个乘法关系是智能体工程的第一课：**优化单步的价值是线性的，减少步数的价值是指数的**。

**双根因定位:** 环境逼迫（真实任务需要外部动作：查库、比对、算数、读文件；模型自己算不出来，也不能凭记忆代替查询）+ 知识积累（智能体的可靠性不来自更强的模型，来自「循环里有没有校验」——每步之后能不能发现错了、错了能不能退回去；没有校验的循环只是把一次错误放大成八次）

## 一、循环的形状

最小可用的智能体是一个四拍循环：

```
观察（读入任务与上一步结果）
  ↓
计划（决定下一步做什么，或结束）
  ↓
调用（执行一个工具，拿到结构化的返回）
  ↓
校验（检查返回是否可用；不可用则改计划或终止）
  ↺
```

四拍里，**校验那一拍最常被省掉**，而它恰恰是唯一能阻止错误传播的环节。省掉校验的循环，会在第三步把第二步的错误当成事实继续推理，最后输出一段逻辑自洽、依据全错的结论——这类输出比「答不上来」危险得多，因为它看不出破绽。

一个具体的校验清单，每步都该过：

| 检查项 | 通过条件 | 不通过时 |
|---|---|---|
| 返回非空 | 有内容且不是占位符 | 重试一次，仍空则终止 |
| 格式合法 | 可解析为约定的结构 | 不解析，直接终止（不要「猜」） |
| 关键字段在 | 必需字段齐全 | 补问或终止 |
| 与已知矛盾 | 不与前序结论冲突 | 记录冲突，交人工 |
| 引用可核 | 引文在库中存在 | 撤销该结论 |

第三行值得展开。「关键字段缺失」在中医任务里极常见：病案没写舌象、没写脉。此时正确的动作是**把缺失显式化**（「舌脉未记录」），而不是让模型从症状推一个「大概舌淡」。后者在语言上很顺，在事实上是编造。

## 二、工具设计：接口即约束

工具不是「给模型一个函数」，是**给模型一个只能表达合法动作的接口**。设计得好，模型想犯错都难；设计得差，模型有无数种方式给出你以为它不会给的参数。

| 设计原则 | 反例 | 正例 |
|---|---|---|
| 参数用枚举，不用自由文本 | `证候: "气虚"`（可写任意串） | `证候: 从术语表选，未命中则返回空` |
| 返回带状态码 | 只返回结果文本 | `{ok, data, reason, source}` |
| 单次返回有上限 | 返回全库 3,000 条 | 返回 Top-10，附「还有 N 条」 |
| 幂等 | 每次调用都新增记录 | 同参数重复调用结果一致 |
| 失败原因可读 | `error: 500` | `error: 未找到该证候，可能是别名，建议查术语表` |

最后一行是「工具教模型怎么用」的典型：错误信息本身就是提示。一个只会返回 500 的工具，模型唯一能做的就是重试同样的调用，直到步数耗尽。

还有一个常被忽略的约束：**工具不该返回自由散文**。若检索工具返回的是一段自然语言说明，模型无法判断哪部分是数据、哪部分是解释，最后会把解释当数据用。返回结构化字段（原文、出处、类型、置信），让模型自己组织语言，是更可靠的分工。

## 三、规划与七种失败模式

智能体的失败不是随机的，它集中在七个地方。识别这七种，比调提示词有效得多。

| 失败模式 | 表现 | 检测信号 | 对策 |
|---|---|---|---|
| 步数耗尽 | 一直重试同一动作 | 相邻两步动作相同 | 设最大步数，超限即降级输出 |
| 工具误用 | 用检索工具算数 | 参数类型不符 | 参数校验＋工具描述写清适用场景 |
| 目标漂移 | 中途开始回答别的问题 | 当前动作与初始目标无关 | 每步复述目标，做相关性检查 |
| 循环依赖 | A 等 B，B 等 A | 依赖图有环 | 静态检查任务图 |
| 过早收敛 | 第一步就下结论 | 无检索动作即输出 | 强制「先取依据再结论」 |
| 依据虚置 | 有检索但未引用 | 输出无引用编号 | 引用校验（缺引用即拒收） |
| 静默降级 | 工具失败但输出照旧 | 日志有错误、输出无提示 | 失败必须传播到输出 |

第七种最隐蔽。工具报错，模型不去处理，而是用「根据一般认识」把答案补完——输出看上去完整，实际上没有任何依据。**这类输出的危害大于直接报错**，因为它让使用者以为查过了。

第四种（循环依赖）可以在设计期消掉：把任务画成有向无环图，检查有没有环。这一步不需要模型参与，纯静态检查，成本极低。

第一、五种可以合并成一条纪律：**先依据、后结论**。把「必须先调用至少一个检索工具，且结论须引用其返回」写成硬约束，能消掉相当一部分幻觉。代价是简单问题也要多一次调用——这个代价通常值得付。

与失败模式配套的，是**降级输出**的设计。循环走不完全程时，不该返回空，也不该硬编一个答案，而应返回「已完成的部分＋缺失的部分＋为什么停」。例如：「已抽取症状 6 项、已检索证候 3 条；舌脉未在病案中记录，故未能给出证候倾向；建议补充四诊信息。」这类输出在临床端比一句「抱歉，我无法回答」有用得多，因为它把不确定性交代清楚了。

降级输出还有一层制度价值：它是**人工接管的接口**。医师看到「缺什么」，就知道该补什么；看到「依据哪三条」，就能直接核对。若系统只输出「失败」，接管者要从零开始，等于这次调用白做。

## 四、检索在循环里的位置

检索不是循环外的一次性预处理，它在三个位置各有不同作用：

**入口处（任务理解）**：把用户的口语化描述映射到术语。用户说「我最近老睡不好，心里烦」，要映射到「不寐」「心烦」这些可检索的词。这一步错了，后面全错。

**中途（证据获取）**：按当前子问题取片段。要点是**每个子问题单独检索**，而不是一次检索服务全部子问题——后者的结果会被平均，哪个子问题都不够。

**出口处（引用核对）**：把输出里的每条引用回库验证。这一步是纯程序，不需要模型。

三处的失败后果不同：入口错导致方向错（表现为答非所问），中途错导致依据偏（表现为引用相关但不足以支持结论），出口漏检导致编造（表现为引用不存在）。**三处都要做，但优先级是出口 > 入口 > 中途**——出口那一步最便宜，也最能兜住。

## 五、多轮与上下文：状态要外置

多轮对话里最容易出的事，是把「状态」放在对话历史里，靠模型自己记。历史一长（超过十几轮），早先的约束就被稀释：用户在第三轮说过「不要给用药建议」，到第十五轮模型又开始建议了。

可靠的做法是**状态外置**：把关键约束、已确认的事实、待办的子任务写进一个结构化的状态对象，每轮都重新注入，而不是指望模型从历史里回忆。

```
state = {
  约束: ["不给用药建议", "结论须标注不确定"],
  已确认: {主诉: "入睡困难", 病程: "3 月", 舌象: null, 脉象: null},
  待办: ["补充舌脉", "检索相关证候"],
  已引用: ["[1]", "[3]"]
}
```

这样做的代价是每轮多付一点 token；收益是行为可预测。**上下文管理的目标不是「记得多」，是「忘得对」**——把无关的历史摘要掉，把约束留在显眼处。

历史压缩也要有规矩：摘要必须保留否定性约束（「不要…」）、数字（剂量、时间）、以及未解决的冲突。删掉这三类，摘要就成了误导。实践中最稳的做法是：原文滚动窗口保留最近 4–6 轮，更早的压成「事实清单」而不是「对话摘要」——事实清单更短，也更不容易变形。

状态外置还有一个副作用需要计算：每轮注入的约束约 150–250 token，十轮下来累计多付两次完整问答的量。这笔开销值得，但不能无节制——约束条目要精简到真正影响行为的那些（通常不超过 5 条），把「一般风格要求」写进系统提示（每轮只付一次），把「本次会话特有的事实」放进状态对象。

## 代价与边界

- 本章所有数值（八步、$0.95^8\approx0.66$、$0.98^8\approx0.85$、Top-10、3,000 条、最近 4–6 轮）均为**演算设定**，用于说明成功率连乘与上下文预算的量级，不对应任何实测系统。
- 「七种失败模式」是工程归纳，不是穷举；实际系统还会遇到权限、并发、超时等与业务耦合的失败。
- 工具的接口设计示例不含任何具体框架、协议或产品；实现方式须结合系统架构与安全要求。
- 本章不提供任何可执行的临床动作，也不评价任何智能体框架；检索与工具的输出须经人工核对后方可用于临床。
