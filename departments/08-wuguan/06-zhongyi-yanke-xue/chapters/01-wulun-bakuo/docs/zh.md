# 第 1 章 · 五轮八廓学说与眼的脏腑配属：一张能查、也能被质疑的映射表

> **MOTTO:** 「五轮者，五脏之精华所发也。」——《银海精微·五轮八廓总论》
>
> **PROBLEM:** 病人白睛红、黑睛有翳、瞳神不清，你知道该「从肺、从肝、从肾」想，但说不清这三个判断的依据是同一套映射，也说不出这套映射在古代就有分歧。
>

## 学习目标

- 背下并写清五轮与五脏的对应（肉轮—脾、血轮—心、气轮—肺、风轮—肝、水轮—肾）及各轮解剖范围
- 把「局部体征 → 轮位 → 脏腑」做成三级查表，并在表里标注**版本与争议**
- 说清八廓与五轮的关系，以及为什么八廓的配属在历代文献里并不统一
- 指出「配属」与「辨证」不是一回事：映射给出思考方向，不给诊断结论

## 核心概念

### 中医：五轮是分区，八廓是另一套分区

《银海精微》把眼由外向内分为肉轮（胞睑）、血轮（两眦）、气轮（白睛）、风轮（黑睛）、水轮（瞳神），分别配属脾、心、肺、肝、肾。这是一套**空间分区 + 脏腑归约**的模型：看到哪一区的病变，就先想到它对应的脏。

八廓是另一套分区，历代配属不同（有以八卦方位配、有以脏腑配、有以部位配），《审视瑶函》与《银海精微》的写法就不完全一致。这一点必须讲清：**五轮相对稳定，八廓相对不稳定**。教材把八廓放在次要位置，是有理由的。

### AI/工程：把映射做成带版本的表

一张可用的映射表至少要有三列：**体征定位**（哪一区的什么表现）、**轮位**、**脏腑**；再加两列元数据：**出处**、**争议标记**。

工程上这意味着：不要把「白睛红 → 肺热」写成一条规则常量，而要写成一条带 `source` 与 `disputed` 字段的记录。否则三年后没人说得清这条规则从哪来，也没法在有新版本时只替换有争议的部分。

## BUILD IT：从零实现

```js
const WULUN = [
  { lun: '肉轮', area: '胞睑', zang: '脾', source: '《银海精微·五轮八廓总论》', disputed: false },
  { lun: '血轮', area: '两眦', zang: '心', source: '同上', disputed: false },
  { lun: '气轮', area: '白睛', zang: '肺', source: '同上', disputed: false },
  { lun: '风轮', area: '黑睛', zang: '肝', source: '同上', disputed: false },
  { lun: '水轮', area: '瞳神', zang: '肾', source: '同上', disputed: false },
];
function locate(sign) { /* 体征 → {轮, 脏, 出处} 或 null */ }
```

八廓单列为 `BAKUO`，并带 `disputed: true` —— 不是「不能用」，而是「用的时候必须说明版本」。

## 代价与边界

- **映射是分区启发，不是病理机制**。白睛属肺不等于白睛病变都由肺引起；把配属当成因果，是这套学说最常被误用的地方。
- **八廓的版本分歧无法在本表内消解**。标 `disputed` 只是承认分歧，不是解决分歧；涉及八廓时必须以具体文献版本为准。
- **一处体征可能落在两区交界**（如眦部与白睛交界），本表的单值返回会掩盖这种模糊，实际应返回多候选。
- **它不包含全身辨证**。五轮只管「眼局部落到哪一脏」，寒热虚实仍需四诊合参。

> **免责声明：** 本章的映射表用于教学与知识编码演练，不构成诊断依据；眼部急性视力下降、剧痛、外伤须立即转急诊眼科处理。

## 练习

1. 把 `locate` 改成返回候选数组（支持跨区体征），说明这对下游规则有什么影响。
2. 查两个不同版本的八廓配属，列出至少两处差异，并设计表结构容纳它们。
3. 若病人白睛红 + 瞳神不清同时出现，按本表应该输出什么？为什么不能简单取「更严重」的那个？

## 进阶思考

中医眼科的分区模型之所以能传下来，不是因为它精确，而是因为它**可教、可记、可指向**。把它编码成表时，最该保留的恰恰是「哪里有争议」——抹掉争议的表看起来更干净，却把最重要的学术信息删掉了。
