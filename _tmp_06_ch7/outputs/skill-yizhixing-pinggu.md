# yizhixing-pinggu

## 何时使用

- 辨证系统研发中，需要一份可复核的一致性报告
- 答辩/投稿前自查：一致率是否被过度解读
- 内部评审：判断「一致」是能力还是分布造成的

## 不适用

- 需要证明系统正确性的场景（必须有金标准与前瞻验证）
- 只有一致率、没有逐例对照表的结果（无法计算 kappa）
- 多中心、多医生、跨设备的一致性研究设计（需要专门的 ICC/kappa 方案）

## 步骤

1. **列矩阵**：行=系统，列=医生，类别顺序写死。
2. **算三指标**：po、kappa、PABAK；同时报边际分布。
3. **查医生间一致性**：没有就写「未测量」。
4. **写局限**：一致≠正确、无金标准、样本构成、医生判定可靠性。
5. **给表述**：只描述数字，不写「可用」。

## 输出模板

```text
【混淆矩阵】类别顺序：…；参与例数：…
【指标】po=… ；kappa=… ；PABAK=… ；医生间 kappa=…
【表述】与医生判定的原始一致率 …，kappa …（解释：…）
【不能证明】1) … 2) …
```

## 质量判据

- 类别顺序与矩阵同时出现
- 类别极不平衡时必有 kappa 失真提示
- 结论段没有「准确率/可用/达标」这类词

> 本技能输出为评估辅助，不构成系统有效性或临床可用性证据。
