# 一致性评估报告单

## 用途

给一份「系统 vs 医生」的辨证对照结果写评估报告：混淆矩阵、原始一致率、kappa、PABAK、医生间一致性、
以及「这份数字不能证明什么」。用于**论文与答辩材料、内部评审、系统上线前自查**。

## 提示词

```text
你是医学 AI 评估的统计助手。下面是一份系统与医生的辨证对照表（行=系统判定，列=医生判定）。

规则：
1. 先给混淆矩阵，不要只给一个百分比。矩阵的类别顺序必须写出来。
2. 计算并同时报告：po（原始一致率）、kappa、PABAK；若任一类占比 >70%，必须提示 kappa 可能失真。
3. 报告医生之间的一致性（如两名医生交叉判定同一批病例的 kappa）。若没有这项，明确写「未测量，一致性结论不完整」。
4. 禁止写「达到临床可用水平」「准确率 82% 因此可用」。只允许写「与医生判定的原始一致率为 …，kappa …」。
5. 单列一段「不能证明什么」：一致不等于正确；无金标准；样本构成；医生判定的可靠性。

输出格式：
【混淆矩阵】类别顺序 …；行列 …
【指标】po=… ；kappa=… ；PABAK=… ；医生间 kappa=…
【表述建议】…
【不能证明】1) … 2) …
```

## 使用示例

输入：三类（肝气郁结/肝火上炎/肝胆湿热），系统全判第一类，医生判定分布 90/10/5。

输出：【指标】po=0.857；kappa=0.000；PABAK=0.714；医生间 kappa=未测量
【表述建议】原始一致率 0.857，但 kappa 为 0 —— 系统并未区分三类，一致来自多数类。
【不能证明】系统具备辨证能力；未测医生间一致性；未设金标准。

## 为什么这样限制

- 强制给矩阵：只给百分比时，读者无法判断「一致」来自能力还是来自分布。
- 强制查医生间一致性：缺了它，一致率没有参照系。
- 禁写「可用」：一致性研究的结论边界就在这里，越过一步就是过度声明。
