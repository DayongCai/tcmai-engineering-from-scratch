## H.1 本章要解决的问题

针灸毕设里的「系统」多半是随访与数据采集工具。它替评价服务，不替演示服务：字段对不对得上 CRF、断网能不能记、导出能不能直接统计，比界面是否好看重要得多。系统出问题多半不是代码写错，而是字段定义和 CRF 打架——那类错误要到分析阶段才暴露，而毕设的时间不允许推倒重来，第一版只做四件事就够了。

## H.2 本章目标（可检验）

- 实现只含登记、随访提醒、量表录入与导出的最小工具
- 保证每个字段与 CRF 逐列对应，导出即可分析
- 为断网、设备故障、失访三种情形准备纸质兜底

## H.3 操作流程

1. 定用途：只做入组登记、随访提醒、量表录入、导出四件事；其余想法一律列入不做，写在文档首页
2. 定字段：以 CRF 为唯一来源，字段名、类型、取值范围逐列对应；多一列必须写理由，少一列不许上线
3. 选技术：优先两周内能跑通的方案（现成表单工具或轻量脚本），不为了技术栈牺牲招募进度
4. 建校验：必填项、数值范围（如 NRS 0 到 10）、日期逻辑（随访日期不早于入组）、重复编号拦截
5. 跑通一例：用真实病例从登记走到导出，记录每步耗时与卡点，卡点超过三处就砍功能而不是加时间，砍完再完整跑一遍
6. 核对：随机抽三条记录与纸质 CRF 逐字段比对，不一致先改字段定义再改程序，改完重抽五条，差异与修正写进附录
7. 定导出：一行一例或一行一次访视，列名用英文短名并附对照表，避免中文缩写导致分析时再改
8. 管权限：谁可录入、谁可修改、谁可删除写进说明；修改留痕，删除只做逻辑删除
9. 做备份：每日自动或手工双备份，备份不与主库同机；恢复演练一次并记耗时，演练失败即视为没有备份
10. 写兜底：断网、设备故障、患者未按时随访三种情形各写纸质流程，事后 24 小时内补录并标「补录」
11. 记版本：工具版本、依赖库版本、部署位置、数据存储位置，升级前先备份再改，改后重跑一例验证
12. 写说明并验收：一页使用说明（谁在何时填什么），请未参与开发的同学按说明独立录一例，记录其提问并修订

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 必填、范围、日期逻辑、重复编号四项校验已实现
- [ ] 一例真实病例全流程跑通，耗时与卡点已记
- [ ] 抽查三条记录与纸质 CRF 一致，改后重抽五条

- [ ] 权限与修改留痕已设置
- [ ] 备份与恢复演练各完成一次，耗时已记

## H.5 模板：工具与数据一致性说明

| 字段 | 填写要求 |
|------|----------|
| 功能清单 | 登记、提醒、录入、导出；不做项与理由 |
| 字段映射 | 工具字段 ↔ CRF 列 ↔ 导出列名 |
| 校验规则 | 必填、范围、日期逻辑、重复拦截 |
| 全流程验证 | 病例号、各步耗时、卡点与处理 |
| 抽查核对 | 三条记录的不一致项与修正 |
| 导出规范 | 行粒度、列名对照、缺失值表示 |
| 权限与备份 | 角色、留痕方式、备份位置、恢复耗时 |
| 兜底流程 | 三种故障情形的纸质步骤与补录规则 |
| 版本与部署 | 工具版本、依赖、存储路径、升级前备份 |

## H.6 常见失效与处置

- **功能越做越多** → 评价才是目的；功能膨胀必然拖到招募期，先跑通一条链路
- **字段与 CRF 不一致** → 导出后还要手工改，错误从这里进入结果；逐列对照并留理由
- **导出用中文缩写列名** → 统计脚本每次重写，口径漂移；用英文短名加对照表
- **没有兜底** → 一次断网或设备故障就丢整段随访；纸质流程要事先演练
- **备份与主库同机** → 硬盘坏一次全丢；异地或异机备份，并做恢复演练
- **删除代替作废** → 审计链断裂，复核无法还原；只做逻辑删除并留痕

## H.7 中期检查与答辩要点

- 字段一致性与校验（35%）
- 全流程验证与抽查（25%）
- 导出可用性（20%）
- 兜底、备份与文档（20%）
