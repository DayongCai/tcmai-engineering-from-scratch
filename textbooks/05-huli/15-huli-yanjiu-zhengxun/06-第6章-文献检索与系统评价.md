# 第 6 章 · 文献检索与系统评价

> **层次**：本文件是**本库撰写层**（无底本表，不是源正文层）。依据是 Cochrane Handbook Ch4（检索）、PRISMA 2020 系列、ROBIS 指南与 JBI 系统评价核查表，条文登记于 `standards/huli-yanjiu-zhengxun/外源条文.json`（91 条，逐字可核）。
> **依据**：`standards/huli-yanjiu-zhengxun/补源登记.json`（`python scripts/build_huli_yanjiu_sources.py --check` 现算）。
> **免责**：本章为检索与系统评价方法的教学整理，不构成诊断或治疗建议；检索结果不构成临床推荐。

## 本章要回答的问题

系统评价与「综述」的差别在哪一步？不在写作，在**检索**。

> 「Searches should aim for high sensitivity, which may result in relatively low precision.」（外源·Cochrane Handbook Ch4 检索 第1条）

这条把取舍讲得很直白：**宁可多检，不可漏检**。系统评价的可信度建立在「我尽力找全了」之上；如果漏掉关键研究，后面的合成再精致也是错的。

## N.1 概念与出处

| 环节 | 依据 | 要点 |
|---|---|---|
| 敏感性优先 | 外源·Cochrane Handbook Ch4 检索 第1条 | 追求高敏感度，精度可以低 |
| 概念块不宜多 | 外源·Cochrane Handbook Ch4 检索 第2条 | 概念少；每个概念内同义词用 OR 展开 |
| 覆盖时间与来源 | 外源·Cochrane Handbook Ch4 检索 第3条 | 时间跨度与来源都要覆盖，避免漏检 |
| 不止 MEDLINE | 外源·Cochrane Handbook Ch4 检索 第4条 | 只检主库既会漏研究，也会引入选择偏倚 |
| 问题要写明 | 外源·JBI 系统评价核查表 第1条 | 系统评价的问题是否清晰明确 |
| 必须做批判性评价 | 外源·JBI 系统评价核查表 第2条 | 对纳入文献的质量评价是「essential」 |
| 要给出推荐 | 外源·JBI 系统评价核查表 第3条 | 理想情况下应给出面向政策与实践的推荐 |
| 评价本身的偏倚 | 外源·ROBIS Guidance on how to use ROBIS 第11条 | Phase 3：整篇系统评价是否处于偏倚风险 |

## N.2 为什么可以这样翻译：五段流水线

```mermaid
flowchart LR
  A[第1章 PICO] --> B[概念块：P + I（同义词 OR）]
  B --> C[多库多源检索：时间与来源全覆盖]
  C --> D[去重 + 双人筛选（PRISMA 第8项）]
  D --> E[批判性评价：RoB 2 / ROBIS / JBI]
  E --> F[合成与分级：第5章]
  F --> G[报告：PRISMA 27 项]
```

| 阶段 | 可核判据 | 依据 |
|---|---|---|
| 检索 | 逐行检索式可复现；时间与来源写明；不止一个库 | Ch4 第2条、第3条、第4条 |
| 筛选 | 记录数与最终纳入数逐级给出；几人筛、是否独立 | PRISMA 2020 Checklist 第3条 |
| 评价 | 工具与版本；判定附理由 | JBI 系统评价 第2条、Cochrane Ch8 第3条 |
| 合成 | 效应量与模型；异质性与敏感性分析 | 第5章（G/MA 条） |
| 报告 | 27 项逐项对应 | PRISMA 2020 expanded checklist |

**筛选损耗要有数字感**：高敏感检索的常态是「记录数远大于纳入数」——一个具体问题上万条记录、最终纳入十几项研究是常见量级。这不说明检索失败，反而说明敏感性起了作用。真正需要警惕的是相反情形：**记录数只有几十条**，通常意味着概念块太多或有未声明的语种/年份限制。

因此 PRISMA 要求把「从检出到纳入」的每一级数字都写出来，不是形式要求，而是让读者能判断「这次检索是不是够宽」。

**第4条的代价要说清**：只检 MEDLINE 不仅「可能漏」，还会**引入选择偏倚**——因为不同语种、不同地区的阳性/阴性结果分布不同。这句话把「多检几个库」从勤快变成了方法学义务。

## N.3 这个翻译丢掉了什么

1. **不给数据库清单与检索语法**。CINAHL、Embase、CNKI、万方各自语法不同，本章不给现成式。
2. **不给筛选工具与流程**。用什么软件去重、如何记录排除理由，要靠机构 SOP 与 PRISMA 流程图。
3. **不给异质性处理的操作细则**。亚组与敏感性分析怎么设（MA05/MA06 有原则），具体分层变量要按临床逻辑定。
4. **不给发表偏倚的检验选择**。漏斗图、Egger 检验各有适用条件，本库无底本。
5. **不给更新频率**。「多久更新一次系统评价」是政策问题，不在方法学条文里。
6. **不覆盖快速评价（rapid review）与证据地图**。这些变体的方法学取舍（缩短检索、单一筛选）本章不涉及。

## N.4 与相邻学科的接口

| 去向 | 接口 |
|---|---|
| 第 1 章 选题与问题化 | PICO 决定概念块；纳入标准（PRISMA 第5条）决定筛选判据 |
| 第 2 章 量性研究与设计类型 | 纳入研究的设计类型决定用哪套偏倚工具（RoB 2 / JBI） |
| 第 3 章 质性研究与访谈分析 | 质性证据综合（meta-aggregation）检索策略与量性不同 |
| 第 4 章 量表的选择与信效度 | 检索测量学研究时，量表名 + reliability/validity 组合 |
| 第 5 章 循证护理的证据分级 | 检索与评价的产物进入分级；ROBIS 判评价本身 |
| 第 7 章 证据到实践的转化 | 系统评价是转化的原料；转化要回答「为什么这条没用上」 |
| 第 8 章 伦理审查 | 仅用公开文献通常不涉人；用未发表数据需审查 |

## N.5 争议与本项目立场

**争议一：敏感性优先会不会淹没筛选。** 会——高敏感意味着成千上万条记录。本项目立场：**用「概念块少 + 同义词全」控制规模**，而不是削减来源；规模问题靠筛选工具与流程解决，不靠少检库。

**争议二：中文库要不要检。** 护理领域的中文研究量大、质量参差，但漏检会引入偏倚。本项目立场：**必检，且在方法里写明**；语种限制只能作为**结果解释**的一部分，不能作为检索的省略理由。

**争议三：只做单库检索能不能叫系统评价。** 不能。第4条把「不止 MEDLINE」写成了方法要求。本项目立场：**单库检索只能叫「文献回顾」**，这个名称差别应在论文标题里体现。

**本项目立场**：检索与系统评价章的产出不是一张流程图，而是**五件可核物**：可复现的检索式（逐库）、覆盖声明（时间+来源+语种限制及理由）、筛选记录（几人/是否独立/排除理由）、评价记录（工具版本+判定理由）、PRISMA 27 项对照表。五件齐，才谈得上「系统」。

> **免责**：本章所列条文与判据不构成诊断或治疗建议；检索与系统评价的结论须结合临床情境判断。

## 小结

1. 系统评价与综述的分水岭在检索：敏感性优先（第1条）。
2. 概念块宜少、同义词用 OR 展开（第2条）；时间与来源要全覆盖（第3条）。
3. 只检 MEDLINE 会漏研究并引入选择偏倚（第4条）。
4. 批判性评价是「essential」（JBI 第2条），且判定要附理由。
5. 引用前先判这篇系统评价本身的偏倚（ROBIS Phase 3）。
6. 单库检索只能叫「文献回顾」，不能叫系统评价。

## 思考题

1. 你的问题是「病房噪声对老年患者睡眠的影响」。请写出两个概念块及各自的 OR 同义词组（各 4 个词）。
2. 若检索只覆盖近 10 年，可能漏掉哪类关键研究？这属于第3条还是第4条的问题？
3. 双人筛选的成本很高。什么情况下可以单人筛选 + 第二人抽查？依据是哪一条？
4. 「单库检索只能叫文献回顾」——如果一篇论文这样标注，你会怎么评价它的结论？
