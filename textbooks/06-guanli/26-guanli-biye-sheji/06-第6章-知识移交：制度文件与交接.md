# 第 6 章 · 知识移交：制度文件与交接

## H.1 本章要解决的问题

管理成果的最终形态不是一篇论文，而是一条能留在制度里的做法。交接不到位，人一走制度就废：下一届不知道指标怎么算、表单谁签、系统校验在哪改，于是同一件事每年重做一遍。本章交付制度文件、表单与系统校验三件套，加一份可签收的移交清单，把个人经验变成科室资产，并把下一届的接手成本压到一天以内。

## H.2 本章目标（可检验）

- 交出一份可发布的流程文件或管理办法（目的、范围、职责、流程、考核五要素）
- 把主指标与复核方式写进考核条款，指明复核周期与责任岗位
- 完成表单与系统校验的落地（谁填、谁签、校验规则、变更流程）
- 完成一次交接演示与四类资产签收

## H.3 操作流程

1. 定文件类型：管理办法（管职责与权限）、流程文件（管步骤与时限）、作业指导书（管动作与判据），按需选一种，不混写，一份文件只解决一类问题
2. 写目的与范围：解决什么问题、适用哪些科室与岗位、不适用什么情形，范围越具体越少扯皮
3. 写职责：逐条落到岗位（科室负责人、质控员、信息科、病案室），不写「相关科室」，不写人名，岗位名称与院内编制口径一致
4. 写流程：步骤、责任人、时限、输入输出，以及异常处置与例外批准权限，注明谁能破例、破例如何留痕；时限写「几个工作日内」而非「尽快」
5. 嵌指标：把主指标的分子分母、数据来源、统计周期写进附则，避免执行时各自解释，口径变更走版本流程
6. 写考核与复核：考核对象、频次、判定标准、复核岗位、复测时点；未达标时的处理路径与升级渠道，复核结果要留档可查
7. 设计表单：字段与指标口径一一对应，必填项明确，签字栏写岗位而非姓名，一表只做一件事，签字栏同时印日期栏
8. 设计系统校验：哪些字段必填、哪些值域受限、哪些情形强制二次确认；改造需求提交信息科并记录排期
9. 征求意见：科室负责人与一线各签注意见，记录未采纳意见及理由，意见要落到具体条款，避免发布后才发现做不到
10. 修订与留位：按意见改一版，文号与生效日留位待院办编号，附修订记录（版本、日期、改动、发起人）
11. 培训与演示：向接手人与执行岗位演示一次完整流程（取数—填表—复核），请对方复述关键三步
12. 移交签收：数据、方法、表单与制度、未完成项四张清单逐项签字；敏感数据脱敏后移交并注明保存期限；签收表注明联系人与交接日期

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 文件类型与用途匹配，未混写
- [ ] 目的、范围、不适用情形已写
- [ ] 职责落到岗位，无「相关科室」与人名
- [ ] 流程含时限、异常处置与破例权限
- [ ] 主指标口径写入附则
- [ ] 考核含频次、判据、复核岗位与升级路径
- [ ] 表单字段与口径一一对应
- [ ] 系统校验规则与改造排期已记
- [ ] 科室与一线意见已签注
- [ ] 文号与生效日留位，修订记录齐全
- [ ] 交接演示完成，对方复述三步
- [ ] 四张清单签字，敏感数据已脱敏

## H.5 模板：制度文件与移交清单

| 字段 | 填写要求 |
|------|----------|
| 文件信息 | 名称、类型、目的、范围、不适用情形 |
| 职责 | 岗位分工、权限边界、破例批准人 |
| 流程 | 步骤、责任人、时限、异常处置 |
| 指标条款 | 口径、数据来源、统计周期、变更流程 |
| 考核与复核 | 对象、频次、判据、复核岗位 |
| 表单 | 字段、必填项、签字岗位 |
| 系统校验 | 规则、改造需求、排期与验收 |
| 意见与修订 | 签注、未采纳理由、版本记录 |
| 文号与生效 | 文号留位、生效日、复审周期 |
| 移交签收 | 四类资产、脱敏说明、保存期限、签字 |

> 本表是本章的交付物：结题时提交，科室与教学秘书各存一份；四张清单签字后归入实验室或科室档案。

## H.6 常见失效与处置

- **写成论文摘要** → 制度要能执行，不是论证；五要素缺一即空转
- **职责写「相关科室」** → 无人认领，出问题互相推
- **无考核与复核** → 没有复核就没有落地，三个月后回弹
- **只有表单没有校验** → 靠人自觉，数据质量随人员流动而波动
- **文号与生效日自拟** → 编号权限在院办，自拟属程序错误
- **口头交接** → 人一走信息全失；必须签字并留清单

## H.7 中期检查与答辩要点

- 文件可执行性（35%）
- 指标与考核条款（25%）
- 表单与系统校验（20%）
- 意见签注与签收（20%）
