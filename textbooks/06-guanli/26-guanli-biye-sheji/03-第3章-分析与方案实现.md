## H.1 本章要解决的问题

管理方案最常见的死法是「方案写了三十页，没人执行」：措施停在纸面，因为没落到岗位、没有时限、缺一个系统开关。本章要求把方案拆成「谁在什么时点做什么动作」，先用一个班组试一周，把做不到的地方找出来，再定稿。方案的价值不在写得全，而在执行率能被数出来、能被第三方按表核对；定稿前不上全院，避免一次改完再回退。

## H.2 本章目标（可检验）

- 把目标指标倒推成岗位动作清单，每条含责任人、频次、时限与所需资源
- 确认三项实施前提：人力、系统、授权
- 完成一次小范围试运行，并按一线反馈修订一版
- 设计一条不依赖人自觉的固化手段（系统校验、表单必填、双签）

## H.3 操作流程

1. 画现状：用泳道图写出从患者到院到离院的每一步、每步耗时、移交次数与卡点，标出等待发生在谁手里
2. 找瓶颈：用等待与排队数据定位，不用「大家反映」；瓶颈多出现在等待、重复录入、审批三处
3. 倒推措施：从目标指标的分子分母出发，问「哪些记录要变、由谁的哪个动作改变」，动作与记录一一对应
4. 三层设计：技术层（系统校验、模板、自动提醒）、流程层（环节合并、前置准备、职责重划）、人员层（培训、排班），优先技术层
5. 落到岗位：每条措施写责任岗位（不是人名）、协作岗位、动作、频次与单次耗时，岗位变动后措施仍可执行
6. 定时限：写开始日、完成日与检查点；跨月措施拆成周任务，避免「持续推进」这种无法验收的表述
7. 核前提：人力（是否需增班或抽调）、系统（是否需改造、谁提需求、排期多久）、授权（谁批准、批到哪一级）
8. 定执行率：为每条主措施定义执行率（实做次数除以应做次数），先测执行率再谈效果，执行率不足六成不谈结论
9. 试运行：选一个班组、一个班次试一周，范围小到出问题不外溢；试运行数据单独保存不混入正式结果
10. 收反馈：问执行者三句——哪一步做不到、为什么、需要什么；记录原话，不做解释性改写
11. 修订留痕：按反馈改一版，写明改动项、理由与是否影响指标口径；影响口径的改动要回到第二章改定义表
12. 固化设计：把有效动作写进系统校验、表单必填或双签，明确谁维护、多久复审一次，写进制度而不是记在脑子里

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 现状流程含每步耗时与移交次数
- [ ] 瓶颈由数据定位而非印象
- [ ] 措施覆盖技术、流程、人员三层
- [ ] 每条措施有责任岗位、动作、频次
- [ ] 每项有时限与检查点，无「持续推进」类表述
- [ ] 人力、系统、授权三项前提已核
- [ ] 主措施有执行率定义与阈值
- [ ] 试运行限于一个班组一个班次
- [ ] 一线反馈按原话记录三条以上
- [ ] 修订版写明改动与理由
- [ ] 修订未破坏指标口径，破坏则已改定义表
- [ ] 固化手段与维护人、复审周期已定

## H.5 模板：方案落地与试运行记录表

| 字段 | 填写要求 |
|------|----------|
| 现状流程 | 步骤、耗时、移交次数、卡点 |
| 瓶颈 | 数据依据、影响量级、责任环节 |
| 措施 | 技术层 / 流程层 / 人员层，逐条编号 |
| 岗位与时限 | 责任岗位、协作岗位、开始与完成日 |
| 前提 | 人力、系统、授权；缺口与解决方式 |
| 执行率 | 应做、实做、执行率，按周记录 |
| 试运行 | 范围、周期、结果、异常与处理 |
| 反馈与修订 | 原话、改动项、理由、版本号 |
| 固化 | 系统校验 / 表单 / 双签；维护人与复审周期 |

> 本表是本章的交付物：方案定稿前一页总表；试运行期间每周更新，答辩时按「措施—执行率—指标」三段展示。

## H.6 常见失效与处置

- **措施没有责任岗位** → 「加强宣教」无人认领，执行率永远为零
- **一次上五条措施** → 分不清哪条有效；主措施应控制在两条以内
- **跳过试运行** → 纸面可行不等于现场可行，正式实施即翻车
- **只看结果不看执行率** → 措施没做就说无效，是最常见的误判
- **方案超出权限** → 要求调整收费或编制，学生无权推动，应改为可落地动作
- **修订不留痕** → 最终方案从哪来无法说明，答辩时讲不清版本

## H.7 中期检查与答辩要点

- 动作与岗位对应（30%）
- 试运行与一线反馈（30%）
- 前提核查与固化设计（25%）
- 修订留痕与口径一致（15%）
