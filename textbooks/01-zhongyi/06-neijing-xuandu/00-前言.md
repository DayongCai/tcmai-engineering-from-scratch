## 这本书是什么

本目录是《内经选读》的**源教材正文层**：31 章正文逐块取自源工作簿的章表，节 / 小节 / 细目层级来自源表的结构列，段落文字一字未改。

做到的三件事：**不手抄**（脚本逐行抽取）、**不重写**（原文即正文）、**可对账**（每章首块的源表名 + sha256 + 字数可复算，`--check` 会逐章比对）。

## 与项目教材契约的关系

| 契约节次 | 本目录现状 |
|---|---|
| 章首「本章要回答的问题」 | ⬚ 待撰写（不由脚本编造） |
| N.1 概念与出处 | 🚧 源正文已含（出处散见于正文，未统一到篇名级） |
| N.2 为什么可以这样翻译 | ⬚ 待撰写 |
| N.3 这个翻译丢掉了什么 | ⬚ 待撰写（本项目的硬规则，必须人工写） |
| N.4 与相邻学科的接口 | ⬚ 待撰写 |
| N.5 争议与本项目立场 | ⬚ 待撰写 |

也就是说：**正文骨架与内容已经落地，改写层仍缺**。把源正文当成品交付是不诚实的 ——
`build_book.js --check` 统计的字数只证明「有字」，不证明「按契约写」。

## 出处与重建

```bash
node scripts/import_textbooks.js --only 黄帝内经(通读注释版)   # 重新抽取（源工作簿需在桌面 textbooks/）
node scripts/import_textbooks.js --check                  # 逐章对账：文件字数 ↔ 源正文
node textbooks/build_book.js --check                      # 全库教材字数统计
```

源工作簿的指纹（sha256 / 字节数 / 章表清单）记在 `standards/materials/textbooks-batch/registry.json`。
原件不入库的理由：100 份合计 51 MB 的二进制，sha256 已足以验证「眼前这份」是不是当初那份。

本文件由 `scripts/import_textbooks.js` 从源工作簿生成，请勿手改 —— 需要修改请改源工作簿后重跑。
