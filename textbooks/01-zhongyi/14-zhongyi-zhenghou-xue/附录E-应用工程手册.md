# 附录 E · 应用工程手册：把辞典当服务用

> 这一卷写给写代码的人。它回答四个问题：数据长什么样、判定怎么写成状态机、
> 改数据怎么不炸、上线前跑什么。所有数字都由 `standards/zhenghou-cidian/` 现算。

## E.1 数据契约（三个文件，读完就能开工）

```text
standards/zhenghou-cidian/
  结构.json   → men[].lei[].zhengList[].houList[]   // 四级树，唯一真相
  张量.json   → cells{ "候位|证位|态": n }，sliceMenWei / sliceLeiTai   // 相似度
  语素-*.json → 位/性/态的词典，含释义、见症、治法、TM1 构件      // 释义合成
```

| 字段 | 类型 | 能不能为空 | 用途 |
|---|---|---|---|
| `full` | string `M01-L01-Z01[a]` | 否 | 主键（**唯一**，原书一码两用时带 a/b 后缀） |
| `code` | string `L01-Z01` | 否 | 书内原码（回查纸书用，不改） |
| `wei` | string | 否 | 位轴取值（22 证位之一） |
| `houList[].tai` | string | 否 | 态轴取值（108 态之一） |
| `page` | string / `-1` | 可 | 目录页；`-1` = 书签目标失效（不是缺页） |
| `declareHou` | int | 否 | 书内声明的候数（与实列不一致的 10 条已登记） |

## E.2 判定怎么写：从 if 到状态机

**阈值不是拍出来的，是跑出来的**。第一版写的是「位 ≥2 且 性 ≥2」，拿 12 门夹具一跑，
最典型的风寒表证（恶寒重、无汗、脉浮紧）被判成**零候选** —— 因为位语素写「无汗或少汗」、
类语素写「无汗」，一个词只落得住一边。改成 **合计 ≥3 且两侧各 ≥1**（`位+性≥3 && 位≥1 && 性≥1`），
并把 `位≥2 && 性≥2` 单列为 **strong 档**用于排序。这份阈值与 `scripts/zhenghou_encode.js` 同一处定义，
改阈值必须同时改 291 条证的「调用块」与本节 —— 三处不一致就是 bug。

第一版可以直接照抄证条目的「调用块」；但真实病人会**同时命中多个证**，所以第二版写成状态机：

```js
// 状态 = 张量里的一个格；转移 = 态族之间的移动（失守→郁→虚→脱绝 是恶化方向）
const ORDER = ['失守', '郁', '虚', '火', '陷逆', '脱绝'];   // 越靠后越危

function step(state, ctx) {
  const hits = CANDIDATES.filter(z => score(z, ctx) >= 2)   // 候选证
                        .sort((a, b) => score(b, ctx) - score(a, ctx));
  const zi = hits[0];                                       // 主证（永远给出）
  const hou = pickHou(zi, ctx);                             // 主证下亮哪一组开关
  return { 主证: zi.full, 主候: hou.full, 危候: ORDER.indexOf(famOf(hou)) >= 4 };
}
```

`危候` 这一位不是装饰：`脱绝` 族（闭脱/厥脱/脱绝/竭绝/阳脱）出现时，
界面必须立刻从「调理建议」切成「立即就医」。这是本辞典唯一允许的**强制性输出**。

## E.3 流水线（CI/CD 六步，与仓库门禁一一对应）

| 步 | 命令 | 失败意味着 |
|---|---|---|
| 1 生成 | `python scripts/build_zhenghou_cidian.py` | 底本读不动（目录格式变了） |
| 2 幂等 | `python scripts/build_zhenghou_cidian.py --check` | 有人手改产物没改底本 |
| 3 断言 | `node tests/test_zhenghou_cidian.js` | 码不唯一 / 正文缺条 / 缺口被悄悄删 |
| 4 编码器 | `node scripts/zhenghou_encode.js --check` | 15 条黄金样例有一门的门/类/危候漂了 |
| 5 契约 | `node scripts/audit_curriculum.js` | 12 章缺 docs/quiz/outputs 或篇幅不足 |
| 6 出处 | `node scripts/figures/check_provenance.js` | 图里的话在正文里找不到 |

六步全绿才允许 `npm run build`（重出站点与看板）。这就是「CI/CD 迭代升级」在这本辞典里的具体形态：
**码不可复用、只能追加；改一条要过六道门；产物永远由底本重算，不许手改。**

**参考实现已可运行**：`scripts/zhenghou_encode.js`（无第三方依赖，直接读这三个 JSON）。
它把这节的流水线真跑通，黄金样例在 `standards/zhenghou-cidian/encode-cases.json`（15 条 = 12 门 + 2 危候 + 1 负例）。

```bash
node scripts/zhenghou_encode.js --ctx "恶寒重 无汗 脉浮紧"    # 单次编码（人读 + JSON 双输出）
node scripts/zhenghou_encode.js --all                      # 15 条黄金样例逐条打印
node scripts/zhenghou_encode.js --check                    # 只断言，给 CI 用
```

## E.4 迁移协议（将来一定会遇到的三件事）

| 场景 | 允许的做法 | 禁止的做法 |
|---|---|---|
| 新增一个候 | 追加 `-Hnnn`（新号段），父码不动 | 重排既有候号 |
| 改一个证名 | 保留 `full` 与 `code`，在新文件名下写「更名」，两者并存 | 直接改字符串（历史数据会断） |
| 合并两证 | 保留两个码，在新码上写 `mergedInto` | 删掉旧码 |

理由只有一条：这本辞典的码已经要被 APP、题库、病历模板同时引用，**码是接口，不是标签**。

## E.5 一次完整请求（往返长什么样）

```http
POST /api/zhenghou/encode
Content-Type: application/json

{"ctx": {"恶风寒": true, "发热": true, "无汗": true, "头身痛": true, "脉浮": true, "脉紧": true}}
```

```json
{
  "候选": [
    {"full": "M01-L01-Z01", "zh": "肺卫风寒证", "命中位": 2, "命中性": 2,
     "主候": "M01-L01-Z01-H001", "开关组": {"失守": 11, "郁": 9, "虚": 5},
     "治法动作": "宣", "危候": false}
    {"full": "M02-L06-Z01", "zh": "肺卫寒热证", "命中位": 2, "命中性": 1,
     "主候": null, "开关组": {"郁": 12, "火": 6, "失守": 2}, "治法动作": "和解", "危候": false}
  ],
  "提示": "候选不是诊断；请由执业中医师结合四诊确认。",
  "未收录词": []
}
```

三个字段值得注意：`候选`（永远 ≥1 条，按命中数排序）、`危候`（true 时前端必须切红）、
`未收录词`（用户说了词表外的话，如实返回，前端据此提示「换个说法试试」而不是静默丢掉）。

## E.7 三条工程红线

1. **不做诊断**：所有输出前面的名词都是「候选」「坐标」「开关」，不是「结论」。
2. **不给剂量**：本辞典所有「方」只到方名，不到克数 —— 剂量要医生按人调。
3. **危候必拦**：`脱绝` 族命中即切就医保底，不留给产品经理做 A/B。
