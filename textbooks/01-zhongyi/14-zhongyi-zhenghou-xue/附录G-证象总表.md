## G.1 这张表在说什么

原表是一张**矩阵**：行是病机（不宣 / 不利 / 不通 / 闭塞 / 不降 / 不升 / 蕴蒸 / 蕴灼 / 蕴炽 / 腐败 / 溃乱 / 不和 / 不宁 / 不振 / 不养 / 不荣 / 不固 / 枯竭 / 脱绝），列是部位与属性（腠理 · 经脉 · 络脉 · 清空 · 清窍 · 气机 · 神志 · 津 · 液 · 营 · 血 · 阳 · 阴）。格内文字就是「部位 + 病机」拼出来的证象，例如 **腠理 × 不宣 = 腠理不宣**。

用工程的话说：这是本书的**证象词法表** —— 它不是证、不是候，而是「证候名里那些两字组合」的合法词库。候名的尾巴（态）从这里取，证的名称（部位+病机）也从这里取。

| 项 | 实测 | 怎么来的 |
|---|---|---|
| 行（病机） | **19** | 原表左列竖排字，逐行读 |
| 列（位/属性） | **13** | 原表两级表头 |
| 格（证象） | **72** | 300 DPI 渲染页逐象限人工读表；每格用字回 OCR 兑现 |
| 书名声明 | 75 | 原页标题「附录一：75证象一览表」 |

**为什么是人工读表而不是自动解析**：OCR 把格内两个字拆成两个文本框（「腠理」「不宣」），又把表头拆成单字（「腧」「理」），自动拼格会整列错位。宁可慢，不可错 —— 自动拼出来的 103 个「格」里有一半是错的，人工读的 72 格每一格都能回页兑现。

## G.3 差额与校验

- 读到 **72 格**，书名声明 **75**，差 **3** 格。
- 差 4 格未读到：原表右侧另有一窄列（郁/滞/结/闭/逆/陷/实变 与 夹/虚/虚逆/损/滑/变/脱/绝）是性质注记，不计入格；余下 4 格可能在「不降」「不固」「枯竭」等行里被我读漏，宁缺不补。
- 表右侧另有一窄列性质注记：郁、滞、结、闭、逆、陷、实变、夹、虚、虚逆、损、滑、变、脱、绝 —— 它是行性质的标注，不是格，未计入。
- 方法：300 DPI 渲染 → 四象限人工读表；OCR 自动拼格只用于交叉核对，不作为唯一依据

## G.4 与 108 态的关系（别混）

附录 A.5 的 **108 态**是从 1866 条候名**尾部实测**得来（失宣、蕴蒸、郁结…），本附录的 **72 格证象**是原书表格里**部位+病机**的组合。两者词形大量重合，但不是一回事：

| | 证象（本附录） | 态（附录 A.5） |
|---|---|---|
| 出处 | 原书附录一原表 | 候名尾部实测 |
| 形态 | 部位 + 病机（腠理不宣） | 病机片段（不宣 / 蕴蒸） |
| 用途 | 校验候名/证名里的组合是否合法 | 给候打「这一步坏在哪」的标签 |

## G.5 这张表已经接进编码器（不是只躺在附录里）

上面 72 格被编成 `standards/zhenghou-cidian/证象-合法组合.json`（部位×病机 → 格内文字），编码器新增 `validateName()`，只在**提示层**用，不改候选、不改分数：

| 气机郁结 | **true** | 组合等于「气机×不通」，表内写法一致 |

三处入口：`node scripts/zhenghou_encode.js --name 腠理不宣`、`/encode` 响应的 `nameChecks[]`、`GET /name?q=`；百姓页跑同一套判定，页面与 Node 由 S6 对齐测试盯着。

**为什么只做提示不改分**：合法格只有 72 个，而候名 1866 条里大量说法不在表内（如「卫气失宣」是「卫气 + 失宣」，表里只有「不宣」）。拿它当分数门槛会把大半候选误杀；当提示用，既能回答「这个说法原书有没有」，又能指出「原表怎么写」。

## G.6 质检：1863 条候的【证象组合】到底能不能用这张表校验

先说结论，免得被数字骗：**这两个字段不是同一套词，72 格只能校验其中一小撮。**

| 字段形态 | 候数 | 长什么样 | 能不能用附录一校验 |
|---|--:|---|---|
| 证象型（带【…】全称） | **3** | `主证：【清空不宣】…` | **能**，逐条比对 |
| 标签型（位缩写+态缩写） | **1810** | `气郁+气滞+阳浮+液灼` | **不能**，语义层不同 |

为什么不能：附录一的格是「位 + **病机**」（不宣 / 不利 / 闭塞 / 蕴灼 / 溃乱 / 脱绝…），而标签串用的是「位 + **态根**」（郁 / 滞 / 逆 / 虚 / 溢 / 浮 / 灼…）。原表里根本没有「郁」「滞」「虚」这些字 —— 拿它去比，只会得到一堆假的不合格。

**待核的是这几个**（次数 ≥20）：滞、逆、溢、热、滑、泄。它们不是「懒」，是按位不同会落到不同格 ——「滞」在血是不利（血滞不行）、在血瘀是不通（血滞瘀结），设一个全局映射必然错一半。

**这张表不接进计分。** 理由两条：① 21.0% → 44.0% 的提升全押在「映射」这一栏，而映射里最容易错的是 结→不通、扰→不宁 这类「近义但不同义」；② 一旦进计分，错了不会报错，只会让候选排序悄悄偏移 —— 这正是本项目一直在防的那种静默错误。要用，先在样例上量准了再说。
