## H.1 本章要解决的问题

社区康复最缺的不是量表，是别人能重跑的评分：同一份评定，两个人算出两个分，复评就对不上。把一套康复评定做成可复现包，最少需要哪些文件才能让别人重跑？数据锚点：本库无现成量表；可复现包口径为数据、脚本、门禁、README 四件。缺口：量表本身需自建并经信度检验，本库不提供信度数据，不能声称量表已经过验证或可直接用于临床结算。包不完整时复评分数不可比，康复计划无从调整，前后两次评定等于白做。

## H.2 本章目标（可检验）

- 把量表条目写成字段，取值范围与计分方向写死
- 评分交给脚本，参数外置，条目数不写进代码
- 三条门禁能各自触发，缺项必须报错
- 让另一位同学照 README 独立跑通一次

## H.3 操作流程

1. 定字段：条目写成字段，给取值范围、缺项含义、计分方向
2. 建数据：十例样例，覆盖满分、零分、缺项三类
3. 写脚本：读表出分，参数外置，不写死条目数
4. 设门禁：字段完整、分数在域内、缺项必须显式三条
5. 验反向：故意缺一项跑一遍，须报错而不是填零
6. 复跑：清空输出重跑，十例分数完全一致
7. 写说明：从哪读起、怎么跑、缺什么会红
8. 请他人：另一位同学按说明独立跑一次，记卡点
9. 留样：把十例样例与当时输出一并存档，供下一届对照重跑是否走样
10. 交付：量表定义、评分脚本、三条门禁、说明

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 每条目有取值范围与计分方向
- [ ] 十例覆盖满分、零分、缺项
- [ ] 脚本参数外置，条目数未写死
- [ ] 三条门禁各自可触发，附触发记录
- [ ] 缺项时脚本报错，未默认填零
- [ ] 清空重跑十例分数一致
- [ ] 说明能让外人独立跑通
- [ ] 他人复跑卡点已记录并修
- [ ] 信度未做已在说明中声明
- [ ] 移交四件齐

## H.5 模板：评定包交付清单

| 字段 | 填写要求 |
|------|----------|
| 量表 | 条目、取值范围、计分方向 |
| 样例 | 十例与三类覆盖说明 |
| 脚本 | 入口、参数区、依赖版本 |
| 门禁 | 三条规则与触发记录 |
| 复跑 | 清空重跑结果对照 |
| 他人复跑 | 卡点、耗时、修法 |
| 声明 | 信度未做与适用范围 |

> 本表是本章的交付物：验收时逐件点数，四件缺一不得签收。

## H.6 常见失效与处置

- **缺项填零** → 缺项当零分，总分虚高，重度被评成轻度
- **条目写死在脚本** → 量表改一条就要改代码，换人不敢动
- **门禁只查格式** → 格式对但分数越界也能过
- **说明写在论文里** → 交付目录里没有，接手人找不到
- **把自建量表当已验证** → 无信度数据却称量表可靠，属越界

## H.7 中期检查与答辩要点

- 字段定义（30%）
- 脚本与门禁（35%）
- 他人复跑（25%）
- 声明与边界（10%）

> **边界声明**：本章为教学与毕设管理材料，交付物不构成诊疗建议，不得用于真实患者决策。
