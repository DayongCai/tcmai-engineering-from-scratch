## H.1 本章要解决的问题

同一组数字在 README、看板与脚本里各写一遍，早晚对不上，而且没人知道哪个是真的。同一组数字（院系、学科、章节、学时）在三个文件里是否一致？不一致能否自动查出？数据锚点：本库现算口径 9 院系 · 187 学科 · 2,093 章节目标 · 11,457 学时。缺口：统计口径只覆盖本库，不含院校真实办学数据，报表不能拿去对外比规模，也不能当作评估依据。口径漂移不会一次出错，而是每次改一处、慢慢分叉。守门员的职责不是把数字改对，而是让改错这件事当场被拦下，并留下谁在何时改过的痕迹。

## H.2 本章目标（可检验）

- 指定唯一真源，其余位置改为引用而非复制
- 四个口径各写出可执行的取值语句
- 故意改坏一个数，验证门禁确实会红
- 把历史散文中写死的旧数全部找出并处置

## H.3 操作流程

1. 定源：指定看板数据为唯一真源，README 与文档改为引用
2. 列项：院系、学科、章节、学时四项各写取值语句
3. 现算：跑计数比对脚本，记四个数与扫描数
4. 比对：README 计数块与现算值逐项比，差异列表
5. 破立：故意把 187 改成 188，跑一次应红，改回应绿
6. 留痕：三次终端输出按时间存档，供答辩调阅
7. 查漏：全库搜历史散文中写死的旧数，逐处标注或删除
8. 对表：把看板、README、脚本三处现值抄成一页并排，差异处标出最后改动人与日期
9. 挂门禁：比对脚本进提交前检查，红灯不许合入
10. 交付：比对脚本、破立记录、口径说明

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 唯一真源已指定，其他处改为引用
- [ ] 四个口径各有取值语句
- [ ] 9／187／2,093／11,457 与脚本输出一致
- [ ] README 与现算的差异逐项列表
- [ ] 改坏一个数后门禁确实变红
- [ ] 修复后变绿，两次输出均存档
- [ ] 历史散文旧数已全库搜过
- [ ] 比对脚本已挂进提交前检查
- [ ] 扫描数与修复后数字同步
- [ ] 缺口写明只覆盖本库

## H.5 模板：口径对齐表

| 字段 | 填写要求 |
|------|----------|
| 真源 | 文件路径与字段 |
| 口径 | 四项的取值语句 |
| 现值 | 四项当前数字 |
| 引用点 | 哪些文件引用了它 |
| 破立 | 改坏、变红、修复、变绿 |
| 残留 | 散文中旧数与处置 |
| 门禁 | 脚本位置与触发时机 |

> 本表是本章的交付物：一处真源、多处引用；答辩时按四个口径逐项追问。

## H.6 常见失效与处置

- **三处各写一遍** → 改一处漏两处，报表长期漂移
- **只改数字不挂门禁** → 这次对齐了，下次照旧
- **破立不做** → 没验证过门禁会红，等于没有门禁
- **历史散文不管** → 正文里的旧数最容易被引用出去
- **拿本库数当办学数** → 自建库规模与院校实际规模不是一回事

## H.7 中期检查与答辩要点

- 真源与口径（30%）
- 比对与破立（35%）
- 门禁落地（25%）
- 边界（10%）
