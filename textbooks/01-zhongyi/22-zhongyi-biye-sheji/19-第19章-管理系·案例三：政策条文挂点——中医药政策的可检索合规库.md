## H.1 本章要解决的问题

政策文件读完就忘，是因为没挂到知识树上：下次要用，只能再翻一遍全文，翻完还是不知道归哪一章。政策条文按五级骨架挂点，哪些条款挂不上？挂不上说明什么？数据锚点：知识树五级骨架 schema 已入库；政策文本待补源。缺口：政策原文需外部补源，本库不含全文；补源必须先登记来源与校验值，再落条文，顺序颠倒就无法复核。挂点的意义是下次检索能一步到条文，而不是再读一遍全文。挂不上的条款往往不是没价值，而是骨架里没有它的位置，这本身就是要写进结论的发现。

## H.2 本章目标（可检验）

- 先补源并登记名称、机构、日期与校验值
- 按条切分落表，条款号保留原文
- 把未挂条款按三类归因，不许用「其他」
- 用关键词挂点做消融，比未挂与错挂

## H.3 操作流程

1. 补源：取政策原文，登记名称、机构、日期、校验值
2. 落条：按条切分，一条一行，条款号照抄不改写
3. 读骨架：抄五级层级名，确认哪几级接政策条文
4. 挂点：每条挂一个主节点，依据词写进备注
5. 出未挂：按无对应节点、综合条款、监督类归因
6. 查硬挂：专挑监督管理类条款，看是否被塞进诊疗分支
7. 回检：从已挂条文里随机抽 10 条，按挂点路径反查原文，反查不到即挂错
8. 消融：改按关键词挂，比未挂数与错挂数
9. 写界：说明本库只做挂点，不做政策解读
10. 交付：挂点表、未挂清单、补源登记

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 每条政策有来源、机构、日期、校验值
- [ ] 条文按条切分，条款号保留原文
- [ ] 五级层级名与 schema 一致
- [ ] 每条只挂一个主节点，依据词非空
- [ ] 未挂条款三类归因，无「其他」
- [ ] 监督类条款硬挂查过一遍
- [ ] 关键词消融的未挂与错挂已算
- [ ] 补源先登记后落条，顺序有记录
- [ ] 声明只做挂点不做解读
- [ ] 移交件齐：挂点表、未挂清单、登记

## H.5 模板：政策挂点表

| 字段 | 填写要求 |
|------|----------|
| 来源 | 文件名称、机构、日期、校验值 |
| 条文 | 条款号与原文摘录 |
| 主节点 | 五级路径与依据词 |
| 未挂 | 原因分类与建议 |
| 错挂 | 硬挂实例与所在层级 |
| 消融 | 关键词挂的未挂与错挂数 |
| 声明 | 只挂点不解读 |

> 本表是本章的交付物：一条一行，未挂条款单独成表，答辩先看未挂那一页。

## H.6 常见失效与处置

- **先落条后补源** → 出处丢了，条款无法核
- **硬挂监督条款** → 为凑覆盖率把管理条款塞进诊疗分支
- **未挂不列** → 挂不上的悄悄丢弃，覆盖率虚高
- **按关键词一把挂** → 同词跨级，错挂无人统计
- **把挂点当解读** → 挂到某节点不等于该条适用于该病

## H.7 中期检查与答辩要点

- 补源登记（30%）
- 挂点与未挂归因（35%）
- 消融（25%）
- 边界（10%）
