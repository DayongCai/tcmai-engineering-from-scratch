## H.1 本章要解决的问题

针灸培训最缺的是一份能按节切分的经络学底本：没有文本层，讲义、题库、继续教育课件只能各写一遍，写完还互相对不上。把中医系的内科底本模板迁到经络学，能在几轮内达到门禁全绿？数据锚点：该系 22 学科、已建 1 章、底本 0 门；可参照 neike 384 单元 / 329,826 字的口径。缺口：该系无教材工作簿在库，第一步必须自建文本层，这是立项前提不是可选项；没有底本，任何覆盖率都是估的。补文本层的工作量按节数估，不按周估，估错就会一路赶工。

## H.2 本章目标（可检验）

- 先补文本层，再谈单元切分与门禁，顺序不许颠倒
- 把 384 单元、329,826 字当作量级参照，报出自己的数
- 让 units.json 由脚本生成，字段与内科模板一致
- 门禁全绿且清空重跑数字不变，才算交付

## H.3 操作流程

1. 立前提：确认 22 学科里只 1 章已建、底本 0 门，把补文本层写成第一里程碑
2. 抄模板：读内科的 units.json 与构建脚本，抄字段名与命名规则
3. 定切法：以节为单元，一节一单元，节内小标题不另立单元
4. 建文本：逐节录入正文，保留原节号，缺节标待补但不跳号
5. 跑脚本：用同一套构建脚本生成 units.json，字段与内科对齐
6. 核量级：单元数与字数同时报，与 384 单元、32 万余字比
7. 过门禁：跑 audit 与章节代码测试，逐条记红项与修法
8. 复跑：清空输出重跑一次，单元数与字数不变才算过
9. 交付：units.json、构建脚本、门禁终端输出留档

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 22 学科、1 章已建、底本 0 门三个数已核
- [ ] 单元字段与内科模板完全一致
- [ ] 切分口径写明「节＝单元」
- [ ] 缺节标待补，节号未跳过
- [ ] units.json 由脚本生成，非手写
- [ ] 单元数与字数同时报出

- [ ] 清空重跑后数字不变
- [ ] 缺口写明本系文本层为自建

## H.5 模板：底本迁移记录表

| 字段 | 填写要求 |
|------|----------|
| 前提 | 学科数、已建章数、底本门数 |
| 模板 | 参照课的字段名与命名规则 |
| 切分 | 单元定义、节号保留方式 |
| 量级 | 单元数、字数、与参照课对比 |
| 门禁 | 逐项红绿与修法 |
| 复跑 | 清空重跑后的两项数字 |
| 缺口 | 缺节数、不可切分的节 |

> 本表是本章的交付物：立项、中期、验收三处通用，红项未清零不得进入下一里程碑。

## H.6 常见失效与处置

- **先写章节后补底本** → 章节数字手填，门禁一跑就红，返工最狠
- **缺节跳号** → 节号断了，单元数看着漂亮，实际缺内容
- **改脚本迁就内容** → 把切分规则改松以过门禁，等于自己给自己发证
- **只报单元数** → 不报字数，无法判断是否切得过碎
- **拿别系数充数** → 把内科的 384 单元写成自己的产出，属造假

## H.7 中期检查与答辩要点

- 底本完整性与切分口径（35%）
- 脚本生成与可复跑（30%）
- 门禁执行（25%）
- 缺口表述（10%）
