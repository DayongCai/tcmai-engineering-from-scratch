## H.1 本章要解决的问题

医学系统的故障不是「页面打不开」，而是「给错了提示」。事故复盘要能追到数据与模型版本。

## H.2 本章目标（可检验）

- 建立最小监控（可用性、错误率、延迟、数据漂移）
- 写一份事故复盘（含时间线）
- 给出防止复发的具体改动

## H.3 操作流程

1. 定监控项：可用性、错误率、P95 延迟、输入分布漂移
2. 定告警：阈值与通知人
3. 复盘：时间线、影响面、根因、处置
4. 改动作：一处代码或流程改动，写清验证方式
5. 回归：加一条用例防止复发

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 四项监控已上线
- [ ] 告警阈值与通知人已定
- [ ] 复盘时间线精确到分钟
- [ ] 根因追到数据或模型版本
- [ ] 改进动作已落地
- [ ] 回归用例已加
- [ ] 影响面已评估并通知

## H.5 模板：事故复盘表

| 字段 | 填写要求 |
|------|----------|
| 时间线 | 发现、响应、恢复 |
| 影响面 | 用户、数据、临床后果 |
| 根因 | 代码/数据/模型版本 |
| 处置 | 止血与修复 |
| 防复发 | 改动与回归用例 |

> 本表是本章的交付物：每次事故一张，24 小时内完成初稿。

## H.6 常见失效与处置

- **复盘写「人为失误」** → 根因要追到系统设计；人为失误是结果
- **不记数据/模型版本** → 无法判断是模型退化还是输入变化
- **改完不加用例** → 同样的问题会再来一次

## H.7 出科考核

- 监控覆盖（30%）
- 复盘深度（40%）
- 防复发改动（30%）
