# 第 6 章 · 交付验收与文档

> **课程**：工程实践与系统交付（🤖 智能系 · 第 9 学期 · 108 学时 · 轮转/实践）
> **契约**：**操作型章（handbook-v1）** —— 本文件是工作手册，不是学术教材：给的是当场能执行的流程、清单与模板。

## H.1 本章要解决的问题

项目移交时最尴尬的场景是：作者毕业走了，接手的人跑不起来，也没人知道模型什么时候该重训。交付验收要证明的不是「我做完了」，而是「别人能接着做」——文档、数据、模型、脚本、责任五项都能交接清楚。

## H.2 本章目标（可检验）

- 产出完整交付包（代码、数据说明、模型、配置、脚本、文档）
- 通过一次「陌生人验收」：由未参与开发的同学按文档从零部署并跑通一次推理
- 写明运维责任与重训触发条件，完成移交签收

## H.3 操作流程

1. 交付清单：代码仓库、数据说明（不可交付原始数据时给字段字典与申请流程）、模型权重与版本、配置模板、部署与运维脚本、用户与运维文档
2. 环境可复现：依赖锁定（版本号）、镜像或安装脚本、系统要求；一条命令完成安装
3. 冒烟测试：提供 3–5 条示例输入与期望输出，验收时逐条跑
4. 文档三类：用户文档（怎么用、看到什么算什么）、运维文档（怎么部署、怎么回滚、看哪些指标）、开发者文档（架构、接口、数据流）
5. 模型卡：训练数据范围、适用人群与场景、已知失效情形、性能指标与阈值、版本与更新记录
6. 运维责任：谁负责日常监控、谁处理告警、升级路径与响应时限
7. 重训触发条件：数据漂移阈值、性能下降阈值、业务规则变化；写明重训流程与审批
8. 合规复核：交付前对照第 1 章边界文件逐条确认（用途未越界、去标识化仍在、外部调用未新增）
9. 陌生人验收：由未参与开发的同学按文档部署，记录卡点并修正文档（不接受口头指导）
10. 问题清单：验收中发现的缺陷分级（阻塞/严重/一般），阻塞项必须修复
11. 签收：移交人、接收人、业务方三方签字，附验收记录与遗留问题清单
12. 复盘：写清「哪份文档最省时间、哪份最没人看」，据此调整文档投入

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 六类交付物齐全（代码/数据说明/模型/配置/脚本/文档）
- [ ] 依赖锁定且有安装脚本，一条命令可装
- [ ] 冒烟测试 3–5 条示例可复现输出
- [ ] 用户/运维/开发者三类文档齐全
- [ ] 模型卡含适用场景、失效情形、指标与版本
- [ ] 运维责任人与响应时限已写明
- [ ] 重训触发条件与流程已定
- [ ] 合规边界逐条复核通过
- [ ] 陌生人验收完成，卡点已修文档
- [ ] 缺陷分级，阻塞项已清零
- [ ] 三方签收并附遗留清单
- [ ] 文档投入复盘完成

## H.5 模板：交付验收单与模型卡

| 字段 | 填写要求 |
|------|----------|
| 交付物清单 | 代码、数据说明、模型、配置、脚本、文档 |
| 环境 | 依赖版本、安装脚本、系统要求 |
| 冒烟测试 | 输入、期望输出、实际输出 |
| 文档 | 用户/运维/开发者三类，位置与版本 |
| 模型卡 | 数据范围、适用场景、失效情形、指标、版本 |
| 运维责任 | 监控人、告警处置人、响应时限、升级路径 |
| 重训 | 触发条件、流程、审批人 |
| 合规复核 | 边界文件逐条确认结果 |
| 陌生人验收 | 验收人、卡点、修正记录 |
| 签收 | 移交/接收/业务三方签字、遗留问题 |

> 本表是本章的交付物：验收会现场逐项打勾；模型卡随版本更新，签收单归档。

## H.6 常见失效与处置

- **只交代码不交环境** → 接手者装不起来，项目在移交日死亡
- **文档写给作者自己看** → 隐含上下文太多，陌生人无法执行
- **无模型卡** → 接手者不知道模型不能用在哪，风险转移
- **不留重训条件** → 模型半年后性能下降，无人知道该动手
- **验收靠口头指导** → 作者在场时能跑，作者离开即失效
- **遗留问题不入清单** → 签收即遗忘，问题永久留存

## H.7 出科考核

- 交付物完整与环境可复现（30%）
- 文档与模型卡质量（30%）
- 陌生人验收通过（25%）
- 运维责任与签收（15%）
