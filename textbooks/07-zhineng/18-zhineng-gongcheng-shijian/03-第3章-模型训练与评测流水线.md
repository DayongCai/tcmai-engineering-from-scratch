## H.1 本章要解决的问题

「准确率 92%」这句话在医疗场景里几乎没有信息量：不知道测试集怎么来的、标签谁标的、阳性样本多少、漏诊与误诊哪个代价高。工程实践要建的是可复核的评测：数据集版本、划分方式、基线、指标定义、置信区间，一个都不能少。

## H.2 本章目标（可检验）

- 建立可复现的训练与评测流水线（数据版本、划分、种子、超参、产物）
- 定义与业务危害对齐的指标（含敏感性/特异性/阳性预测值，而非仅准确率）
- 产出评测报告：基线对比、分层结果、失败案例分析

## H.3 操作流程

1. 数据版本：数据快照加哈希、标注版本与标注人；记录纳排标准（哪些病例进、哪些排除）
2. 划分策略：训练/验证/测试按患者而非按样本划分（避免同一患者跨集泄漏）；时间外推场景按时间切分
3. 标签质量：抽样复核标注一致性（如 50 例双人盲标，算一致率），不一致的定仲裁规则
4. 基线：至少两个基线（随机/规则或简单模型/上一个版本），基线不定就不谈提升
5. 指标定义：明确正类是什么、阈值怎么定；报告敏感性、特异性、PPV、NPV 与置信区间；类别不平衡时用 PR 曲线与 AUPRC
6. 分层评价：按亚组（年龄、性别、设备、科室、病情严重度）分别报告，找出性能塌陷的亚组
7. 可复现：固定随机种子、记录环境与依赖版本、保存配置与产物哈希
8. 失败分析：抽 30–50 例错误样本，分类（标注错、图像质量、罕见表现、边界模糊），给占比
9. 阈值选择：按业务代价（漏诊 vs 误诊）选阈值，写明依据与对应指标
10. 报告成文：按 H.5 模板，数字附样本量与置信区间；未达标项如实写
11. 交接产物：数据快照、配置、权重、评测脚本、报告五件齐全，他人可复跑
12. 复盘：挑一个「准确率高但敏感性低」的案例，说明为什么这种模型不能上临床

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 数据快照有哈希、标注版本与纳排标准
- [ ] 按患者划分，未出现同一患者跨集
- [ ] 标签一致性抽检≥50 例并记录一致率
- [ ] 至少两个基线，基线可复现
- [ ] 报告敏感/特异/PPV/NPV 与置信区间
- [ ] 不平衡数据报告 PR 曲线或 AUPRC
- [ ] 亚组分层结果已出，塌陷亚组已标出
- [ ] 随机种子与环境依赖已记录
- [ ] 失败样本 30–50 例已分类并给占比
- [ ] 阈值选择有代价依据
- [ ] 五件产物齐全可复跑
- [ ] 未达标项如实写明

## H.5 模板：训练与评测报告模板

| 字段 | 填写要求 |
|------|----------|
| 数据 | 来源、纳排标准、快照哈希、标注版本 |
| 划分 | 按患者/按时间、各集样本量与正类比例 |
| 标签质量 | 抽检量、一致率、仲裁规则 |
| 基线 | 基线名称与指标 |
| 指标 | 敏感性/特异性/PPV/NPV/置信区间；AUPRC |
| 分层 | 亚组列表与各自指标 |
| 阈值 | 取值、依据、对应漏诊与误诊代价 |
| 可复现 | 种子、环境、依赖版本、配置哈希 |
| 失败分析 | 错误类型与占比 |
| 产物 | 快照/配置/权重/脚本/报告，交接路径 |

> 本表是本章的交付物：每次训练一版；报告顶部写数据快照哈希与配置哈希，便于复跑对比。

## H.6 常见失效与处置

- **按样本随机划分** → 同一患者跨集会虚高指标，是最常见的隐性作弊
- **只报准确率** → 类别不平衡时准确率毫无意义，敏感性可能低得不能上临床
- **没有基线** → 「92%」不知道是好还是差
- **不报置信区间** → 样本 100 例的 92% 与 10000 例的 92% 完全不同
- **不做分层** → 整体达标但老年组或某设备组塌陷，临床会出事
- **不留种子与配置** → 结果无法复跑，等于没有证据

## H.7 出科考核

- 数据与划分规范（30%）
- 指标定义与基线（30%）
- 分层与失败分析（25%）
- 可复现与产物交接（15%）
