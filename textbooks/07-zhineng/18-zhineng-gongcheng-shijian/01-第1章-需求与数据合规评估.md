## H.1 本章要解决的问题

医学数据的第一道门不是技术，是合规：数据能不能用、能不能出库、能不能留存，决定了后面所有设计。

## H.2 本章目标（可检验）

- 写清数据来源与使用边界
- 判断是否需伦理审查与授权
- 列出不可做的功能并说明原因

## H.3 操作流程

1. 列数据：来源、字段、规模、是否含个人健康信息
2. 判合规：伦理批件、数据授权、脱敏要求逐条确认
3. 定边界：数据不出院 / 不出科 / 可用不可见
4. 划红线：列出因合规不做或缓做的功能
5. 留痕：把上述结论写进需求文档首页

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 数据来源与字段清单已写
- [ ] 是否含个人健康信息已判定

- [ ] 脱敏方式已写
- [ ] 数据出域边界已写
- [ ] 不做/缓做的功能已列
- [ ] 责任人已签字

## H.5 模板：数据合规评估表

| 字段 | 填写要求 |
|------|----------|
| 数据清单 | 来源、字段、规模 |
| 敏感判定 | 是否含个人健康信息 |
| 授权状态 | 伦理批件/授权文件编号 |
| 边界 | 不出院/不出科/可用不可见 |
| 红线 | 不做或缓做的功能 |

> 本表是本章的交付物：项目立项首页，后续每次数据变更须更新。

## H.6 常见失效与处置

- **先开发后补授权** → 属重大违规；授权是前置条件
- **脱敏只看姓名** → 影像与文本可再识别；须写清方法
- **不列红线** → 开发到一半才发现不能做，返工最大

## H.7 出科考核

- 合规评估完整（一票否决项）
- 边界表述（40%）
- 红线清单（30%）
