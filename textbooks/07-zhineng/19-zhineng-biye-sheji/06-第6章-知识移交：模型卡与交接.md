## H.1 本章要解决的问题

模型最容易变成「只有作者能跑」的黑盒：权重在本地、配置在脑子里、评测脚本在一个临时目录。移交不是交一个压缩包，而是让下一个人在不问你任何问题的前提下跑出同一个数，并且知道这个模型不该用在谁身上。模型卡就是这份说明书：谁来用、能用到什么程度、在哪种情形下必须停手、停手之后找谁。

## H.2 本章目标（可检验）

- 产出一份写清适用人群、指标阈值与失效情形的模型卡
- 交出可在干净环境复现的训练与推理包
- 由未参与的第三方完成一次复现并在清单上签字

## H.3 操作流程

1. 写用途：任务是什么、输入什么、输出什么、给谁用、在门诊或教学的哪个环节用；用途一旦写宽，责任范围也随之放大
2. 写训练数据：来源、时间跨度、规模、标注方式、一致性系数、许可，与数据卡版本号对应；不得只写「某医院数据」
3. 写指标：在哪个测试集上、按什么切分、主辅指标数值与置信区间、评测脚本版本；三样缺一，数字不可比；测试集一旦更换须整段重写并注明日期
4. 写阈值：多少分以上可用于提示、多少分以下必须人工复核、阈值依据是验证集曲线还是临床要求，写明
5. 写失效情形：列出已知会错的场景（方言、罕见证型、多病共存、文本过短、检查缺失），每条配一个脱敏例子与编号
6. 写不适用范围：儿童、孕妇、急危重症等未覆盖人群明确排除；排除写不清，等于默认可用于所有人
7. 写合规：脱敏方式、可用于科研还是教学、能否商用、二次使用条件；权重与数据的许可分别注明
8. 打包：权重、配置文件、推理脚本、依赖锁、最小示例输入输出、环境说明（驱动与框架版本）同包，缺一即无法加载
9. 写复现步骤：三条命令内跑通，给一条最小示例使输出可对齐；环境安装单独一节，列出常见报错与处理
10. 第三方验证：找一位未参与的同学，在干净机器按文档跑一次，记录结果差异、耗时与卡住的地方；差异须解释
11. 记已知问题：显存下限、推理延迟、批处理限制、并发能力；每条附一次实测数值，并注明测量时的硬件型号
12. 归档签收：按仓库约定命名目录，模型卡、复现包、验证记录一并入库；移交人、接手人、导师三方签字

## H.4 现场清单（逐项打勾，缺一项不算完成）

- [ ] 模型卡含用途、数据、指标、阈值、失效情形
- [ ] 指标注明测试集、切分与脚本版本
- [ ] 阈值有依据与复核规则
- [ ] 失效情形至少三条且各附例子
- [ ] 不适用人群与场景已明确排除
- [ ] 许可与二次使用条件已写
- [ ] 权重、配置、脚本、依赖同包
- [ ] 三条命令内可跑通
- [ ] 最小示例输入输出可对齐
- [ ] 第三方在干净环境复现成功
- [ ] 硬件与显存要求已写

## H.5 模板：模型卡与移交清单

| 字段 | 填写要求 |
|------|----------|
| 用途 | 任务、输入、输出、使用者、使用环节 |
| 数据 | 来源、时间跨度、规模、标注一致性、许可 |
| 指标 | 测试集、切分、主辅指标、置信区间、脚本版本 |
| 阈值 | 提示可用线、强制复核线、定阈依据 |
| 失效情形 | 场景、表现、脱敏示例编号 |
| 不适用 | 人群、病种、文本类型、语言风格 |
| 合规 | 脱敏方式、可用范围、二次使用条件 |
| 复现包 | 权重、配置、脚本、依赖锁、环境版本 |
| 验证 | 验证人、环境、结果差异、耗时 |
| 归档 | 目录路径、版本号、签收人与日期 |

## H.6 常见失效与处置

- **只交权重** → 没有配置与依赖，加载即失败；四件须同交
- **模型卡不写失效情形** → 被用到已知会错的场景，责任在作者
- **指标不写测试集与切分** → 数字无法比较，也判断不出是否泄漏
- **阈值拍脑袋** → 没有依据的阈值在临床就是隐患
- **自己机器能跑就算复现** → 环境差异是复现失败首因；须他人干净环境验证
- **目录命名随意** → 仓库里找不到，等于没交

## H.7 中期检查与答辩要点

- 模型卡完整性与失效描述（30%）
- 复现包可运行（25%）
- 指标与阈值可核（20%）
- 第三方验证（15%）
- 归档规范（10%）
