> 机器可读常量在 `standards/semtensor/axis-colors.json`；

## 1. 定位

| 项 | 内容 |
|---|---|
| 承载对象 | 中医药语义单元：病证单元（DSU）、内经语义域、六经域、四系统、精气神三宝 |
| 承载方式 | **方向承载语义** —— 每个语义单元归一为单位球面上的一个方向 n̂(θ, φ) |
| 尺度方式 | r ∈ (0, 1] 承载语义张量尺度，供尺度伸缩（加权、剪枝、聚合） |
| 读色方式 | 点的颜色 ← 该点三轴坐标按颜色公理合成 ⇒ **色—义一一对应** |
| 读图方式 | 同类语义聚色成区，便于读「聚集 / 类别 / 相关」 |

**颜色是坐标的函数，不是装饰。** 这条不是美学要求，而是可验证性的前提：
只有颜色成为坐标的确定函数，「球面图能不能被机器判对错」才有答案（见 §12）。

## 2. 坐标系与口径（本仓库采 v1.0 仰角口径）

| 量 | 区间 | 含义 |
|---|---|---|
| r | (0, 1] | 径向距离 = 语义张量尺度 |
| θ | [−90°, +90°] | **仰角** elevation（赤道 0，天顶 +90°，天底 −90°） |
| φ | [0°, 360°) | **方位角** azimuth（自 +X 轴起算，绕 +Z 轴逆时针） |

```
球 → 笛卡尔： X = r·cosθ·cosφ ,  Y = r·cosθ·sinφ ,  Z = r·sinθ
笛卡尔 → 球： r = |v| ,  θ = asin(Z/r) ,  φ = atan2(Y, X)（归一至 [0°,360°)）
```

### 2.1 口径裁定：θ/φ 的字母分工

源资料里存在**两套互不兼容的口径**，此前一直挂着未裁定：

| 来源 | θ | φ | 公式 |
|---|---|---|---|
| 用户规格书《中医药领域语义向量极坐标表示.docx》§03/§05 | 极角 polar angle (0, π) | 方位角 (0, 2π) | `X = r·sinθ·cosφ, Y = r·sinθ·sinφ, Z = r·cosθ` |
| 平台代码（`axis_color.sph_vec`）与 `SHL_目录.json` | **方位角** | **仰角** | `u = (cosφ·cosθ, cosφ·sinθ, sinφ)` |

**本仓库采 v1.0 规范的仰角口径**（θ = 仰角、φ = 方位角），理由：
它使 θ、φ 与「仰角/方位角」的字面含义一致，且与源数据集里的 `φ`（−54…+60）自洽 ——
真正的仰角取值范围必然有正有负，而极角恒为正。源数据集的 `θ`（−180…+180）则显然是方位角。

换算（旧稿极角 → 本仓库仰角）：`θ_仰角 = 90° − θ_极角`，φ 不变。
旧稿「赤道 θ=90°」→「θ=0」；「北极 θ=0°」→「θ=+90°」；「南极 θ=180°」→「θ=−90°」。

读源数据集时**必须换算**，不能把两套 θ 直接比较 —— 见 `scripts/build_semtensor_datasets.js` 的
`source` 字段（原样保留源口径）与 `theta`/`phi`（v1.0 口径）并列存放。

## 3. 数轴两段三点 I / O / T

两段：负值段 I[−1] → O[0]；正值段 O[0] → T[+1]（T 端带实体箭头）。
三点：I 负端、O 原点、T 正端。

**O 点三轴共有，基准色 = 绿 `#00B050`（533 nm）—— 不是灰。**

| 轴 | 语义 | I (−1) | O (0) | T (+1) |
|---|---|---|---|---|
| X | 阴阳（左右） | 橙 605nm `#FF8C00` | 绿 533nm `#00B050` | 紫 415nm `#8A2BE2` |
| Y | 表里（前后） | 蓝 458nm `#1F61D9` | 绿 533nm `#00B050` | 红 685nm `#DB1C1C` |
| Z | 精气神（足→首） | 黄 578nm `#F2C200` | 绿 533nm `#00B050` | 青 493nm `#00C7C7` |

端色基准 = 可见光波长序段中位数（序段跨度 50nm）：
红 685 / 橙 605 / 黄 578 / 绿 533 / 青 493 / 蓝 458 / 紫 415（nm），
对应中位能容 1.81 / 2.05 / 2.15 / 2.33 / 2.52 / 2.65 / 2.99（eV）。
红外 >750nm（<1.80eV）、紫外 <350nm（>3.00eV）、白光 560nm（2.21eV）。

| 轴 | I 语义 | O 语义 | T 语义 |
|---|---|---|---|
| X | 阴 | 中（阴阳平和） | 阳 |
| Y | 表 | 半表半里 | 里 |
| Z | 精（形质） | 气（能量） | 神（神志情志） |

## 4. 颜色公理

```
单轴渐变  ramp(t, 轴)：在 [−1, 0, +1] 三色间逐通道线性插值
合成色    w_i = clip(|v_i|, 0, 1) ； k = max(w_i)
          C = (1 − k)·绿 + k·( Σ w_i·c_i / Σ w_i )
```
其中 `c_i` 取第 i 轴在 `sign(v_i)` 一侧的端色（v_i<0 取 I 端，v_i>0 取 T 端，v_i=0 时 w_i=0 不参与）。

性质：
- **O 点回基准绿**：三轴全零时 k=0 ⇒ C = 绿（不是灰，也不是黑）。
- **弱偏离近基准绿**：三轴都很小时颜色仍接近绿。
- **三轴同强时趋向三端色的加权混合**（等权时即三端色的算术平均）。
- **镜像不变色**（见 §6）。
- **对符号敏感**：v 与 −v 必异色，否则读不出方向。

### 4.1 一个必须分清的地方：颜色取「方向」，不取「尺度」

规范 §10 明写「尺度伸缩 r′ = clip(r×gain)（方向与颜色不变）」。
若合成色的输入取 `r·n̂`，缩放 r 就会改色，这条不变式立刻不成立。

§5 的 `C = comp(x, y, z)` 与 §10 并不冲突：那里的 (x,y,z) 是**八纲编码分量**，
与 §5 自己的 r（证据等级/症状密度/桥接完备度）是**两套独立输入** ——
(x,y,z) 定方向与颜色，r 只定尺度。渲染与相似度一律用单位方向取色。

## 5. 三轴语义定义与确定性编码

```
x = 0.60·阴阳(八纲) + 0.40·寒热(八纲)
y = 0.70·表里(八纲) + 0.30·虚实(八纲)
z = (神分 − 精分) / (精分 + 气分 + 神分 + 1)          ← 精气神关键词判位
r = clip( 0.35·证据等级 + 0.35·症状密度 + 0.30·桥接完备度 , 0.20 , 1.00 )

n̂ = unit(x, y, z) ； θ = asin(z/|v|) ； φ = atan2(y, x) ； C = comp(x, y, z)
```

八纲取值：阳证 +1 / 阴证 −1；热证 +1 / 寒证 −1；表证 −1 / 半表半里 0 / 里证 +1；
实证 +1 / 虚证 −1；**未列项 0**。

证据等级：A 1.00 / B 0.75 / C 0.50 / 其它 0.40。
症状密度：`min(1, (主症数 + 次症数)/10)`。桥接完备度：`min(1, len(桥接描述)/200)`。

同一份输入必然得到同一组数字 —— 这是「零文本依赖」通道的前提。

### 5.1 未定义情形：三轴全零（本仓库裁定）

八纲与精气神全空时 `(x,y,z) = (0,0,0)`，而 `unit(0,0,0)` **未定义**。
原规范没有写这一条。本仓库的裁定：

- 方向取基准方位（θ = 0、φ = 0）；
- 同时返回 `degenerate = true`，渲染层用**空心点**画它。

理由：若不打标记，一个「三纲未列」的单元会与真实落在该方位的单元长得一模一样，
读者会把「没有信息」误读成「就是阳/表/气」。宁可画得显眼，也不要画出假精度。

### 5.2 未实现：自由文本启发式投影

原规范提到查询侧的自由文本投影 `encoder.encode_text()`（长关键词按序切除避免二次计数）。
本仓库**不实现**它：原文只给了思路、没有给可判定的规则，凭思路复刻出来的东西
无法与源系统对齐，只会造出一个「看起来能用」的黑箱。权威分量始终来自八纲字段的确定性映射。

## 6. 母子父三球与镜像

| 球 | 称谓 | 性别 | 镜像符号 (sx,sy,sz) | 三轴图面角 X+/Y+/Z+ | X–Y 图面夹角 |
|---|---|---|---|---|---|
| ① | 母 | 女 | (−1, −1, +1) | 180° / 135° / 90° | 3π/4 |
| ② | 子 | 男 | (+1, +1, +1) | 0° / 45° / 90° | π/4 |
| ③ | 父 | 男 | (+1, +1, +1) | 0° / 45° / 90° | π/4 |

场景：三者迎面走向医生；医生「左侧-中间-右侧」= 母-子-父；三者左手侧 = 医生右手侧。

**镜像规则：**
```
几何位置 = M(sex) · n̂
取色坐标 = M(sex) · (M(sex) · n̂) = n̂        ← 反镜像补偿
⇒ 同一语义单元在母/子/父三球上同色，三球共用同一张轴色表
```
实现上必须**按规范写成两次镜像的复合**，不能直接返回 n̂ ——
直接返回会让「镜像不变色」这条性质变成同义反复，测试随之失去意义。

②子与③父镜像符号相同，故几何与着色一致；差异在语义点云的**域归属**
（子 = 成长/受教侧，父 = 家学/传承侧），由平台按会话域决定挂载哪些语义单元。

## 8. 画布规范

**画布内不出现汉字**：球面图内只用 X/Y/Z、θ/φ 数字与圈号 ①②③。
所有汉字母语（六经域/语义域名/口径说明）**全部下沉图注**。

理由：球面图是要被机器核对的（§12），而汉字会引入字体依赖与不可控的排版差异；
更重要的是它逼着图注承担说明职责 —— 而图注是可编辑、可实例化的文本。

## 9. 图注规范（INI 风格三段制）

图注是**可实例化的参数载体**，不是说明文字。**改文本即改图。**

```ini
[球]
no = 1
name = 母
sex = 女
sign = -1,-1,1
angle_x = 180
angle_y = 135
angle_z = 90
xy_face = 3π/4
mirror_point_cloud = true

[参数]
rings = 45
seg = 70
azimuth_step_deg = 30
elev_ticks_deg = 30
arrow_head = 13
cloud_point_size = 9
cloud_alpha_rim = 0.95
cloud_alpha_face = 0.30
view_elev_deg = 20
view_azim_deg = -60

[图注正文]
# 自由多行；# 开头为注释
数字 ↔ 域名映射表写在这里。
```

参数应用实例化三条通道：
1. 交互视图中「编辑图注文本 → 应用参数并重绘」；
2. 交互视图中「从文件载入 .txt」；
3. HTTP 环境下页面自动 fetch 同目录 `图注-*.txt`（`file://` 下自动回退内嵌文本）。

## 10. 语义张量计算

| 量 | 公式 |
|---|---|
| 方向相似 | `cosΔ = sinθ₁·sinθ₂ + cosθ₁·cosθ₂·cos(φ₁−φ₂)` |
| 尺度相似 | `min(r₁,r₂)/max(r₁,r₂)` |
| 色差 | `ΔRGB/√3`（归一 0–1） |
| 张量相似 | `S_T = 0.65·(cosΔ+1)/2 + 0.15·尺度相似 + 0.20·(1−色差)` |
| 尺度伸缩 | `r' = clip(r × gain, 0.05, 1.00)`（方向与颜色不变） |
| 域聚合 | 方向取加权平均方向并归一；r 取加权平均；颜色由聚合方向重新合成 |

## 11. 独立成库与三通道融合

独立成库（`kg/semtensor.db`，自持单一 SQLite 文件，三条通道可单独使用）：

| 通道 | 载体 | 说明 |
|---|---|---|
| 语义张量 | `st_units`（三分量 / r / θ / φ / RGB / HEX / 元数据） | `search_tensor(分量)` 零文本依赖 |
| 词法 | `st_fts`（FTS5 trigram） | 中文子串级召回，无需分词器；<3 字走 LIKE 兜底 |
| 词袋 | `st_tfidf`（字符 bigram TF-IDF 稀疏向量） | 零依赖 |

与平台既有可计算参数融合：`S(u) = α·S_vec + β·S_fts + γ·S_tensor + δ·S_color`，
默认 α=0.45 β=0.25 γ=0.20 δ=0.10；模式 `fuse` / `tensor_rerank` / `tensor_scale` / `standalone`。

**RRF 口径**：只命中单一引擎的条目，另一引擎 rank 记 `None`（贡献 0），**不得以 0 充数**
（否则单引擎条目虚高）；小库 k = 2。

冻结的对外契约：`GET /semtensor/spec` 为标准的机器可读镜像；`GET /semtensor/health` 给出口径与公理指纹。
前端、图注、文档一律读此二者，**不得复制常量**。

> 本仓库当前状态：§11 的数据库与 API 属**平台侧**能力，尚未在本仓库实现。
> 本仓库提供的是 §2–§10 的计算核心、呈现层与硬证据测试。不要把它说成已经接通。

### 12.1 为什么第 6 条最值钱

实测中它一次抓出两个**不会报错**的网格 bug：

- `curvatureDensity` 里把「顶点的**坐标**」当成「顶点的**下标**」用。
  拿字符串当 TypedArray 下标是静默无效的 —— 面积全为 0，均值变成 `NaN`，不抛异常。
- `ring 0` 的 θ 落在**南极**附近却被接到北极点上，那些三角面横跨整个球互相覆盖，
  **Σ面积反而大于 4π**（内接多面体不可能超过球面积）。

两条都不报错、不影响程序退出码，只让图悄悄画错。Σ角度亏损 = 4π 这条断言把它们一次抓干净。

## 14. 待裁定项（实测发现，需源系统或人工裁定）

### 14.1 颜色公理未定义 `c_i`，且源实现自身给出了两条互不相符的取色路径 ★★

书面规范 §4 写的是：

```
C = (1 − k)·绿 + k·( Σ w_i·c_i / Σ w_i )
```

**但全文没有定义 `c_i`。** 两种自然读法：

| 读法 | `c_i` 取什么 |
|---|---|
| A | 该轴在 `sign(v_i)` 一侧的**端色**（纯色） |
| B | `ramp(v_i, 轴)` —— 该分量取值处的**插值色** |

两者在 `|v_i| = 1` 时相同，在 `0 < |v_i| < 1` 时不同。

**实测（源实现自带的 116 个单元，脚本可复核）**：

```
$ node scripts/verify_semtensor_axiom.js
  样本        116 个带 x/y/z 与 hex 的单元
  A 端色读法  2/116 吻合
  B ramp 读法 2/116 吻合
  ✅ 仅 |v|=1 的单轴点命中（精 #F2C200、神 #00C7C7）
```

**结论（比原先的判断更进一步）**：源实现内部本身就有**两条互不相符的取色路径** ——

- `DATA.units[].hex` 由 Python 编码器（`kg/semtensor/axioms.py` + `encoder.py`）产出；
- 页面渲染时用 **JS 的 `comp()` 重算颜色，并忽略 `u.hex` 字段**
  （源实现第 232 行：`const c = comp([u.x,u.y,u.z]);`）。

也就是说：**同一个单元，源数据的元数据说一种颜色，源页面画的是另一种颜色。**
连同书面规范里那条空的 `c_i` 定义，一共有三处口径没有对齐。

因此本仓库的处理是：

1. **不声称复现源系统的配色**；
2. 数据集同时保留 `colorSourceHex`（源值，原样）与 `colorDerived`（按本仓库公理算出），逐点可对照；
3. 采用读法 **A**（端色）：它与书面规范里「轴端色表」是同一套概念，且能保证
   `comp` 对符号敏感、`|v|=1` 时精确落在端色上这两条性质。**这是一次显式裁定，不是"实现细节"。**
4. 若要改为读法 B（源页面做法），改 `site/semtensor.js` 的 `comp` 一处即可，
   但必须同时重跑全部颜色断言并更新本节。

### 14.6 退化单元在源数据里真实存在

源数据的「气」节点是 `x = y = z = 0` —— 正是 §5.1 里那个书面规范未定义的情形。

| 口径 | 「气」的取值 |
|---|---|
| 源数据 `hex` 字段 | `#00C7C7`（Z 轴 T 端青） |
| 按颜色公理 | `#00B050`（基准绿） |

**源数据在这一点上与自身公理不一致**（其值恰好等于 Z 轴正端的颜色，
像是编码器在零分量处走到了轴的起点）。

本仓库的处理：取基准绿 + `degenerate = true` + 渲染为**空心点**（§5.1）。
与源数据不同，也不假装相同 —— 空心点的意义正是「这个单元没有方向信息」，
把它画成一个落在某方位上的实心点会凭空造出不存在的语义。

### 14.7 源实现比书面规范多出的常量

源实现（`standards/semtensor/sources/`）的 `params` 有 23 个键，书面规范只规定了其中一部分。
已全部记录进 `axis-colors.json` 的 `sourceImplementation.params`。两处值得注意：

- **箭头**：书面规范 §7 写「箭头锥半顶角约 13°」，源实现的参数是 `arrow_head = 6.5`
  —— 量纲不符合角度，二者命名相同而含义不同。本仓库按书面规范取 13°。
- **仰角刻度**：源实现在仰角上也画刻度（`elev_ticks_deg = −60/−30/0/30/60`），
  书面规范只规定了方位刻度。本仓库当前只实现方位刻度，这一点在 §13 的未实现项里。

### 14.2 内经域的球面映射是本仓库的本地约定

§5 的编码公式针对 DSU，需要「证据等级/症状密度/桥接完备度」三字段；
域级数据（篇/章/节/字数）没有这些字段。本仓库的映射（见生成器注释与数据集 `mapping` 字段）：

```
φ (方位角) = (内序 − 1) × 30°                       ← 12 域 × 30° = 360° 闭合
θ (仰角)   = (2 × 篇占比/最大篇占比 − 1) × 90°        ← 占比最大的域接近天顶
r (尺度)   = clip(0.20 + 0.80 × 篇占比/最大篇占比, 0.20, 1.00)
```

这是**本地约定，不是规范原文**。它被完整写在数据集的 `mapping` 字段里，可被复核与替换。

### 14.3 母子父的 A/B 方案

- A：三球共用几何坐标系、阳侧随人翻转；
- B：严格按规格书让 T(+1) 随性别镜像。

本仓库采 **B + 反镜像补偿**（即 §6 的规则），三球同色。A/B 的取舍影响「母球右阳左阴」的读法，
需人工裁定。

### 14.4 是否改为严格波长 → sRGB 配色

现为 RGB 逐通道线性近似（端色已按波长序段中位数取定，但**段内**的插值不是物理的波长→色度转换）。
若要严格，需引入 CIE 1931 色匹配函数 —— 与「零依赖」约束冲突，需先裁定。

### 14.5 三轴全零的退化方向（本仓库已裁定，仍待确认）

见 §5.1。本仓库取「基准方位 + `degenerate` 标记」，需确认是否符合源系统意图。
