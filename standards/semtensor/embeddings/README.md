# 嵌入层 · 实现源材料 `embedding-code` 规格

> 生成的机器可读产物：`index.json`（**不入版本库** —— 纯派生，`node scripts/build_embeddings.js` 可重跑）
> 实现：`scripts/build_embeddings.js` · 测试：`tests/test_embeddings.js`

## 规格从哪来

`standards/knowledge-tree/sources/中医知识树.xlsx` 的 `embedding-code` 工作表，标题写着
「embedding-code · ICD-11 / TF-IDF / FTS5 / RRF / 上下文工程（**tcmP 真实实现**）」。
它把平台的检索编码引擎写成八个编号组件，并附了线上实测输出。

**这张表在本仓库里躺了很久，八个组件一个都没实现。** 本文件是第一次实现，并逐条记录
"规格要什么"与"我有什么"的差距。

## 规格的八个组件 × 实现状态

| # | 规格 | 状态 | 说明 |
|---|---|---|---|
| ① | Document 构建（病侧＋证侧 → 单文本） | ✅ 实现，**输入不全** | 见下「输入字段」 |
| ② | 中文分词（字符 bigram + 英文词） | ✅ | `tokenizeBigram()` |
| ③ | TF-IDF 字符 n-gram（零依赖起步） | ✅ | sklearn 默认口径：`smooth_idf` + `norm='l2'` |
| ④ | SQLite FTS5 全文索引（BM25） | ⚠️ **等价物** | 见下「偏离 2」 |
| ⑤ | RRF 融合（k=60） | ✅ | `rrf(rankLists, k=60)`，测试钉死 1/61 |
| ⑥ | 上下文工程（只送 Top-5 叶 ≈1.5K token） | ✅ | `--query` 走的就是 Top-5 |
| ⑦ | ICD-11 客户端（双通道） | ❌ **未实现** | 需要内网 `192.168.0.111:8080` 与本地 `data/icd11_mms.db`（31,838 实体）——**本机都没有** |
| ⑧ | 知识树查询（`path()` / `neighbors_full()`） | ⚠️ 部分 | `path()` 可用（12 个 DSU 有学科枝）；`neighbors_full()` 需要的边值不在资料里（只有边型**条数**） |

## 输入字段：规格吃 10 个，我手上只有 1 个是满的

规格的 `build_document()` 读 10 个字段。实测 103 个 DSU 的供给：

| 字段 | 覆盖 | 来源 |
|---|---|---|
| `syndrome`（证名） | **103/103** | `reference-units.json` |
| `disease`（西医病） | **12/103** | xlsx「图谱接口」**样例表**（12 行，非全表） |
| `icd`（ICD-11 编码） | **7/103** | 同上；样例里还有 5 行的编码单元格是**空的** |
| `dcat` / `dsym` / `pat` / `zf` / `six` / `ssym` / `formula` | **0/103** | 不在本仓库的资料里（源平台 `kg/` 下那 7 个病证单元文件没有随资料来） |

**空字段的处理是刻意的：缺席表现为缺席。** 不写「疾病：未知」，也不拿证名去猜病名 ——
写进去的占位词会拿到自己的 IDF 权重，把整个向量空间污染，而污染是看不见的。

## 实测结果（2026-10-13，本机）

语料：**443 个文件 / 1860 万字**（`textbooks/` `standards/` `glossary/` `departments/`）。
文档集：116 个语义单元（103 DSU + 13 概念单元）；每个 DSU 的文档 = 规格模板（有值的片段）
+ 该证名在语料中出现的上下文窗口（至多 4 段 × ±140 字）。

### 变体对比（②bigram 与 ③1–3gram 在源材料里本身就互不一致，两个都跑）

| 变体 | 词表 | 每篇 token | kNN 纯度（证尾族） | 轮廓系数 | 轮廓系数 |
|---|---|---|---|---|---|
| `ngram13` | 15,689 | 2,137 | 0.198 | **−0.027** | |
| `bigram2` | 5,202 | 221 | **0.320** | +0.056 | |

**两个变体的轮廓系数都在 0 附近或为负 —— 即：这些向量没有恢复出语义邻域。**
轮廓为负意味着簇内散度大于簇间散度，比随机指派还差。1–3gram 的词表大 3 倍、
每篇 token 多 10 倍，结果反而更差：**长文档把区分度稀释了**（这是词袋模型的经典失效，不是调参能救的）。

### 检索冒烟：规格记录了 3 条端点行为，复现 1 条

| 规格记录的端点 | 期望 | 实现结果（全部单元） | 判定 |
|---|---|---|---|
| `/semantic-search?q=失眠` | 心脾两虚证 | `DSU-00035 · 心脾两虚证` | ✅ **一致** |
| `/bianzheng?q=口苦,咽干` | 肝胆湿热证 | `DSU-00099 · 肝气郁结、冲任失调证` | ❌ |
| `/diag?q=恶寒,发热,无汗` | 风寒束表证 | `DOM-SIX-少阴病 · 少阴病` | ❌ |

**失败的原因能定位，而且不是算法。** 后两条的查询是**症状**（恶寒/发热/无汗、口苦/咽干），
而规格的 Document 正是靠 `dsym`/`ssym`（西医症状 / 主症）去接这些词 ——
那两个字段我 **0/103**。第一条命中的 `失眠` 之所以能成，是因为「失眠」这个词
在语料里与「心脾两虚证」共现得足够密，是靠**语料上下文**兜住了。

换句话说：**① 的字段缺口与 🔍 的命中率是同一件事的两面。**

### 与上游 `vectorization-ICD11` 的对照

上游的结论是 **"Descriptions are all you need"** —— 在 ICD-11 上，把描述
（而非仅仅编码/标题）向量化，七个模型横评，才拿到可用的语义结构。

对照到本仓库，结论方向相同但**当前落在反面**：

- 我**没有描述**。103 个 DSU 的"描述"是用证名在教材语料里的上下文窗口拼的，
  这些窗口大量来自表格行与顺带提及 —— 它是**关键词共现**，不是**定义**。
- 上游评测嵌入质量用轮廓系数 / Calinski-Harabasz / Davies-Bouldin / kNN 邻域；
  本层借了 **kNN 纯度 + 轮廓系数**两项（纯 Node 可实现）。**两项都在 0 附近，是一致的信号。**

**这不是"嵌入模型选得不好"，是"还没有东西可嵌入"。** 要跨过这一步，缺的不是换模型，
是给 103 个 DSU 写出真正的描述（病因、病机、主症、舌脉、治法）—— 那正是本仓库
`textbooks/` 这条交付物线该产出的东西。

## 三处与规格的偏离（都显式记录在 `index.json.deviations`）

1. **输入字段不全**（上表）。空字段不占位、不倒推。
2. **④ 不是 SQLite FTS5。** 本机没有 SQLite，且本仓库坚持零第三方依赖。
   BM25 是**公式**而不是数据库特性，这里在进程内实现它（倒排索引 + BM25，`k1=1.2, b=0.75`）。
   排序与 FTS5 同源，但「是 FTS5」这句话不成立，所以不这么写。
3. **② 与 ③ 在源材料里互不一致**：②写 bigram，③用 `ngram_range=(1,3)`。
   两个都实现，默认 1–3gram，**不做取舍** —— 取舍的依据不在我手上。

## 用法

```bash
node scripts/build_embeddings.js              # 出向量 + 评测 + 报告
node scripts/build_embeddings.js --query 失眠  # 检索（向量 ∪ BM25，RRF 融合）
npm run embeddings                            # 同上
```
