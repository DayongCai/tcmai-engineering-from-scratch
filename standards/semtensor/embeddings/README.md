## ④ 为什么能撤：上次说「本机没有 SQLite」，这次为什么不成立了

上一版这里写着「本机没有 SQLite，所以 ④ 用进程内 BM25 做等价物」。那句当时为真，**现在为假**：

```bash
node -e "new (require('node:sqlite').DatabaseSync)(':memory:').exec(
  'CREATE VIRTUAL TABLE t USING fts5(a)')"     # 本机 v22.22.0 通过，sqlite 3.50.4
```

**依赖一个都没加**，用的是运行时自带模块。所以偏离被**撤销**，不是被封存 ——
测试 `「本机没有 SQLite」这条偏离必须已被撤销，不许留在报告里` 会盯着这件事，
防止旧话术回流。

### 中文进 FTS5 的实测坑（这是 ④ 唯一的真问题）

FTS5 自带分词器没有一个能直接用中文。本机实测：

| 分词器 | `心脾两虚`（文档里是「心脾两虚证」） | `失眠`（空格隔开的完整 token） |
|---|---|---|
| `unicode61` | **0 命中** —— 整段 CJK 被当成**一个** token | 命中 |
| `trigram` | 命中（子串，≥3 字符） | **0 命中** —— trigram 要求查询 ≥3 字符 |

两个都残，所以**不在 SQLite 侧分词，在写入侧分词**：

- `docs_terms` 表：写入前用 ② 的 bigram 切好、空格连接，交给 `unicode61`。
  「心脾两虚证」变成 `心脾 / 脾两 / 两虚 / 虚证` 四个 token，查询串走同一个分词器 → 命中是必然的。
- `docs_substr` 表：原文交给 `trigram`，负责**子串**检索（补「只记得标题一半」）。
- 两张表在同一个 db 文件里，各自出分、由 RRF 融合。**分词口径与向量通道的 ② 是同一个函数**
  （测试钉死 `F.segment(s) === E.tokenizeBigram(s)`），三通道共用一套词，不是三套。

#### 第 2 条为什么复现不了 —— 定位到了，不是算法

`口苦,咽干 → 肝胆湿热证` 这条**在本仓库的数据里不可能由词面检索得到**，原因是可核的：

- 肝胆湿热证（DSU-00007）的 `sampleSymptoms` = 发热、汗出黏腻、口干、口渴不多饮、痰多、身重困倦 —— **没有「口苦」，也没有「咽干」**；
- 它的 5 条外源释义里，**两个字一次都没出现过**；
- 而这两个词在库里有落点：含「口苦」的证候 6 条（膀胱湿热证、胆郁痰扰证、肝火上炎证、肝胃不和证、肝郁脾虚证、脾胃湿热证），含「咽干」的 6 条（肺阴亏虚证、肝火上炎证、肝肾阴虚证、心肾不交证、血热风盛证、**阴虚肺燥证**）。

所以 top1 落在阴虚肺燥证（它有「咽干」）而不是肝胆湿热证 —— **这是数据的缺口，不是排序的 bug**。
规格那条期望是**临床判断**（口苦咽干 = 少阳/肝胆），临床判断不会自己变成词频。
补法只有一条：给 DSU-00007 补上这两个症状词，且**必须有出处**（不能为了跑通测试而写进去）。

## ⑦ ICD-11 术语通道（本轮真正「启用」的那一半）

`scripts/icd11_terms.js` 把 `data/icd11/` 的 13,960 条实体做成**术语嵌入层**：

- **entity 单元 13,062 条**（有编码的实体）—— 按论文 Listing 2 的字段拼；
- **term 单元 61,846 条**（10,855 个实体的索引词去重 61,130 + 第 26 章 WHO 官方中文名 472 + 索引词扩容）——
  一条术语一条向量，`Term: {term} → Maps to disorder: {title} ({code})`。
  **这就是「术语嵌入性编程」**：先命中术语、再由术语带着编码回来，而不是全靠整段定义去撞；
- 词表 20,000 · nnz 1,202,315 · CSR 9.5 MB · FTS5 两表 · top-k 4。

**第 26 章分两个体系，单元带 `module`**（依 ICD-11 Reference Guide §3.2.26 / §2.23.24，
原文与推导见 [`standards/icd11/tm1/README.md`](../../icd11/tm1/README.md)）：

| module | 条数 | 是什么 |
|---|---|---|
| `TM1` | 472 | 中医/日韩传统医学：脏腑、六经、卫气营血、气血津液（`SF/SG/SH` 是 **pattern 证候**） |
| `TM2` | 648 | Module II：阿育吠陀 `Vata predominant`、悉达 `Varmam and Marmam` —— **不是中医** |

`runSearch({modules:['TM1']})` 的语义是**只拦 TM2，不拦第 1–25 章**：参考指南 §2.23.24 的编码方案
就是「WM 诊断 + TM1 证候」并列（原文例子：Asthma `CA23.32` + `SF86`）。上一版用「标题含 `(TM1)`」
当滤网，把西医章节一起拦了，结果「失眠」只能落到血证条目 —— 那是用法错误，不是数据缺失。

**中文有两条腿**（各管一段，混着说就会把「名字对上了」说成「诊断对了」）：

1. **官方中文名 → 同名通道**：第 26 章 TM1 侧 472 条（含 173 条 pattern 证候）有 WHO 官方中文名，
   查询逐字相同即排第一。回查 **472/472（100%）**。这是**名字级**的命中，不涉及语义。
2. **等价类 → 英文探针**：其余中文（证候名、症状词）换成语义张量等价点上的英文成员再检索。

```
中文查询 ──等价类（同一个张量点 (θ,φ,r)）──▶ 英文成员 / 组合探针 / 词表直译 ──▶ ICD-11 术语层
         └─官方中文名（150 条）─────────────── 同名通道（逐字相同）────────────┘
```

上一版这里是「中文 → 该证候的 **WHO 英文名字段** → 术语层」，而那个字段**只有 26/104 个证候有** ——
桥太窄，等于没有桥。现在换成语义张量的等价映射（`standards/semtensor/equivalence/`，
等价 = 同一个张量点，不是相似度近邻），四级判据各有出处：

| 级 | 判据 | 例 |
|---|---|---|
| A/B/C | 等价类成员（真等价，带 WHO 代码与书页） | 肝胆湿热证 ↔ `liver-gallbladder dampness-heat pattern/syndrome`（WHO ISTT 2.9.91） |
| D | 切词拼出的**组合探针**（不是等价，只给检索用） | 痰热壅肺证 → `phlegm + heat + lung + pattern/syndrome`（覆盖 0.80） |
| E | 词表直译（覆盖自由文本，不宣称等价） | 失眠 → `inability to sleep`（WHO 2.3.53） |

**DSU 可翻译 93/104（89.4%）**（有英文成员 33 · 仅组合探针 60），未解析 11 条如实列出。
纯中文查询时限定 ICD-11 第 26 章（TM1，传统医学补充章）—— 不限定会把 2 型糖尿病拽进来（实测过）：

```
失眠           → SF62 Dual deficiency of heart qi and blood pattern (TM1) · SF6J
恶寒 发热 无汗   → SF87 Exterior cold with lung heat pattern (TM1) · SE76 Exterior pattern (TM1)
痰热壅肺证      → SF89 Phlegm heat obstructing the lung pattern (TM1)（组合探针直取）
```

产物里每条记 `path: 'direct' | 'equivalence' | 'none'`、`probes[]`（带级别）与 `fallbackUnfiltered`；
`index.json.icd11TermLayer.equivalence` 记等价层计数。
中文直查命中率（`npm run icd11:terms:eval`，104 证候，排除 TM2）：**top-1 落到 TM1 103/104 · top-4 含 TM1 104/104 · 无命中 0**，
改造前（字面通道）是 **0/104**。官方中文名回查 **472/472（100%）**（同名通道，名字级，非语义级）。
复合证名的 D 级探针改由**四轴组合器**生成（`build_tm1_axes.js`）：切词 → 每片归轴 → 按官方轴序重排
（locus → severity → cause → property）→ 查同构先例；**归不了轴的词如实列出**，不假装它也是四轴词。
「名字撞上」与「语义懂了」分开记，才知道补的是哪一半。

## 仍然存在的偏离（`index.json.deviations` 里逐条可查）

1. **输入字段不全**（见上表）。空字段不占位、不倒推。
2. **③ 不是稠密向量**：论文用 LangChain + ChromaDB + 稠密 embedding；本层是 TF-IDF 稀疏 + 余弦，
   语义泛化弱于稠密向量 —— **口径差，不是等价实现**。
3. **② 与 ③ 在源材料里互不一致**（②写 bigram，③用 `ngram_range=(1,3)`）。两个都实现：
   向量默认 1–3gram，FTS5 写入侧用 bigram，**不做取舍** —— 取舍的依据不在我手上。

## 用法

```bash
node scripts/build_embeddings.js                    # 出向量 + 评测 + 报告（含 FTS5 建库）
node scripts/build_embeddings.js --query 失眠        # 三通道检索
node scripts/build_embeddings.js --context 失眠 --topk 4  # 论文式上下文块（含 ICD-11 侧）
npm run embeddings                                  # 同上
npm run equivalence                                 # 重建语义张量等价类（约 1 s）
npm run equivalence:check                           # 等价映射体检
npm run icd11:terms                                 # 重建 ICD-11 术语层（约 27 s）
npm run icd11:terms:eval                            # 中文直查评测（104 证候 / 症状词 / 规格端点）
npm run icd11:terms:stats                           # 只读现状
node scripts/icd11_terms.js --query "insomnia"      # 直查术语层（英文）
```
