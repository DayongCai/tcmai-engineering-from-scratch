# [textbooks-batch] 桌面 100 份学科种子稿 → [textbooks] 学科教材

本目录记录一批**源工作簿 → 教材正文**的抽取账本。它回答三个问题：这批教材正文从哪来、
抽了多少、哪些没抽进来。

| | |
|---|---|
| 源 | `C:\Users\user\Desktop\textbooks\qhzy-<学科>.xlsx`（100 份，51 MB，**不入库**） |
| 抽取 | `node scripts/import_textbooks.js` |
| 产物 | `textbooks/<院系>/<学科>/00-前言.md` + `NN-第N章-<标题>.md`（99 门学科） |
| 保全 | `fulltext/<学科>.md`（0 份树外学科 + 1 份人工定稿底本） |
| 账本 | `registry.json`：sha256 · 字节 · 表数 · 章表清单 · 逐章字数 · 状态 · 缺口 |

## 为什么原件不入库

100 份合计 51 MB 二进制，而每份的 `sha256 + 文件名 + 字节数` 已足以验证「眼前这份是不是当初那份」。
入库的是**可核对的指纹**，不是 51 MB 的副本。要连原件一起自包含，可另行把 xlsx 拷进
`fulltext/` 旁并更新 registry —— 本脚本不做这件事，因为它会让仓库体积翻倍而可验证性不增加。

## 四种状态（registry.json 的 `status`）

| status | 含义 | 数量 |
|---|---|---|
| `textbook` | 已写入 `textbooks/<dept>/<subject>/` | 99 |
| `fulltext` | 学科树里仍没有对应学科，正文保全在 `fulltext/`（现已清零） | 0 |
| `manual` | 人工稿已定稿，源工作簿只作底本留档（不再生成教材） | 1 |
| `no-body` | 工作簿只有大纲表（Part/Chapter/Section/Notes），没有逐章正文段落 | 1 |

## 抽取口径（可复核）

- **不改写**：正文逐块搬运，节 / 小节 / 细目层级来自源表结构列（五列「章/节/小节/段/内容」、
  两列「类型/内容」、三列「类型/四级编码/内容」、五列「卷/…」五种形态，逐份实测判定）。
- **不抽样**：每份的每一张章表都抽，逐章字数写进 `registry.json`，`--check` 逐章对账。
- **不编造**：章首「本章要回答的问题」、N.2–N.5 这些改写层节次**一律留空**，只在前言里写明缺什么。
  源正文当成品交付是不诚实的 —— 字数只证明「有字」，不证明「按契约写」。
- **表与代码**：源表的 markdown 表行原样接续成表；「代码」行包进 ```text 围栏。

## 已知差异（写在这里，免得被当成 bug）

1. 《中医信息学》《中医知识树》《中医智能仪器与可穿戴设备》另有「0正文总表」，比章表多出
   字段列（内涵/知识点/桥接等），本脚本只取章表正文，总表里的附加字段**未并入**。
2. 《中医药AI导论》是纯大纲表，没有正文段落，故 `no-body`；其正文需另找源（或按大纲写）。
3. 章序号取自源表名/章标题（`第N章`、`卷N`、表名数字前缀）；无编号的附章排在最后，序号顺延。

## 重建

```bash
node scripts/import_textbooks.js --list        # 先量：文件 ↔ 学科 ↔ 章数/字数
node scripts/import_textbooks.js --all         # 全量抽取（约 15 s）
node scripts/import_textbooks.js --batch 2 --of 5   # 分批
node scripts/import_textbooks.js --only 方剂学      # 单科
node scripts/import_textbooks.js --check       # 逐章对账，不一致退出非 0
node textbooks/build_book.js --check           # 全库教材字数统计
```
