## 引擎从哪来（不是我自己设计的）

`外因六淫.xlsx` 的 `9数字人对话架构` 表里有一份**完整的「逆转推理引擎（症状 → 病机 → 病位 → 六淫）」**，
标注为源平台的**辨证诊断核心**。它给出了算法与数据：

**算法（源表 §2.1，逐字落地）**

```
强度档 x：明显 0.8 / 中等 0.5 / 轻微 0.2
高斯 g(x)：σ=0.42, μ=1.0  →  0.8→0.89 / 0.5→0.49 / 0.2→0.16      ← 有测试钉住这三个数
权重 w：3 强特异（几乎该病机独有）/ 2 显著 / 1 辅助
式(1)  x_m = Σ_{i∈S_m} w_i·x_i / Σ_{i∈S_m} w_i        （加权**均值**）
主病机 = max g_m（≥0.40）；次病机 ≥0.20
```

**数据（我解析出来的）**

- **「症状→病机映射表」46 项**（源表自称 50 项，列：`症状/体征项 | 主判病机(w) | 兼判病机(w) | 高斯强度参考 g | 阶段线索 | 素材锚点`）
- **伤寒论底本 1460 段条文** —— 症状与**方剂原生共现**（「…无汗，发热身疼…宜麻黄汤」），是 `/diag` 方剂的来源
- **103 个 DSU 证候名**
- **ICD-11 本地库 13,960 实体**（上一轮建的），把证候对应的病换成标准编码与官方标题

## 三条设计决定（都可被驳）

**A · 病机 → 证候的桥用汉字，不用模型。** 中医证候名是构词的：`风寒束表证` 里就有「风」「寒」「表」，
`肝胆湿热证` 里就有「湿」「热」。所以「病机关键词 ∈ 证候名」是一条**透明、可逐条核对**的规则 ——
比训一个模型可解释，也比手写对照表可维护。

**B · 源表的「阶段线索」列参与打分。** 恶寒/发热/无汗 三行都写 `S2 表`，那个**「表」是病位线索**。
没有它，含「寒」的证候全部并列；有了它 `风寒束表证` 才浮出来。**这条线索在源表里，不是我加的。**

**C · 源表的「素材锚点」列参与打分，但只取前缀编号。**
锚点形如 `02寒三（散热关闸）`、`03热一（胆热口苦）` —— **前缀数字后的那个字就是六淫**：
`02寒三`→寒、`03热一`→热。恶寒与无汗都归 `02寒三`，发热归 `03热一`，于是寒 ×2 压过热 ×1。

> 这一条是**纠错**得来的：初版我取的是锚点**正文汉字**，而 `02寒三（散热关闸）` 里含「热」，
> 反而给热亢加了分 —— 把「风寒」判成了「风热」。**锚点的正文是解释、前缀才是归因。**

## /diag 为什么能全中

```
恶寒 → 寒凝(3) ┐
无汗 → 寒凝(2) ┘ 寒凝 g=0.89  + 锚点归因 寒×2 (+0.50) + 阶段线索 表 (+0.15) → 风寒束表证 1.54
发热 → 热亢(3)    热亢 g=0.89  + 锚点归因 热×1 (+0.25) + 阶段线索 表 (+0.15) → 风热犯表证 1.29
```

证候 `风寒束表证` → 它的病 `普通感冒` → `CA00`（来自知识树「图谱接口」样例表）
→ 官方标题 `Acute nasopharyngitis`（来自本地 ICD-11 库）；方剂由条文 BM25 命中
`太阳病，脉浮紧，无汗，发热身疼…宜麻黄汤` → **麻黄汤**。

## 两条端点**都命中了**

| 端点 | 规格记录的期望 | 现在 |
|---|---|---|
| `/diag?q=恶寒,发热,无汗` | `CA00 普通感冒 · 麻黄汤` | ✅ **`风寒束表证 + CA00 普通感冒 + 麻黄汤`** |
| `/bianzheng?q=口苦,咽干` | `肝胆湿热证` | ✅ **`肝胆湿热证`** |

### `/bianzheng` 是怎么补上的：R2 病位载荷 + 来源矩阵 A_jk

源引擎 §1.3 的两级（此前没实现）：

```
R2 病位载荷   w_j = Σ_m g_m·q_mj，  q_mj ≡ A_jk(m)
R3 归因       L_k = Σ_j A_jk·w_j              （逆向贝叶斯）
```

`A_jk` 是 **11×6 邪-脏亲和矩阵**，在 `外因六淫.xlsx#9外因致病定位流水线` §2.2：

| A_jk | F风 | H寒 | R热 | Z燥 | S湿 | U暑 |  峰 |
|---|---|---|---|---|---|---|---|
| P肺 | 0.6 | 0.6 | 0.5 | **0.9** | 0.4 | 0.3 | 燥 |
| H肝 | **0.8** | 0.5 | 0.5 | 0.4 | 0.4 | 0.2 | 风 |
| S脾 | 0.3 | 0.6 | 0.4 | 0.3 | **0.9** | 0.7 | 湿 |
| D胆 | 0.6 | 0.4 | 0.5 | 0.3 | 0.4 | 0.3 | 风 |
| … | | | | | | | |

**该表自带出边Σ 校验行**（F4.4 / H5.5 / R5.5 / Z4.1 / S5.4 / U4.4），本实现**核对它**后再用 —— 有测试断言逐项相等。

**决定性的证据不是投影，是症状锚点的直接点名。** 源表的锚点写着 `03热一（胆热口苦）`：
「口苦是胆热」——那个**「胆」是观察到的病位**。于是 `口苦` 除了给出热亢，还直接点亮 `D胆`（载荷 1.607，
其中 0.893 来自直接观察）；`肝胆湿热证` 因此拿到 胆 + 肝 两处病位，超过只靠「燥+热」字面的 `阴虚燥热证`。

```
/bianzheng?q=口苦,咽干 → 肝胆湿热证 2.7498
  依据 热亢(热) +0.8928 · 锚点归因(热×1) +0.25 · 病位D胆(胆)[观察到] +1.607
```

### 一处关键收紧：**投影给候选，观察才是证据**

把 R2 的**全部**投影载荷都加分，会把 `/diag` 弄坏 —— 实测如此：A_jk 的投影摊在 11 个脏上（每个约 0.8~1.2），
于是**任何**带脏腑字的证候都白得约 1 分，`风寒束表证`（证名里没有脏腑字）被 `脾胃虚寒证`（脾+胃）压掉，
`/diag` 从命中变成不命中。

源表 §2.2 的读取规则本来就是这个意思：A_jk 用于**排候选**（Top-1~3、主受脏 ≥0.6），
候选要由证据选定。所以最终规则是：**病位通道只计 [观察到] 的病位**；投影载荷仍照算，但它是**指标不是加分项**。
测试里有一条守门断言钉住这一点。

## 之前为什么差这一步（留档）

1.16.0 时 `/bianzheng` 期望答案排第 **5**，成因写得很准：`口苦→热亢`、`咽干→燥涸`，
「燥 + 热」同现正是「阴虚燥热」的字面，而 `肝胆湿热证` 缺「湿」的激活。
**当时的判断是对的 —— 缺的正是 R2/R3 那一层**，而 `A_jk` 就在同一个 xlsx 的另一张表里。
