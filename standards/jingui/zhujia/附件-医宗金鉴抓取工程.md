## 二、怎么找到的（这一步以前是空白）

笈成给《醫宗金鑑》的**总目页只有 1 KB 元数据**，没有目录：

```text
https://gitlab.com/jicheng/jc.data/-/raw/master/pages/book/醫宗金鑑/index.html   →  1,088 字节（只有作者/朝代/底本）
```

于是改用 GitLab API 枚举 `pages/book/` 全部 1,326 个子目录，按「金鑑 / 金匱」筛选，命中 5 个相关条目：

| 目录 | 说明 |
|---|---|
| `醫宗金鑑` | 多卷版（16 个子书目录） |
| `醫宗金鑑_1` / `_2` | 残卷（只有 `index.html` / `訂正仲景全書`） |
| **`醫宗金鑑_條列版`** | **11 个子书目录，其中 `訂正仲景全書金匱要略註` 即本条目标** |
| `醫宗金鑑_條列版/訂正仲景全書金匱要略註` | 单页 459 KB，**每条一个 `<pre>`** ← 采用 |

结论：**條列版是唯一可逐条定位的版式**（自带「編號：藏府001」），原版虽也可用，但注散在段中、需另做切分。

## 四、版式与解析规则（五个坑，都踩过）

每条一个 `<pre data-sec="p">`，形如：

```text
篇名：藏府經絡先後病脈證第一  編號：藏府001  經文：夫人秉五常…（原文）
按：[1]此篇乃一書之綱領…     註：[1]五常者，五行也…      集註：徐彬曰：「假如肝經之病…」
```

| # | 坑 | 现象 | 处理 |
|--:|---|---|---|
| 1 | `集註` 与 `註` 字段名重叠 | 「集註：」被切成「集」+「註：」 | 正则把 `集註` 排在 `註` 之前 |
| 2 | 金鑑**篇序与底本不同** | 「驚悸吐衄下血」金鑑是第十二、底本是第十六 | 篇按**名字**匹配，不按序号（按序号会整篇错位） |
| 3 | 底本篇名是**简体**、金鑑是繁体 | 相似度仅 0.36，**22 篇只认出 4 篇**（第一版实际结果） | 比对前先 t2s |
| 4 | 附篇 23-25 粒度不同 | 底本附篇「整篇 1 条」，金鑑逐方分立（191 个方块） | 附篇不参与条级对齐，`tiao` 留空、如实单列 |
| 5 | 底本附篇 `no` 为 None | 三篇被并成一篇，「雜療方」吞下 191 块 | 键改为 `("附", 篇名)` |

对齐仍以**文本相似度（≥0.60，前 60 字）**为准，金鑑「編號」作交叉验证；相似度认不出的块按編號兜底。

## 七、缺口（照录，不补写）

1. **金鑑「方」段只解析到 14 段**——方剂多以「方劑：」行内嵌在註段里，未单独立块；若要逐方方解，需另立解析。
2. **附篇 191 块无条号**——底本附篇不分条，本项目不替它编条号。
3. **卷次未标**——條列版不写卷次（原版有），教材出处行以篇名定位，不写「卷十八」这类未经核对的卷号。
4. **`〔鉴〕` 与金鑑本体的关系**：輯義转引的「〔鉴〕」引文与金鑑原文可能有删节，两处并存时以金鑑原书为准（已在 `校勘登记.md` 口径 §1 登记）。
