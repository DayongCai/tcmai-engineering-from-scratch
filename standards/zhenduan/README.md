## 1. 这是什么

中医系「中医诊断学」12 章课程引用的**教材底本**。母本为项目方提供的 Excel 工作簿（与中基同一套体系）：

| 版本 | 多智能体协同种子内容 · Hermes 改写版（v2.0-qhzy，2026-08） |
| 工作表 | 27（14 内容表 + 13 方法与平台表） |
| sha256 | `051d830a627c04cfd6e684f76537c19c691b63590fe3c0ca6bd3efa3ab9c5355` |

## 2. 产物

| 文件 | 内容 |
|---|---|

## 3. 口径（与 standards/jichu 一致）

- 引用写 **「教材·第N章·第M.M节」**，不写「底本」「原文」「经文」；
- 工作簿不按编号排列时**按编号归位**（中基曾出现 9.6.4 排在 9.7 之后）；
- 段末无句末标点的段记截断，不推断补字；
- 字数只算正文段，不算段标题（与各章口径统一：望诊 2,812 · 舌诊 1,249 · 闻诊 855 均按此）。

## 9. 两把尺子落地（2026-10-30，与病理学同级）

§8 的扫描结论是「数值不必返工，缺的是引证与覆盖」。这一轮把两件都做了。

**一、72 题引证（第 9 项门）**

| 类型 | 含义 | 是否核正文覆盖 | 题数 |
|---|---|---|--:|
| `依据` | 这一节的正文就是答案来源 | 核（≥15%） | 20 |
| `口径见` | 这一节规定的是本题口径或边界（如「不作判定」「不引全诗」） | 不核 | 8 |
| `算见` | 答案由本仓脚本对底本现算（字数、占比、条数、规则阈值），教材正文不含这个结论 | 不核 | 44 |
| `前提` | 前置题问「进本章之前要具备什么」 | 不核 | 0 |

**`算见` 是这一册新增的类型**，原因是实测出来的：本册 72 题里有 44 题问的是「望诊 2,812 字里哪一节最大」「26 单元 18 病 16 证」「score 为什么不能跨表比较」——这些答案不在教材任何一节的正文里，而在 `code/main.js` 对底本与规则的计算里。若强行标 `依据`，覆盖率判据会全部判红；若标 `口径见`，又把「可复算」与「不可核」混成一类。所以单立一类，语义是「可复算，但不在教材原文」——标的是统计或规则所落在的那一节，供人回查对象。

这一条同时暴露了本册 quiz 的性质：**六成题考的是教材统计与课程规则，不是条文内容**。门对它们只能核「引的节存在且属本章」，不能核内容对错。这一点写在这里，不粉饰。

实测：**72 / 72 有引证** · 硬错 0 · 软警 32 题（解析更贴近某干扰项，字面法固有假阳性）· 同词不同序 0 处。

**顺手修的一处假阴性**：选项常是「青赤黄白黑」「风关/气关/命关」这种以顿号、斜线分隔的枚举，教材原文写「青、赤、黄、白、黑」。原来只比原串，真·依据会被判成 0 覆盖。现改为「原串或去标点串命中即算命中」——放宽的是**匹配方式**，不是判据本身（仍要求 ≥15%）。

**二、单元级正文 99 段（第 10 项门）**

课程 12 章对应底本 13 章（第 9 章经络辨证在课程里没有对应章，**未映射，显式记账**），共 **99 个小节**，一小节一段：

| 项 | 值 |
|---|--:|
| 段落数 | **99 / 99**（每章 4–14 段，各不相同） |
| 总字 / 平均 / 最短 | 13,712 / **139** / 122 |
| docs 增长 | 12 章各加一节「教材小节：逐条落位」 |
| 每段结构 | 这一节在问什么 → 答案落在哪一层 → 与相邻小节什么关系 |

源文件 `standards/zhenduan/unit-notes/<课程章>.json`（含 `sources` 字段记住底本章号），由 `scripts/render_zhenduan_unit_notes.js` 渲染进 docs（`UNITNOTES:BEGIN/END` 幂等，`--check` 只比对）。第 10 项门核六件事：12 章齐、小节不重复落位、标题与底本一致、每段 ≥120 字、docs 与现算逐字一致、标题数等于段数。

**三、与病理学的差距，说清楚**

病理学 252 段平均 158 字（正在扩写到 ~300）；本册 99 段平均 139 字。两册的「层与门」完全相同，**深度都还不到生理学的 332 字**。诊断学底本本身只有 22,215 字（14 章），平均每小节约 210 字——正文比底本厚，但没有厚到可以展开推演的程度。

**重算**

```bash
node scripts/render_zhenduan_unit_notes.js          # 渲染 99 段进 docs（--check 只比对）
node scripts/apply_quiz_cites.js zhenduan <assign>  # 幂等写入引证（章号取自小节号，不取课程章号）
node tests/test_zhenduan_chapters.js                # 10 项门（含 quiz 语义 + 单元级正文）
```

**一处必须记住的坐标系差异**：课程第 5 章（问诊）对应教材第 4 章，课程第 8 章（脏腑辨证）对应教材第 8 章，课程第 10 章对应教材第 10+11+12 章。所以引证写成「教材·第4章·4.2.1」而课程章号是 5——`apply_quiz_cites.js` 因此改为**从 sub 推章号**，不取课程章号。

## 10. 单元层（units.json，2026-11-13 补）

| 项 | 值 |
|---|---|
| 切分 | 一小节一单元：章＝底本章，节＝底本节，小节＝单元 |
| 规模 | **105 单元** · 14 章 · 17,636 汉字 |
| locator | `教材·第N章·N.M.K`，沿用底本四级编号，可逐字回查 `底本.json` |
| 轴 | **不设三辨/四位面**：本底本没有那套编排，硬套一套词表算出来的是脚本的轴，不是教材的轴。只带 `measure`（digits / valueLike / listItems）与 `counts` |
| 重建 | `python scripts/build_textbook_units.py zhenduan`；校验 `python scripts/build_textbook_units.py --check`（已并入 `npm run check`） |

为什么补这一层（不是格式洁癖）：本课此前只有「底本 + 正文」两层，`standards/zhenduan/units.json` 缺席，
`scripts/build_kt_sphere_data.py` 与 `scripts/build_kt_history.py` 只扫 `standards/*/units.json`，
于是知识树与语义张量球面把本课记成**单元 0**——内容在库里，却不在统计口径里。
补上之后知识点按「一节一单元」进树，`brief` 取底本条目名（`items`），`goals` 取正文里的【学习目标】。
